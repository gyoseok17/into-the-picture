# 09. 비기능 요구사항 (NFR)

> 기능 외 품질 기준. 초기 MVP에서 지킬 최소선 + 향후 강화(10-future 연계).

## 반응형 / 호환

- **모바일 우선**. 브레이크포인트: ~640(모바일) / 641–1024(태블릿) / 1025+(데스크탑).
- 동일 코드로 **웹 + Android 앱(Capacitor)** 동작. iOS는 추후 동일 코드 빌드(A3).
- 지원: 최신 모바일 브라우저(크롬·사파리) + Android WebView.

## 성능

| 항목 | 기준/방법 |
|------|----------|
| 사진 피드 | 무한스크롤 + 페이지네이션(size 20), 이미지 lazy load·종횡비 고정 |
| 서버 상태 | TanStack Query 캐싱으로 재요청 최소화 |
| 외부 호출 | 어댑터에 타임아웃(예: 5s). 트래픽↑ 시 캐싱 데코레이터 추가(A1/C3) |
| 이미지 | (향후) 썸네일·WebP·CDN (C1) |

## 외부 API 의존 대응 (실시간 호출 리스크)

- **타임아웃 + 1회 재시도**, 실패 시 사용자에게 명확한 빈/에러 상태(앱 죽지 않게).
- **쿼터 초과(429)/장애(502)** 구분 메시지. 향후 서킷브레이커·폴백(D1).
- 집중률 매칭 실패는 정상 흐름으로 처리(섹션 숨김), 에러 아님.
- 관광사진 이미지 HTTP→HTTPS 치환/프록시(06 X4).

## 보안

- 전 구간 **HTTPS**, 적절한 **CORS** (허용 출처 화이트리스트).
- JWT 서명키·API 키는 환경변수/시크릿(`secrets.local.txt`는 git 제외). 운영은 시크릿 매니저(E3).
- 업로드: 매직바이트 검증·재인코딩·크기 제한·랜덤 파일명(07, E1).
- 인증 필요한 `/me/**`는 본인 리소스만 접근.
- (향후) rate limiting(E2), CSP(E4).

## 에러 처리 UX

- 모든 화면에 **로딩(Skeleton) / 빈 상태 / 에러+재시도** 3종 상태 정의.
- 에러는 공통 응답 포맷(04) → 프론트 공통 핸들러로 토스트/인라인 표시.

## 접근성 / 국제화 (향후)

- 이미지 `alt`, 충분한 대비, 키보드 포커스(F3).
- 다국어(i18n): 외부 데이터가 국/영문 동시 제공 → 글로벌 확장 유리(F1, G8).

## 관측성 (향후)

- 구조화 로깅, 에러 트래킹(Sentry 등, D2), 기본 헬스체크 엔드포인트.

## 테스트 / 품질

- 백엔드: 단위(서비스·파서) + 통합(컨트롤러·외부 어댑터 모킹).
- 프론트: 컴포넌트 + 주요 플로우.
- **경계면 검증**: API 응답 shape ↔ 프론트 훅 타입 일치 (하네스 QA 에이전트가 점진 검증).
