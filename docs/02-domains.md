# 02. 도메인 분해

> 이 문서는 하네스 구성의 **뼈대**다. 각 도메인이 하네스의 전문 에이전트로 매핑된다.
> (harness SKILL.md Phase 1 "주요 모듈 파악" → Phase 2 "전문 영역으로 분해" → Phase 3 "에이전트 정의")

## 도메인 분해 원칙

기능을 **응집도 높은 도메인** 단위로 나눈다. 각 도메인은:
- 백엔드: 독립 패키지 (`com.toursnap.{domain}`) — controller / service / repository / external-adapter
- 프론트: 독립 기능 폴더 (`src/features/{domain}`)
- 외부 API 의존이 있으면 어댑터 계층으로 격리

## 도메인 목록

| # | 도메인 | 핵심 책임 | 외부 API | 인증 필요 |
|---|--------|----------|----------|:---:|
| D1 | **auth** | 카카오 로그인, JWT 발급/검증, 회원 프로필 | Kakao OAuth | — |
| D2 | **photo-search** | 키워드(단풍/야경 등) 기반 관광 사진 피드 | 관광공사 사진 | X |
| D3 | **contest** | 공모전 수상작 탐색 (계절/키워드/등급 필터) | 공모전 수상작 | X |
| D4 | **crowd-timing** | 집중률 예측 → 30일 혼잡도·추천 방문일 캘린더 | 집중률 예측 | X |
| D5 | **map** | 촬영지 위치를 지도에 표시 | Kakao Map | X |
| D6 | **photo-compare** | 사용자 사진 업로드 + 수상작 나란히 비교 | — | O |
| D7 | **user-content** | 즐겨찾기/저장 등 개인화 (공통) | — | O |
| D8 | **shared/external-client** | 외부 API 호출·캐싱·에러 격리 공통 계층 | (전체) | — |

## 도메인별 상세

### D1. auth
- 카카오 OAuth2 인가 코드 → 액세스 토큰 → 사용자 정보 조회
- 신규 사용자 자동 가입, 기존 사용자 로그인
- 자체 JWT 발급 (이후 API 호출 인증)
- **작업 유형**: 생성(회원), 검증(토큰)

### D2. photo-search
- 키워드 → 관광공사 관광사진 API 조회 → 피드 형태 응답
- 키워드 사전: 단풍, 야경, 설경, 바다, 벚꽃 (+확장 가능)
- 페이지네이션, 캐싱
- **작업 유형**: 분석(키워드 매핑), 조회

### D3. contest
- 공모전 수상작 목록 조회 + 필터(계절·키워드·수상등급)
- 상세 보기 (사진, 수상정보, 촬영지)
- **작업 유형**: 조회, 필터링

### D4. crowd-timing
- 관광지 ID → 집중률 예측 API → 향후 30일 혼잡도
- 혼잡도 기반 추천 방문일 산출 로직
- 캘린더 형태 응답
- **작업 유형**: 분석(추천 산출), 조회

### D5. map
- 촬영지 좌표 → Kakao Map 표시 (프론트 SDK 중심)
- 백엔드는 좌표/장소 메타데이터 제공
- **작업 유형**: 조회, 표시

### D6. photo-compare
- 사용자 사진 업로드 (인증 필요) → 저장 (07 참고)
- 수상작과 나란히 비교 뷰
- 내 업로드 사진 관리(목록/삭제)
- **작업 유형**: 생성(업로드), 조회, 삭제

### D7. user-content
- 즐겨찾기(사진/수상작/관광지) 추가·조회·삭제
- 개인화 피드 기반 데이터
- **작업 유형**: 생성, 조회, 삭제

### D8. shared / external-client
- 4개 외부 API의 호출 클라이언트 + 응답→내부모델 변환 어댑터
- 캐싱(Caffeine), 재시도, 쿼터/장애 폴백
- 모든 외부 의존 도메인(D2~D5)이 공유
- **작업 유형**: 공통 인프라

## 예상 하네스 에이전트 매핑 (참고 — 하네스가 최종 결정)

도메인을 그대로 1:1 에이전트로 두면 너무 잘게 쪼개진다. 작업 성격으로 묶으면:

| 에이전트 후보 | 담당 도메인 | 역할 |
|--------------|-----------|------|
| **backend-domain** | D1~D7 백엔드 | 도메인별 controller/service/repository, JPA 엔티티 구현 |
| **external-integration** | D8 + D2~D5 외부연동 | 외부 API 어댑터·캐싱·DTO 변환 |
| **frontend** | D2~D7 화면 | React 컴포넌트, 라우팅, API 연동 훅 |
| **auth-security** | D1 | 카카오 OAuth + JWT + Spring Security |
| **qa-integration** | 전체 경계 | API 응답 ↔ 프론트 훅 shape 교차검증 (harness QA 가이드) |

> 위는 제안일 뿐, 실제 에이전트 구성은 하네스 스킬이 Phase 2~3에서 확정한다.
> 핵심은 이 도메인 경계가 명확해야 하네스가 잘 나눈다는 것.
