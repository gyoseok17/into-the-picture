- 변경 이유: 빈 스토리의 넓은 중앙 공간을 안내와 다음 행동에 직접 사용해 화면의 의도를 더 분명히 전달한다.

- 영향 범위: 비교 사진 크롭 편집기의 입력 처리만 바꾸며, 크롭 저장 형식·API·원본 사진은 변경하지 않는다.

- 변경 내용: 드래그로 바뀐 마지막 크롭 위치와 확정 시 서버에 보내는 크롭 값이 항상 일치하도록 상태 갱신·확정 흐름을 점검하고 보완한다.

- 영향 범위: 비교 크롭 편집기의 클라이언트 상태 처리와 확정 입력만 변경하며, 서버 API·DB 저장 형식은 유지한다.

- 영향 범위: 비교 결과 표시 컴포넌트만 변경하며, 저장 API·DB·원본 사진은 변경하지 않는다.

- 역할 분담: 백엔드는 마이그레이션 대상과 순서를 구현하고, QA·보안 검토는 기존 데이터·인덱스 의존성 및 Flyway 적용 안전성을 검토한다. 통합 리드는 문서·검증 결과를 대조한다.

## 다음 작업

### 001. 전체 기능 점검에서 기록한 후속 개선 후보 (2026-09-20)

- 운영 안정성: `docker-compose.yml`과 `.env.example`의 기본 이미지 태그가 현재 커밋 기준보다 오래된 `m8.3`이다. 배포 환경에서 태그를 생략해도 이전 이미지를 받지 않도록 기본값을 정리한다.
- 데이터 안전성: 묶음 삭제는 DB 트랜잭션 중 파일 저장소 삭제를 순차 실행한다. 뒤 단계가 실패하면 DB는 롤백돼도 먼저 지운 파일은 복구되지 않을 수 있으므로, 삭제 순서·보상 처리 또는 비동기 정리 방식으로 재설계한다.
- 성능: 앨범 묶음 조회와 저장 수상작 조회에 반복 조회(N+1)가 있어, 묶음·수상작 수가 늘면 요청과 DB 조회가 함께 증가한다. 일괄 조회 또는 조인/사전 적재로 개선한다.
- 오류 복구: 라우터에 전역 `errorElement`가 없어 예기치 않은 렌더 오류는 기본 오류 화면으로 끝난다. 사용자용 오류 화면과 다시 시도·이동 행동을 제공한다.
- 정리와 유지보수: 현재 웹 앱이 쓰지 않는 단일 사진 조회/지도 훅과 비교 사진 교체·저장 후 구도 수정 서버 API의 유지 여부를 결정한다. 유지한다면 호환 API임을 문서화하고, 제거한다면 소비자 확인 뒤 별도 마이그레이션으로 정리한다.
- 검증과 성능: V17을 실제 DB에 적용하는 Flyway 통합 검증과 배포 전 백업 절차를 추가하고, 큰 프런트 번들은 경로 단위 지연 로딩·컴포넌트 분리 후보와 함께 다음 작업에서 검토한다.
