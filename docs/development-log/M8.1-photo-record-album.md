# M8.1 사진 기록 앨범 — 완료

- 현재 상태: 완료
- 담당 통합 리드: Codex
- 관련 설계 문서: `docs/10-m6-photo-record.md`, `docs/04-api-spec.md`, `docs/08-screens.md`

> M8의 사진 중심 경험을 이어, 개인 사진을 기록·정리하는 다음 독립 기능 변경으로 분리했다.

## 계획

### 076. 단일 도메인 Docker Compose 배포 구성 (2026-09-17) — 진행 중

- 목표: Docker Compose만으로 프런트 정적 화면과 백엔드를 한 HTTPS 도메인에서 실행할 수 있게 한다.
- 구조: Caddy를 포함한 프런트 컨테이너가 외부 80/443을 받고, `/api/*`는 내부 `backend:8080`으로 프록시한다. Supabase는 외부 PostgreSQL로 유지하며 백엔드는 외부 포트를 열지 않는다.
- 환경: `APP_DOMAIN`과 운영용 `APP_AUTH_REFRESH_COOKIE_SECURE=true`를 배포 환경값으로 요구한다. 프런트 JavaScript 키만 빌드 인자로 전달하고, DB·JWT·서버 API 시크릿은 프런트 이미지·컨테이너에 주입하지 않는다.
- 범위 밖: S3/Supabase Storage 구현·파일 이관, 배포 서버 구매·DNS 연결·카카오 콘솔 실제 등록, DB/API 기능 변경은 포함하지 않는다.
- 역할: 프런트엔드는 정적 빌드·Caddy 설정을 맡는다. 백엔드는 Compose 네트워크·환경값·백엔드 노출 경계를 맡는다. QA·보안은 단일 도메인 프록시·시크릿 경계·HTTPS·빌드와 기존 실행 경로를 교차 검토한다.
- 검증: Compose 문법, 프런트·백엔드 이미지 빌드, 공개 포트·내부 API 경로, 시크릿 미포함, Docker 실제 기동 가능 여부를 확인한다.

### 075. Supabase 외부 DB용 Docker Compose 정리 (2026-09-16) — 진행 중

- 목표: 오래된 로컬 MySQL 전용 Docker Compose를 제거하고, Supabase PostgreSQL을 외부 DB로 사용하는 백엔드 컨테이너 실행 구성으로 바꾼다.
- 범위: 백엔드 이미지 빌드 정의, `backend/.env` 기반 환경변수 주입, 백엔드 포트와 임시 로컬 사진 볼륨을 포함한다. Supabase를 컨테이너로 띄우거나 DB 자격증명을 저장소에 넣지 않는다.
- 범위 밖: S3/Supabase Storage 구현·파일 이관, 운영 배포 플랫폼 선택, DB 스키마·API·인증 동작 변경은 포함하지 않는다.
- 역할: 백엔드는 컨테이너 구성과 Spring 실행 계약을 구현한다. QA·보안은 시크릿 미포함·외부 DB 연결·볼륨·실행 문서와 기존 실행 경로를 교차 검토한다.
- 검증: Compose 설정 문법, 이미지 빌드, 실제 DB 비밀값이 저장소에 없는지, 기존 Gradle 실행·테스트와 충돌하지 않는지 확인한다.

### 074. 수상작 비교 내 사진 메타데이터 표기 (2026-09-16) — 진행 중

- 목표: 수상작 비교 화면에서 노출되는 내 사진 파일명을 장소명과 촬영일 중심의 기록 정보로 바꾼다.
- 표기 규칙: 제목은 `장소명`을 우선하고, 없으면 촬영일, 둘 다 없으면 `내 사진`으로 표시한다. 촬영일은 제목 아래 보조 정보로 표시할 수 있으며, 메모는 목록·비교판 제목에 넣지 않는다.
- 범위: 수상작 비교 생성·사진 선택·결과 목록·결과 비교판의 사용자용 내 사진 명칭을 포함한다. 이미지 대체 텍스트, 원본 파일명 저장, 앨범 일반 화면·API·DB는 바꾸지 않는다.
- 역할: 프런트엔드는 공통 표시 규칙을 구현한다. QA는 장소 있음/없음·날짜 있음/없음·레거시 사진·사진 전용 결과와 화면별 일관성을 교차 검토한다.
- 검증: 사용자에게 파일명이 보이지 않고 같은 장소의 사진도 촬영일로 구별되며, 빈 기록에서 깨진 텍스트 없이 `내 사진`으로 안전하게 표시되는지 확인한다.

### 073. 수상작 비교 명칭과 사진형 진입점 정리 (2026-09-15) — 진행 중

- 목표: 비교 기능의 사용자용 명칭 `사진 놓기`를 `수상작 비교`로 통일하고, 사진 확대창의 `비교 보기` 텍스트 버튼을 수상작 원본 사진 진입점으로 바꾼다.
- 범위: 비교 기능 화면·안내·버튼의 사용자용 문구와 사진 확대창 하단의 비교 결과 진입 표현을 포함한다.
- 범위 밖: 앨범·사진 추가·사진 기록의 일반 문구, `/compare` 라우트·API·DB·비교 동작 변경은 포함하지 않는다.
- 역할: 프런트엔드는 명칭 범위와 사진형 진입점을 구현한다. QA는 문구 범위·지도/스토리·다중 비교·접근성·페이지 이동 없음을 교차 검토한다.
- 검증: 비교 기능만 새 명칭으로 표시, 수상작 원본 사진 클릭으로 인라인 비교창 열기, 미연결/다중/모바일에서 정보·진입점 일치 여부를 확인한다.

### 072. 사진 확대창 수상작 정보 하단 배치 (2026-09-15) — 진행 중

- 목표: 수상작 비교 사진의 확대창에서 사진 위에 겹치던 수상작 원본 미리보기를 제거하고, 사진 아래에서 수상작 정보와 비교 결과 진입을 제공한다.
- 범위: 지도·스토리 사진 확대창의 공통 수상작 연결 표현, 제목·지역·비교 보기 버튼과 인라인 비교 결과 연결을 포함한다.
- 범위 밖: 수상작 연결 데이터·비교 결과·사진 확대 자체·API/DB와 공개 정책 변경은 포함하지 않는다.
- 역할: 프런트엔드는 겹침 없는 하단 정보 구성을 구현한다. QA는 지도·스토리·단일/다중 비교·`PHOTO_ONLY`·반응형·중첩 창을 교차 검토한다.
- 검증: 연결 사진은 이미지가 가려지지 않고 하단 수상작 정보·비교 보기를 제공하며, 미연결 사진은 정보 영역이 없고 버튼은 페이지 이동 없이 비교창을 여는지 확인한다.

### 071. 지도 큰 사진 수상작 비교 트로피 배지 (2026-09-15) — 진행 중

- 목표: 지도 사진 패널의 중복 비교 연결 텍스트를 제거하고, 현재 큰 사진이 수상작과 비교됐을 때 사진 위 트로피로 알린다.
- 범위: 사진 좌측 상단 아이콘 배지와 인라인 비교 결과 진입을 포함한다.
- 범위 밖: 비교 연결 데이터·썸네일 트로피·사진 확대·비교 API/DB 변경은 포함하지 않는다.
- 역할: 프런트엔드는 사진 위 배지와 클릭 전파를 구현한다. QA는 연결 판정·사진 전환·확대와 비교창 충돌·접근성·모바일을 교차 검토한다.
- 검증: 연결 사진만 배지 표시, 배지는 비교창만 열고 큰 사진 확대는 열지 않음, 단일/다중 사진과 썸네일 표시 일치 여부를 확인한다.

### 070. 인라인 수상작 비교 창 가운데 화살표 제거 (2026-09-15) — 진행 중

- 목표: 앨범·수상작 상세에서 여는 PC 비교 확대 창의 가운데 화살표를 제거한다.
- 범위: 인라인 비교 결과 창의 비교판 표현만 조정한다.
- 범위 밖: 사진 놓기 관리·다른 비교 화면의 화살표, 비교 데이터·API·DB와 모바일 레이아웃 변경은 포함하지 않는다.
- 역할: 프런트엔드는 공통 비교판을 범위 있게 구성한다. QA는 인라인/비인라인 비교판·PC/모바일 회귀를 교차 검토한다.
- 검증: PC 인라인 비교 창 화살표 없음, 다른 비교 화면 유지, 이미지 정렬·모바일 동작 유지 여부를 확인한다.

### 069. 지도 사진 썸네일 전환과 확대 동작 분리 (2026-09-15) — 진행 중

- 목표: 지도 패널의 아래 사진 목록은 큰 사진만 전환하고, 확대 보기는 큰 사진을 눌렀을 때만 열리게 한다.
- 범위: 지도 다중 사진 썸네일의 클릭 처리·접근성 문구를 조정한다.
- 범위 밖: 사진 확대창·트로피·비교 결과·방문 기록·파일 API와 DB 변경은 포함하지 않는다.
- 역할: 프런트엔드는 클릭 책임을 분리한다. QA는 다중/단일 사진·트로피·확대·모바일을 교차 검토한다.
- 검증: 썸네일 클릭은 큰 사진만 변경하고, 큰 사진 클릭만 확대 창을 여는지 확인한다.

### 068. 지도 사진 목록 수상작 연결 표시 정리 (2026-09-15) — 진행 중

- 목표: 지도 정보 패널의 사진 목록에서 수상작과 비교한 사진을 트로피로 바로 알아보게 하고, 중복되는 연결 수상작 목록은 제거한다.
- 범위: 지도 패널 다중 사진 썸네일의 연결 표시와 `연결된 수상작` 목록 제거를 포함한다. 비교 결과 접근은 사진 확대 안의 수상작 원본으로 유지한다.
- 범위 밖: 수상작 연결 데이터·API·DB, 스토리 카드의 기존 트로피, 비교 생성·공개 정책 변경은 포함하지 않는다.
- 역할: 프런트엔드는 지도 썸네일 트로피와 중복 목록을 정리한다. QA는 사진별 연결 판정·다중 사진·확대 비교 접근·모바일 적층을 교차 검토한다.
- 검증: 연결/미연결 사진이 섞인 묶음에서 해당 썸네일만 트로피 표시, 선택 상태와 겹치지 않음, 목록 제거 뒤 확대 비교 결과 접근 유지 여부를 확인한다.

### 067. 수상작 상세 안 비교 결과 보기 (2026-09-15) — 진행 중

- 목표: 수상작 상세에서 비교 결과를 확인해도 사진 놓기 페이지로 이동하지 않고, 현재 상세 화면 위에서 확인하고 돌아오게 한다.
- 범위: 수상작 상세의 비교 결과 진입점과 공통 인라인 비교 창 연결, 중첩 오버레이의 닫기·초점·모바일 레이어를 포함한다.
- 범위 밖: 비교 생성·수정·공개 정책·비교 API/DB와 수상작 상세 데이터 변경은 포함하지 않는다.
- 역할: 프런트엔드는 상세 진입점과 인라인 비교 창을 연결한다. QA는 본인/공개 비교·빈 상태·상세 유지·중첩 창·반응형을 교차 검토한다.
- 검증: 상세에서 비교 확인 뒤 URL 이동 없음, 창 닫기 뒤 같은 수상작 상세·공개 사진 선택 상태 유지, 모바일·PC Escape·초점·적층을 확인한다.

### 066. 앨범 안 수상작 비교 결과 보기 (2026-09-15) — 진행 중

- 목표: 앨범 사진 확대 보기에서 연결 수상작이나 비교 결과를 눌러도 사진 놓기 페이지로 이동하지 않고, 현재 스토리·지도 화면 위에서 비교 결과를 확인하게 한다.
- 범위: 앨범의 스토리·지도 사진 상세에서 비교 결과 오버레이를 열고 닫은 뒤 원래 사진·지도 상태로 복귀하는 흐름을 포함한다.
- 범위 밖: 비교 생성·수정·삭제·공개 관리, 비교 데이터·API·DB와 사진 놓기 페이지 자체의 동작 변경은 포함하지 않는다.
- 역할: 프런트엔드는 앨범과 비교 결과의 인라인 연결을 구현한다. QA는 스토리·지도·중첩 확대창·PHOTO_ONLY·모바일·키보드·복귀를 교차 검토한다.
- 검증: 수상작 원본/비교 링크 클릭 뒤 URL 이동 없음, 비교 결과 닫기 뒤 원래 앨범 확대 상태 유지, 지도·스토리·여러 연결 사진·사진만 표시 모드를 확인한다.

### 065. 앨범 지도 사진 확대 보기 (2026-09-15) — 진행 중

- 목표: 지도에서 장소 마커를 선택한 뒤 표시되는 사진을 누르면 스토리와 같이 확대해 볼 수 있게 한다.
- 범위: 지도 정보 패널의 대표 사진·묶음 썸네일에서 사진 상세 라이트박스를 열고 닫는 흐름, 모바일·PC 레이어와 키보드 닫기를 포함한다.
- 범위 밖: 지도 좌표·마커·방문 기록·대표 설정·수상작 비교 연결·파일 API와 DB 변경은 포함하지 않는다.
- 역할: 프런트엔드는 지도 패널과 기존 사진 상세 보기의 연결을 구현한다. QA는 다중 사진·방문 기록·비교 링크·레이어·복귀 흐름을 교차 검토한다.

### 001. 기존 사진 기록 모델 확장 — 2026-08-25

- 결정: 원본 파일(`UserPhoto`)과 사진 기록(`PhotoRecord`)의 분리를 유지하고, 사진첩 메타데이터·보관·표시 상태는 사진 기록에 둔다.

### 002. 촬영일 EXIF와 개인정보 — 2026-08-25

- 결정: 새 JPEG에서 `DateTimeOriginal`(대체 `DateTime`)만 읽어 촬영일을 보완한다. GPS를 포함한 위치 메타데이터는 읽거나 저장하지 않는다.
- 이유: 기록 편의성은 제공하되 원치 않는 위치 정보 수집을 피한다.

### 003. 업로드 전 촬영일 확인 — 2026-08-26

- 결정: 사진을 선택한 직후 브라우저에서도 JPEG·PNG·WebP 촬영일 EXIF를 읽어 촬영일 입력칸에 미리 채운다. 사용자가 이미 쓴 날짜는 덮어쓰지 않으며, 추출 중·미상 상태를 바로 안내한다.
- 이유: 서버 업로드 뒤에야 자동 추출 결과를 확인하면 사용자가 날짜의 정확성을 보고 수정할 기회를 놓친다.
- 호환성: 서버의 EXIF 추출은 그대로 유지해 브라우저 추출 실패·우회 요청에서도 최종 보완 역할을 한다. GPS는 계속 읽거나 저장하지 않는다.

### 004. 개인 사진 업로드 형식 확장 — 2026-08-26

- 결정: 개인 사진의 모든 업로드 경로에서 JPEG·PNG·WebP·HEIC/HEIF 네 형식을 지원한다. 확장자가 아닌 요청 MIME과 실제 파일 서명을 함께 검증한다.
- 이유: 일반 갤럭시·디지털카메라 사진은 JPEG가 많고, 고효율 사진을 켠 갤럭시와 아이폰 원본은 HEIC/HEIF일 수 있다. PNG·WebP는 스크린샷·웹에서 가져온 사진 대응에 남긴다.
- 호환성: HEIC/HEIF를 렌더링하지 못하는 브라우저도 업로드·기록·삭제는 가능하며 미리보기만 안내 상태로 대체한다. AVIF와 RAW는 이번 범위 밖이다.

### 037. 앨범 지도 transform-origin 행렬 재검증 (2026-09-10)

- 구현: 프런트는 Node 빌드 뒤 Caddy 런타임으로 실행하고, Caddy만 외부 `80/443`을 열도록 구성했다. 같은 도메인의 `/api/*`와 기존 호환 `/files/*`는 내부 `backend:8080`으로 먼저 프록시하고 나머지는 SPA fallback으로 제공한다. 백엔드 호스트 포트 노출은 제거했다.

- 범위 보존: Supabase는 외부 DB로 유지하며 기존 Gradle 실행 경로·API·DB·인증 계약은 바꾸지 않았다. S3/Supabase Storage는 구현하지 않았으므로 업로드 볼륨은 단일 서버 임시 운영 한계로 유지한다.
- QA: 공개 포트·내부 네트워크, 프록시와 SPA fallback 순서, 인증서 볼륨, 키 이름, 시크릿 경계, `.dockerignore`, 기존 실행 경로를 교차 검토했다. `docker compose config --quiet`(안전 placeholder), 프런트 typecheck/build, Gradle 테스트, `git diff --check` 통과. Docker Desktop Linux 엔진 미기동으로 실제 이미지 빌드·컨테이너 시작·TLS 발급은 미검증이다. 배포 전 `backend/.env`의 `APP_DOMAIN`·`VITE_KAKAO_JS_KEY` 설정과 Docker 기동 검증이 필요하다. 근거: `_workspace/contracts/M8.1-single-domain-compose.md`, `_workspace/contracts/M8.1-frontend-caddy-static-proxy.md`, `_workspace/backend/M8.1-single-domain-compose-report.md`, `_workspace/frontend/M8.1-frontend-caddy-static-proxy-report.md`, `_workspace/qa/M8.1-single-domain-compose-qa.md`.
