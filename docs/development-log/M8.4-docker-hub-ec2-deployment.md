- 목표: 현재 Compose가 로컬 `build:` 대신 Docker Hub의 M8.3 이미지를 pull하여 EC2에서 실행하게 한다.
- 이번 범위: Compose 이미지 참조 전환, 배포 환경 변수 설명, Compose·프런트·보안 교차 검증.

- 역할 분담: 백엔드·배포는 Compose 변경, 프런트엔드는 빌드 시점 변수와 Caddy 경계 검토, QA·보안은 환경 변수·포트·IAM 경계를 검증한다.
- 검증 계획: Compose 렌더링, Docker Hub 이미지 pull, 프런트 빌드 및 설정 문서 대조.

## 설계 결정

### 001. 로컬 빌드가 아닌 고정 Docker Hub 태그 실행 (2026-09-18)

- 결정: Compose가 `gyoseok/into-the-picture-{frontend,backend}:${APP_IMAGE_TAG:-m8.3}`를 사용한다.
- 이유: EC2에는 소스·빌드 도구가 아닌 검증된 이미지와 운영 환경값만 전달한다.
- 영향 범위: 로컬 Compose도 Hub 이미지를 pull해 실행한다. 프런트 공개 키 변경은 새 이미지 빌드·푸시가 필요하다.

## 구현 변경

### 001. Docker Hub 이미지 실행 전환 (2026-09-18 / 백엔드·배포)

- 변경 내용: frontend/backend `build:`를 각각 Docker Hub `image:`로 교체하고, 이미지 태그 환경값과 EC2 실행 명령을 문서화했다.
- 변경 이유: EC2에 소스 전체를 업로드하지 않고 Hub의 M8.3 이미지를 pull해 실행하기 위해서다.
- 영향 범위: backend Compose, 환경 변수 예시, 배포 안내. API·DB 계약은 변경하지 않았다.
- 호환성 메모: `APP_IMAGE_TAG` 미지정 시에도 현재 검증 태그 `m8.3`을 사용한다.
- 관련 계약·설계·QA 근거: `_workspace/contracts/M8.4-docker-hub-compose.md`, 역할별 M8.4 보고서.

## 역할별 결과

### 001. 백엔드·배포 (2026-09-18)

- 변경 범위: 이미지 참조 Compose, `.env.example`, README.
- 검증: `docker compose config --quiet`, 이미지 목록이 두 Hub `m8.3` 태그를 가리키는지 확인.
- 발견·해결한 위험: 기존 `--build` 안내와 런타임 Vite 키 안내를 제거했다.

### 002. 프런트엔드·프록시 (2026-09-18)

- 변경 범위: 검토만 수행, 프런트 코드 변경 없음.
- 검증: `npm run build`, Hub frontend `m8.3` pull, Caddy API·파일 프록시 경로 확인.
- 발견: Kakao JS 키는 빌드 시점 번들 값이라 EC2 `.env`만 바꿔서는 교체되지 않는다.

### 003. QA·보안 (2026-09-18)

- 판정: 통과. 실제 EC2 DNS/TLS·IAM S3·DB 연결은 배포 시 확인한다.
