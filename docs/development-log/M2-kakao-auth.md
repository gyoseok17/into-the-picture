# M2 — Kakao 로그인 및 세션 보안 · 완료

- 구현 커밋: `5ad6e25` (`feat: M2 카카오 로그인 및 세션 보안`)
- 기간: 2026-08-02 ~ 2026-08-03

## 구현

- Kakao 인가 코드 리다이렉트 로그인, 서버 측 코드 교환, 회원 생성·갱신을 구현했다.
- 액세스 토큰은 15분 수명의 메모리 상태로만 사용하고, 리프레시 토큰은 14일 수명의 HttpOnly 쿠키로 전달한다.
- 리프레시 토큰은 DB에 해시로 저장하고 갱신마다 회전한다. 로그아웃은 인증을 요구하며 쿠키를 만료한다.
- 비로그인/로그인 헤더와 모바일 메뉴의 로그인·로그아웃 동선을 분리했다.

## 설계 결정과 이유

- 초기 SDK 직접 로그인 대신 인가 코드 리다이렉트 방식을 사용해 브라우저에 토큰을 보관하지 않도록 변경했다.
- 배포 환경에서는 HTTPS와 `Secure` 리프레시 쿠키를 사용하고, 로컬 HTTP 개발에서는 해당 옵션을 비활성화한다.

## 검증

- 백엔드 자동 테스트와 프런트엔드 프로덕션 빌드를 통과했다.
- 로컬 브라우저에서 실제 카카오 로그인, 세션 복원, 로그아웃, 리프레시 쿠키의 `HttpOnly`·`SameSite=Lax` 속성을 확인했다.
- 리프레시 쿠키가 없는 비로그인 초기 요청의 `401`은 정상 상태로 처리한다.

## 특이사항 / 다음 작업

- 배포 전 HTTPS, 허용 Origin/CORS, Kakao 플랫폼·리다이렉트 URI, 운영 환경의 클라이언트 시크릿 설정을 점검한다.
- 배포 HTTPS 환경 검증은 별도 후속 항목으로 관리한다.
