## 계획

### 001. 로컬·S3 사진 저장소 선택 지원 (2026-09-17)

- 목표: 기존 로컬 파일 저장을 보존하면서, 환경값만으로 S3 저장소를 선택해 사진 업로드·조회·삭제를 처리한다.
- 이번 범위:
  - `FileStorage`의 로컬 구현을 기본값으로 유지한다.
  - AWS SDK 기반 `S3FileStorage`와 `APP_STORAGE_TYPE`, 리전·버킷 환경값을 추가한다.
  - 저장 키 `u/{userId}/{uuid}.{ext}`와 기존 API·DB 계약을 유지한다.
  - S3 권한·오류·삭제·기존 로컬 데이터 호환성을 검증한다.
- 범위 밖:
  - 기존 로컬 업로드 파일의 S3 이관, CloudFront, 브라우저 직접 S3 업로드, 이미지 변환, EC2 생성·실배포.
- 역할 분담과 의존성:
  - 백엔드: SDK, 설정 바인딩, S3 구현, 단위 테스트, API/저장 키 계약 보고.
  - QA·보안: 최소 IAM 권한, private bucket 전제, 로컬 기본 동작·S3 오류 경로와 회귀 위험 검토.
  - 통합 리드: 계약, 문서, 역할 결과 통합, 최종 검증과 단일 커밋.
- 계약과 검증 계획:
  - `_workspace/contracts/M8.3-selectable-file-storage.md`에 선택 규칙과 키·URL 불변 계약을 남긴다.
  - 백엔드 테스트와 `./gradlew.bat test`를 실행한다. 실제 S3 연결은 사용자의 로컬 AWS 자격 증명 준비 뒤 별도 통합 확인한다.

## 설계 결정

### 001. 저장 키와 조회 경로를 유지하는 저장소 교체 (2026-09-17)

- 결정: `APP_STORAGE_TYPE`의 기본값은 `local`이며, `s3`일 때만 S3 구현체를 선택한다. 두 구현체 모두 `u/` 접두어와 API가 권한 확인 후 파일을 제공하는 현재 접근 방식을 유지한다.
- 이유: 배포 전 로컬 S3 검증과 운영 전환을 설정으로 분리하고, 기존 DB의 `storage_key`와 프런트 파일 URL 계약을 변경하지 않기 위함이다.
- 검토한 대안과 선택하지 않은 이유:
  - S3를 항상 강제: 로컬 개발과 기존 서버 디스크 데이터 접근을 깨뜨린다.
  - S3 공개 URL 직접 제공: 비공개 사진·공개 비교 사진의 서버 권한 검증 경계를 약화한다.
- 영향 범위: 백엔드 저장소 구현·환경 예시·배포 문서·테스트.
- 후속 조건 또는 작업: 실제 EC2에서는 IAM 역할을 이용하고 장기 AWS 접근 키를 환경값에 넣지 않는다.

## 계획 변경

## 구현 변경

### 001. Local/S3 저장소 어댑터 선택 (2026-09-17 / 백엔드)

- 변경 내용: AWS SDK v2 기반 `S3FileStorage`, 설정 바인딩과 조건부 빈을 추가했다. `APP_STORAGE_TYPE` 미설정·`local`은 기존 로컬 저장소를 사용하고, `s3`은 리전·버킷을 검증한 뒤 S3를 사용한다.
- 변경 이유: 개발·테스트 환경의 서버 디스크 저장을 유지하면서 운영용 S3 전환을 코드 재배포 없이 설정으로 선택하기 위함이다.
- 영향 범위: 사진 업로드·조회·삭제의 내부 저장 위치, backend 환경 예시·Compose·저장소 문서. API DTO·DB 스키마·저장 키·프런트 URL은 변경하지 않았다.
- 호환성 메모: 기존 로컬 파일은 자동 이관하지 않는다. 해당 DB 레코드가 있는 상태에서 S3 모드로 전환하려면 별도 이관이 필요하다.
- 관련 계약·설계·QA 근거: `_workspace/contracts/M8.3-selectable-file-storage.md`, `_workspace/backend/M8.3-selectable-storage-report.md`, `_workspace/qa/M8.3-selectable-storage-qa.md`

### 002. 로컬 Docker S3 자격 증명 분리 (2026-09-18 / 백엔드)

- 변경 내용: Git 제외 `docker-compose.local.yml`이 호스트 `%USERPROFILE%/.aws`만 appuser 홈으로 읽기 전용 연결하고 `AWS_PROFILE=into-the-picture-local`을 선택하도록 했다. 실제 `.env`의 로컬 도메인은 `localhost`로 설정했다.
- 변경 이유: 기본 운영 Compose·Docker 이미지·저장소에 AWS 키를 넣지 않고, 로컬 컨테이너에서만 AWS CLI 프로필을 사용할 수 있게 하기 위함이다.
- 영향 범위: 로컬 Docker S3 통합 검증 방식. 운영 EC2 Compose와 IAM 역할 방식은 변경하지 않았다.
- 호환성 메모: override 파일은 Git 제외이며, AWS CLI 프로필을 만들지 않은 PC에서는 S3 모드 요청이 인증 실패한다.
- 관련 계약·설계·QA 근거: `_workspace/backend/M8.3-local-compose-s3-report.md`, `_workspace/qa/M8.3-local-compose-s3-qa.md`

### 003. WSL 로컬 Compose S3 업로드 확인 (2026-09-18)

- 로컬 Docker Compose에서 `APP_STORAGE_TYPE=s3`로 사진 업로드가 성공했다. S3 쓰기 경로와 애플리케이션의 DB 기록 경로가 함께 동작함을 확인했다.
- 원인과 보정: 기존 로컬 override의 Windows 형식 AWS 설정 폴더 경로가 Docker Desktop/WSL 경계에서 빈 디렉터리로 마운트됐다. Git 제외 로컬 override의 bind source를 WSL에서 확인한 실제 경로로 보정했다.
- 영향 범위: `docker-compose.local.yml`만 변경했으며, 이 파일은 Git 제외 대상이다. 배포 Compose 및 EC2 IAM 역할 방식에는 영향을 주지 않는다.

## 역할별 결과

### 001. 백엔드 (2026-09-17)

- 변경 범위: S3 SDK, 조건부 저장소 구성, S3 저장·조회·삭제 어댑터, 환경 예시, 단위 테스트.
- 설계 결정과 이유: AWS SDK 기본 자격 증명 체인을 사용해 로컬 AWS CLI/SSO와 EC2 IAM 역할을 같은 코드로 지원했다. S3 URL 대신 기존 백엔드 권한 경로를 유지했다.
- 검증: `gradlew.bat test`, `gradlew.bat bootJar` 성공.
- 해결한 위험: Local/S3 저장 키 생성 규칙을 공통 모듈로 합쳤고, 잘못된 저장소 종류·S3 필수값 누락을 시작 단계에서 실패하게 했다. 신뢰하지 않는 원본 파일명에서 경로 세그먼트가 만들어지지 않도록 안전 확장자만 허용했다.
- 남은 위험 또는 후속 작업: 실제 AWS 자격 증명으로 private S3의 upload/load/delete를 실행해야 하며, 기존 로컬 객체 이관은 별도 결정이 필요하다.

### 002. QA·보안 (2026-09-17)

- 변경 범위: 저장소 선택 계약, 최소 IAM 권한, private bucket 경계, 오류·호환성·파일명 안전성 교차 검토.
- 검증: `backend\\gradlew.bat test --rerun-tasks`, `backend\\gradlew.bat bootJar` 성공.
- 발견·해결한 위험: AWS SDK mock 오버로드, 중복 키 생성, 잘못된 저장소 타입, 파일명의 경로 삽입 가능성을 발견해 회귀 테스트와 함께 해소했다.
- 다음 역할 전달 사항: 실제 S3 통합 검증 시 버킷이 private인지, 객체가 `u/` 아래에만 생성되는지, API 밖 S3 URL이 노출되지 않는지 확인한다.

### 003. QA·보안 — 로컬 Compose override (2026-09-18)

- 검증 범위: AWS 키 미포함, Git 제외, 읽기 전용 bind mount, 프로필 이름 일치, 기본 Compose 비변경과 병합 설정 검증.
- 검증: `docker compose -f docker-compose.yml -f docker-compose.local.yml config --quiet` 성공.
- 차단 이슈: 없음.
- 남은 작업: AWS CLI 프로필 준비 뒤 실제 private S3 Put/Get/Delete를 실행한다.

## QA

### 001. 선택형 저장소 통합 검토 (2026-09-17)

- 검증 범위와 방법: Local/S3 조건부 빈, S3 필수 설정 fail-fast, 키·URL 불변 계약, IAM 최소 권한, 예외 경계와 기존 업로드 보상 경로를 코드·단위 테스트로 교차 검토했다.
- 통합 교차 검증: API·DB `storage_key`·파일 조회 권한 계약은 유지되고, S3는 private 객체 저장소로만 사용한다.
- 차단 이슈: 없음. 발견한 세 가지 구현·테스트 이슈는 수정과 회귀 테스트까지 완료했다.
- 권고 사항: EC2 생성 전 로컬 AWS 자격 증명으로 실제 private bucket upload/load/delete를 한 번 확인한다.
- 통합 판정: 통과. 실제 AWS 통합 검증은 운영 전 확인 항목이다.

### 002. 로컬 Docker S3 쓰기 통합 확인 (2026-09-18)

- 검증: WSL에서 Compose 설정 문법 검증 후 컨테이너에 AWS 프로필 파일이 마운트되는 것을 확인했고, 사용자 사진 업로드가 성공했다.
- 판정: 통과. S3 자격 증명 전달 및 쓰기 경로에 차단 이슈 없음.
