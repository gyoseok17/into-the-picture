## 계획

### 001. 초기 계획 — 2026-08-12

- 목표: 탐색과 개인 사진 기록 경험을 사진 중심의 차분한 화면 구조로 개편하고, 사진첩의 앨범·스토리·지도 기능을 단계적으로 완성한다.
- 이번 범위: 첫 슬라이스로 메인 화면, 공통 화면 패턴, 내비게이션의 시각적 구조를 개편한다. 기존 API와 기능은 유지한다.
- 범위 밖 항목: 사진 기록 편집·정렬·보관 API, 사진첩 스토리·지도 화면, 공유·좋아요, 외부 장소 검색 연동.
- 역할 분담과 의존성: 프런트엔드는 메인·공통 UI·내비게이션을 구현한다. 통합 QA는 기존 API·반응형·접근성 회귀를 병렬 검토한다. 통합 리드는 정보 구조·기록·통합을 담당한다.
- 계약과 검증 계획: 기존 공개 데이터 API만 사용하며 API 계약 변경은 없다. 프런트 프로덕션 빌드, 모바일·데스크톱 화면 흐름, QA 교차 검토를 확인한다.

## 계획 변경

### 001. 에디토리얼 홈 구조로 전환 (2026-08-14)

- 변경 내용: 일반적인 `히어로 + 동일 크기 카드 그리드 + 링크` 구조를 중단하고, 대표 장면·가로 사진 필름·혼잡도 탐색·간결한 검색 진입을 순서대로 경험하는 홈으로 전환한다.
- 변경 이유: 색상만 바꾼 기존 구조는 여행 서비스 템플릿처럼 보이며, 사진 중심 서비스의 개성이 충분히 드러나지 않았다.
- 영향 범위: 홈 화면과 공통 색상 토큰만 변경한다. 기존 수상작·검색·혼잡도·사진 기록 API와 라우팅 계약은 유지한다.
- 되돌리기: `HomePage`의 섹션 구성과 공통 토큰을 이전 M8 첫 화면 상태로 복원하면 된다.

### 002. 모바일을 별도 장면 구성으로 조정 (2026-08-14)

- 변경 내용: 데스크톱의 좌우 분할을 모바일에 단순히 세로로 쌓는 방식 대신, 옅은 민트 배경 면과 사진·문장이 하나의 장면으로 이어지는 모바일 전용 히어로 흐름으로 조정한다.
- 변경 이유: 모바일의 흰 여백과 텍스트·사진 분리는 첫 화면을 심심하고 부자연스럽게 만들었다.
- 영향 범위: 모바일 전용 레이아웃·간격·배경 표현만 바꾼다. 콘텐츠 순서와 기능 경로는 유지한다.

### 003. 홈 전체를 하나의 흐름으로 정리 (2026-08-14)

- 변경 내용: 히어로와 추천 구간만 스타일을 바꾸는 데서 멈추지 않고, 혼잡도·검색·개인 사진 진입까지 같은 민트 기반의 에디토리얼 리듬으로 연결한다.
- 변경 이유: 구간마다 흰 배경·테두리·카드 방식이 달라 홈이 기능 묶음처럼 분절되어 보였다.
- 영향 범위: 홈의 섹션 표면, 여백, 사진 비중, 전환 표현을 변경한다. 데이터·기능·라우팅은 유지한다.

### 004. 기능 인덱스 시범 추가 (2026-08-14)

- 변경 내용: 히어로 뒤에 수상작·사진 검색·혼잡도·내 사진 기능을 한눈에 훑는 작은 목차를 추가한다.
- 변경 이유: 감성적인 화면 흐름만으로는 서비스가 제공하는 기능 범위를 처음 방문한 사용자가 빠르게 파악하기 어려웠다.
- 구현 원칙: 색 카드 묶음이 아닌 번호·가는 선·짧은 설명의 에디토리얼 인덱스로 만들고, 별도 블록으로 두어 피드백에 따라 쉽게 제거할 수 있게 한다.

### 005. 이달의 원본 대표 사진 (2026-08-14)

- 변경 내용: 최근 등록 수상작의 썸네일을 대표로 쓰는 방식을 바꾸고, 현재 달에 촬영된 작품 중 한 건을 선택해 상세 원본 이미지로 표시한다.
- 변경 이유: 목록 첫 항목은 홈 대표 기준이 아니며, 썸네일 확대는 히어로에서 화질이 낮다.
- 계약: `_workspace/contracts/M8-monthly-featured-contest.md`에 기존 공개 API 두 건과 폴백을 기록한다. API·DB 변경은 없다.

### 006. 모바일 사진 열 수 설정 (2026-08-14)

- 변경 내용: 수상작과 키워드 검색 결과에서 모바일 사진을 1열·2열로 전환할 수 있게 하고, 기본은 2열로 둔다.
- 변경 이유: 한 장씩만 크게 보이는 결과에서는 여러 사진을 훑고 비교하기 어렵다.
- 계약: `_workspace/contracts/M8-mobile-grid-preference.md`에 공통 저장값, 폴백, 접근성 기준을 기록한다.

### 007. 무한 스크롤 빠른 조작 추가 (2026-08-14)

- 변경 내용: 결과를 많이 내린 뒤 위로 가기와 다시 검색·조건 변경을 바로 할 수 있는 고정 도구를 수상작과 검색에 추가한다.
- 변경 이유: 무한 스크롤에서는 상단 입력·필터 영역으로 복귀하기가 불편하다.
- 계약: `_workspace/contracts/M8-infinite-scroll-assist.md`에 화면별 포커스 이동, 모션, 하단 탭 안전 여백 기준을 기록한다.

### 008. 결과 위치에서 인라인 검색·필터로 변경 (2026-08-14)

- 변경 내용: 상단으로만 이동하던 다시 검색·조건 변경을 아이콘 전용 빠른 조작으로 바꾸고, 현재 위치에서 열리는 패널로 검색어·필터를 바로 적용한다.
- 변경 이유: 무한 스크롤을 다시 올리지 않으려는 목적과 기존 동작이 맞지 않았다.
- 계약: `_workspace/contracts/M8-inline-result-actions.md`에 상태 공유·패널 접근성·스크롤 유지 기준을 기록한다.

### 009. 목록 복귀와 앨범 모달 스크롤 보존 (2026-08-16)

- 변경 내용: 수상작 상세에서 뒤로 돌아올 때 목록 스크롤 위치를 복원하고, 키워드 검색 앨범 모달의 내부 스크롤이 배경 목록으로 전파되지 않게 한다.
- 변경 이유: 긴 목록 탐색 흐름이 상세 진입·앨범 확인 뒤 끊기고, 사진이 많은 앨범에서 배경 결과까지 함께 움직였다.
- 계약: `_workspace/contracts/M8-scroll-state.md`에 복귀 시점, 직접 진입 예외, 모달 잠금·복원 기준을 기록한다.

### 010. 버전 범위 정정 (2026-08-25)

- 변경 내용: M8은 사진 중심 화면 개편으로 완료 처리하고, 다음 독립 기능인 사진 기록 앨범은 M8.1로 분리한다.
- 변경 이유: 확정한 버전에 후속 기능을 계속 누적하지 않고, 사용자가 한 번에 확인·승인할 기능 변경 묶음마다 버전·기록 파일을 구분하는 규칙을 고정했다.
- 영향 범위: M8의 기존 구현·커밋은 바꾸지 않는다. 앨범의 계약·QA·진행 기록은 M8.1 파일과 `_workspace/*/M8.1-*` 문서로 옮긴다.

## 설계 결정

### 002. 선택 화면 대신 장면을 읽는 흐름 (2026-08-14)

- 결정: 균일한 카드 반복보다 사진의 크기와 여백에 변주를 주고, 각 구간이 다음 탐색 행동으로 자연스럽게 이어지도록 구성한다.
- 이유: 홈의 목적을 기능 목록 제공이 아니라 여행 장면 발견으로 바꾸고, 이후 개인 사진첩·공유 기능도 같은 서사 구조에 연결하기 쉽도록 한다.
- 제외: 자동 슬라이드, 과도한 애니메이션, 새 API·새 데이터 모델은 이번 단계에 넣지 않는다.

### 001. 조용한 사진 에디토리얼 톤 — 2026-08-12

- 결정: 큰 사진과 충분한 여백을 중심으로 하고, 모든 영역을 테두리 카드·버튼·배지로 감싸지 않는다.
- 이유: 기능이 많아져도 초보적인 UI 조립 느낌이나 과도한 장식을 피하고, 여행 사진과 기록에 시선이 머물게 하기 위해서다.
- 검토한 대안과 선택하지 않은 이유: 대형 배너·자동 애니메이션·다중 캐러셀 조합은 시선을 분산시키고 초기 구현 느낌을 강화할 수 있어 사용하지 않는다.
- 영향 범위: 메인 화면, 공통 섹션 헤더·사진 카드·빈 상태, 내비게이션.
- 재검토 조건 또는 후속 작업: 사진첩 스토리·지도 화면 구현 시 동일한 정보 밀도와 톤을 유지하는지 QA로 재점검한다.

## 구현 변경

### 001. 에디토리얼 홈 첫 구현 (2026-08-14)

- 대표 수상작 사진과 짧은 소개, 앵커형 스크롤 유도로 첫 화면을 구성했다.
- `추천 여행지`는 동일 크기 카드 대신 높낮이가 다른 가로 사진 필름으로 바꾸고, 각 장면에서 수상작 상세로 이동한다.
- 혼잡도와 검색을 각각 독립된 탐색 구간으로 두고, 검색 키워드는 기존 `/explore?keyword=` 계약으로 연결했다.
- 로그인 사용자에게만 `사진 놓기`의 개인 사진 진입을 표시한다.
- 공통 색상 토큰과 홈의 빈 이미지 상태를 저채도 파스텔 민트·짙은 청록 계열로 변경했다.

### 002. 모바일 히어로 재구성 (2026-08-14)

- 모바일은 문장과 대표 사진을 하나의 민트 장면 안에 배치하고, 사진을 둥근 프레임과 반투명 캡션 패널로 표현했다.
- 추천 필름의 좌우 여백과 스냅 흐름을 모바일 너비에 맞췄으며, 순백 바탕 대신 저채도 민트 배경을 기본으로 사용한다.
- 데스크톱의 좌측 문장·우측 사진 구조와 기존 기능 연결은 유지했다.

### 003. 홈 전체 표면과 리듬 통일 (2026-08-14)

- 추천·혼잡도·검색·내 사진 진입을 같은 저채도 민트 배경 안에서 밝기와 여백을 달리한 에디토리얼 면으로 재구성했다.
- 기존의 순백 블록과 단순한 가로선 구분은 제거하고, 사진과 공간의 흐름으로 구간을 구분한다.
- 링크, API 호출, 인증 조건은 변경하지 않았다.

### 004. 추천 여행지 출처와 필름 조작 정리 (2026-08-14)

- 추천 여행지 설명에 사진이 전국 관광 사진 공모전 수상작임을 명시했다.
- 가로 필름은 스냅·터치·휠·키보드 이동을 유지하면서 브라우저 스크롤바만 숨겼다.

### 005. 홈 기능 인덱스 시범 적용 (2026-08-14)

- 히어로 뒤에 수상작·사진 찾기·혼잡도·내 사진 남기기의 네 기능을 번호·가는 선·짧은 설명으로 보여주는 독립 인덱스를 추가했다.
- 데스크톱에서는 4열, 모바일에서는 네 항목을 한 번에 읽는 세로 목록으로 표시한다.
- 비로그인 사용자에게도 내 사진 기능을 감추지 않고 로그인 후 이용할 수 있음을 표시한다.

### 006. 이달의 대표 원본 사진 적용 (2026-08-14)

- 95개 수상작의 `filmMonth`가 모두 `YYYYMM` 형식으로 채워져 있고, 각 월의 후보가 있음을 전수 확인했다.
- 홈 전용 목록 조회는 최대 100건으로 분리해 현재 월 후보 전체에서 한 건을 선택하며, 선택값은 브라우저 세션 동안 유지한다.
- 선택 작품에만 상세 요청을 추가해 `imageUrl` 원본을 히어로에 표시한다. 현재 달 후보·상세·원본 이미지가 없을 때는 기존 목록 작품의 썸네일로 폴백한다.

### 007. 모바일 사진 1열·2열 보기 적용 (2026-08-14)

- 수상작 목록과 키워드 검색 결과에 공통 1열·2열 전환을 추가하고, 기본값을 2열로 설정했다.
- 선택값은 브라우저 저장소에서 공유·복원하며, 저장소를 쓸 수 없으면 2열로 안전하게 동작한다.
- 데스크톱 열 수, 검색 앨범 묶기, 무한 스크롤, API·URL 계약은 유지했다.

### 008. 모바일 3열 보기 추가 (2026-08-14)

- 모바일 사진 보기 선택지를 1열·2열·3열로 확장했다. 기본값과 잘못된 저장값의 폴백은 계속 2열이다.
- 수상작·검색 앨범·검색 로딩 상태에 같은 선택값을 적용하고, 데스크톱 규칙은 유지했다.

### 009. 무한 스크롤 빠른 조작 적용 (2026-08-14)

- 결과를 480px 이상 내리면 고정 도구를 표시한다. 위로 가기는 상단으로 이동하고, 검색은 검색 입력·수상작은 필터 입력으로 포커스를 이동한다.
- 현재 검색어·필터·결과·무한 스크롤 동작은 보존한다.
- 모바일은 하단 탭과 안전 영역 위에, 데스크톱은 우측 하단에 표시하며 모션 감소 설정을 따른다.

### 010. 결과 위치 인라인 검색·필터 적용 (2026-08-14)

- 빠른 검색·필터 버튼을 아이콘 전용으로 바꾸고, 클릭 시 현재 위치의 작은 패널에서 바로 편집·적용하도록 변경했다.
- 검색 패널은 기존 검색어·URL·결과 갱신 경로를 사용한다.
- 수상작 패널은 상단 필터와 같은 `ContestQuery`, 계절 칩, 선택 컨트롤을 재사용하며, 적용 전 드래프트를 따로 둔다.
- Escape·바깥 클릭·열릴 때 첫 입력 포커스와 하단 탭 안전 여백을 적용했다.

### 011. 빠른 조작을 접는 메뉴로 변경 (2026-08-14)

- 기본 노출은 메뉴 아이콘 하나로 줄이고, 누르면 왼쪽으로 위로 가기와 검색·필터 아이콘이 펼쳐지도록 바꿨다.
- 메뉴·패널 상태는 동시에 열리지 않게 분리하고, Escape·바깥 클릭·패널 종료 뒤 포커스 복귀를 처리했다.
- 포커스 트랩 없이 사용하던 패널의 `aria-modal` 선언을 제거해 비모달 팝오버 의미에 맞췄다.

### 012. 펼친 메뉴를 두 동작 타원으로 정리 (2026-08-14)

- 메뉴를 연 상태에서는 메뉴 아이콘을 숨기고, 위로 가기·검색 또는 필터 아이콘 두 개만 하나의 가로 타원 안에 표시한다.
- 열린 뒤 첫 동작으로 포커스를 옮기고, Escape·바깥 클릭으로 접으면 다시 메뉴 아이콘으로 포커스를 돌린다.

### 013. 키워드 재검색을 인라인 입력 타원으로 변경 (2026-08-14)

- 키워드 검색에서 재검색을 누르면 메뉴와 동작 아이콘을 숨기고, 같은 위치에 검색어 입력과 검색 아이콘만 든 가로 타원으로 교체한다.
- 적용·Escape·바깥 클릭 뒤에는 기본 메뉴 상태로 복귀하며, 검색 URL·결과 갱신과 현재 스크롤 위치는 유지한다.
- 수상작의 다중 조건 필터 패널은 별도 UX로 유지한다.

### 014. 수상작 필터를 임시 선택·명시 적용으로 통일 (2026-08-14)

- 즉시 목록이 바뀌던 원인은 상단 필터가 옵션 변경마다 `setQuery`를 직접 호출하던 구조였다.
- 상단과 빠른 필터 모두 공통 임시 필터 훅을 사용하도록 바꾸고, 적용·검색 아이콘을 누를 때만 목록을 갱신한다.
- 초기화도 임시 선택만 비우며 적용 전 결과는 유지한다. 빠른 필터 표면은 둥근 민트 계열로 검색 패널과 맞췄다.

### 015. 수상작 복귀와 검색 앨범 스크롤 보존 적용 (2026-08-16)

- 수상작 카드 클릭 전 현재 히스토리 항목에 목록 상태·스크롤 위치를 저장하고, 브라우저 뒤로가기로 같은 항목에 복귀하면 목록 렌더 뒤 위치를 복원한다.
- 키워드 검색 앨범 모달은 문서 스크롤을 잠그고 내부 본문에 스크롤 경계 차단을 적용해, 사진 목록 끝에서 배경 결과가 움직이지 않게 했다.
- 모달 종료 시 잠금 전 문서 위치를 복원하며 API·검색 URL·무한 스크롤 계약은 유지한다.

### 016. 상세의 목록 복귀도 히스토리 복원으로 통일 (2026-08-18)

- 모바일·데스크톱 공통으로, 목록 카드에서 상세에 진입한 경우 상세의 수상작 목록 복귀 버튼도 기존 목록 히스토리 항목으로 돌아가게 했다.
- 홈·혼잡도·마이·주소 직접 진입 등 목록 외 경로에서는 안전하게 수상작 목록으로 이동한다.

### 017. 목록 위 수상작 상세 오버레이로 전환 (2026-08-18)

- 변경 내용: 목록에서 상세로 갈 때 목록을 언마운트하지 않고 상세 오버레이를 덮는다. 뒤로가기는 오버레이만 닫는다.
- 변경 이유: 무한 목록의 페이지·이미지 렌더 시점에 의존한 스크롤 복원은 실제 사용에서 신뢰성이 부족했다.
- 계약: `_workspace/contracts/M8-contest-detail-overlay.md`에 목록 진입·독립 상세·접근성 규칙을 기록한다.

### 018. 수상작 상세를 일반 페이지 표면으로 정리 (2026-08-18)

- 변경 내용: 목록 상태는 유지하되, 상세는 검은 배경과 둥근 팝업 창 대신 마이 화면처럼 앱 본문을 덮는 일반 페이지 형태로 표시한다.
- 동작: 상단 내비게이션과 모바일 하단 탭은 유지하고, 목록 복귀·브라우저 뒤로가기·Escape로만 상세를 닫는다.
- 이유: 목록 보존을 위한 내부 구현이 사용자에게 모달 창처럼 보이지 않게 한다.

### 019. 화면 개편 뒤 구조 정리 예정 (2026-08-18)

- 원칙: 사용자 화면과 API 계약은 바꾸지 않으며, 공통화가 오히려 사용 지점을 흐리게 만드는 경우에는 억지로 분리하지 않는다.

### 020. 화면 개편 뒤 구조 정리 완료 (2026-08-18)

- 제거: 목록 유지형 상세로 전환되며 불필요해진 `history.state`·`sessionStorage` 기반 수동 스크롤 복원, 페이지 재요청, 카드 열기 시 저장 호출을 제거했다.

- 가독성: 수상작 카드, 탐색, 사진 앨범을 화면·결과·세부 상호작용 단위로 정리했다. 스크롤 잠금은 아직 두 UI가 동시에 열리지 않아 공통 훅으로 억지 추상화하지 않았다.
