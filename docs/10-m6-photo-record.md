# 10. M6 수상작 비교와 개인 사진 기록

> M6에서 만든 사진 기록 모델을 기준으로 하고, M8.1(2026-08-25)의 앨범 메타데이터와 M9(2026-09-19)의 보관함 제거까지 반영한 최신 구현 문서다. 이전의 사진 비교 계획 문구와 충돌할 경우 이 문서를 우선한다.

## 데이터 구조

```
User 1 ── N UserPhoto 1 ── N PhotoRecord N ── 0..1 ContestWork
                         └── (향후) PhotoPost ── N PhotoLike
```

- `UserPhoto`: 실제 업로드 파일. `storageKey`, 원본 파일명, MIME 타입, 크기만 보관한다.
- `PhotoRecord`: 사진첩의 한 기록. 촬영 시각·장소·메모·표시 방식과 선택적인 수상작 연결을 가진다.
- 하나의 원본 파일은 기존 데이터 호환을 위해 여러 기록이 참조할 수 있다. 원본 파일은 참조하는 기록이 없어질 때만 삭제한다.
- 수상작을 연결한 기록은 `WITH_CONTEST`, 해제한 기록은 `PHOTO_ONLY` 상태다.

## API와 동작

모든 경로는 `/api/v1` 기준이며 인증이 필요하다.

| 메서드 | 경로 | 동작 |
| --- | --- | --- |
| POST | `/me/photos` | JPEG·PNG·WebP·HEIC/HEIF(10MB 이하) 업로드 후 사진 기록 생성 |
| GET | `/me/photos` | 호환용 단일 사진 기록 목록 조회 (현재 앨범 UI는 묶음 목록 사용) |
| GET | `/me/photos/map` | 호환용 단일 사진 지도 핀 목록 조회 (현재 앨범 UI는 묶음 지도 사용) |
| GET | `/me/photos/map/locations` | 지도 지역·시군 선택지 목록 조회 |
| PUT | `/me/photos/map/representative` | 한 장소의 대표 사진 기록 변경 |
| PATCH | `/me/photos/{recordId}` | 촬영일·장소·메모·수상작 표시 방식 수정 |
| GET | `/me/photos/{recordId}/file` | 소유자만 원본 파일 조회 |
| DELETE | `/me/photos/{recordId}` | 수상작 연결이 없는 기록과 필요 시 원본 파일 삭제 |
| POST | `/me/photos/bundles` | 1~3장 사진을 한 여행 기록 묶음으로 업로드 |
| GET | `/me/photos/bundles` | 내 앨범의 여행 기록 묶음 목록 조회 |
| GET | `/me/photos/bundles/map` | 내 앨범 묶음의 지도 핀 목록 조회 |
| DELETE | `/me/photos/bundles/{bundleId}` | 여행 기록 묶음과 포함 사진 삭제 |
| GET | `/me/comparisons` | 수상작 연결 기록 목록 조회 |
| POST | `/me/comparisons` | 사진 기록과 수상작 연결 및 선택 구도 저장 |
| PATCH | `/me/comparisons/{recordId}` | 비교 결과 수정에서 다른 사진 기록으로 교체 및 선택 구도 저장 |
| PATCH | `/me/comparisons/{recordId}/crop` | 비교 결과 수정에서 비교용 표시 구도만 수정 |
| DELETE | `/me/comparisons/{recordId}?deletePhoto=false` | 수상작 연결만 해제 |
| DELETE | `/me/comparisons/{recordId}?deletePhoto=true` | 기록과 원본 파일 함께 삭제 |

`POST /me/photos`는 `file` 외에 `takenAt`, `placeName`, `memo`를 선택적으로 받는다. 촬영일을 비우면 JPEG·PNG·WebP·HEIC/HEIF에서 EXIF의 `DateTimeOriginal`(대체 `DateTime`)을 시도해 보완한다. 메타데이터가 없거나 읽을 수 없는 형식도 업로드는 성공하며 촬영일만 빈값으로 둔다. GPS 등 위치 메타데이터는 읽거나 저장하지 않는다.

`PATCH /me/photos/{recordId}`에서는 `takenAt`, `placeName`, `memo`를 명시적으로 `null`로 보내 기존 값을 비울 수 있다. `displayMode`는 수상작 연결 사진의 `WITH_CONTEST`/`PHOTO_ONLY` 표시 방식을 바꾼다. `PHOTO_ONLY`면 비교 결과 목록과 상세에서 수상작 이미지를 숨기고 내 사진만 보인다. 수상작이 없는 기록에는 `WITH_CONTEST`를 설정할 수 없다.

수상작 비교에는 원본 파일과 별개인 표시 구도 `crop`을 둔다. 수상작 원본의 실제 비율을 `aspectRatio`로 저장하고, `zoom`과 `offsetX`·`offsetY`로 내 사진의 보이는 영역만 정한다. 이동값은 `-1`부터 `1`까지이며 `0`은 가운데다. 앨범 사진 원본은 자르거나 바꾸지 않는다. 기존 비교 기록은 4:3·1배율·가운데 구도로 호환한다. 공개 비교 목록에도 이 구도만 전달해 같은 화면 구성을 재현하며, 장소·메모·촬영일 같은 개인 기록 값은 공개하지 않는다.

## 파일 접근 정책

- `/files/**`는 차단한다. 원본 파일을 정적으로 공개하지 않는다.
- API는 사진 기록의 소유자와 로그인 사용자가 같을 때만 파일을 반환한다.
- 프런트는 Bearer access token으로 파일을 blob으로 받아 표시한다. `<img>` 태그가 직접 공개 URL을 요청하지 않는다.
- 향후 공유는 공개 여부를 가진 게시물 모델을 별도로 두고, 공개 정책 또는 만료형 서명 URL을 추가한다.

## 화면 흐름

1. `수상작 비교`에서 즐겨찾기한 수상작과 내 사진을 고른다.
2. 내 사진은 앨범에서 선택하거나 새로 업로드한다. 앨범 선택은 실제 여행 기록 묶음을 먼저 고르고, 그 안에서 한 장을 선택한다. 예전 단일 사진도 한 장짜리 묶음으로 함께 보인다. 이미 다른 수상작과 비교 중인 사진도 목록에는 보이지만 `비교 중` 상태로 표시되며 선택할 수 없다. 업로드 직후 미리보기를 제공한다. 비교 화면에서 내 사진의 이름은 장소명, 촬영일, `내 사진` 순으로 표시하며, 장소명이 있으면 촬영일은 보조 정보로 함께 표시한다.
   - 수상작 비교 안에서 새 파일을 고르면 EXIF 촬영일의 날짜를 먼저 채우고, 찾지 못하면 업로드 전에 촬영일을 직접 입력해야 한다. 시간은 입력받지 않으며 선택한 날짜는 서버에 그날 자정으로 전달한다.
3. 사진을 연결할 때 수상작 원본 비율의 틀 안에서 내 사진을 드래그·확대해 비교 구도를 정한다.
4. 저장한 결과를 열면 현재 사진과 수상작을 비교 결과 팝업에서 확인한다.
5. 저장한 결과의 `수정`에서 사진 변경, 크롭 변경, 결과만 삭제, 사진까지 삭제를 선택한다. 사진 변경은 새 사진과 크롭을 함께 저장하고, 크롭 변경은 현재 사진을 유지한다.
6. 수정·삭제·업로드 실패는 해당 팝업 또는 선택 창 안에서 안내한다.
   - 수상작 상세에서 이미 저장한 비교 결과를 확인해도 수상작 비교 페이지로 이동하지 않고, 현재 상세 위의 비교 결과 창으로 열어 상세 상태를 유지한다.
8. `마이`에서 별도 `내 앨범` 화면으로 들어가 사진을 직접 추가하고 촬영일·장소·메모를 수정한다. 기본 `스토리`는 촬영 월 순서로, `맵`은 입력한 장소명으로 사진을 살펴본다. 지도 패널의 사진 목록과 현재 큰 사진에서는 수상작과 비교한 사진만 트로피로 표시하며, 큰 사진의 트로피를 누르면 앨범 위 비교 결과 창을 연다. 사진이나 묶음 썸네일을 누르면 확대 보기로 열 수 있고, 비교 사진의 확대 보기 아래에는 트로피·수상작 제목·지역·수상작 원본 사진을 표시한다. 이 사진을 누르면 별도 비교 페이지로 이동하지 않고 앨범 위 비교 결과 창을 연다.
9. 실제 삭제는 편집 화면에서 한 번 더 확인하며, 비교에 연결된 사진은 비교 결과를 먼저 정리해야 한다.
