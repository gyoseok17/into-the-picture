# 공통 엔지니어링 원칙

모든 에이전트(backend·external·frontend)가 함께 따르는 행동 규율. SOLID·클린코드의 **일반 정의는 이미 안다고 전제**하고, 이 프로젝트에서 **실제로 지켜야 할 행동**만 적는다.

## 1. 확장성 우선 (이 프로젝트 1순위)
- 새 기능은 **확장으로 추가**한다 — 기존 코드 수정 최소(OCP). 새 콘텐츠 종류=enum 값 추가, 새 외부 소스=Provider 구현 추가, 새 화면=feature 폴더 추가.
- 변동·외부 의존은 **인터페이스/어댑터 뒤로 격리**한다. 구체 구현이 도메인에 새지 않게.
- **단, 추측성 일반화 금지(YAGNI).** 지금 필요 없는 추상화는 만들지 않는다. "교체가 예견되는 경계"(외부 API·스토리지·인증제공자)만 추상화한다. 확장성과 과설계는 다르다.

## 2. 수정 규율 (가장 중요)
버그·요구를 고칠 때, **눈앞 현상에 국한된 국소 패치가 아니라 설계 원칙·전체 구조에 정합하는 방향**으로 해결한다:
- **현상이 아니라 구조로 해결한다.** 이 케이스만 통과시키는 국소 수정 금지. "왜 이 문제가 생기나"를 **설계 수준**에서 보고, 설계 원칙과 시스템 전체 로직에 맞는 **올바른 위치/추상화 수준**에서 고친다.
- **전체 정합성을 본다.** 수정이 다른 기능·유사 케이스와 논리적으로 일관되는지 확인한다. **같은 부류의 문제가 다른 곳에도 있으면 함께(일반적으로) 해결**한다 — 한 곳만 고쳐 시스템 로직이 어긋나게 두지 않는다.
- **올바른 수준에서 풀되, 범위는 절제.** 무관한 대량 리팩터링·포맷 변경은 섞지 않는다(blast radius). 단 "쉬워서" 국소로 때우는 것과 혼동하지 않는다 — 올바른 해결이 더 넓은 변경을 요구하면 리더와 상의 후 진행.
- **기존 동작·계약을 보존한다.** 공개 API·응답 shape·DB 스키마 변경 시 영향 추적 + 회귀 방지(Flyway 누적).
- (기본선) 증상만 덮는 방어 코드·`any` 캐스팅·하드코딩 같은 임시 우회는 당연히 지양. 불가피하면 `// TODO:` + 사유.

## 3. 응집·결합 (SRP·DIP 적용 포인트)
- 한 클래스/함수는 **한 가지 책임(SRP)**. 서비스가 여러 일을 하면 분리한다.
- **추상에 의존(DIP).** 도메인→외부는 인터페이스로(Provider 패턴). 구체 클래스 직접 의존 지양.
- 결합을 낮춘다 — 불필요한 양방향 참조·전역 가변 상태 금지.

## 4. 가독성·중복
- **의미 있는 이름** — 약어·모호한 이름 금지. 이름이 의도를 설명하게.
- **작은 단위** — 함수는 한눈에 들어오게, 깊은 중첩 대신 early return.
- **중복 제거(DRY)** — 같은 로직이 반복되면 추출. 단, *우연한* 중복(이유가 다른데 모양만 같음)은 성급히 합치지 않는다.
- 주석보다 자명한 코드. 주석은 "왜"를 설명할 때만.

## 5. 추측 금지
- 스펙이 모호하면 **추측하지 말고** `docs/`를 확인하거나 리더에게 질문한다. (과거에 추측 필드로 설계가 틀렸던 전례가 있다.)
