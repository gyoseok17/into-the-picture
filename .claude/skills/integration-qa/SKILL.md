# 통합 정합성 검증 (Integration QA)

각 부분이 개별적으로 맞아도 **연결 지점에서 계약이 어긋나는** 경계면 버그를 잡는다. 정적 리뷰·빌드 통과로는 못 잡는 결함이 대부분이다.

## 왜 정적 리뷰로 못 잡나
- TS 제네릭 캐스팅(`fetchJson<T>`)은 런타임 응답이 달라도 컴파일 통과.
- `npm run build` 성공 ≠ 정상 동작. `any`/캐스팅이 불일치를 숨긴다.
- "존재하는가"와 "양쪽 계약이 일치하는가"는 다른 검증이다.

## 핵심 방법: 양쪽 동시 읽기
경계면은 반드시 **생산자와 소비자 코드를 같이 열어** 비교한다.

| 대상 | 생산자 | 소비자 |
|------|--------|--------|
| API 응답 shape | 컨트롤러 응답 DTO (`docs/04`) | 프론트 훅 타입(types.ts) |
| 페이지네이션 | `{content, page}` 반환 | 훅이 `.content` unwrap |
| 외부→내부 변환 | 어댑터 DTO 변환 | 도메인/응답이 쓰는 필드 |
| 라우팅 | `src/routes`·페이지 경로 | href/router 이동 값 |
| API↔훅 1:1 | 컨트롤러 엔드포인트 목록 | 호출하는 훅 존재·URL 일치 |
| DB→API→UI | 엔티티 필드명 | API 응답 필드 → 프론트 타입 |

## 체크리스트 (Into the Picture)

### API ↔ 프론트
- [ ] 각 엔드포인트 응답 shape와 대응 훅 타입 일치 (`docs/04` 대조)
- [ ] 목록 래퍼 `{content,page}`를 훅에서 unwrap
- [ ] 필드명 camelCase 일관 (snake_case 혼입 없음)
- [ ] 옵셔널/null(예: crowdAvailable=false, 좌표 null) 양쪽 처리 일관
- [ ] 모든 엔드포인트에 대응 훅 존재·실제 호출

### 외부 연동
- [ ] 외부 필드명이 응답/도메인에 새지 않음 (어댑터에서 내부 DTO로 변환됨)
- [ ] 이미지 URL https 처리, 집중률 매칭 실패 시 graceful(빈/숨김)

### 라우팅
- [ ] 모든 href/router.push가 실제 라우트와 매칭 (`docs/08`)
- [ ] 보호 라우트 인증 가드 동작

### 인증/데이터
- [ ] 401 시 refresh 재발급 인터셉터 동작
- [ ] DB 필드 → API → 프론트 타입 매핑 일관

### 수정 규율 (engineering-principles 위반 점검)
- [ ] **현상 국소 패치가 아니라** 설계 원칙·전체 로직에 맞는 위치/수준에서 해결됐는가 (다른 기능·유사 케이스와 정합, 같은 부류 문제는 일반적으로 해결)
- [ ] 증상 땜질(불필요한 방어코드·캐스팅)로 근본 원인을 덮지 않았는가
- [ ] 변경 범위가 작업 목표를 벗어나지 않았는가 (무관한 대량 수정·포맷 변경 없음)
- [ ] `any`/강제 캐스팅·하드코딩 우회가 없는가 (있으면 TODO+사유 명시됐는가)
- [ ] 공개 계약(응답 shape·API·스키마) 변경 시 회귀 영향을 확인했는가

## 운영 원칙
- **incremental QA**: 각 모듈(예: contest API + 그 훅) 완성 **직후 즉시** 검증한다. 전체 완성 후 몰아서 하면 버그가 누적·전파된다.
- 발견 시: 해당 에이전트에 **파일:라인 + 구체 수정법** 전달, 경계면 이슈는 **양쪽 모두**에 알림.
- 리포트는 `_workspace/`에 통과/실패/미검증 구분해 기록.

## 검증 보조
- Grep으로 패턴 일괄 추출(컨트롤러 응답, 훅 타입, href). 가능하면 간단한 대조 스크립트로 자동화.
