# M8.1 사진 묶음 API 형태

작성일: 2026-08-28
상태: 백엔드 구현 중

## 공통 응답 객체

`PhotoRecordBundleDto`

```json
{
  "id": 42,
  "legacy": false,
  "photos": [
    {
      "id": 301,
      "url": "/me/photos/301/file",
      "originalFilename": "trip-01.jpg",
      "contentType": "image/jpeg",
      "fileSize": 12345,
      "takenAt": "2026-08-28T00:00:00",
      "placeName": "수원",
      "mapRegionCode": "GYEONGGI",
      "mapCityCode": "SUWON",
      "memo": null,
      "archivedAt": null,
      "contestId": null,
      "displayMode": "PHOTO_ONLY",
      "createdAt": "2026-08-28T12:00:00"
    }
  ],
  "takenAt": "2026-08-28T00:00:00",
  "placeName": "수원",
  "mapRegionCode": "GYEONGGI",
  "mapCityCode": "SUWON",
  "memo": null,
  "archivedAt": null,
  "createdAt": "2026-08-28T12:00:00"
}
```

- `id`: 실제 묶음 ID. 기존 개별 사진 항목은 `null`이다.
- `legacy`: 실제 묶음은 `false`, 기존 개별 사진은 `true`다.
- `photos`: 실제 묶음은 그 묶음의 사진 전체, 기존 개별 사진은 한 장 배열이다.
- 묶음의 공통 필드는 내부 사진에도 같은 값으로 저장한다. `photos[*]`는 기존 `/me/photos` 응답과 같은 `UserPhotoDto`다.

## 엔드포인트

### POST `/api/v1/me/photos/bundles`

`multipart/form-data`

- `files`: 1~3개, 동일한 필드명으로 반복 전송. 각 파일은 10MB 이하이며 multipart 요청 전체는 32MB 이하다.
- 선택 공통 필드: `takenAt` (ISO local date-time), `placeName`, `mapRegionCode`, `mapCityCode`, `memo`
- 201 Created + `PhotoRecordBundleDto`
- 잘못된 파일/지역/입력값은 400, 인증 없음은 401

### GET `/api/v1/me/photos/bundles?archived=false`

- 200 + `PhotoRecordBundleDto[]`
- 실제 묶음과 `bundle_id IS NULL`인 기존 개별 사진을 시간 역순으로 같은 배열에 반환한다.

### DELETE `/api/v1/me/photos/bundles/{bundleId}`

- 204 No Content
- 소유하지 않았거나 없는 묶음은 404.
- 내부 사진 중 하나라도 공모전 비교(`contestId`)에 연결되어 있으면 409. 이 경우 묶음·사진·파일은 하나도 삭제하지 않는다.

### GET `/api/v1/me/photos/bundles/map`

- 200 + `PhotoRecordBundleMapPinDto[]`

```json
{
  "id": 42,
  "legacy": false,
  "photos": [{ "id": 301, "url": "/me/photos/301/file" }],
  "placeName": "수원",
  "mapRegionCode": "GYEONGGI",
  "mapCityCode": "SUWON",
  "takenAt": "2026-08-28T00:00:00",
  "lat": 37.2636,
  "lng": 127.0286,
  "locationSource": "CITY"
}
```

- 실제 묶음은 사진 수와 무관하게 마커 하나다. `photos`에 묶음의 전체 사진을 담는다.
- 기존 단일 사진은 `id: null`, `legacy: true`, 사진 한 장의 마커로 반환한다.
- 기존 `GET /api/v1/me/photos/map`은 호환을 위해 그대로 유지한다.

## 현재 요청 한도 정정 (2026-09-12)

`POST /api/v1/me/photos/bundles`의 `files` multipart part는 1~3개다. 각 파일은 10MB 이하이고 요청 전체는 32MB 이하이다. `manualTakenAts`가 있으면 files와 같은 순서·개수로 보낸다. 이전 4~20개 또는 동시 업로드 서술은 초기 계획으로, 현재 API 형태를 설명하지 않는다.
