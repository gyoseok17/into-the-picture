# M8.1 네 가지 사진 형식 백엔드 형태

## `POST /me/photos` 파일 허용 정책

| 실제 형식 | 허용 요청 MIME | 파일 서명 검사 | 저장·응답 MIME |
| --- | --- | --- | --- |
| JPEG | `image/jpeg` | `FF D8 FF` SOI | `image/jpeg` |
| PNG | `image/png` | PNG 8바이트 서명 | `image/png` |
| WebP | `image/webp` | `RIFF` + `WEBP` | `image/webp` |
| HEIC/HEIF | `image/heic`, `image/heif` | ISO BMFF `ftyp` + HEIF 계열 브랜드 | 검증된 요청 MIME 유지 |

- 확장자는 검증 기준이 아니다.
- MIME과 실제 형식이 맞지 않거나 10MB를 넘으면 400 `INVALID_REQUEST`다.
- HEIC/HEIF의 경우 `heic`, `heix`, `hevc`, `hevx` 등의 브랜드와 AVIF가 아닌 일반 MIAF(`mif1`)만 허용한다. AVIF 브랜드는 이 범위에서 거부한다.
- 기존 파일 URL은 그대로 `/me/photos/{recordId}/file`이며 저장한 검증 MIME으로 응답한다.

## `takenAt` 보완

- 요청의 `takenAt`이 있으면 우선 사용한다.
- 비어 있으면 `metadata-extractor 2.19.0`이 처리할 수 있는 JPEG, PNG, WebP, HEIC/HEIF 컨테이너에서 EXIF `DateTimeOriginal`, 대체 `DateTime`만 읽는다.
- 촬영일이 없거나 메타데이터 처리 실패는 업로드 실패가 아니라 `takenAt: null`이다.
- GPS, 위치, 카메라 모델 등의 메타데이터는 읽거나 저장하지 않는다.

## 스키마·호환성

- 업로드 형식 확대는 `PhotoRecord`/`UserPhoto` 스키마를 변경하지 않는다.
- 기존 JPEG 업로드, 사진 파일 소유권 검사, 비교 API와 삭제의 마지막 참조 규칙은 유지한다.
