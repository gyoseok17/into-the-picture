# M8.1 사진 기록 앨범 API 형태

## 공통

- 모든 경로는 로그인한 사용자 자신의 `PhotoRecord`만 읽고 변경한다.
- `id`와 파일 URL의 `{id}`는 `UserPhoto` ID가 아니라 사진 기록(`PhotoRecord`) ID다.
- 날짜는 ISO-8601 지역 시각(`2026-08-25T14:30:00`)이며, 촬영 시각에 시간대·GPS 정보는 저장하거나 응답하지 않는다.

## `GET /me/photos?archived=false`

- `archived`를 생략하면 `false`다. `true`는 보관한 기록만, `false`는 활성 기록만 반환한다.
- 결과는 `takenAt`이 있으면 촬영일, 없으면 `createdAt` 기준의 최신순이다.

## `POST /me/photos` (multipart/form-data)

| 필드 | 필수 | 의미 |
| --- | --- | --- |
| `file` | 예 | JPEG, PNG, WebP, HEIC, HEIF; 10MB 이하 |
| `takenAt` | 아니오 | ISO-8601 촬영 시각. 없으면 지원 형식의 EXIF `DateTimeOriginal`만 시도 |
| `placeName` | 아니오 | 최대 255자. 빈 문자열은 `null` |
| `memo` | 아니오 | 최대 500자. 빈 문자열은 `null` |

EXIF에서는 촬영 시각만 읽으며, 위치와 다른 메타데이터는 읽거나 API에 넣지 않는다. EXIF가 없거나 읽을 수 없으면 `takenAt`은 `null`이다. HEIC/HEIF는 브라우저가 미리보기를 지원하지 않을 수 있으나 업로드·기록은 가능하다.

## `PATCH /me/photos/{recordId}`

부분 갱신 JSON이다. `takenAt`, `placeName`, `memo`를 명시적으로 `null` 또는 빈 문자열로 보내면 해당 값을 비운다. 필드를 보내지 않으면 바꾸지 않는다.

```json
{
  "takenAt": "2026-08-14T08:30:00",
  "placeName": "주전골",
  "memo": "아침 산책",
  "archived": false,
  "displayMode": "WITH_CONTEST"
}
```

- `archived: true`는 물리 삭제가 아닌 보관 처리이고, `false`는 복원이다.
- `displayMode`는 `PHOTO_ONLY` 또는 `WITH_CONTEST`다. 후자는 연결된 수상작이 있을 때만 가능하다.

## 응답

`GET`, `POST`, `PATCH`는 같은 객체를 반환한다.

```json
{
  "id": 42,
  "url": "/me/photos/42/file",
  "originalFilename": "morning.jpg",
  "contentType": "image/jpeg",
  "fileSize": 123456,
  "takenAt": "2026-08-14T08:30:00",
  "placeName": "주전골",
  "memo": "아침 산책",
  "archivedAt": null,
  "contestId": 13,
  "displayMode": "WITH_CONTEST",
  "createdAt": "2026-08-25T10:00:00"
}
```

기존 비교 API의 `ComparisonDto.userPhoto`도 같은 확장 객체를 사용한다. `ComparisonDto.displayMode`는 비교 목록·상세에서 수상작 이미지를 보일지 결정한다. 비교 생성·교체·삭제 경로는 유지한다.

## 데이터 이관

- V5에서 기존 `user_photo`와 비교 행은 이미 사진 기록으로 이관됐다. 기존 `takenAt`·`placeName`·`memo`의 `null`은 유효한 데이터다.
- V6은 기록을 변경하지 않고 활성/보관 목록 조회 인덱스만 추가한다.
- 파일은 참조하는 사진 기록이 하나도 없을 때만 기존 삭제 규칙에 따라 삭제한다.
