# M8.1 앨범 지도 안내 제거·부산 위치 진단 — 프런트엔드 결과

- 날짜: 2026-09-09
- 담당: 프런트엔드
- 변경 파일: `frontend/src/features/photo-record/components/PhotoRecordMapView.tsx`

## 구현

- 지도 stage 상단의 `맵에 기록 n개 · 사진 n장 · 장소를 기록한 사진...` 안내 `<p>`를 완전히 제거했다.
- 해당 요소는 stage 안의 `absolute` 요소였으므로 문서 흐름의 높이·폭을 차지하지 않았다. 제거 후에도 바깥 지도 높이, 2:3 stage 계산, marker 좌표 기준, 지역 필터와 포커스 패널 위치는 변하지 않는다.
- `unplacedCount` props·빈 결과 처리·마커 묶음 로직은 변경하지 않았다.

## 부산 marker 진단 — 좌표 변경 없음

- 현재 코드: `BUSAN: point(70, 72)`.
- 전수 감사의 최초 지리 보정안은 `71, 74`였지만, 실제 PNG 색상 영역 검사에서 도형 밖/해안 경계 위험을 피하려고 최종 `70, 72`로 되돌린 이력이 있다. 근거: `_workspace/qa/M8.1-album-map-city-position-audit.md`의 경상도 표 및 최종 조정 표.
- 지도 자산은 시·군 경계가 없는 6권역 일러스트이며, 경상 남동쪽 해안·부속 섬이 하나의 큰 녹색 도형으로 연결되어 있다. 그래서 `70,72`는 도형 안의 남동부지만, 실제 부산보다 남쪽 섬 쪽에 가까워 보일 수 있다.
- 반응형 stage 정합은 SVG와 marker의 기준 상자 차이를 제거했지만, 이 문제는 반응형 오차가 아니라 해당 일러스트 안에서의 **시각적 대표 위치** 판단 문제다.
- 좌표표는 이번 작업에서 수정하지 않았다. QA가 도형 내부 안전성·인접 김해(66,71)·양산(70,73)와의 구분을 재확인한 뒤에만 후속 보정을 결정한다.

## 검증

- 정적 검토: 안내 문구는 absolute overlay였으므로 제거가 stage·marker·filter·focus의 레이아웃을 밀지 않는다.
- `npx tsc -p tsconfig.app.json --noEmit`: PASS. 안내 제거 뒤 호출 props 계약은 유지하되 내부 미사용 값임을 `_unplacedCount`로 명시했다.
- `npx vite build`: PASS. 기존 500kB 초과 청크 권고만 출력됐다.
- `git diff --no-index --check -- NUL frontend/src/features/photo-record/components/PhotoRecordMapView.tsx`: PASS. 현재 M8.1 파일이 Git 추적 전이므로 no-index 방식으로 공백 오류를 확인했다.
