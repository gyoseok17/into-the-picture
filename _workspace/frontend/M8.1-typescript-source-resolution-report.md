# M8.1 TypeScript 원본 해석 복구 — 프런트엔드 결과

- 날짜: 2026-09-09
- 담당: 프런트엔드
- 계약: `_workspace/contracts/M8.1-frontend-typescript-source-resolution.md`

## 원인

- `frontend/src`에 TypeScript compiler가 생성한 `.js`와 `.d.ts`가 원본 `.ts/.tsx`와 나란히 남아 있었다.
- 과거 `typecheck` 스크립트가 `noEmit`을 `false`로 덮어써 이 산출물을 source tree에 만들었다.
- Vite 기본 extensionless import 우선순위에서 `.js`가 `.ts/.tsx`보다 앞서므로, 개발 화면은 변경된 TypeScript가 아니라 오래된 JavaScript를 실행했다. 부산 화면이 `70,72`로 보인 것이 직접 증거다.

## 삭제 전 정확한 대상과 provenance

- 대상 조건: `frontend/src` 아래 `.js` 또는 `.d.ts` 중 같은 경로·이름의 `.ts` 또는 `.tsx` 원본이 존재하는 파일.
- 대상 수: `.js` 97개 + `.d.ts` 32개 = **129개**.
- 모든 대상은 TypeScript 원본 97개와 경로·이름이 1:1 대응했고, 내용도 TypeScript emit 형식이었다. 실제 JavaScript source는 없었다.
- 보존: 대응 TypeScript 원본이 없는 수동 선언 `src/vite-env.d.ts`, `src/types/kakao.d.ts` 두 파일.
- 재현 목록 명령:

```powershell
Get-ChildItem frontend/src -Recurse -File |
  Where-Object { $_.Extension -eq '.js' -or $_.Name.EndsWith('.d.ts') } |
  Where-Object {
    $base = if ($_.Name.EndsWith('.d.ts')) { $_.FullName.Substring(0, $_.FullName.Length - 5) } else { $_.FullName.Substring(0, $_.FullName.Length - 3) }
    (Test-Path "$base.ts") -or (Test-Path "$base.tsx")
  }
```

## 적용

- 129개 생성물을 실제로 제거했다. ignore만 추가하는 방식은 Vite의 기존 파일 해석을 막지 못하므로 해결책이 될 수 없다.
- `vite.config.ts`의 `resolve.extensions`를 `.mts/.ts/.tsx`가 `.js/.jsx`보다 앞서도록 명시했다.
- `package.json`의 `typecheck`를 `tsc -b`로 바꿔 `tsconfig`의 `noEmit: true`를 그대로 지킨다.
- `.gitignore`에 source tree의 생성 `.js/.d.ts`를 추가하고, 수동 선언 두 파일은 예외로 보존했다.

## 검증

- `npm run typecheck`: PASS. 실행 뒤 `src`에는 수동 선언 두 파일만 남았고 새 `.js/.d.ts` 생성물은 0개.
- `npm run build`: PASS. 빌드 뒤에도 생성물은 0개이며 기존 500kB 초과 청크 권고만 출력됐다.
- `dist/assets` 확인: `BUSAN:A(68,69)`와 `YANGSAN:A(69,67)`가 포함되고 `70,72`, `70,73`은 없다.
- 후속 수동 확인: 이미 떠 있던 개발 서버는 모듈 그래프를 다시 읽도록 브라우저를 새로고침하거나 서버를 재시작해야 한다.
