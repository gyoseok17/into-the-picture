# M8.1 사진 묶음 프런트 결과

작성일: 2026-08-28

## 변경 범위

- `GET/POST /me/photos/bundles`, `DELETE /me/photos/bundles/{id}`, `GET /me/photos/bundles/map` API 타입과 React Query 훅을 추가했다.
- 다중 사진 추가는 개별 POST 반복 대신 파일 배열 하나를 `files`로 보내는 묶음 POST로 전환했다. 서버가 원자적으로 성공·실패를 판단하므로, 실패 항목도 묶음 전체가 다시 저장 대상이 된다.
- 스토리는 묶음의 대표 사진과 사진 수를 하나의 카드로 보여주고, 기존 개별 기록은 `legacy` 항목으로 그대로 표시·수정·보관한다.
- 맵은 bundle map endpoint를 사용하며, 동일 `bundleId`의 사진을 하나의 마커/사진 넘김 묶음으로 조합한다.
- 스토리 관리 모드에서 묶음 또는 기존 단일 기록을 체크해 선택 삭제할 수 있다. 서버 409은 기존 삭제 오류 안내로 표시된다.

## 설계 결정

- 기존 `PhotoRecord` 타입을 없애지 않고 `PhotoRecordBundle`을 조회 전용 상위 단위로 추가했다. 비교 화면과 기존 단일 수정 API의 계약을 깨지 않는다.
- 삭제의 실제 권한·비교 참조 검사는 서버에만 둔다. 프런트는 선택 및 확인 UI만 담당한다.

## 검증

- `frontend/npm run build` 통과.
- `git diff --check` 통과.

## QA 보완

- 선택 삭제는 `Promise.all`을 쓰지 않고 순차 처리한다. 그래서 일부 묶음이 공모전 비교 참조(409) 또는 다른 오류로 유지돼도, 앞서 삭제된 대상과 남은 대상을 분리해 성공·유지·실패 수를 정확히 보여 준다.
- 성공한 대상만 선택 상태에서 제거하고, 실패하거나 비교 참조로 유지된 대상은 계속 체크된 상태로 남긴다.

## 남은 통합 확인

- 백엔드 구동 후 새 bundle API의 실제 JSON, 201/409, 기존 legacy 항목, 맵의 여러 장 묶음 마커를 브라우저에서 확인해야 한다.
- 현재 묶음 카드 상세 열람은 대표 사진·사진 수 표시까지이며, 카드 클릭으로 별도 전체 사진 뷰를 여는 UX는 다음 UI 보완 항목이다.
