# M10 비교 결과 수정 흐름 프런트엔드 보고

- 작업일: 2026-09-20
- 범위: `PhotoComparisonResultDialog`, `ComparisonCropEditor`

## 변경 내용

1. 결과 확대 팝업의 `수정`은 별도 행동 메뉴 없이 즉시 현재 사진의 크롭 편집 화면을 연다.
2. 크롭 편집 화면 안에 `사진 변경`, `삭제` 행동을 함께 배치했다.
3. `사진 변경`은 기존 앨범 선택·새 사진 업로드 선택기로 이어지고, 선택 또는 업로드 후 새 사진 크롭을 확정할 때 `PATCH /me/comparisons/{id}`를 호출한다.
4. 기본 크롭 편집 저장은 `PATCH /me/comparisons/{id}/crop`을 호출한다.
5. `삭제`를 누를 때만 별도 확인 오버레이를 열고, 여기에서 `결과만 삭제` 또는 `사진도 삭제`를 선택한다. 기존 `deletePhoto` 구분과 삭제 API는 유지했다.

## 설계 결정

- 크롭 편집기는 비교 생성과 결과 수정에서 공통으로 쓰이므로, 결과 수정 화면에만 필요한 행동 영역을 선택적 `actions` 슬롯으로 추가했다.
- 삭제 선택은 편집 화면을 항상 복잡하게 만들지 않도록 `삭제`를 눌렀을 때만 열었다.
- 기존 선택기, 업로드, mutation, 오류 표시, 관련 캐시 갱신은 변경하지 않았다.

## QA 반영

- 최상위 오버레이별 `Escape` 복귀 경로를 분리했다. 삭제 확인은 크롭 편집으로만 돌아가며, 사진 선택은 크롭 편집으로, 새 사진 크롭은 사진 선택으로 돌아간다. 따라서 삭제 확인에서 `Escape`를 눌러도 수정 화면 전체가 닫히지 않는다.

## 수동 확인 항목

1. 결과 확대 → 수정 시 현재 크롭 화면이 곧바로 열리는지
2. 크롭 조정 후 저장 시 구도만 바뀌는지
3. 사진 변경 → 앨범 선택/새 사진 업로드 → 크롭 저장이 가능한지
4. 삭제 → 결과만 삭제와 사진도 삭제가 구분되어 동작하는지
