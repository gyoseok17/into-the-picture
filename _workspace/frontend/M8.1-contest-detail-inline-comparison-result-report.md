# M8.1 수상작 상세 내부 비교 결과 보기 프런트 결과

## 변경 범위

- `ContestDetailPage`에서 현재 수상작의 저장 비교 기록을 모아 상세 오버레이 위 `PhotoComparisonResultDialog`로 전달했다.
- `ContestComparisonEntry`는 기본적으로 기존 경로 링크를 유지하되, `onOpen`을 받은 화면에서는 버튼으로 렌더링해 현재 문맥 안에서 결과를 열 수 있게 했다.
- 공통 `PhotoComparisonResultDialog`의 Escape 닫기도 배경·닫기 버튼과 같은 `close` 경로를 사용하게 해, 모든 닫기 방식에서 열기 버튼으로 초점을 복귀한다.
- 마이 페이지의 기존 링크 동작은 `onOpen`을 전달하지 않으므로 바뀌지 않는다.

## 설계 결정

- 앨범에서 이미 검증한 공통 결과 창과 `ComparisonPlacementPair`를 재사용해 비교 표현과 다중 비교 선택을 통일했다.
- 수상작 상세가 오버레이로 열린 경우에도 자식 결과 창이 Escape를 먼저 소비하고, 부모 상세의 Escape·포커스 트랩은 자식 창이 열려 있는 동안 중단한다.
- 저장된 비교가 없는 경우의 `사진 놓기` 시작 경로는 새 비교를 만드는 흐름이므로 변경하지 않았다.

## 검증

- `npm run typecheck` 통과
- `npm run build` 통과 (기존 Vite 청크 크기 경고만 발생)
- `git diff --check` 통과 (기존 줄바꿈 경고만 발생)

## 영향 및 남은 위험

- API·DB·비교 저장·공개 비교 모음 계약은 변경하지 않았다.
- 실제 브라우저에서 수상작 목록 오버레이와 직접 상세 URL 각각에서 결과 창을 닫은 뒤 상세가 유지되는지 수동 확인이 필요하다.
