# M8.1 사진 놓기 앨범 묶음 선택 프런트 구현 보고

작성일: 2026-09-14
담당: 프런트엔드

## 변경 범위

- `ComparisonPhotoPickerDialog`의 앨범 탐색을 `기록 묶음 목록 → 묶음 안 사진 선택 → 확정`의 2단계로 바꿨다.
- 묶음 카드에는 대표 사진, 장소, 방문 기간, 선택 가능한 사진 수를 표시한다.
- 기존 `/me/photos/bundles?archived=false` 응답을 재사용했다. 선택 후보는 호출자가 넘긴 사진 id와 교집합을 내므로, 이미 다른 비교에 쓰여 제외된 사진은 보이지 않는다.
- `usePhotoRecordBundles`에 `enabled` 인자를 분리해, 대화상자가 처음 열릴 때는 요청하지 않고 `앨범에서 고르기`에 진입한 뒤에만 활성 기록을 조회한다.

## 설계 결정

- 비교 생성·교체가 요구하는 결과는 여전히 한 장의 `UserPhoto.id`뿐이다. 따라서 묶음은 탐색 UI의 경계로만 사용하고, 확정 계약·백엔드·DB를 바꾸지 않았다.
- 레거시 단일 사진도 서버가 한 장짜리 `PhotoRecordBundle`으로 돌려주므로 같은 카드로 표시한다.
- 묶음 응답 오류에는 재시도, 후보가 전혀 없을 때는 빈 상태, 묶음 선택 뒤에는 두 단계 뒤로가기를 제공한다.

## 영향과 호환성

- 공통 대화상자를 쓰는 새 비교 생성, 기존 비교 사진 교체, 앨범에서 수상작 비교 시작에 동일하게 반영된다.
- 새 사진 업로드·EXIF 날짜 미리채움·date-only `takenAt` 전송 흐름은 변경하지 않았다.
- 보관함(`archived=true`) 조회는 사용하지 않는다.
