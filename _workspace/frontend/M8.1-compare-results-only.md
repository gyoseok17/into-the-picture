# M8.1 사진 놓기 결과 목록 전환

## 변경 범위

- `src/pages/ComparePage.tsx`
- `/compare`에서는 새 사진 놓기 작성·수상작 선택 UI를 렌더링하지 않는다.
- `/compare?contestId=<id>`에서는 해당 수상작을 고정하고 내 사진 선택·추가와 저장만 제공한다.
- 기존 결과가 있으면 해당 결과를 자동으로 연다.

## 설계 결정

- 새 결과 작성은 수상작 상세·즐겨찾기에서 전달한 `contestId` 진입점에서만 시작한다.
- 결과 목록과 결과 상세는 기존 비교 데이터 계약을 그대로 사용한다.
- 상세의 삭제는 즉시 실행하지 않는다. `결과만 삭제`는 내 사진을 앨범에 남기고, `사진도 삭제`는 비교와 사진을 함께 삭제한다.
- 사진 변경과 위 삭제 선택은 기존 비교 결과 상세 안에서 제공한다.

## 품질 정리

- `ComparePage`의 화면 조립, 비교 결과 목록, 사진 고르기, 결과 상세, 삭제 선택을 읽을 수 있는 컴포넌트로 분리했다.
- API 호출·deep-link 조건·삭제 및 사진 교체 동작은 기존 훅과 계약을 그대로 유지했다.
- 외부 생성 코드와 이전 `SelectionPanel` 경로는 남기지 않았다.

## 검증

- `frontend`: `npm run build` 통과.
- `git diff --check -- src/pages/ComparePage.tsx` 통과.
- `SelectionPanel`, 이전 composer 관련 문자열 검색 결과 없음.
- Vite의 기존 500 kB 청크 경고만 발생.

## 남은 위험 / 통합 확인

- 상세·마이에서 `contestId`로 진입했을 때 기존 비교가 있으면 결과를 열고, 없으면 해당 수상작 고정 작성 화면을 표시해야 한다.
