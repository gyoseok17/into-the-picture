# M8.1 사진 기록 앨범 책임 분리 보고

## 변경 범위

- `PhotoRecordAlbum`에서 순수 표시 규칙(묶음 키, 날짜·기간 표시, 정렬·그룹화, 입력 정규화)을 `lib/photoRecordAlbumPresentation.ts`로 분리했다.
- 스토리 타임라인의 레이아웃·연결선·카드 배치 반복은 `PhotoRecordStoryTimeline.tsx`로 분리했다.
- 사진 묶음 카드와 비교 연결 표시는 `PhotoRecordBundleCard.tsx`로 분리했다.

## 설계 결정

- 상위 화면은 조회·뮤테이션·화면 전환·선택 상태만 조립한다.
- 하위 컴포넌트는 API 호출이나 전역 라우트 상태를 갖지 않고, 표시 데이터와 이벤트만 받는다.
- 사용자 URL, API DTO, 업로드·삭제·보관 동작은 변경하지 않았다.
- 카드에 필요한 날짜/빈 값 표시는 공통 presentation 유틸을 한 곳에서 사용해 스토리와 보관함의 규칙이 갈라지지 않게 했다.

## 현재 업로드 정책 정합성

- 현재 승인 코드 정책은 한 묶음 요청당 사진 1~3장, 파일당 10MB, multipart 요청 전체 32MB이다.
- 이 정책은 `_workspace/contracts/M8.1-photo-record-batch-upload-limits.md`와 `_workspace/api-shapes/M8.1-photo-record-batch-upload-limits.md`에 기록되어 있다.
- 이전 4~20장/동시 업로드 서술은 과거 계획이며, 본 구현의 현재 정책을 대체하지 않는다.

## 검증

- `npm run typecheck` 통과.
- 최종 빌드 및 화면 회귀 확인은 통합 QA에 인계한다.

## 정리 완료

- 과거 단일 업로드·구형 헤더·inline 카드/표식 구현을 제거했다.
- 비교 연결 여부로 나뉘었던 두 라이트박스는 하나의 컴포넌트로 합치고, 비교가 연결된 사진에만 오버레이를 표시한다.
- 따라서 현재 렌더 경로에는 같은 카드·라이트박스 동작을 중복 구현한 코드가 남아 있지 않다.
