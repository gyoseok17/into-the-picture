# M8.1 앨범 큰 지도 직접 지역 선택 설계

## 확인 결과

- 원본 지도는 `1024 x 1536`이고, 주 지도 본토의 실제 범위는 대략 `x=160~885, y=235~1,210`, 제주가 `x=275~440, y=1,270~1,380`에 있다.
- 현재 `koreaRegions.ts`의 SVG는 `viewBox 0 0 100 150`인데, 경로가 임의의 단순 다각형이다. 예를 들어 강원 경로의 꼭대기는 `y=12`(원본 123px)인 반면 그림 본토 꼭대기는 약 `y=22~25`(225~255px)부터다. 이 때문에 최상단 영역부터 실제 블록보다 위로 떠 있다.
- `RegionArtwork`는 작은 선택 UI용 `max-w-[15rem]` 컴포넌트를 재사용했다. 큰 지도 오버레이에서 `h-full max-w-none`로 보정해도, 작은 지도용 경로와 큰 지도용 클릭/강조/도시선택 책임이 섞여 있어 계속 맞추기 어렵다.

## 큰 지도 전용 최소 구조

`PhotoRecordMapView` 안에서만 아래처럼 조립한다.

1. `AlbumMapRegionLayer`: 큰 PNG와 동일한 `viewBox="0 0 1024 1536"` SVG 레이어. 8개 투명 영역 클릭과 선택 강조만 담당한다.
2. `AlbumMapCitySheet`: 선택한 권역의 도시/지역 칩만 하단 시트(PC는 우측 작은 패널)로 보여 준다.
3. 사진 핀은 레이어보다 위에, 도시 시트보다 아래에 둔다. 권역 클릭은 사진 선택을 닫고 도시 선택 단계로 간다.
4. 기존 `PhotoRegionField`는 업로드 폼 전용으로 둔다. 같은 `koreaRegions` catalog와 `RegionSelection` 타입만 공유한다.

즉 큰 지도에 작은 `PhotoRegionField` 전체를 올리지 않고, 지도 자체가 첫 단계가 된다.

## 구현 전 확인/QA

- 위 경로는 투명 fill에도 클릭되도록 `pointer-events: all`을 두고, 핀은 `z-index`로 우선한다.
- 1024px 원본, 375px 모바일, 넓은 PC에서 각 8개 영역의 중앙/경계 1회씩 눌러 본다. 흰 경계선 위는 인접 영역 어느 쪽으로 골라도 되는 완충 터치 영역으로 둔다.
- 배경 PNG가 바뀌면 경로를 다시 맞춰야 하므로, `mapArtworkVersion` 또는 에셋 파일명을 catalog 주석에 함께 기록한다.
- 이 변경은 프런트 UI 설계만이다. 선택값 저장/API 계약은 `mapRegionCode`, `mapCityCode` optional 계약을 유지한다.
