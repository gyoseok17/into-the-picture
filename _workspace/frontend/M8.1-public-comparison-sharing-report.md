# M8.1 공개 수상작 비교 - 프런트엔드 보고

## 변경 범위

- `comparison` 도메인에 소유자 공개 상태(`PUBLIC`/`PRIVATE`)와 공개 전용 DTO를 분리했다.
- 수상작 상세에서 공개 비교 사진을 별도 갤러리로 표시한다.
- 비교 결과 상세에서 소유자가 공개/비공개를 전환할 수 있다.

## 설계 결정

- 공개 목록은 개인 `UserPhoto` DTO를 재사용하지 않고, `{ id, photoUrl, createdAt }`만 받는다. 장소, 메모, 촬영일, 파일명, 소유자와 앨범/지도 정보는 화면 코드에도 전달하지 않는다.
- 공개 이미지는 `/api/v1/contests/.../file` 전용 경로를 쓴다. `/me/photos/**` 경로나 인증 Blob 로더를 사용하지 않아 공개 화면이 개인 파일 권한에 의존하지 않는다.
- 로그인 사용자는 자신의 비교 목록이 준비된 뒤 공개 목록을 표시하고 자신의 비교 ID를 필터링한다. 따라서 수상작 상세에서 자신의 결과가 두 번 보이지 않는다.
- 공개 상태 변경·사진 교체·삭제·새 비교 생성 뒤에는 공개 목록 캐시도 함께 무효화한다.

## 후속 UI 정리 (2026-09-13)

- 비교 결과의 공개 상태 버튼은 상태 전환 문구를 함께 쓰지 않고 `공개` 또는 `비공개`만 표시한다. 비공개 상태는 낮은 대비의 테두리·텍스트로 꺼진 상태를 드러내며, 보조 기술에는 현재 상태와 누를 때의 전환 결과를 `aria-label`과 `title`로 제공한다.
- 수상작 상세의 공개 비교 사진은 본문에 항상 펼치지 않는다. 하트 바로 옆의 사진 모음 아이콘 버튼으로 연 뒤, 별도 모달에서만 공개 비교 사진을 확인한다. 요청도 모달을 열 때 시작해 상세 첫 진입의 불필요한 목록 호출을 없앤다.
- 모달은 본인 비교를 계속 제외하고, 로딩·빈 목록·오류·재시도 상태를 기존 공개 목록과 동일하게 유지한다. 상세 오버레이 위에서도 Escape·Tab이 바깥 상세로 새지 않도록 부모 포커스 트랩을 일시 중지하고, 닫을 때 열었던 버튼으로 포커스를 돌려준다.
