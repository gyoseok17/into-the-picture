# M8.1 앨범 지도 지역 선택 UI 제안

## 현재 확인

- 지도는 `1024 x 1536` PNG(`album-map-korea.png`) 위에 위경도 기반 사진 핀만 얹는 구조다.
- PNG의 도 경계는 장식용 이미지이므로 클릭 가능한 경계 데이터가 없다. 현재 `PhotoRecord`에는 `placeName`, `lat`, `lng`만 있고 행정지역 필드는 없다.

## 최소 2단계 UI

1. 지도 위의 8개 권역을 투명 SVG 경로로 덮는다. 권역을 누르면 해당 영역만 민트색 테두리/반투명 채움으로 강조한다.
2. 같은 지도 위에 작은 바텀시트(PC는 우측 패널)를 열어, 해당 권역의 대표 `시·군·구`를 칩으로 고른다. 전국 시·군·구 폴리곤을 새로 그리지 않는다.
3. 선택 결과는 `시·도 + 시·군·구` 텍스트와 해당 시·군·구의 대표 좌표를 한 항목으로 저장한다. 세부 장소명은 기존 자유 입력값으로 유지한다.

## 권역·도시 데이터 모듈

`features/photo-record/lib/koreaRegions.ts` 한 곳에 순수 데이터와 조회 함수를 둔다.

```ts
type KoreaRegion = {
  id: 'capital' | 'gangwon' | 'chungcheong' | 'jeonbuk' | 'jeonnam' | 'gyeongbuk' | 'gyeongnam' | 'jeju'
  label: string
  mapPath: string // PNG 비율(viewBox 0 0 100 150) 기준 SVG path
  cities: Array<{ id: string; label: string; lat: number; lng: number }>
}
```

- 권역: `수도권(서울·경기·인천)`, `강원`, `충청(대전·세종 포함)`, `전북`, `전남(광주 포함)`, `경북(대구 포함)`, `경남(부산·울산 포함)`, `제주`.
- 2단계 목록은 법정 시·군·구 단위로 완전하게 시작한다. 이름만 '도시/지역 고르기'로 보여서 군 지역도 누락하지 않는다.
- 초기에는 각 항목의 대표 청사/중심 좌표 하나만 둔다. 같은 지역 사진은 약간씩 겹침을 피해서 배치하고, 이후 장소 좌표가 있으면 기존 좌표를 우선한다.
- 데이터 범위 예: 수도권 `서울 25구, 인천 10구·군, 경기 31시·군`, 강원 18시·군, 충청 28시·군·구, 전북 14시·군, 전남 22시·군, 경북 22시·군, 경남 18시·군, 제주 2시. 총 약 190개로 정적 TS 데이터에 무리 없는 규모다.

## 컴포넌트 분리

- `RegionMapLayer`: 지도 PNG와 8개 SVG 클릭 경로, 선택 강조만 담당.
- `CityRegionPicker`: 선택 권역의 시·군·구 칩 검색/선택과 취소만 담당.
- `PhotoRecordMapView`: 앨범 핀/사진 선택만 유지하고 위 두 UI를 조립한다.
- 업로드 폼에는 `PhotoRegionField`를 별도 추가해 동일 선택값을 재사용한다. 지도에서 선택하는 UI와 저장 폼이 같은 `RegionSelection` 타입을 사용한다.

## API·데이터 변경 전제

- 지역을 '미리 저장'하려면 이후 `PhotoRecord`에 `regionCode`, `regionLabel`, `regionLat`, `regionLng`(또는 지역 FK)를 추가하고 업로드/수정/목록/지도 응답 계약을 함께 확장해야 한다.
- 기존 `lat/lng`은 장소 지오코딩 결과이므로 덮어쓰지 않는다. 지도 표시는 `장소 좌표 > 저장 지역 대표 좌표` 우선순위로 정한다.
- 기존 사진은 null 지역으로 보존한다. 장소 지오코딩 성공 사진은 그대로 지도에 표시하고, 지역 선택을 강제하지 않는다.

## 위험과 검증

- PNG의 경계와 SVG 경로가 정확히 일치하지 않을 수 있으므로 실제 지도 이미지를 기준으로 넓은 터치 영역을 잡아 PC·375px 모바일에서 8개 권역을 모두 눌러 본다.
- 권역 선택은 지도 표시용 보조 정보이며 실제 주소의 정밀 행정구역 판정으로 쓰지 않는다.
