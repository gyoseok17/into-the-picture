# M8.1 프런트엔드 Caddy 정적 배포 보고

## 변경 범위

- `frontend/Dockerfile`: Node 20 Alpine 빌드 단계에서 `npm ci`와 `npm run build`를 실행하고, Caddy 2.8 Alpine 런타임에 `dist`만 복사하도록 구성했다.
- `frontend/Caddyfile`: 런타임 `{$APP_DOMAIN}` 사이트 주소에서 `/api/*`, `/files/*`를 `backend:8080`으로 먼저 프록시하고, 나머지는 정적 파일 및 SPA fallback으로 처리한다.
- `frontend/.dockerignore`: 의존성·산출물·Git·로컬 환경 파일·모바일 산출물을 build context에서 제외했다.

## 설계 결정

- `VITE_API_BASE`(기본 `/api/v1`)와 `VITE_KAKAO_JS_KEY`만 build ARG/ENV로 전달한다. 둘은 브라우저 번들에 포함되는 공개 설정이며 서버 DB·JWT·OAuth 시크릿은 받지 않는다.
- 사이트 주소에는 Caddy 런타임 환경 치환 문법 `{$APP_DOMAIN}`을 사용한다. 이를 통해 Compose가 실제 도메인을 주입하면 Caddy가 자동 HTTPS와 80→443 리다이렉트를 관리한다.
- 기존 개발 프록시와 API 응답의 이미지 URL 호환성을 유지하려고 `/files/*`도 같은 백엔드로 프록시했다.
- `handle` 블록은 서로 배타적이며 API·파일 프록시가 SPA `try_files`보다 먼저 처리된다. 따라서 `/api/*` 요청이 `index.html`로 떨어지지 않는다.

## 검증

- `npm run typecheck` 통과.
- `npm run build` 통과. 기존 Vite 500kB 청크 권고만 비차단으로 남는다.
- `git diff --check` 통과. 기존 CRLF 안내만 출력된다.
- Docker Desktop Linux 엔진이 실행 중이지 않아 `docker version` 연결과 실제 Caddy 이미지 빌드·설정 검증은 수행하지 못했다. 엔진 기동 뒤 `docker compose build frontend`와 `docker compose config`로 확인이 필요하다.

## 영향과 후속 위험

- 프런트 이미지에는 정적 산출물과 Caddy 설정만 남아 서버 시크릿·소스·`node_modules`가 포함되지 않는다.
- `APP_DOMAIN`은 Caddy 사이트 주소이므로 Compose 런타임에서 반드시 실제 도메인으로 제공해야 한다. 이 값은 프런트 담당 범위 밖의 Compose 통합 항목이다.
