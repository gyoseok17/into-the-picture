# M8.1 6블록 앨범 지도 SVG 에셋 전환안

## 목표

승인된 텍스트 없는 6블록 지도(경기·강원·충청·전라·경상·제주)를 래스터 PNG 대신 실제 SVG로 둔다. 화면에 보이는 경계와 클릭 영역은 **같은 path**를 재사용한다.

## 단일 원본 구조

새 `frontend/src/assets/album-map-korea.svg`를 경계의 단일 원본으로 둔다.

```svg
<svg viewBox="0 0 1024 1536" xmlns="http://www.w3.org/2000/svg">
  <defs>
    <path id="region-gyeonggi" d="..." />
    <path id="region-gangwon" d="..." />
    <path id="region-chungcheong" d="..." />
    <path id="region-jeolla" d="..." />
    <path id="region-gyeongsang" d="..." />
    <path id="region-jeju" d="..." />
    <symbol id="album-map-artwork" viewBox="0 0 1024 1536">
      <use href="#region-gyeonggi" class="region region-gyeonggi" />
      <!-- 나머지 5개 -->
    </symbol>
  </defs>
  <use href="#album-map-artwork" />
</svg>
```

`RegionArtwork`와 `PhotoRecordMapView`는 새 `AlbumMapSvg` 조립 컴포넌트를 사용한다. 이 컴포넌트는 같은 SVG 경로를 두 번 쓰되, 한 번은 채움/경계 표시용, 한 번은 투명한 버튼 레이어용이다.

```tsx
<svg viewBox="0 0 1024 1536">
  <use href={`${albumMapSvg}#album-map-artwork`} />
  {regions.map((region) => (
    <use
      href={`${albumMapSvg}#${region.svgId}`}
      className="fill-transparent cursor-pointer"
      onClick={() => onChoose(region.code)}
    />
  ))}
</svg>
```

따라서 `d` 값은 SVG 파일 한 곳에만 있고, 보이는 블록·선택 강조·클릭 영역이 동일한 geometry를 참조한다. Vite 번들에서 SVG가 같은 origin으로 제공되는지 1회 확인한다. 외부 `use` 호환 문제가 생기면 동일 path를 TS에 복사하지 말고, SVG 내용을 `?raw`로 불러 DOMParser로 path를 읽어 렌더링하는 폴백을 쓴다.

## 6블록 path 모델

| 코드 | SVG id | 구성 |
| --- | --- | --- |
| `GYEONGGI` | `region-gyeonggi` | 기존 수도권 블록. 화면 표기는 `경기` |
| `GANGWON` | `region-gangwon` | 북동 대형 블록 |
| `CHUNGCHEONG` | `region-chungcheong` | 중앙 블록 |
| `JEOLLA` | `region-jeolla` | 기존 전북·전남 경계를 없앤 하나의 남서 블록 |
| `GYEONGSANG` | `region-gyeongsang` | 기존 경북·경남 경계를 없앤 하나의 남동 블록 |
| `JEJU` | `region-jeju` | 제주 본섬 블록 |

각 region metadata는 `lib/mapRegions.ts`에서 `code`, `label`, `svgId`, `cities`만 가진다. `path` 문자열은 여기 두지 않는다. 즉 데이터 카탈로그와 벡터 geometry의 중복을 막는다.

```ts
export const mapRegions = [
  { code: 'GYEONGGI', label: '경기', svgId: 'region-gyeonggi', cities: [...] },
  // 5개
] as const
```

## 기존 컴포넌트 변경 범위

- `RegionArtwork`: PNG `<img>` + 자체 path loop를 제거하고 `AlbumMapSvg`만 렌더링한다. 업로드 폼에서는 `interactive` 옵션을 켠다.
- `PhotoRecordMapView`: PNG와 별도 `RegionArtwork` 오버레이를 없애고 `AlbumMapSvg` 하나를 배경/클릭 레이어로 쓴다. 지도 직접 클릭 → `AlbumMapCitySheet` 도시 칩으로 이어진다.
- `PhotoRegionField`: 도시 선택 상태/폼 연결만 유지한다. 지도 도형 책임은 갖지 않는다.
- `koreaRegions.ts`: 8개 분할과 자체 `path`를 제거하고, 서버의 6권역 코드/도시 카탈로그와 일치하는 metadata만 남긴다.

## 주의·검증

- 기존 `album-map-korea.png`과 8권역 path는 같은 커밋에서 사용처를 제거한다. 호환성 목적의 중복 보관은 하지 않는다.
- `use`의 `fill`/`stroke` 우선순위를 SVG 내부 CSS가 막지 않게, 색상은 `currentColor` 또는 외부 class로 제어한다.
- PC와 375px에서 6개 권역 중앙/경계 클릭, 키보드 Enter/Space, 선택 강조, 도시 시트, 선택 해제를 확인한다.
- 새 SVG는 텍스트를 포함하지 않는다. 지역명은 접근성 `aria-label`과 도시 선택 시트에만 둔다.
