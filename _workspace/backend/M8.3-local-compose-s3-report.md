# M8.3 로컬 Docker Compose S3 자격 증명

## 변경 범위

- `backend/docker-compose.local.yml`을 로컬 전용 Compose 오버라이드로 만들었다.
- `backend` 서비스에 `AWS_PROFILE=into-the-picture-local`을 설정했다.
- 호스트 `${USERPROFILE}/.aws`를 컨테이너 `/home/appuser/.aws`에 읽기 전용으로 bind mount했다.
- `backend/.env`의 `APP_DOMAIN`만 `localhost`로 설정했다. 다른 환경값은 읽거나 변경하지 않았다.
- 로컬 Compose 파일과 `.env`는 Git 제외 상태다.

## 사용 방법

```powershell
cd backend
docker compose -f docker-compose.yml -f docker-compose.local.yml up --build
```

AWS SDK 기본 자격 증명 체인은 컨테이너 안의 `/home/appuser/.aws`에서 `into-the-picture-local` 프로필을 읽는다. 이 파일은 EC2 운영 배포에는 사용하지 않으며, EC2 IAM 역할을 사용한다.

## 검증

- `docker compose -f docker-compose.yml -f docker-compose.local.yml config --quiet` 성공.
- `git check-ignore -v backend/docker-compose.local.yml`로 로컬 Compose 파일이 root `.gitignore`에 의해 제외됨을 확인.
- `backend/.env`도 기존 Git 제외 규칙을 유지함을 확인.

## 위험과 후속

- 호스트에 `${USERPROFILE}/.aws/config`와 `credentials`가 존재하고 `into-the-picture-local` 프로필이 있어야 S3 요청이 인증된다.
- bind mount는 읽기 전용이므로 컨테이너가 로컬 AWS 자격 증명을 변경할 수 없다.
- Caddy의 localhost 동작, Docker 실제 기동 및 실제 S3 Put/Get/Delete는 별도 로컬 통합 검증 대상이다.
