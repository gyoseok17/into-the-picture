# M8.1 수동 촬영일 multipart 백엔드 보고

## 변경 범위

- `PhotoRecordBundleService`에 자동 촬영일 예약값 `__AUTO__`를 추가했다.
- `manualTakenAts`가 전달됐을 때 `files`와 동일한 개수를 요구하는 기존 검증은 유지했다.
- 예약값은 해당 파일의 수동 촬영일 없음(`null`)으로 파싱한다.
- 예약값과 뒤 파일의 수동 날짜가 섞인 경우 파일별 순서가 보존되는 서비스 테스트를 추가했다.

## 설계 결정

multipart의 빈 문자열 파트는 Spring 바인딩 과정에서 누락될 수 있다. 따라서 빈 값을
순서 맞춤 신호로 쓰지 않고 명시적인 `__AUTO__` 예약값을 사용한다. 값 수가 부족할 때
서버가 임의로 null을 보충하면 뒤 파일 날짜가 앞 파일에 적용될 위험이 있으므로 계속
400으로 거절한다.

프런트는 수동 날짜가 없는 각 파일에 빈 문자열 대신 `__AUTO__`를 전송해야 한다.

## 검증

- 기존 파일 수/수동 날짜 수 불일치 거절 테스트 유지.
- `["__AUTO__", "2026-08-30"]` 입력이 파일별 `[null, 2026-08-30T00:00]`으로
  해석되는 테스트 추가.
- Gradle 대상 테스트는 작업 공간의 기존 Gradle 실행/파일 접근 지연으로 제한 시간 안에
  완료 출력을 얻지 못했다. 통합 QA에서 재실행 필요.

## 남은 위험

- 예약값으로 바꾸지 않은 이전 프런트는 빈 multipart 파트 누락 시 계속 400을 받는다.
  프런트 요청 변경과 함께 배포해야 한다.
