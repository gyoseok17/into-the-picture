# M8.1 사진 기록 묶음 업로드 한도 — 백엔드 보고

## 변경 범위

- `PhotoRecordBundleService`: 묶음 최대 사진 수를 20장에서 3장으로 변경했다.
- `application.yml`: 각 파일 10MB는 유지하고 multipart 요청 전체 한도를 10MB에서 32MB로 올렸다.
- `PhotoRecordBundleServiceTest`: 4장 거절과 저장·파일 처리 미실행을 검증하도록 조정했다.

## 설계 결정

전체 요청 한도는 30MB가 아니라 32MB다. 세 파일이 각각 정확히 10MB일 때 multipart 경계와 선택 텍스트 필드가 더해져도 정상 요청이어야 하기 때문이다. 단일 파일 10MB 제한은 Spring이 요청 파싱 단계에서, 이미지 검증기는 서비스 저장 직전에 중복 방어한다. 파일 수는 서비스 계층에서 검증해 API 호출 경로나 클라이언트 우회를 막는다.

## 검증과 남은 위험

- 단위 테스트는 4장 입력이 bundle 저장 및 물리 파일 처리 전에 거절되는지 확인한다.
- multipart 32MB 초과는 컨테이너 요청 파싱 이전/중에 발생하므로 서비스 단위 테스트 대신 Spring 설정으로 제한한다.
- 프런트가 아직 최대 3장·합계 제한 안내를 제공하는지는 프런트 역할과 통합 QA가 대조해야 한다.
