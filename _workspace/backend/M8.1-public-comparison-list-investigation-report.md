# M8.1 수상작 공개 비교 목록 조사 - 백엔드 보고

## 조사 범위

- 공개 비교 목록·파일 endpoint의 라우팅, 보안, 조회 조건
- 공개 기본값과 공개 상태 변경 뒤 목록 반영 조건
- 현재 수상작 상세에서 사진이 보이지 않는 가능한 원인

## 확인 결과

- `PublicContestComparisonController`는 모든 REST 컨트롤러 공통 prefix에 따라 `GET /api/v1/contests/{contestId}/comparisons`를 제공한다.
- SecurityConfig의 `anyRequest().permitAll()` 범위에 있으므로 공개 목록은 인증 때문에 차단되지 않는다.
- 서비스는 수상작 ID 일치, `comparison_visibility = PUBLIC`, `archived_at is null` 조건을 모두 적용한다. 기본 공개값은 엔티티와 V14 마이그레이션에서 `PUBLIC`이다.
- 로컬 실행 서버에서 contest 94 목록을 호출해 `200 []`를 확인했다. 서버 라우팅이나 권한 오류가 아닌, 해당 필터에 맞는 데이터가 없다는 응답이다.
- 공개 사진 파일도 목록과 동일한 조건을 재검사하므로 비공개·삭제·다른 수상작의 파일을 노출하지 않는다.

## 프런트와의 교차 확인

- 현재 공개 갤러리는 자신의 비교 ID를 제외하도록 되어 있다. 같은 계정에서 만든 비교를 공개로 바꾼 뒤 같은 계정으로 수상작 상세를 열면, 목록에서 보이지 않는 것은 의도된 동작이다.
- 다른 계정의 공개 비교가 있거나 로그아웃 상태에서만 그 공개 사진이 갤러리에 나타난다.

## 수정 여부

서버 수정 없음. endpoint·조회 조건·보안 경계가 요구사항(다른 사람이 비교한 사진만 노출)에 맞고, 현재 빈 목록은 데이터 상태 또는 본인 비교 제외 동작으로 설명된다.

## 검증

- 로컬 HTTP 확인: `GET /api/v1/contests/94/comparisons` -> `200 []`
- `PhotoComparisonServiceTest`는 공개 목록이 PUBLIC·활성 경계만 사용하고, 비공개/다른 수상작 파일은 저장소를 읽지 않는 단위 테스트를 포함한다.
- 해당 Gradle 단일 테스트 실행은 기존 장시간 실행 중인 Java/Gradle 프로세스 환경에서 124초 제한에 도달해 완료 결과를 얻지 못했다. 테스트 실패로 판정하지 않았으며, 서버 코드 변경도 하지 않았다.
