# M10 백엔드 역할 결과

## 변경 범위

- `PhotoRecordBundleService.list`: 묶음별 사진 조회를 묶음 ID 전체의 일괄 조회로 전환.
- `FavoriteService.favoriteContests`: 즐겨찾기별 수상작 조회를 수상작 ID 전체의 일괄 조회로 전환.
- `UserPhotoService`와 `AfterCommitFileDeletion`: 사진 레코드 삭제 시 물리 파일 삭제를 DB 커밋 뒤로 지연.
- 관련 repository 메서드와 단위 테스트 추가.

## 설계 결정과 이유

- 외부 파일 저장소는 DB 트랜잭션에 참여하지 않는다. 기존처럼 트랜잭션 중 파일을 먼저 지우면 이후 DB 롤백 시 복구된 레코드가 없는 파일을 가리킨다.
- 따라서 DB 삭제가 커밋된 뒤에만 파일 삭제를 실행한다. 커밋 전/롤백 시에는 파일을 유지한다.
- 파일 저장소가 커밋 후 실패하면 DB를 되돌릴 수 없으므로 오류를 기록하고 고아 파일로 남긴다. 사용자 데이터가 깨져 보이는 경우보다 운영 정리 가능한 고아 파일을 선택한 것이다.
- 목록 API 응답 구조와 정렬은 바꾸지 않고, 묶음 사진은 최대 1회, 저장 수상작은 최대 1회의 추가 조회로 줄였다.

## 검증

- `gradlew.bat test` 전체 통과.
- 묶음 목록의 일괄 조회, 즐겨찾기 목록의 일괄 조회·순서 유지·삭제된 수상작 제외·빈 목록 무조회 테스트 추가.
- 파일 삭제의 커밋 전 미실행, 롤백 미실행, 커밋 후 1회 실행, 커밋 후 저장소 오류 비전파 테스트 추가.
- `git diff --check` 통과.

## 영향받는 계약

- HTTP API 경로·응답 DTO·상태 코드는 변경하지 않았다.
- 상세 계약: `_workspace/contracts/M10-album-data-safety.md`
- API 형태 확인: `_workspace/api-shapes/M10-album-data-safety-api.md`

## 남은 위험·후속 작업

- 커밋 후 저장소 삭제 실패는 고아 파일을 남길 수 있다. 재시도 가능한 삭제 작업 테이블 또는 스토리지 정리 배치가 필요하면 별도 마일스톤으로 추가한다.
- DB 레벨에서 실제 쿼리 수를 계측하는 통합 테스트는 이번 범위에 포함하지 않았다. 현재는 repository 호출 단위 테스트로 회귀를 막는다.
