# 로컬 JWT fallback 키: 백엔드 결과

## 변경 범위

- `backend/src/main/resources/application-local.yml`
- `backend/README.md`
- `docs/05-auth.md`
- `_workspace/contracts/M8.1-local-jwt-development-key.md`

## 결정

`local` 프로필에만 `JWT_SECRET`의 32바이트 이상 공개 개발용 fallback 값을 추가했다. 환경변수가 있으면 Spring placeholder 규칙에 따라 해당 값이 우선한다. 기본 설정과 운영·배포 프로필은 계속 환경변수 주입을 요구한다.

## 이유

개발용 저장소를 다른 PC·경로로 옮겨도 별도 환경변수 준비 없이 기동할 수 있어야 한다. 동시에 운영 키를 소스에 넣거나 운영 프로필의 보안 경계를 낮추지 않는다.

## 영향 및 위험

- fallback 키는 공개값이므로 local 개발 외 용도로 사용하면 안 된다.
- fallback을 사용할 경우 기존 local JWT·refresh 쿠키는 새 키와 맞지 않아 재로그인이 필요할 수 있다.
- DB 연결 정보는 기존처럼 별도 설정이 필요하다.

## 검증 계획

- `JWT_SECRET` 미설정 local 기동
- `JWT_SECRET` 명시 local 기동

## 검증 결과

- `./gradlew.bat test --no-daemon` 성공: Spring 컨텍스트 테스트를 포함해 빌드와 테스트를 통과했다.
- `JWT_SECRET` 미설정 상태의 `bootRun`은 이전의 JWT 길이 예외 없이 시작 단계로 진행했다. 다만 현재 local DB 기본값은 `localhost`와 빈 사용자 정보이므로 49초 안에 8080 포트가 열리지 않아 전체 기동 확인은 DB 연결 설정이 갖춰진 환경에서 다시 해야 한다.
