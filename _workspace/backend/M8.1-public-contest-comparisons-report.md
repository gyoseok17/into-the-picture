# M8.1 공개 수상작 비교 — 백엔드 결과

## 변경 범위

- `photo_record.comparison_visibility`를 추가했다. 값은 `PUBLIC`/`PRIVATE`이며 DB 기본값과 새 연결 기본값 모두 `PUBLIC`이다.
- 비교 소유자는 `PATCH /me/comparisons/{id}/visibility`으로 공개 상태를 바꾼다. 소유 확인은 기존 `findOwnedRecord(userId, id)`를 그대로 사용한다.
- 공개 조회와 파일은 `/contests/{contestId}/comparisons` 아래 별도 경로다. 목록 DTO에는 비교 id, 공개 파일 URL, 비교 생성 시각만 담는다.
- 공개 파일 요청은 `(comparison id, contest id, PUBLIC, archivedAt is null)`을 한 번에 조회한 뒤에만 저장소 키를 읽는다. 실패 시 `404`이며 `/me/photos/**`나 임의 저장소 경로로 우회하지 않는다.
- 공개 URL은 브라우저 이미지 태그가 Vite SPA로 가지 않도록 `/api/v1/contests/.../file` 전체 API 경로를 반환한다.
- 비교 사진 교체 시 기존 공개 상태를 새 사진에 유지한다. 비공개 비교가 교체만으로 공개되는 회귀를 막는다.

## 검증

- `./gradlew.bat test --tests com.intothepicture.domain.comparison.service.PhotoComparisonServiceTest` 통과
- 테스트: 기본 공개, 소유자 공개 상태 변경, 비소유자 차단, 공개 목록의 repository visibility/active 경계, private/wrong-contest 파일 요청의 저장소 미접근, public scoped file 로드, 교체 시 공개 상태 보존

## 남은 위험

- 이 작업은 비교 사진의 공개 경계만 제공한다. 작성자 표시, 좋아요, 댓글, 신고/관리 기능은 포함하지 않는다.
- 브라우저가 이미 내려받은 이미지를 사용자가 별도로 저장한 경우까지 회수할 수는 없다. 서버 응답에는 `Cache-Control: no-store`를 사용해 공개 상태 전환 뒤 브라우저 캐시 재노출은 줄인다.
