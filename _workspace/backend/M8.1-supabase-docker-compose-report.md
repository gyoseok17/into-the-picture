# M8.1 Supabase Docker Compose 백엔드 보고

## 변경 범위

- `backend/docker-compose.yml`에서 MySQL 서비스와 고정 DB 비밀번호를 제거했다.
- 백엔드만 빌드·실행하며 `backend/.env`를 `env_file`로 주입해 외부 Supabase PostgreSQL에 연결한다.
- `backend/Dockerfile`은 Java 17 런타임에서 Spring Boot JAR를 비루트 사용자로 실행한다.
- 현재 `LocalFileStorage`의 `/app/uploads`는 named volume `itp-uploads`에만 연결했다. S3/Supabase Storage 구현은 추가하지 않았다.
- Spring의 `.env` 파일 import를 선택적으로 바꿔, 로컬 Gradle 실행은 파일을 읽고 Docker/운영은 주입된 환경변수만으로 시작할 수 있게 했다.

## 설계 결정

- Supabase는 이미 운영하는 외부 PostgreSQL이므로 Compose에 DB 서비스·포트·초기 비밀번호를 중복 정의하지 않는다.
- `backend/.env`는 이미지에 복사하지 않고 `env_file`로만 주입한다. `.dockerignore`가 `.env`와 로컬 업로드를 빌드 컨텍스트에서 제외한다.
- named volume은 컨테이너 재생성에는 안전하지만 서버나 볼륨 자체 손실에는 안전하지 않다. 영속 오브젝트 스토리지는 후속 S3 작업에서 교체한다.

## 검증

- `cd backend; docker compose config` 통과.
- `cd backend; .\\gradlew.bat test` 통과.
- `git diff --check` 통과.
- `docker compose build backend`는 Docker Desktop Linux 엔진이 실행 중이지 않아 이미지 빌드 시작 전에 실패했다. Docker 데몬을 시작한 뒤 재검증이 필요하다.

## 영향과 호환성

- 기존 로컬 실행 `cd backend; .\\gradlew.bat bootRun`은 유지된다.
- Compose 실행은 `cd backend; docker compose up --build`다.
- API, DB 스키마, 인증 계약, 파일 접근 권한은 변경하지 않았다.
