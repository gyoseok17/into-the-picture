# M8.1 local dotenv configuration — backend report

## Change scope

- `application-local.yml` imports the ignored `backend/.env` for local Gradle execution.
- Removed local YAML fallbacks for the JWT signing key and datasource host, port, and database name.
- Updated backend run documentation without recording any secret values.

## Design decision

- Spring Boot's native config import with the `.properties` extension hint is used instead of a dotenv runtime dependency.
- The import is local-profile-only, so deployed profiles continue to receive configuration from their deployment environment or secret store.

## Verification

- `./gradlew test --no-daemon` passed.
- Startup was not attempted after this change. QA found that the moved backend `.env` does not declare the `DB_PORT` and `DB_NAME` keys required by the no-default datasource contract. No values were invented or added.

## Open decision

- The `backend/.env` import is required for local execution. A missing file fails startup so a moved project does not silently use unrelated machine settings.

## Relocation (2026-09-07)

- Moved the ignored local backend config file to `backend/.env` without reading or recording any values.
- Added `backend/.env.example` with key names only and an explicit root `.gitignore` rule for `backend/.env`.
- Changed the local config import to required `file:.env[.properties]`; a missing backend-local file now fails clearly instead of falling back to unrelated machine settings.
- Verification: `backend/gradlew.bat test --no-daemon` passed and `git diff --check` passed.
