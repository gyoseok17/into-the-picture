# M10 앨범 삭제 안전성·조회 계약

## 범위

- 대상: `DELETE /me/photo-record-bundles/{bundleId}`, 앨범 묶음 목록, 저장 수상작 목록.
- 제외: HTTP 경로·상태 코드·응답 DTO 및 파일 저장소 종류 변경, 삭제 재시도용 영속 작업 큐 도입.

## 묶음 삭제

1. 요청자는 자신의 묶음만 삭제할 수 있다.
2. 수상작 비교에 연결된 사진이 하나라도 있으면 `409 CONFLICT`로 거절하며 DB·파일 모두 변경하지 않는다.
3. 비교 연결이 없으면 사진 레코드와 사진 메타데이터, 묶음을 하나의 DB 트랜잭션에서 삭제한다.
4. 물리 파일 삭제는 DB 커밋 **후** 실행한다. 따라서 DB 롤백 시 이미 지워진 파일 때문에 복구된 레코드가 깨지는 일은 없다.
5. 커밋 후 파일 저장소 삭제가 실패하면 삭제 API의 DB 결과는 유지되고 고아 파일만 남을 수 있다. 이 범위에서는 오류를 기록하며, 고아 파일 재시도·정리는 운영 후속 작업이다.

## 목록 조회

- 앨범 묶음 목록은 묶음 조회 1회, 해당 묶음의 사진 레코드 일괄 조회 1회, 레거시 단일 레코드 조회 1회로 구성한다.
- 저장 수상작 목록은 favorite 조회 1회와 참조된 수상작 일괄 조회 1회로 구성한다.
- 반환 정렬과 누락된 수상작/잘못된 `externalId`를 건너뛰는 기존 동작은 유지한다.

## 검증 기준

- 삭제 거절 시 파일 삭제 예약과 DB 삭제가 수행되지 않는다.
- 트랜잭션 커밋 전에는 파일 저장소 삭제를 호출하지 않는다.
- 묶음 수와 무관하게 목록 변환 과정에서 묶음별/즐겨찾기별 추가 repository 조회가 발생하지 않는다.
