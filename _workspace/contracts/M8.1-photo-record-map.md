# M8.1 사진 기록 지도 계약

## 목표와 범위

- 사진 기록의 직접 입력 `placeName`을 지도 마커로 보되, EXIF 위치 정보는 사용하지 않는다.
- 시간순 앨범의 `takenAt ?? createdAt` 정렬은 기존 API·화면 규칙을 그대로 유지한다.
- 장소가 비어 있거나 좌표를 찾지 못한 기록은 삭제·오류 없이 지도에서만 제외한다.

## 좌표 보강 전략

- `PhotoRecord`에 `lat`, `lng`, 마지막으로 좌표화한 장소명, 마지막 시도 시각을 저장한다.
- 장소를 바꾸거나 비우면 이전 좌표·시도 상태를 즉시 지운다. 다른 장소의 오래된 핀이 남지 않는다.
- 지도 조회(`GET /me/photos/map?archived=false`)에서만 아직 좌표가 없는 장소를 카카오 `GeocodingProvider`로 최대 20건 보강한다. 업로드·편집 저장은 외부 API를 기다리지 않는다.
- 외부 응답 없음·쿼터·키 미설정은 요청 전체 실패가 아니라 해당 기록의 좌표 없음으로 처리한다. 실패 시각을 남겨 24시간 안에는 반복 요청하지 않는다.
- 좌표가 있는 기록만 지도 핀 응답에 넣는다. 다시 열었을 때 다음 미처리 후보를 계속 보강할 수 있다.

## 데이터 안전성과 보안

- 기존 사진 기록의 새 좌표 필드는 모두 nullable이다. 마이그레이션은 기존 행을 변경하거나 삭제하지 않는다.
- 지도·파일·수정·삭제는 기존 `/me/**` 인증과 사용자 소유권 경계를 유지한다.
- 지도 좌표는 사용자가 직접 입력한 장소명에서만 얻는다. EXIF GPS·원본 EXIF 위치를 읽거나 저장하지 않는다.

## API

> 구현 정정(2026-08-26): 실제 엔드포인트는 쿼리 없는 `GET /me/photos/map`이며, 활성 사진만 대상으로 한다. `archived=true` 지도 조회는 제공하지 않는다.

- `GET /me/photos/map?archived=false`는 해당 사용자의 좌표 있는 사진 기록을 최신 촬영일(없으면 업로드일) 순으로 반환한다.
- 각 핀은 `id`, `url`, `placeName`, `takenAt`, `lat`, `lng`를 포함한다.
- `archived=true`은 보관 사진 지도이며, 기본은 활성 사진이다.
