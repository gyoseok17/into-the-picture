# M8.1 사진 놓기 후보 일관성과 앨범 조회 재사용 계약

작성일: 2026-09-14
검토 역할: QA·계약 검토

## 목적

사진 놓기에서 이미 다른 수상작과 비교에 연결된 사진도 목록에서 확인할 수 있게 남기되, 다시 선택할 수는 없게 한다. 세 진입 경로는 같은 정책을 사용하고, 앨범에서 시작할 때는 이미 읽은 활성 묶음 목록을 재사용한다.

## 후보 선택 계약

| 항목 | 계약 |
| --- | --- |
| 후보 표시 | 활성 앨범의 모든 사진을 묶음 안에 표시한다. 보관함 사진은 포함하지 않는다. |
| 비교 연결 상태 | 현재 사용자의 비교 목록에 `userPhoto.id`가 있으면 해당 사진은 `이미 비교 중` 상태를 표시한다. |
| 조작 | 비교 연결 사진은 버튼을 비활성화하고 선택·확정·자르기 단계로 진행할 수 없다. 현재 비교 결과의 사진도 교체 후보에서는 동일하게 비활성이다. |
| 적용 경로 | 새 비교, 기존 비교 사진 교체, 앨범에서 수상작 비교 시작이 공통 선택창과 같은 `usedPhotoIds` 입력을 사용한다. |
| 빈 상태 | 활성 묶음이 없거나 선택 가능한 사진이 없을 때 각각 원인을 구분해 안내한다. |

이 정책은 한 사진을 하나의 비교에만 연결한다는 현재 제품 규칙을 UI에서 예방적으로 반영한다. 서버의 비교 생성·교체 권한 및 중복 검증은 계속 최종 경계다.

## 앨범 묶음 재사용 계약

- `AlbumComparisonPicker`는 앨범 화면에서 받은 활성 `PhotoRecordBundle[]`을 공통 선택창에 전달한다.
- 공통 선택창은 외부 묶음이 전달되면 `GET /me/photos/bundles?archived=false`를 실행하지 않는다. 외부 묶음이 없을 때만 앨범 진입 외 두 경로에서 직접 조회한다.
- 보관함(`archived=true`)은 외부 전달·직접 조회 어느 경우에도 후보가 될 수 없다.
- 외부 묶음이 갱신되어도 선택창의 선택 id는 해당 묶음에 남아 있을 때만 유효하다. 사라지면 확정할 수 없다.

## 업로드 뒤 캐시 계약과 결정

- 비교 전용 `POST /me/photos` 성공 뒤에는 `user-photos`와 활성 앨범 목록·지도 관련 쿼리를 오래됨으로 표시할 수 있다.
- 이는 화면이 열려 있을 때만 재조회하므로 즉시 모든 화면을 강제로 호출하지 않는다.
- 단, 업로드 직후 비교 생성으로 이동하는 흐름에서 앨범의 즉시 실시간 반영이 제품 필수 조건은 아니다. 추가 무효화가 별도 API 호출·UI 깜빡임을 유발하지 않는지 구현 뒤 확인해, 이득이 불분명하면 현 `user-photos` 갱신만 유지한다.

## QA 위험

1. `usedPhotoIds`가 늦게 도착하는 동안 후보가 잠시 선택 가능하게 보이면 안 된다. 비교 목록 로딩을 선택창의 로딩 조건에 포함한다.
2. 비교 교체에서 현재 연결 사진을 예외로 선택 가능하게 두면 한 사진 한 비교 규칙과 모순된다.
3. 외부 묶음 전달 뒤에도 내부 훅이 실행되면 중복 GET이 발생한다. `enabled` 조건을 네트워크 탭 또는 훅 인자로 확인한다.
4. 새 사진 업로드 성공 후 비교를 저장하기 전에는 아직 비교 연결 상태가 아니므로, 업로드한 사진은 자르기·저장 단계로 진행 가능해야 한다.
