# M8.1 사진 기록 앨범 계약

## 범위

- 사진 기록은 원본 파일과 분리된 `PhotoRecord`를 계속 기준으로 삼는다. 비교 기록은 같은 사진 기록의 선택적 수상작 연결이다.
- 이번 단계는 직접 추가, 촬영일·장소·메모 편집, 시간·장소 정렬, 보관(숨김)·복원, 수상작 표시 전환을 제공한다.
- 공유, 좋아요, 공개 범위, 지도·스토리 화면은 이번 범위 밖이다.

## 기존 데이터와 빈값

- 기존 사진 기록은 보존한다. `takenAt`, `placeName`, `memo`가 비어 있어도 유효하다.
- 날짜가 없으면 화면은 `촬영일 미상`으로 표시하고 업로드일로 정렬을 보완한다. 장소가 없으면 `장소 미상`으로 표시한다.
- 새 JPEG·PNG·WebP는 선택 직후 브라우저에서 촬영 시각 EXIF를 읽어 입력칸에 미리 보인다. HEIC/HEIF는 브라우저 호환성에 따라 직접 입력 안내를 보이되 업로드는 허용한다. 이미 사용자가 입력한 날짜는 덮어쓰지 않는다. 브라우저가 읽지 못해도 서버가 업로드 때 다시 시도하며, EXIF의 위치 정보는 읽거나 공개하지 않는다.

## API

- `POST /me/photos`: 파일과 선택적 `takenAt`, `placeName`, `memo`를 받아 사진 기록을 만든다. 요청 날짜가 없으면 서버가 JPEG EXIF 촬영 시각을 시도한다.
- `GET /me/photos?archived=false`: 활성 사진 기록 목록. `archived=true`이면 보관한 기록만 반환한다.
- `PATCH /me/photos/{recordId}`: 촬영일·장소·메모·보관 상태·수상작 표시 방식을 수정한다. 모든 요청은 소유자만 수정할 수 있다.
- 응답은 기록 ID, 파일 정보, 촬영일·장소·메모·보관 시각·수상작 연결/표시 정보를 포함한다.

## 표시·삭제 규칙

- `archivedAt`은 사진을 삭제하지 않는 숨김 상태다. 복원하면 다시 활성 목록에 나온다.
- 수상작이 연결된 기록은 수상작 연결을 지우지 않고도 `PHOTO_ONLY`로 표시를 감출 수 있다. 다시 `WITH_CONTEST`로 바꾸려면 연결된 수상작이 있어야 한다.
- `PHOTO_ONLY`면 비교 결과 목록과 상세에서 수상작 이미지를 숨기고 내 사진만 보인다.
- 기존 비교 삭제·사진 삭제 규칙은 유지한다. 파일은 참조하는 사진 기록이 없을 때만 삭제한다.
