# M9 앨범 스토리 빈 상태 계약

- 조건: 앨범의 스토리 모드(`layout=story`)에서 조회 완료 후 묶음이 0개다.
- 표시: 사진 기록이 없다는 안내와 사진 추가 행동을 스토리의 중앙 배경 영역 안에 세로 중앙 정렬해 제공한다.
- 행동: 사진 추가를 누르면 기존 사진 추가 시트가 열리고, 사용자가 사진을 추가한 뒤 완료하면 시트가 닫히고 스토리 목록이 갱신된다.
- 제외: 지도 빈 상태의 기존 동작은 변경하지 않는다.

## PC 비교 사진 크롭 입력 계약

- 조건: 수상작과 다른 비율의 사진을 비교용으로 맞추기 위해 크롭 편집기를 연다.
- 입력: 마우스·터치로 사진 영역을 끌면 브라우저의 이미지 파일 드래그가 아니라 기존 크롭 오프셋 조절로 처리한다.
- 유지: 확대·초기화·확정 동작과 저장되는 `ComparisonCrop` 값의 형식은 바꾸지 않는다.
- 표시: 저장 후 일반 수상작 비교 결과도 같은 `ComparisonCrop`의 비율·확대·위치를 적용해 렌더한다.
- 일관성: 수상작 비교에 속한 목록·상세·공개 비교는 모두 같은 `ComparisonCrop`을 적용하며, 앨범과 일반 사진 목록은 원본 사진을 유지한다.

## 비교 결과 관리와 이동 계약

- 비교 저장: 앨범에서 수상작 비교를 저장한 뒤 현재 앨범에 남고 선택 창만 닫는다.
- 결과 관리: 로그인한 본인의 비교 결과 팝업에서 결과만 삭제, 사진까지 삭제를 제공한다. 사진 교체는 제공하지 않는다.
- 경로: `/compare` 라우트와 내부 이동 경로를 제거한다. 직접 접속은 별도 리다이렉트 없이 기본 Not Found 처리한다.
- 비교 관리: `/me/comparisons`는 `비교 관리`라는 이름으로 공개·비공개 일괄 변경을 제공한다.
- 계정 메뉴: 닉네임 메뉴는 바깥 클릭·Esc·경로 변경·마이 메뉴 클릭에서 닫힌다.

## 보관함 제거 계약

- 프런트: 앨범에서 보관함 전환, 보관·꺼내기 버튼과 `archived` 조회를 제거한다.
- 백엔드: 사진 조회·수정 API에서 보관 상태를 노출하거나 변경하지 않는다.
- 데이터(초기 전환): 과거 보관 사진도 일반 앨범 조회에서 다시 보이게 한다.

### 스키마 정리 보정 (2026-09-20)

- V17은 `photo_record.archived_at`, `photo_record_bundle.archived_at`와 종속 인덱스를 제거하고, 현재 조회 목적에 맞는 인덱스를 다시 만든다.
- 따라서 과거 보관 시각 값도 마이그레이션 시 영구 삭제된다. 보관함 기능 자체가 없으므로 현재 화면·API 동작에는 영향이 없다.
- 운영 DB 적용 전 백업이 필요하며, 보관 상태를 되살려야 하면 별도 마이그레이션으로 열과 기능을 다시 설계해야 한다.

## 비교 사진 선택 레이아웃 계약

- 직접 업로드 파일을 고른 뒤에는 파일 선택용 큰 추가 카드가 남지 않는다.
- 선택한 사진 미리보기와 촬영일 입력을 같은 편집 영역에 배치하고, 파일 교체는 작은 `다른 사진` 행동으로 제공한다.
- 직접 업로드 기본·별도 앨범 선택·이미 비교 중인 사진의 선택 불가 규칙은 유지한다.

## 수상작 표준 위치·길안내 계약

- 수상작 95건의 승인된 `mapRegionCode`, `mapCityCode`는 앨범 지도와 같은 코드 체계로 `ContestWork`에 저장한다. ID 42는 `CAPITAL / INCHEON`이다.
- ID 34·83은 포항 스페이스워크, ID 63은 여수 영취산, ID 79는 밀양 표충사의 실제 좌표로 보정한다.
- 수상작 상세 API는 표준 지도 코드를 제공하며, 길안내는 작품 제목 대신 실제 `location` 촬영지 텍스트를 목적지로 사용한다.
- 신규 DB에서 외부 수상작 동기화가 Flyway 뒤에 실행돼도 같은 정적 보정표가 적용돼야 한다.
