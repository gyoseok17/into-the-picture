# 로컬 JWT 서명 키 계약

## 목적

> 대체됨(2026-09-07): 공개 개발용 JWT fallback과 `local` 프로필 의존성은 제거했다. 현재 JWT 키는 `backend/.env` 또는 배포 시크릿의 `JWT_SECRET`에서만 읽는다. 상세 계약: `M8.1-single-backend-config.md`.

프로젝트를 새 PC 또는 새 작업 폴더로 옮긴 뒤에도 `local` 프로필의 백엔드가 별도 `JWT_SECRET` 환경변수 없이 기동된다.

## 설정 규칙

- `application.yml`의 기본 설정은 계속 `JWT_SECRET` 환경변수만 사용하며, 빈 값은 기동 실패로 처리한다.
- `application-local.yml`에서만, `JWT_SECRET`이 없을 때 공개된 개발 전용 고정 키를 fallback으로 사용한다.
- `JWT_SECRET`이 설정되어 있으면 local 프로필에서도 그 값을 우선 사용한다.
- 운영·배포 프로필은 local 파일을 읽지 않으므로 이 fallback 키를 사용하지 않는다.

## 보안 경계

- fallback 값은 운영 비밀값이 아니며, 로컬 개발용 토큰에만 사용한다.
- 운영에서는 예측 불가능한 32바이트 이상 값을 시크릿 저장소 또는 실행 환경변수로 반드시 주입한다.
- 이 변경은 이미 발급된 로컬 JWT를 무효화할 수 있다.

## 검증

- `local` 프로필에서 `JWT_SECRET` 미설정 상태로 Spring Boot 컨텍스트가 기동되어야 한다.
- `JWT_SECRET`을 명시하면 local fallback보다 명시값이 우선해야 한다.
