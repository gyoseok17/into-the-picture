# M8.1 사진 놓기 앨범 묶음 선택 계약

작성일: 2026-09-14
검토 역할: QA·계약 검토

## 목적

사진 놓기의 `앨범에서 고르기`는 개별 사진을 날짜·장소로 다시 묶지 않고, 사용자가 저장한 실제 여행 기록 묶음을 먼저 선택한 뒤 그 안의 사진 한 장을 선택한다.

## 기존 서버 계약

### `GET /api/v1/me/photos/bundles?archived=false`

- 인증된 현재 사용자만 조회한다.
- `archived=false`이면 활성 묶음과 활성 레거시 단일 사진만 반환한다.
- 일반 묶음은 `PhotoRecordBundleDto`로, `id`, `legacy=false`, `photos[]`, `takenAt`, `endedAt`, `placeName`, `mapRegionCode`, `mapCityCode`, `memo`, `archivedAt`, `createdAt`를 준다.
- 과거 단일 사진은 `id=null`, `legacy=true`, `photos` 한 장으로 감싼 같은 DTO 형태다.
- 서버는 묶음과 레거시를 시간순으로 합쳐 반환한다. 사진 배열은 묶음 안에서 생성 순서다.

## 프런트 소비 계약

- `PhotoRecordBundle` 타입은 위 DTO와 일치한다.
- 비교 생성/교체 소비자는 여전히 `UserPhoto` 형태의 한 장과 `id`만 필요하다. `PhotoRecord`는 `UserPhoto`의 필수 표시·식별 필드를 포함하므로, 선택 결과는 `photo.id`로 기존 비교 훅에 전달한다.
- 선택 대화상자는 `PhotoRecordBundle[]`을 입력으로 받고, 묶음 카드 → 해당 `bundle.photos[]` 순서로 이동한다.
- `legacy=true`인 항목은 한 장짜리 묶음 카드로 동일하게 보이며, 제외하지 않는다.
- 보관함(`archived=true`) 데이터는 어떤 진입 경로에서도 후보에 포함하지 않는다.
- 새 파일 업로드는 별도 `POST /me/photos` 계약을 유지한다. 날짜 입력은 UI에서 `YYYY-MM-DD`, 전송 시 `YYYY-MM-DDT00:00:00`이다.
- 이미 저장된 비교에 연결된 사진은 묶음과 사진 목록에서 숨기지 않는다. 해당 썸네일에는 `비교 중` 상태와 접근성 레이블을 표시하고 선택을 막는다. 비교 사진 교체 화면에서는 현재 비교에 쓰는 사진도 같은 규칙으로 다시 선택할 수 없다. 같은 사진으로의 무의미한 교체와 다른 비교 기록의 재사용을 모두 막기 위한 정책이다.
- 앨범 화면이 이미 활성 묶음을 조회한 상태로 비교 선택창을 열면, 그 묶음을 선택창 `bundles` 입력으로 전달한다. 이 경우 선택창은 `/me/photos/bundles`를 다시 요청하지 않는다. 일반 사진 놓기와 사진 교체는 선택창을 열 때만 기존처럼 조회한다.
- 비교 전용 단일 사진 업로드가 성공하면 `user-photos`와 앨범 기록·묶음·지도 쿼리를 무효화한다. React Query는 현재 구독 중인 화면만 다시 요청하므로, 앨범을 보지 않는 사용자에게 강제 조회를 만들지 않는다.

## 진입 경로와 결과

| 진입 | 후보 데이터 | 확정 결과 |
| --- | --- | --- |
| 사진 놓기에서 새 비교 | 선택창을 열 때 활성 `GET /me/photos/bundles` | 선택한 `photo.id`로 비교 생성 |
| 기존 비교의 사진 교체 | 선택창을 열 때 활성 `GET /me/photos/bundles` | 선택한 `photo.id`로 교체 |
| 앨범에서 수상작 비교 시작 | 이미 열린 앨범의 현재 활성 묶음 목록 | 선택한 `photo.id`로 비교 생성 |

## 검토 위험과 기준

1. 기존 비교 컴포넌트가 단순 `GET /me/photos`만 받으면 새 묶음 API를 실제로 주입해야 한다. UI만 묶어 보이고 데이터가 평면 목록이면 목적을 충족하지 못한다.
2. 목록이 비었을 때, 묶음 목록과 묶음 내부 사진 목록 각각에 빈 상태·되돌아가기 동작이 있어야 한다.
3. `photos=[]`인 비정상 응답은 카드로 선택할 수 없어야 하며, 표시 전 필터링한다.
4. 선택한 뒤 다른 묶음으로 돌아가면 이전 선택·확정 버튼이 남아 다른 사진을 저장하지 않아야 한다.
5. 후보 조회 실패는 기존 오류 상태와 재시도로 노출되어야 하며, 권한은 서버의 `/me` 인증으로 강제된다.
6. 아카이브/삭제 직후 React Query 무효화 키가 `photo-record-bundles`와 비교 후보 조회 키에 맞아야 오래된 사진이 나타나지 않는다.
7. 비교 중인 사진을 목록에서 필터링하면 사용자에게 사진이 사라진 이유가 보이지 않는다. 따라서 목록에는 남기되 클릭·키보드 선택을 모두 막고, 저장 직전에도 같은 id를 방어해야 한다.
