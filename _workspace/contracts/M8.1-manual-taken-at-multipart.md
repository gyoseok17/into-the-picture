# M8.1 묶음 사진별 촬영일 multipart 계약

## 요청

`POST /api/v1/me/photos/bundles` (`multipart/form-data`)

- `files`: 1~3개. 각 파일은 10MB 이하이고 multipart 요청 전체는 32MB 이하다. multipart에 추가한 순서가 사진별 촬영일 배열의 기준 순서다.
- `manualTakenAts`: 선택 필드.
  - 사진별 직접 지정값이 하나도 없으면 **필드 전체를 생략**한다.
  - 하나라도 있으면 파일 수와 정확히 같은 수의 항목을 보낸다.
  - 직접 지정하지 않은 항목은 빈 문자열이 아니라 고정 placeholder `__AUTO__`를 보낸다. 일부 multipart binder가 빈 항목을 생략해 인덱스가 밀리는 문제를 막기 위함이다.
  - 직접 지정값은 `yyyy-MM-ddT00:00:00` 또는 ISO local datetime이다.

## 서버 해석

- `manualTakenAts`가 없으면 모든 파일의 직접 지정값은 `null`이다.
- 배열이 있으면 길이가 `files`와 다를 때 `400 INVALID_REQUEST`로 거부한다.
- 같은 인덱스의 `files[i]`와 `manualTakenAts[i]`만 대응한다.
- `__AUTO__` 또는 빈 값은 직접 지정 없음(`null`)으로 해석한다.
- 촬영일 우선순위는 파일별 EXIF → 같은 인덱스의 직접 지정값 → 묶음 시작일(`takenAt`)이다.

## 필수 교차 사례

| 사례 | 전송 | 기대 결과 |
| --- | --- | --- |
| 직접 입력 없음 | `manualTakenAts` 생략 | 모든 사진이 EXIF, 없으면 묶음 시작일로 결정 |
| 모두 EXIF | `manualTakenAts` 생략 | 각 사진 자신의 EXIF가 유지 |
| 혼합 입력/EXIF | 예: `[__AUTO__, 2026-09-08T00:00:00]` | 첫 사진 EXIF, 둘째 사진 직접 입력으로 인덱스 유지 |
| 여러 직접 입력 | 파일 수와 같은 배열 | 각 파일이 같은 번호의 값 사용 |
| 길이 불일치 | files 수와 다른 배열 | 저장 전 400 거부, 파일·묶음 생성 없음 |

## 현재 묶음 한도 정정 (2026-09-12)

수동 촬영일 배열은 같은 multipart 요청의 `files`와 1:1로 대응한다. 현재 요청은 사진 1~3장만 허용하며, 파일당 10MB·요청 전체 32MB 제한을 적용한다. 이전 20장/동시 업로드 언급은 과거 계획으로 대체되었다.
