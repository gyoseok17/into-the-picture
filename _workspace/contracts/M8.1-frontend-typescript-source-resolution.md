# M8.1 프런트 TypeScript 원본 해석 계약

## 문제와 원칙

- `frontend/src`의 실행 원본은 TypeScript(`.ts`, `.tsx`)다.
- extensionless import는 TypeScript를 JavaScript보다 먼저 해석해야 한다. 오래된 산출 `.js`가 원본을 가려서는 안 된다.
- 타입 검사·빌드 스크립트는 `src`에 JavaScript 또는 declaration 산출물을 만들지 않는다.

## 생성물 정책

- 제거 대상은 `frontend/src` 아래의 `.js` 또는 `.d.ts` 중 같은 경로·이름의 `.ts` 또는 `.tsx` 원본이 존재하는 95개 파일이다. 모두 TypeScript compiler emit 형태와 일치하는 생성물임을 대조했다.
- `src/vite-env.d.ts`, `src/types/kakao.d.ts`는 대응 TypeScript 원본이 없는 수동 선언 파일이므로 보존한다.
- `.gitignore`는 source tree 안의 생성 `.js/.d.ts`를 막되, 위 두 선언 파일은 예외로 남긴다.

## 불변 조건

- API·도메인·화면 기능과 좌표값 자체는 이 계약에서 바꾸지 않는다.
- Vite 개발 서버와 프로덕션 빌드는 동일한 TypeScript 원본을 사용해야 한다.
