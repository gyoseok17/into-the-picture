# M8.1 사진별 촬영일 multipart 통합 QA

## 생산자·소비자 교차 확인

- 프런트 `manualTakenAtsForUpload`은 직접 지정값이 하나도 없으면 `undefined`를 반환한다.
- 프런트 API serializer는 값이 하나라도 있으면 파일 순서를 유지한 채, 자동 슬롯을 `__AUTO__`로 직렬화한다.
- 백엔드 controller는 반복 multipart 필드를 `List<String>`으로 그대로 서비스에 전달한다.
- 백엔드는 목록 생략을 파일 수만큼 `null`로 해석하고, 목록이 있으면 파일 수와 길이가 다를 때 저장 전에 `INVALID_REQUEST`로 거부한다.
- 백엔드는 `__AUTO__`를 `null`로 변환하고 같은 index의 파일에만 전달한다. 파일별 EXIF → 같은 index의 직접 지정일 → 묶음 시작일 순서가 보존된다.

## 필수 사례 판정

| 사례 | 교차 결과 | 판정 |
| --- | --- | --- |
| 직접 입력 없음 | 필드 생략 → 서버가 전 파일 `null` 배열 생성 | 통과 |
| 전부 EXIF | 필드 생략, 파일별 EXIF가 독립적으로 우선 | 통과 |
| 혼합 직접 입력/EXIF | `__AUTO__`가 빈 슬롯 축약을 막고 index 유지 | 통과 |
| 여러 직접 입력 | 동일 길이 배열의 각 ISO 값이 같은 번호 파일로 전달 | 통과 |
| 길이 불일치 | `resolve`/bundle save 이전 `INVALID_REQUEST` | 통과 |

## 검증 상태

- 백엔드 서비스 테스트에 mismatch 거부 및 `[__AUTO__, 2026-08-30]` → `[null, 2026-08-30T00:00]` 매핑 사례가 있다.
- 이 작업 환경에서 backend Gradle 재실행은 hang/시간 제한으로 완료 결과를 얻지 못했다. 프런트 기본 typecheck도 기존 `tsconfig`의 TS5096 충돌로 실패한다. 변경 자체가 만든 실패로 판정하지는 않았지만, 커밋 전 CI 또는 정상 로컬 환경에서 backend test와 frontend build를 다시 실행해야 한다.

## 최종 판정

- 계약 및 코드 교차 검토: **통과**.
- 실행 검증 게이트: **조건부 보류** — 위 두 기존 환경 문제와 별개로, 정상 도구 환경에서 재실행 결과를 확인해야 한다.
