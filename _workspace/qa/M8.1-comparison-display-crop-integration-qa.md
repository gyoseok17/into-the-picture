# M8.1 수상작 비율 기반 비교 구도 통합 점검

## 판정

조건부 통과. 자동 검증과 코드 교차 확인은 통과했으며, 브라우저에서 실제 사진으로 드래그·확대 저장과 공개 사진 다수 선택을 한 번 확인해야 한다.

## 확인한 계약

- API의 `crop` JSON은 `aspectRatio`, `zoom`, `offsetX`, `offsetY`로 통일되어 있다.
- 값 범위는 각각 0.25~4.0, 1.0~4.0, -1.0~1.0, -1.0~1.0이며 0은 가운데다.
- `POST`, 사진 교체 `PATCH`, 구도 수정 `PATCH /me/comparisons/{id}/crop`, 내 목록, 공개 목록이 같은 값을 사용한다.
- 공개 목록에는 사진 URL·식별자·생성 시각·표시 구도만 포함하며 개인 앨범 정보는 추가하지 않는다.

## 회귀 및 대량 목록 점검

- 기존 비교에 `crop`이 없을 때 4:3·1배율·중앙으로 표시하도록 프런트와 서버의 기본값을 대조했다.
- 공개 비교창은 기준 사진과 선택 사진 영역을 고정하고, 썸네일 영역만 `max-height`와 세로 스크롤을 사용한다.
- 선택한 공개 사진이 목록에서 사라지면 첫 항목으로 복귀한다.
- 소유자 확인은 서버 `findOwnedRecord` 경계를 유지한다.

## 제한 및 수동 확인

병렬 QA 에이전트가 최종 브라우저 점검 전에 실행 한도에 도달해, 통합 리드가 코드·자동 검증을 직접 완료했다. 실제 브라우저에서 다음을 확인한다.

1. 가로·세로 사진 각각을 수상작 원본 비율 틀에서 드래그·확대하고 저장 후 다시 열어 같은 구도가 보이는지 확인한다.
2. 공개 사진이 여러 장인 작품에서 썸네일을 눌러도 원본·선택 사진 비교판이 움직이지 않고 선택 사진만 바뀌는지 확인한다.
3. 모바일에서도 비교창과 썸네일 목록이 화면 안에서 스크롤되는지 확인한다.
