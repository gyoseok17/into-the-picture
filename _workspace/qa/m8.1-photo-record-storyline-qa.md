# M8.1 사진 기록 스토리라인 UI 통합 QA

작성일: 2026-08-29
기준 계약: `_workspace/contracts/M8.1-photo-record-storyline.md`
상태: 구현 전 회귀 검토 완료, 최종 대조 대기

## 변경 경계

- 이번 변경은 활성 앨범의 **스토리 표시 방식**만 날짜별 세로 타임라인으로 바꾼다.
- 사진 묶음/legacy 단일 기록 조회, 카드 상세 조작, 관리 선택·삭제, 보관함, 사진 추가, 지도 모드는 기존 동작을 유지한다.
- 타임라인은 화면 조립 레이어여야 하며 `usePhotoRecordBundles`, mutation 훅, DTO·API 계약을 새로 해석하거나 복제하지 않는다.

## 현재 조립 구조 대조

- `PhotoRecordAlbum`은 `view`(active/archive), `layout`(story/map), `isManaging`, `selectedItems`, 수정 패널을 한 곳에서 조립한다. timeline 변경은 `!(active && map)`인 카드 목록의 날짜 그룹 표현에 한정해야 한다.
- 날짜 그룹은 이미 `groupBundles(..., 'time')` 결과를 사용한다. 새 타임라인도 같은 `group.bundles`와 `bundleKey`를 사용해 선택·삭제 키가 달라지지 않아야 한다.
- `PhotoRecordBundleCard`는 legacy와 새 묶음의 카드 조작 차이를 책임진다. 타임라인 래퍼가 카드 내부의 수정·보관·복원 버튼을 대체하지 않는다.
- 현재 빈 상태는 map이 아닌 목록 화면에서만 `groupedBundles.length === 0`일 때 나타난다. timeline container가 비어 있어도 별도의 빈 상태를 중복 렌더하면 안 된다.

## 빈·로딩·오류 상태

- active 기록이 0건: 타임라인 선·빈 카드·날짜 헤더가 아닌 기존 `아직 남긴 사진이 없어요` 상태 하나만 보인다.
- archive가 0건: 기존 `보관한 사진이 없어요` 상태 하나만 보인다.
- bundles loading/error: 타임라인과 카드가 동시에 나타나지 않으며, 재시도는 기존 `bundles.refetch`를 사용한다.
- map loading/error는 타임라인과 독립이다. map 오류에서 active story 빈 상태가 중복 표시되지 않는다.
- 날짜 미상 기록은 기존 `촬영일 미상` 그룹을 사용하며, 타임라인도 null 날짜로 정렬·렌더 오류가 나지 않는다.

## 일자 단위 그룹·정렬 계약 (2026-08-29)

- 타임라인 그룹의 단위는 월이 아니라 **한 날짜(YYYY-MM-DD)**다. 각 그룹은 날짜 노드 하나와 그 날짜의 카드 목록으로 구성한다.
- 그룹 날짜는 `takenAt`의 로컬 날짜를 우선 사용한다. `takenAt`이 null이면 `createdAt`의 로컬 날짜를 fallback으로 사용한다. fallback을 쓴 경우에도 카드의 촬영일 표시는 기존 의미(촬영일 미상)를 숨기거나 거짓 날짜로 바꾸지 않는다.
- 날짜가 같은 여러 bundle은 같은 노드 아래에서 정해진 최신순으로 모두 보인다. bundle 내부 사진 수가 여러 장이어도 카드 하나이며 날짜 그룹을 늘리지 않는다.
- 데이터가 없는 날짜는 타임라인에 빈 노드·빈 선·"기록 없음" 행을 만들지 않는다. API에서 실제 반환된 bundle이 있는 일자만 렌더한다.
- `takenAt`, `createdAt` 모두 없거나 유효하지 않은 legacy 데이터는 `촬영일 미상` 단일 그룹으로 안전하게 모은다. 이 그룹은 시간 순서상 마지막에 두며 날짜 포맷터가 invalid date를 출력하지 않아야 한다.

| 데이터 | 그룹 | 카드 표시 | 정렬 기대 |
| --- | --- | --- | --- |
| `takenAt=2026-08-29`, `createdAt` 존재 | 2026-08-29 | 촬영일 2026-08-29 | takenAt 기준 |
| `takenAt=null`, `createdAt=2026-08-29` | 2026-08-29 | 촬영일 미상 유지 | createdAt fallback 기준 |
| 같은 날 3개 bundle | 노드 1개, 카드 3개 | 각 bundle의 대표 사진/사진 수 | 같은 날짜 내 최신순 |
| 중간 날짜에 데이터 없음 | 노드 없음 | 없음 | 선이 빈 날짜를 암시하지 않음 |
| 두 날짜 모두 null/invalid | 촬영일 미상 노드 1개 | 촬영일 미상 | 모든 실제 날짜 뒤 |

## 일자 그룹과 모바일·관리 상호작용

- 모바일에서 같은 날 카드가 많아지면 날짜 노드와 선은 그룹의 시작에만 고정하고, 카드 수만 세로로 늘어난다. 카드마다 날짜 노드를 반복하지 않는다.
- 관리 모드의 checkbox는 날짜 노드/그룹 전체 선택이 아니라 **각 bundle/legacy 기록** 단위다. 같은 날 3개 중 1개만 골라 삭제할 수 있어야 한다.
- 선택한 마지막 카드가 삭제되면 해당 일자 노드와 그 주변 선 구간도 함께 사라진다. 다른 날짜의 노드·선·선택 상태는 유지한다.
- 날짜 그룹이 추가·삭제·정렬 변경되어도 `bundleKey` 기반 선택이 다른 카드로 이동하지 않는다. 특히 takenAt을 직접 수정해 다른 날로 옮겼을 때 선택/수정 패널 대상이 바뀌면 안 된다.
- 모바일 좁은 폭에서 날짜 라벨이 길어져도 카드 영역을 압박하거나 관리 checkbox와 겹치지 않는다. 날짜 노드는 스크린리더에 날짜 그룹 제목으로 읽히고 장식 선은 포커스를 받지 않는다.

## 확대된 스토리라인 여백·카드 배치 점검 (2026-08-29)

### 레이아웃 불변 조건

- 타임라인은 날짜 열과 카드 열을 `minmax(0, 1fr)`로 분리해야 한다. 카드 열 안의 이미지·긴 파일명·버튼 때문에 전체 페이지에 가로 스크롤이 생기면 안 된다.
- 모바일은 2열 카드, `sm` 이상은 3열, 넓은 화면은 4열로 제한한다. flex 항목의 폭 합계와 gap 합계가 항상 카드 열 너비를 넘지 않는지 확인한다.
- 같은 날짜에서 홀수 카드만 작은 세로 offset을 받는다면, offset은 `sm` 이상에서만 적용한다. 모바일에서는 모든 카드를 같은 기준선에 두어 지그재그가 터치·스크롤을 방해하지 않게 한다.
- 날짜 노드·연결선은 `aria-hidden` 장식이고 카드·checkbox보다 낮은 stacking context에 둔다. 확대된 여백은 카드 클릭 가능 영역을 가리거나 포커스를 받지 않는다.

### 회귀 시나리오

| 상황 | 기대 결과 |
| --- | --- |
| 320px 폭, 같은 날 1/2/3/7개 bundle | 가로 overflow 없음, 2열 유지, 마지막 카드·다음 날짜가 잘리지 않음 |
| 375px→768px→desktop 리사이즈 | 열 수만 자연스럽게 변경되고 카드 폭/이미지 비율/타임라인 선이 겹치지 않음 |
| 같은 날 5개 다장 bundle | 각 bundle은 카드 하나로만 보이고 사진 수가 카드 개수를 늘리지 않음; 같은 날짜 노드는 하나 |
| 관리 모드 켜기 | 카드 우측 상단 checkbox가 사진 위에서 항상 눌리고, 타임라인 선·노드·카드 이미지가 checkbox 클릭을 가로채지 않음 |
| 관리 모드에서 여러 날짜 3개 선택 | ring/checkbox 상태가 각 카드에만 적용되고, sticky 선택 삭제 바가 날짜 라벨·첫 카드·모바일 네비게이션을 가리지 않음 |
| 관리 모드에서 스크롤 | checkbox와 카드 버튼의 터치 영역이 충분하며 세로 스크롤이 의도치 않은 선택으로 바뀌지 않음 |
| 키보드 탭 | 날짜 제목은 읽히되 장식 노드/선은 포커스를 받지 않으며, 카드별 checkbox→카드 조작 순서가 DOM 순서와 일치 |
| 긴 장소명/사진 수/한 줄 이상 메모 | 카드 높이만 늘고 다음 카드·세로 offset·연결선과 시각적으로 충돌하지 않음 |

### 현재 구조의 주의점

- 현재 story 카드 열은 flex-wrap과 계산 폭을 사용한다. 디자인 여백이나 gap을 바꿀 때 각 breakpoint의 `카드 폭 × 열 수 + gap`을 함께 조정하지 않으면 모바일 가로 overflow가 생길 수 있다.
- 관리 checkbox는 카드 내부 `absolute z-10` 오버레이다. 타임라인 노드/선에 z-index를 추가할 때 checkbox보다 위로 올리면 선택 불가가 되므로 금지한다.
- 타임라인의 세로 선은 그룹 바깥의 absolute 요소이므로, 마지막 카드 높이·번역된 카드 offset 후에도 다음 날짜의 노드까지 선이 침범하지 않는지 실제 데이터(같은 날 7건)로 확인한다.

## 폴라로이드 사진 프레임 QA (2026-08-30)

### 시각 경계

- 필름 퍼포레이션·스티커 장식은 사용하지 않는다. 카드에는 사진을 돋보이게 하는 **흰 프레임, 아래쪽의 넓은 여백, 은은한 그림자**만 둔다.
- 래퍼는 시각 스타일만 책임지며 사진 카드의 클릭, checkbox, 수정·보관·복원 버튼, 이미지 alt 텍스트와 DOM 순서를 바꾸지 않는다.
- 별도 장식 DOM이 필요하다면 `aria-hidden="true"`, pointer-events 없음, tabIndex·role·클릭 핸들러 없음이 필수다. 가능하면 border/shadow CSS만으로 표현한다.
- 아래 여백은 폴라로이드의 시각적 프레임이지 별도 조작 영역이 아니다. 밝은 사진에서도 사진 경계가 보일 정도여야 하지만, 타임라인·카드 정보보다 강한 대비나 과한 그림자로 시선을 빼앗지 않는다.

### 회귀 시나리오

| 상황 | 기대 결과 |
| --- | --- |
| 일반 스토리 카드의 수정/보관/복원 클릭 | 폴라로이드 프레임/그림자가 클릭을 가로채지 않고 기존 버튼만 동작 |
| 관리 모드 checkbox 클릭 | checkbox가 사진·흰 프레임보다 위에 있으며, 선택 ring이 카드 전체에서 명확히 보임 |
| 키보드 탭 | 장식은 포커스를 전혀 받지 않음; checkbox와 카드 조작 버튼의 focus ring이 흰 프레임에 잘리지 않고 대비 있게 보임 |
| 스크린리더 | 날짜 그룹 제목·사진 alt·버튼 이름만 읽히며 장식 정보는 읽히지 않음 |
| 모바일 320px, 긴 날짜/장소명, 다장 bundle | 테두리·그림자를 포함해 카드 폭이 컨테이너를 넘지 않고 가로 스크롤 없음 |
| 같은 날 7개 카드 스크롤 | 그림자가 인접 카드 또는 다음 날짜 노드의 터치 영역을 덮지 않음 |
| 선택 카드와 오류/비활성 버튼 | primary ring, muted 테두리, disabled 버튼 텍스트가 밝은 테두리·사진 배경 위에서도 식별 가능 |

### 차단 기준

- 폴라로이드 프레임이 카드 조작을 막거나, 키보드 포커스를 가리거나, 스크린리더 탐색에 불필요한 항목을 추가하거나, 320px에서 가로 overflow를 만들면 **차단**이다.
- 흰 테두리 두께·그림자 농도처럼 기능에 영향 없는 미세한 시각 차이는 권고로 기록한다.

## 대형 묶음 뷰어와 폴라로이드 스택 상호작용 QA (2026-08-30)

### 클릭·관리 경계

- 일반 모드에서만 폴라로이드의 **사진 영역** 클릭으로 대형 묶음 뷰어를 연다. 아래 프레임의 정보/수정·보관 버튼 클릭은 뷰어를 열지 않는다.
- 관리 모드에서는 사진 클릭도 뷰어를 열지 않고 해당 카드 선택/선택 해제만 수행한다. checkbox는 항상 가장 우선하는 선택 진입점이다.
- 수정·보관·복원 버튼은 event propagation을 중단해 카드/사진 클릭과 동시에 뷰어·선택이 실행되지 않는다.
- legacy 단일 사진과 새 다장 묶음 모두 뷰어를 열 수 있으나, legacy 전용 수정/보관 규칙은 기존대로 유지한다.

### 대형 뷰어 계약

- 묶음 뷰어는 대표 사진부터 열고, 다장 묶음은 이전/다음과 썸네일 또는 카운터로 모든 사진을 탐색할 수 있다. 한 장짜리는 불필요한 탐색 버튼을 노출하지 않는다.
- 사진을 넘기거나 스택의 다른 묶음을 열 때 index는 새 사진 수 범위로 동기 보정한다. 다장 마지막 사진→한 장 묶음 전환에서 undefined 접근·렌더 중단이 없어야 한다.
- 모달은 `role="dialog"`, `aria-modal="true"`, 제목 또는 접근 가능한 label, 닫기 버튼을 가진다. 열릴 때 포커스를 모달로 옮기고 닫을 때 원래 사진 카드로 돌려준다.
- Escape·배경 클릭·닫기 버튼은 뷰어만 닫는다. 열려 있던 앨범의 관리 선택·스크롤 위치·날짜 그룹은 유지한다.
- 모달이 열리면 body scroll lock을 적용하고 닫을 때 이전 overflow 값을 정확히 복원한다. 중첩된 수정 패널/방문 내역 시트와 lock 값이 충돌하지 않게 한다.

### 필수 회귀 시나리오

| 상황 | 기대 결과 |
| --- | --- |
| 일반 모드 사진 영역 클릭 | 해당 묶음 대형 뷰어 열림, 대표 사진부터 표시 |
| 일반 모드 수정/보관/복원 클릭 | 해당 mutation/panel만 실행, 뷰어 미개방 |
| 관리 모드 사진 영역/checkbox 클릭 | 뷰어 미개방, 해당 bundle만 선택 상태 전환 |
| 다장 묶음 이전/다음/썸네일 | 모든 사진을 순환·선택 가능, 현재 사진 카운터 정확 |
| 다장 3번째→단장 묶음 뷰어 전환 | 단장 첫 사진 표시, 범위 오류·깨진 이미지·`3/1` 표기 없음 |
| Escape/배경/닫기 | 모달만 닫히고 원래 카드에 포커스 복귀, 페이지 스크롤 가능 상태 복원 |
| 320px 모바일 | 모달이 화면 폭·높이를 넘지 않고 내부만 스크롤, 하단 네비게이션·닫기 버튼과 겹치지 않음 |
| 키보드 탭/스크린리더 | 포커스가 모달 밖으로 빠지지 않고 사진 이동·닫기 버튼 이름과 현재 사진 정보 제공 |

이 상호작용에서 관리 모드가 뷰어를 열거나, 수정/보관 버튼이 뷰어와 함께 실행되거나, 닫은 뒤 body scroll이 잠긴 채 남으면 **차단**이다.

## 모바일·접근성 시나리오

- 모바일에서 날짜 노드와 카드가 겹치지 않고, 카드는 화면 폭을 넘지 않는다. 타임라인 선은 장식 요소여서 카드 버튼의 클릭/스크롤을 막지 않는다.
- 긴 장소명·여러 줄 메모·다장 사진 수 표시에서도 다음 날짜 카드와 침범하지 않는다. 그룹 사이 여백만 늘어나고 카드 자체의 기존 여백 규칙을 해치지 않는다.
- 관리 checkbox, 수정/보관/복원 버튼의 탭 순서와 accessible name은 카드 구조 변경 뒤에도 유지된다.
- 화면 폭을 PC→모바일로 바꾸고 다시 돌아와도 선택 상태·추가 패널·수정 패널이 의도치 않게 초기화되지 않는다.
