# M8.1 지도 패널 썸네일 확대 분리 QA

## 범위

- 지도에서 장소/방문 기록을 선택했을 때, 아래 사진 목록의 썸네일은 큰 사진 선택만 바꾸고 확대 창을 열지 않는지 확인한다.
- 큰 사진은 기존처럼 확대 창을 열고, 수상작 연결 트로피·방문 기록·반응형 흐름에 회귀가 없는지 확인한다.

## 계약 대조

| 조작 | 기대 결과 | 코드 확인 |
| --- | --- | --- |
| 지도 패널의 큰 사진 클릭 | 현재 선택 사진을 초기값으로 확대 창을 연다 | `photoTriggerRef` 버튼만 `setLightboxPhotoIndex(safePhotoIndex)`를 호출한다. |
| 아래 썸네일 클릭 | 패널의 큰 사진과 선택 테두리만 바꾼다 | 썸네일 버튼은 `setPhotoIndex(itemIndex)`만 호출하며 확대 상태를 바꾸지 않는다. |
| 확대 창 속 썸네일/이전/다음 | 확대 창의 사진을 바꾸고 지도 패널 선택도 동기화한다 | `selectPhoto`가 로컬 인덱스와 `onPhotoChange`를 함께 갱신한다. |
| 연결된 사진 | 지도 패널·확대 창의 썸네일 모두 트로피를 표시한다 | 두 목록 모두 `comparison.userPhoto.id === item.id`로 판정한다. |

## 경계 검토

- 단일 사진 기록은 하단 썸네일 목록이 없고 큰 사진만 확대 가능하다.
- 다중 사진 기록은 썸네일 선택 뒤 큰 사진을 누를 때만 해당 사진으로 확대된다.
- 이전 방문 기록을 선택하면 `record.id` 변경 효과가 사진 인덱스·확대 상태를 초기화하므로, 다른 방문 기록의 확대 창이 남지 않는다.
- 모바일과 데스크톱 모두 같은 `MapFocus` 이벤트 핸들러를 사용한다. 패널의 레이아웃만 달라져 클릭 계약은 동일하다.

## 자동 검증

- `frontend/npm run typecheck` 통과.
- `frontend/npm run build` 통과. Vite 500kB 청크 권고만 비차단으로 남음.
- `git diff --check` 통과. 기존 작업 트리의 CRLF 경고만 출력됨.

## 판정

통과. 사진 목록 썸네일이 확대 창을 여는 경로는 없고, 큰 사진만 확대 진입점으로 남아 있다. 실제 터치 기기에서 썸네일 한 번 탭 시 확대 창이 열리지 않는지 수동 확인만 권고한다.
