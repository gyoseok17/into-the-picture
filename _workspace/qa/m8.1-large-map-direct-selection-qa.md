# M8.1 큰 지도 직접 선택 전환 QA

작성일: 2026-08-27
범위: 사진 추가의 지역 선택 UI를 작은 지도/버튼 목록에서 큰 지도 직접 클릭으로 바꿀 때의 회귀·반응형 점검. 프로덕션 코드 수정 없음.

## 현재 구조와 먼저 막아야 할 계약 이슈

- `PhotoRegionField`는 일괄 업로드 패널의 공통 `mapRegionCode`·`mapCityCode` 입력과 지도 화면의 필터(`compact`) 양쪽에 쓰인다.
- `RegionArtwork`가 지도 PNG와 같은 2:3 비율 위에 8개 SVG path를 올리므로, 큰 지도도 **이미지와 SVG를 동일한 `relative aspect-[2/3]` 컨테이너 안에 둬야** 경계와 터치 영역이 어긋나지 않는다. `object-contain` 이미지의 바깥 여백 전체에 SVG를 절대 배치하면 안 된다.
- **차단 이슈:** 프런트 `koreaRegions`의 현재 권역 코드는 소문자(`capital`)이고 도시 코드는 표시명에서 생성된다. 서버 `MapLocationCatalog`는 대문자 ASCII 안정 코드(`CAPITAL`, `SEOUL` 등)만 허용한다. 현재 그대로는 선택 후 업로드가 400으로 실패한다. 직접 클릭 UI 전환 전에 `GET /me/photos/map/locations`의 서버 카탈로그를 소비하거나, 최소한 프런트 상수의 코드·도시 목록을 서버와 완전히 일치시켜야 한다.
- 선택 UI의 지역 상태(`regionCode`)가 내부 state로 한 번 초기화된다. 부모 값이 초기화·수정·재진입으로 바뀌어도 자동 동기화되지 않을 수 있으므로, 큰 지도 전환 시 현재 선택값을 단일 제어 상태로 만들거나 value 변경 동기화를 검증한다.

## PC QA

- [ ] 지도에서 8개 권역 각각을 클릭하면 정확히 하나만 강조되고, 그 권역의 도시 목록만 열린다. 경계선 근처를 여러 번 눌러도 옆 권역이 선택되지 않는다.
- [ ] 선택 상태에서 지도 핀/필터·닫기·헤더 버튼보다 SVG가 의도치 않게 위에 올라오지 않는다. 반대로 권역을 고르는 모드에서는 핀이 클릭을 가로채지 않도록 핀을 비활성화하거나 선택 오버레이의 z-index를 우선한다.
- [ ] 권역을 고른 뒤 도시를 선택하면 `mapRegionCode`와 `mapCityCode`가 한 세트로 부모 draft에 저장된다. 다른 권역으로 바꾸면 이전 도시 코드는 즉시 비워진다.
- [ ] 현재 선택값·강조·"다시 고르기"·초기화가 서로 맞고, 키보드 Tab/Enter/Space로 8개 권역과 도시를 모두 선택할 수 있다. 포커스 링은 실제 지도 경계 위에서 보인다.
- [ ] ESC 또는 명시적 뒤로가기/닫기로 도시 선택 단계에서 권역 단계로만 돌아가며, 이미 저장된 draft를 의도치 않게 비우지 않는다.
- [ ] 마우스 hover는 보조 피드백일 뿐 선택의 유일한 단서가 아니며, 선택 전/후 안내 문구가 명확하다.

## 모바일·터치 QA

- [ ] 320px 폭부터 지도와 SVG가 같은 비율·위치로 축소되며, 가로 스크롤이나 이미지 바깥 터치 영역이 생기지 않는다.
- [ ] 손가락 탭 한 번당 한 번만 선택된다. `touchstart`와 `click`을 함께 연결해 이중 실행하지 않고, 44px보다 작은 좁은 영역은 보이지 않는 hit-area 또는 충분한 stroke hit 영역으로 보완한다.
- [ ] 페이지 세로 스크롤 중에는 권역이 선택되지 않고, 탭에서만 선택된다. 지도 영역의 `touch-action`은 불필요하게 전체 페이지 스크롤을 막지 않는다.
- [ ] 도시 목록은 지도 아래 또는 바텀시트로 열려 헤더·업로드 버튼·브라우저 하단 영역에 가려지지 않는다. 목록이 길면 자체 스크롤 가능하고 선택 뒤 현재 선택 결과가 보인다.
- [ ] 모바일에서 선택 오버레이·사진 핀 상세 패널·앨범 헤더가 동시에 열렸을 때, 최상단 레이어 하나만 터치를 받고 바깥 탭의 닫기 동작이 엉뚱한 상태를 지우지 않는다.

## 저장·지도 회귀 QA

- [ ] 단일/일괄 업로드 모두 같은 선택값을 multipart로 보내며, 최대 20장·동시 3개 업로드 중 일부 실패 후 재시도에도 선택 코드가 유지된다.
- [ ] 서버가 반환한 canonical 코드로 선택 UI를 다시 열었을 때 같은 권역·도시가 강조된다. 대소문자·표시명 변환에 의존하지 않는다.
- [ ] 장소명이 없는 사진도 도시 선택만 있으면 지도에 도시 앵커(`locationSource: CITY`)로 나타난다. 장소 정확 좌표가 있으면 그 좌표가 우선(`PLACE`)이며 도시 코드는 필터·표시에 계속 남는다.
- [ ] 선택하지 않은 기존 사진은 기존 장소 지오코딩 핀/지도 제외 규칙을 유지한다. 보관함 사진은 활성 지도에 섞이지 않는다.
- [ ] 도시 코드를 지우면 지도 필터·강조·업로드 draft가 모두 초기화되고, PATCH에서 권역만 남기는 경우와 권역/도시를 함께 지우는 경우가 서버 계약대로 동작한다.

## 권장 통합 순서

1. 서버 카탈로그 응답을 기준으로 프런트 코드·도시 목록을 통일한다.
2. 큰 지도 전용 선택 모드와 일반 지도 필터 모드를 분리한다. 같은 `PhotoRegionField`를 억지로 두 용도로 확장해 핀 레이어·바깥 클릭 처리가 섞이지 않게 한다.
3. PC 키보드 + 모바일 실기기/DevTools 320·375·768 폭에서 위 체크리스트를 실행하고, 실제 업로드 후 새로고침·지도 재진입까지 확인한다.
