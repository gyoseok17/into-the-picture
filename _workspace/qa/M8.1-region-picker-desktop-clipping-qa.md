# M8.1 지도 지역 선택 드롭다운 클리핑 QA

- 점검일: 2026-09-10
- 범위: 앨범 지도 `RegionPicker`의 PC 상향 전개, 높이 제한·내부 스크롤, 모바일·지도 상호작용 회귀

## 검증 결과

### 화면 높이와 스크롤

- PC(`sm` 이상): 선택 대화상자는 trigger의 `bottom-full`과 `mb-2`를 사용하므로, 좌하단 trigger **위쪽**으로 열린다.
- 지도 viewport 자체에 `container-type: size`가 선언되어 있다. 대화상자의 `max-h: calc(100cqh - 5rem)`은 실제 지도 높이를 기준으로 하므로, 넓고 높은 desktop뿐 아니라 높이가 짧은 desktop에서도 상단을 넘지 않는다. trigger·여백을 제외한 최대 높이는 viewport 안에 남는다.
- 대화상자 바깥은 `overflow-y-auto overscroll-contain`, 시·군 chip 목록은 기존 `max-h-52 overflow-y-auto`를 유지한다. 긴 권역 목록은 대화상자 또는 목록 내부에서 스크롤되며 지도 페이지에 스크롤 체인이 전달되지 않는다.
- 모바일 기본값은 여전히 `bottom-0`이다. 따라서 하단 지역 선택 trigger 위로 대화상자가 열리는 기존 사용성을 유지한다.

### 지도 레이어·입력 회귀

- 기본 지도 SVG `z-1`, marker `z-2`, 빈 상태 `z-10`, MapFocus `z-20` 순서를 유지했다.
- 최초 검토에서 열린 선택 대화상자가 부모 `z-10` 때문에 MapFocus(`z-20`) 뒤에 가려질 위험을 발견했다. 구현은 `isChoosing ? z-30 : z-10`으로 보정되어 열린 대화상자가 MapFocus·marker보다 위에 놓이고, 닫히면 기존 기본 stack으로 복귀한다.
- 지역 열기·닫기·시군 선택은 모두 native `button`이고, 검색은 native `input`이다. Tab 이동 및 Enter/Space 활성화 경로가 유지된다. city 선택 시 기존대로 filter를 적용하고 dialog를 닫으며, filter 변경은 focused marker를 해제한다.
- marker 선택·확대, filter 적용, 사진 추가 callback의 상태·호출 순서는 바뀌지 않았다.

## 판정

통과. PC 드롭다운은 지도 내부에서 위로 열리고 목록이 내부 스크롤되며, 모바일 상향 전개·지도 marker/filter/add/focus 레이어·키보드 기본 조작 경로에 회귀가 없다. 실제 브라우저에서 가장 많은 시·군 권역을 열어 mouse wheel 및 Tab 흐름을 한 번 수동 확인하는 것은 권고 사항이다.
