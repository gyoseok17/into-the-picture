# M8.1 지도 사진 목록 수상작 연결 표시 QA

## 판정

통과. 지도 포커스의 사진 목록에서 비교 연결 여부를 사진 ID 기준으로 표시하고, 중복된 수상작 목록을 제거해도 확대 창의 비교 결과 접근 경로가 유지된다.

## 계약 교차 확인

- `PhotoRecordBundleMapPin.photos`의 각 항목은 `UserPhotoDto`이며 `id`는 `PhotoRecord` ID다.
- `PhotoComparison.userPhoto`도 같은 `UserPhotoDto`를 사용하므로 `comparison.userPhoto.id === item.id` 비교는 동일한 레코드 식별자 기준이다.
- 사진별 비교 연결은 `comparisons.some(...)`으로 판단한다. 한 사진에 여러 비교가 연결되어도 트로피는 한 번만 표시되고, 선택·확대 동작은 사진 ID와 독립적으로 유지된다.

## 화면·회귀 확인

- 여러 장 기록: 하단 썸네일 각각에만 트로피를 표시하며, 연결되지 않은 사진은 표시하지 않는다.
- 한 장 기록: 원래 하단 썸네일 목록이 없으므로 기존 `비교 연결` 상태와 확대 창 원본 오버레이를 유지한다.
- `PhotoComparisonLinks` import·렌더링이 지도 포커스에서 제거되어 `연결된 수상작` 탭이 남지 않는다.
- 확대 창의 원본 오버레이(`PhotoComparisonOverlay`)는 유지되어 비교 결과를 현재 화면 위에서 계속 열 수 있다.
- 확대 창 썸네일에도 동일 트로피와 접근성 이름을 적용했다.
- 트로피는 버튼 내부의 장식 요소이며 `sr-only` 설명을 포함한다. 썸네일 버튼의 접근성 이름에도 연결 여부를 포함해 모바일 터치 영역과 키보드 선택을 바꾸지 않는다.
- 지도 포커스(`z-20`)보다 확대 창 포털(`z-90`)이 높아 모바일에서도 확대 창이 가려지지 않는다.

## 실행 검증

- `frontend`: `npm run typecheck` 통과
- `frontend`: `npm run build` 통과
- `git diff --check` 통과. 기존 작업 트리의 CRLF 변환 경고와 Vite 500KB 청크 권고만 출력됨.

## 남은 위험

- 브라우저 실기기에서 비교 연결·미연결 사진이 섞인 2장 이상 기록의 트로피 위치를 한 번 수동 확인하면 시각적 검증까지 완료된다. 계약·빌드 차단 이슈는 없다.
