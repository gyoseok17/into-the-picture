# M1.1 공모전 지도 — 클러스터·선택 패널 계약 / QA 체크리스트

> 대상: M1.1의 `GET /api/v1/contests/map` 지도 뷰 UX 확장.
> 기준 계약: `_workspace/contracts/M1.1_lead_contest-mapview.md`, 실제 shape: `_workspace/api-shapes/M1.1_backend_mapview-shapes.md`.
> 이 마일스톤은 프론트엔드 전용이며 API·DTO·DB 스키마를 변경하지 않는다.

## 경계 계약

| 항목 | 확정 조건 |
| --- | --- |
| API | 기존 `GET /api/v1/contests/map`을 그대로 사용한다. 요청 필터와 `ContestMapPin[]` 응답 shape(7필드)는 변경·추가 호출하지 않는다. |
| 지도 SDK | Kakao Maps JS SDK를 기존 공용 로더로 한 번만 로드한다. 클러스터러 사용 시 `libraries=clusterer`를 SDK 로딩 계약에 포함하되, 키 미설정·스크립트 실패·클러스터러 미가용이면 앱이 죽지 않고 기존 지도 준비중 placeholder 또는 개별 마커로 graceful 처리한다. |
| 클러스터 | 현 줌 레벨에서 가까운 핀만 묶는다. 축소 시 숫자 클러스터, 확대 시 자동 분리되어 개별 마커 선택이 가능해야 한다. 클러스터 클릭은 해당 클러스터의 모든 `ContestMapPin`을 선택 목록으로 만든다. |
| 선택 패널 | 개별 마커 클릭은 1개, 클러스터 클릭은 여러 개를 선택한다. 데스크톱은 지도 우측의 충분히 큰 사진·정보 패널, 모바일은 지도 아래/하단 시트 등 지도 밖의 읽기 쉬운 목록으로 표시한다. 각 항목은 썸네일, 제목, 등급, 지역을 보여 주며 클릭하면 `/contests/{id}`로 이동한다. |
| 선택 상태 | 필터로 `pins`가 바뀌면 선택을 비운다. 지도 이동/줌으로 현재 선택 클러스터가 해체되거나 화면 밖이 되면 stale 그룹 정보를 유지하지 않는다(선택을 비우거나 현재 가시/클러스터 상태에 맞게 재계산). 패널 닫기 동작도 선택을 비운다. |
| 기존 동작 | 빈 결과, 로딩/오류 UI, 목록↔지도 토글, 상세용 단일 `ContestMap.tsx`는 회귀가 없어야 한다. 지도 인스턴스 중복 생성 및 유령 마커/리스너가 재발하지 않아야 한다. |

## 구현 전후 점검

- [ ] SDK URL/로더의 기존 `autoload=false`, Promise 캐시, 오류 처리와 StrictMode 안전성이 유지된다.
- [ ] 마커 또는 클러스터러를 재생성할 때 이전 마커/클러스터러와 이벤트 리스너가 지도에서 해제된다.
- [ ] `pins` 변경 시 bounds 갱신과 선택 초기화가 함께 수행된다.
- [ ] 패널은 Kakao 지도 컨트롤보다 위에 놓이되, 지도 영역을 불필요하게 가리지 않는다.
- [ ] 목록 항목 키는 `pin.id`이고, 이미지 실패 시 공용 이미지 컴포넌트의 fallback을 사용한다.
- [ ] 키보드로 패널 닫기/항목 이동이 가능하고 닫기 버튼에 의미 있는 `aria-label`이 있다.

| Q8 | React StrictMode 개발 환경에서 지도 뷰 토글·필터 변경을 반복 | 지도 레이어가 중첩되지 않으며 모든 현재 마커/클러스터 클릭이 동작한다. |
| Q9 | 빈 지도 결과와 단일 핀 결과 확인 | 빈 결과 안내가 정상이고, 단일 핀은 과도한 최대 확대 없이 선택 가능하다. |

## 구현 검토 결과 (2026-08-02)

- **정적 경계 검토: PASS.** 기존 `ContestMapPin[]` 계약과 `/contests/map` 호출은 변경하지 않았다. 클러스터의 `getMarkers()`를 `Marker → ContestMapPin` 매핑으로 해석해, 클러스터 클릭이 해당 작품들만 선택한다.
- **수명주기 보완: PASS.** 필터 결과 교체 시 클러스터·마커·선택을 비우며, 줌·드래그 시 선택을 비운다. 지도 언마운트 시 `zoom_changed`·`dragend`·`clusterclick` 리스너를 명시적으로 제거한 뒤 클러스터러를 해제한다.
- **반응형: PASS (정적 검토).** `lg` 이상에서는 지도 우측 22–28rem 패널, 그 미만에서는 지도 아래 패널로 렌더한다. 개별 핀은 1개, 클러스터는 여러 작품 카드로 표시한다.
- **빌드: PASS.** `npm.cmd run build` 통과 (`tsc -b`, Vite production build). Vite의 500kB 초과 청크 경고만 있으며 이번 변경의 실패 원인은 아니다.
- **수동 브라우저 smoke: PASS.** 사용자 확인에서 지도 전환·표시 등 실제 동작 이상이 없었다. Q1–Q9 전체 회귀 시나리오는 후속 UI 변경 시 다시 실행한다.

### 지도 초기화 회귀 수정 (2026-08-02)

- 증상: 리스트에서 지도 뷰로 전환하면 `지도 준비중` placeholder만 표시됨.
- 원인: `autoload=false` SDK는 `maps.load()` 완료 전에는 `MarkerClusterer`가 준비되지 않을 수 있는데, 공용 로더가 스크립트 `onload` 직후 이를 검사해 정상 초기화를 실패로 처리함.
- 수정: 공용 로더가 항상 `maps.load()` 완료 콜백 안에서 `MarkerClusterer`를 검증하도록 순서를 변경. 이미 로드된 SDK도 같은 경로를 사용한다.
- 검증: `npm.cmd run build` 재통과. 실제 카카오 키 브라우저에서 지도 전환 확인은 수동 QA에 포함.
