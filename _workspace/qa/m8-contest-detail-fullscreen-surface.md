# M8 수상작 상세 전체 화면 표면 QA

- 검토일: 2026-08-18
- 범위: 목록 상태를 보존하는 상세 표면을 팝업이 아닌 앱 내부 상세 화면처럼 보이도록 전환

## 사전 판정

현재 `ContestDetailPage`의 `DetailPresentation`은 다음 요소 때문에 사용자에게 모달 팝업으로 보인다.

- 반투명 검은 배경(`bg-black/35`)과 배경 흐림
- 바깥 여백(`p-3`, `sm:p-6`), 둥근 모서리(`rounded-2xl`), 큰 그림자
- 배경 클릭으로 닫히는 `role=dialog`, `aria-modal=true` 동작

따라서 목록 유지라는 라우팅 목적은 충족하지만, 이번 시각 UX 요구에는 부적합하다.

## 전환 조건

- 목록 진입일 때만 `fixed inset-0 z-50 bg-background overflow-y-auto`의 전체 화면 표면을 사용한다.
- 검은 backdrop, 둥근 컨테이너, 외곽 여백, 배경 클릭 닫기를 제거한다.
- 상세 본문은 일반 상세 페이지와 같은 폭(`max-w-*`)과 여백을 가져 마이 화면처럼 보이게 한다.
- 목록은 뒤에서 계속 마운트되어 있어야 하며, 브라우저 뒤로가기·명시적인 상단 목록 복귀·Escape만 상세를 닫는다.
- 화면이 `TopNav`와 `BottomTabBar`보다 위(`z-50`)에 있으므로 모바일에서 하단 탭이 겹치지 않게 상세 스크롤 영역의 하단 safe-area 여백을 둔다.

## 접근성 확인 기준

- 전체 화면 표면도 이전 목록을 조작할 수 없으므로 포커스는 상세에 머물러야 한다.
- Escape로 닫힌 뒤 원래 카드에 포커스를 복귀한다.
- 배경 클릭 닫기는 제거한다. 페이지처럼 보이는 화면이 화면 가장자리 클릭으로 사라지면 예측 가능성이 낮다.
- 직접 URL, 홈·혼잡도·마이 진입은 기존 독립 상세 화면을 유지한다.

## 최종 판정
