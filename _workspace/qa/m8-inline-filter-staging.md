# M8 인라인 수상작 조건 변경 QA

- 검토일: 2026-08-14
- 범위: `/contests`의 상단 `ContestFilterBar`, 결과 하단 `ContestQuickFilterPanel`, `ScrollAssist`
- 코드 변경: 없음

## 현재 동작과 즉시 적용 위험

1. 결과 하단의 `ContestQuickFilterPanel`은 이미 `draft`를 별도 상태로 두고 `적용`에서만 `onApply`를 호출한다. 계절 칩과 등급·부문·지역 선택은 이 패널 안에서는 즉시 목록을 다시 조회하지 않는다.
2. 반면 화면 상단의 `ContestFilterBar`는 계절 칩과 세 `FilterSelect`의 `onChange`에서 곧바로 상위 `setQuery`를 호출한다. `useContests(query)`의 query key가 즉시 바뀌므로, 옵션 하나를 바꿀 때마다 목록·무한 스크롤 페이지가 새로 조회된다. 사용자가 말한 즉시 적용 문제의 실제 원인이다.
3. 두 UI가 같은 `query`를 읽지만 적용 방식이 달라, 빠른 패널에서 적용한 값은 상단에 바로 보이는 반면 상단에서는 여러 조건을 고르기 전에 결과가 여러 차례 바뀐다. 같은 필터를 두 곳에서 제공하는 계약이 일관되지 않다.
4. 빠른 패널의 `초기화`는 현재 초안만 비우며 적용하지 않는다. 이는 staged 동작으로는 옳지만, 안내가 없으면 상단의 즉시 초기화와 다르게 느껴질 수 있다.

## 권장 계약

- `appliedQuery`: 실제 목록·지도 조회와 상단의 확정 표시가 사용하는 유일한 조건값.
- `draftQuery`: 현재 열려 있는 조건 편집 UI 안에서만 바뀌는 값. 칩·셀렉트·키워드 입력은 이것만 수정한다.
- 적용: `draftQuery`를 정리(trim, 빈 값 제거)해 한 번만 `appliedQuery`에 복사하고 편집 UI를 닫는다. 이때만 목록과 지도 조회가 갱신된다.
- 취소: Escape·바깥 클릭·메뉴 닫기는 `draftQuery`를 버리고, 기존 `appliedQuery`와 목록을 유지한다.
- 초기화: 초안만 빈 조건으로 만든다. 이후 `적용`을 눌러야 실제 목록이 전체 결과로 바뀐다. 필요하면 버튼명은 `초안 지우기`보다 짧은 아이콘과 aria-label을 쓰되, 사용자에게 적용 전이라는 상태가 보여야 한다.
- 재열기: 언제나 최신 `appliedQuery`에서 새 초안을 시작한다. 이미 열려 있는 동안 외부에서 확정값이 바뀌면 초안을 그 값으로 동기화할지, 편집 중 초안을 보존할지 한 정책만 정해야 한다. 이번 화면에서는 다른 변경 경로가 없으므로 재열기 동기화만으로 충분하다.

## 시각·반응형 수용 기준

- 빠른 검색 pill과 같은 계열로, 메뉴를 열면 메뉴 아이콘은 숨고 결과 하단 우측에 조건 편집 표면만 남는다.
- 검색과 달리 필터는 계절·세 선택 항목이 있어 한 줄 타원에 억지로 넣지 않는다. 바깥은 둥근 패널, 안쪽은 얇은 구분선/낮은 대비의 칩과 셀렉트로 구성해 검색 pill의 크기·테두리·배경·그림자 톤을 공유한다.
- 긴 설명 문장이나 큰 제목은 넣지 않는다. 아이콘·짧은 접근성 이름·명확한 적용 행동만 남겨, 검색 pill보다 한 단계 넓은 '필터 pill'로 읽혀야 한다.
- 360px에서 패널 폭은 viewport 및 좌우 여백을 넘지 않고, 내용이 길어지면 패널 내부만 세로 스크롤된다. 하단 탭과 safe area 위에 남아야 한다.
- 768px·1280px에서도 우하단 기준과 패널 최대 폭이 유지되고, 셀렉트 세 개가 불필요하게 줄바꿈해 클릭 영역이 작아지지 않는다.
- 메뉴, 적용, Escape, 바깥 클릭 뒤의 포커스 복귀 대상이 실제로 존재해야 하며 `aria-expanded`/`aria-controls`는 열린 상태와 일치해야 한다.

## 기능 수용 기준

1. 현재 결과를 충분히 스크롤한 뒤 필터 메뉴를 연다. 현재 적용한 계절·등급·부문·지역·키워드가 초기에 정확히 표시된다.
2. 계절, 등급, 부문, 지역, 키워드를 여러 번 바꾸는 동안 `/contests` 요청, 스켈레톤, 결과·지도 마커 변화가 없어야 한다.
3. `적용`을 한 번 누르면 정리된 조건으로 요청이 한 번만 발생하고, 결과와 상단 확정 상태가 동시에 갱신된다. 빈 키워드는 query에서 제거된다.
4. `초기화` 뒤 적용 전에는 기존 결과가 유지되고, 적용하면 전체 조건으로 정확히 한 번만 갱신된다.
5. Escape·바깥 클릭·메뉴 닫기 후 다시 열면 적용하지 않은 선택값은 남지 않고 마지막 확정값이 보인다.
6. 적용 후 무한 스크롤의 이전 페이지나 진행 중 sentinel 관찰이 새 조건 결과에 섞이지 않는다.
7. 지도 보기로 전환한 뒤 확정 조건을 바꾸면 목록과 같은 `appliedQuery`만 사용해 마커가 갱신된다. 지도에 떠 있는 필터 패널이 없다면 이 경로는 상단 확정 편집 UI를 통해서도 같은 staged 계약을 지켜야 한다.
8. 필터 옵션 로딩 실패 시에는 기존 keyword-only graceful degradation을 유지한다. 빈 옵션을 선택 가능한 것처럼 보이거나, 적용이 예외를 내면 안 된다.

## 통합 판정

**현재 상태: 조건부 차단.** 빠른 패널 단독은 staged 구조이지만, 상단의 동일 필터가 즉시 `setQuery`를 호출해 사용자가 보고한 동작과 충돌한다. 구현 시 두 편집 진입점의 적용 시점 계약을 통일하고 위 시나리오를 확인한 뒤 통합 가능으로 전환한다.
