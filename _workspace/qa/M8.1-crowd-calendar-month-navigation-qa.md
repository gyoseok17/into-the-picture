# M8.1 방문 집중률 월 전환·미지원 안내 QA

## 범위

- `CrowdCalendar`의 30일 예측 월 단위 표시와 이전·다음 월 이동
- `CrowdPage`, 수상작 상세의 204(매칭 없음)·빈 관광지 목록 안내
- API/백엔드 기간 계약은 변경하지 않음

## 계약 대조

| 항목 | 확인 결과 |
| --- | --- |
| 예측 기간 | 기존 API의 일별 최대 30일 응답을 그대로 사용한다. |
| 월 표시 | 일별 날짜의 최소·최대 월을 탐색 범위로 잡고 한 번에 한 달만 렌더링한다. |
| 월 이동 | `fromMonth`/`toMonth`로 첫·마지막 데이터 월 밖 이동을 막고, DayPicker 기본 이전·다음 버튼으로 인접 월만 이동한다. |
| 날짜 선택 | 선택한 날짜의 집중률·추천일 표시 규칙은 기존과 같다. 새 예측을 받으면 첫 예측일로 선택 상태를 초기화한다. |
| 204 | 두 API 클라이언트 모두 204를 `null`로 변환하며, 오류 상태가 아니라 제공 불가 안내로 표시한다. |
| 지원 관광지 없음 | 시군구 선택 뒤 관광지 목록이 빈 배열이면 제공 불가 안내를 보이고, 일반 관광지 선택 안내는 함께 보이지 않는다. |

## 경계 조건 검토

- 단일 월: 한 개 월만 표시되며 양쪽 이동은 데이터 범위 밖으로 진행되지 않는다.
- 두 달 경계: 첫 월을 먼저 보이고 다음 버튼으로 둘째 월만 전환해 본다. 두 달을 세로로 이어 렌더링하지 않는다.
- 첫·끝: 예측 시작 월에서는 이전, 종료 월에서는 다음 이동이 DayPicker 범위 제한으로 비활성화된다.
- 부분 월: 시작일 전·종료일 후 날짜는 `fromDate`/`toDate` 밖이므로 예측일로 선택되지 않는다.
- 빈 `daily`: `CrowdCalendar` 자체도 제공 불가 안내를 반환한다.
- 로딩·통신 오류: 기존 `LoadingState`/`ErrorState`를 유지해 204 안내와 구분한다.
- 반응형: `numberOfMonths={1}`이므로 좁은 화면과 넓은 화면 모두 월을 하나만 표시한다. 내비게이션 버튼은 기본 버튼 요소여서 키보드 초점·비활성 상태를 제공한다.

## 발견 및 조치 확인

1. 처음 구현은 204만 안내하고, 시군구에 관광지 목록 자체가 없는 경우 빈 선택 메뉴만 남았다.
   - 조치: `hasNoAttractions`를 계산해 동일한 제공 불가 안내를 표시했다.
2. 위 안내와 “관광지를 선택하면…” 문구가 동시에 나타나는 상태가 있었다.
   - 조치: 빈 목록일 때 일반 선택 안내를 숨겨 상태 메시지가 충돌하지 않도록 했다.

## 판정

**통과.** API·DB 계약 변경 없이 두 화면이 동일한 월 전환·204·빈 관광지 목록 정책을 사용한다. 실제 브라우저에서는 월 경계(예: 월말 시작~다음 달 초 종료) 데이터 한 건과 빈 관광지 시군구 한 건을 선택해 이전·다음 버튼 비활성 상태를 최종 확인하면 된다.
