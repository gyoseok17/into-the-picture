# M8.1 지도 ‘이전 방문 기록’ 전환 기준 QA

작성일: 2026-08-29
범위: 읽기 전용. 현재 지도 핀 그룹·상세 상태·API 시간 계약을 점검했다.

## 현재 상태

- 지도 상세 `MapFocus`는 선택된 `recordIndex`의 사진을 보여 주고, 겹친 기록이 있으면 현재 선택을 포함한 `group.pins` 전체를 썸네일로 나열한다.
- 별도의 `이전 방문 기록` 목록, 최신 2건 미리보기, 전체 목록 전환은 아직 없다.
- 핀 그룹은 같은 `mapRegionCode + mapCityCode` 또는 사실상 같은 place 좌표를 같은 방문 장소 그룹으로 묶는다. `group.pins`의 각 원소는 사진 묶음 1개 또는 legacy 사진 1개라는 기록 단위다.

## 올바른 전환 기준

### 1. 현재 선택 제외

- `previousRecords = group.pins.filter((_, index) => index !== recordIndex)`.
- 비교 기준은 사진 ID가 아니라 **현재 선택한 방문 기록(묶음/legacy) 자체**다. 같은 묶음의 다른 사진은 `record.photos` 내부 사진 탐색으로만 다루며 이전 방문 기록에 섞이면 안 된다.
- 선택 기록이 바뀌면 이전 목록도 즉시 다시 계산하고, 선택한 기록이 이전 목록에 남지 않아야 한다.

### 2. 최신 2건 미리보기

- `previousRecords`만 시간 내림차순으로 정렬한 뒤 앞의 2개만 표시한다.
- UI에 두 개만 보더라도 실제 이전 기록이 3개 이상이면 ‘전체 보기’가 나타나야 한다. 0개면 영역 자체를 숨기고, 1개면 하나만 보인다.
- 미리보기 항목을 고르면 그 항목이 현재 선택으로 승격된다. 그러면 직전 선택이 새 `previousRecords`에 들어간다.

### 3. 전체 목록

- 전체 목록도 같은 `previousRecords` 데이터에서 렌더한다. 미리보기용 별도 slice 데이터를 상태로 저장하지 않는다.
- 전체 목록을 열고 닫아도 `recordIndex`·`photoIndex`는 바꾸지 않는다.
- 전체 목록에서 기록을 고르면 목록은 닫아도 되고 유지해도 되지만, 선택 대상/사진 인덱스는 반드시 새 기록의 첫 사진(0)으로 초기화한다.

## 시간 정렬 계약 위험

- 현재 map DTO에는 `takenAt`만 있고 `createdAt`/명시적 `sortAt`은 없다.
- 백엔드 내부 조회는 `coalesce(takenAt, createdAt) desc` 순이지만, map 응답 계약에는 그 정렬 의미가 명시돼 있지 않다.
- 따라서 프런트가 ‘최신 2건’을 정확히 독립 판단하려면 `takenAt` 우선, `createdAt` 보조값(또는 서버 제공 `sortAt`)이 필요하다. API 확장을 하지 않는다면 **서버 배열 순서가 최신순이라는 계약을 문서화하고 그대로 사용**해야 한다. null 촬영일 기록까지 프런트에서 완전한 최신순을 보장할 수는 없다.

## 회귀 QA

- 방문 기록 1개: 이전 기록 영역·전체 보기 버튼이 보이지 않는지.
- 같은 시군의 방문 기록 2개: 현재 선택은 이전 목록에서 제외되고, 다른 1개만 미리보기로 보이는지.
- 같은 시군의 방문 기록 4개: 최신 2개만 미리보기, 전체 보기에서 3개(현재 제외)가 날짜 내림차순인지.
- 미리보기/전체 목록에서 항목 선택: 선택 대상이 바뀌고 사진 캐러셀은 1번 사진으로 초기화되며, 이전 목록에서 새 선택이 빠지는지.
- 한 방문 기록 안 사진 3장 + 다른 방문 기록 2개: 사진 썸네일은 현재 기록의 3장만, 이전 방문 목록은 다른 기록 2개만인지.
- 촬영일 null 기록: 문서화한 fallback(`createdAt` 또는 서버 순서)이 최신 2건에 일관되게 적용되는지.
- 권역/시군 필터 변경, 빈 지도 클릭, 새 업로드/삭제 뒤: 선택·전체 목록 상태가 남은 기록과 불일치하지 않고 닫히거나 재계산되는지.
- 모바일: 전체 목록이 지도 뒤에 가려지지 않고, 카드 선택과 닫기 터치가 가능한지. 키보드 사용 시 현재 선택 표시와 버튼 aria-label도 확인.

## 판정

프런트는 이미 ‘방문 기록’과 ‘묶음 안 사진’을 분리할 수 있는 `PhotoRecordBundleMapPin` 구조를 사용한다. 다만 이전 기록 UI를 넣을 때 현재 선택 제외와 정렬 원본을 공통 계산으로 두고, 최신 판단의 `createdAt` fallback 계약을 명확히 해야 한다.
