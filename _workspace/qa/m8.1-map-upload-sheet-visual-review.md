# M8.1 지도 사진 추가 시트 UI 검토

작성일: 2026-08-28
범위: `BatchPhotoUploadPanel.tsx`, `PhotoRecordMapView.tsx` 읽기 전용 검토

## 현재 흐름과 문제

현재 지도 시트는 `사진 추가` 제목 아래에 기존 `BatchPhotoUploadPanel` 카드가 그대로 들어간 형태다. 기능은 갖춰졌지만, 카드 제목·설명, 선택한 지역, 사진 선택 영역, 촬영일·메모, 파일 목록, 업로드 버튼이 한 덩어리로 이어져 있어 처음 보는 사용자가 무엇을 먼저 해야 하는지 한눈에 구분하기 어렵다.

- 시트 제목의 `사진 추가`와 내부 카드의 `여러 장 추가`가 같은 일을 두 번 설명한다.
- 지역은 수정 불가한 값인데 입력칸과 같은 테두리 상자여서 정보의 성격이 모호하다.
- 사진을 고르기 전에는 촬영일·메모가 보이지 않고, 고른 뒤에는 파일 목록과 입력 항목의 위계가 약하다.
- 여러 파일을 골랐을 때 `사진 고르기`가 상단 보조 버튼으로 바뀌고, 빈 상태의 큰 선택 영역도 남아 있어 같은 행동의 표현이 나뉜다.
- EXIF 안내 문장이 길어 모바일 시트에서 실제 조작 요소보다 먼저 눈에 들어온다.

## 적용 권장 구성

시트 내부를 별도 카드들의 나열이 아니라, 한 장의 기록 흐름으로 구성한다. 기존 업로드·EXIF·재시도 로직은 유지하고 표시 컴포넌트만 다음 네 구역으로 분리한다.

1. **시트 헤더**
   - 제목: `사진 추가`
   - 우측: 닫기 아이콘
   - 중복되는 `여러 장 추가` 제목과 긴 설명은 제거한다.

2. **기록 위치**
   - 헤더 바로 아래에 작은 민트 톤 위치 칩: `지도 핀 아이콘 · 경기 · 수원`
   - 입력창이나 카드가 아니라 읽기 전용 보조 정보로 보이게 한다.
   - 위치가 없으면 시트를 열 수 없는 현재 지도 규칙을 그대로 따른다.

3. **사진 선택 및 목록**
   - 미선택: 전체 폭의 점선 영역 하나만 사용한다. 아이콘, `사진 고르기`, `최대 20장` 보조 문구를 한 곳에 둔다.
   - 선택 후: 같은 위치를 `N장 선택됨` 요약과 작은 썸네일 열로 바꾸고, 우측의 아이콘 버튼 하나로 사진을 교체·추가한다. 미선택 영역과 별도 상단 버튼을 동시에 보여주지 않는다.
   - 파일명 목록은 썸네일 아래 접히지 않는 짧은 목록으로 두고, 5개 초과분은 내부 스크롤로 제한한다. 실패 상태와 재시도 대상은 기존 상태 표시를 보존한다.

4. **기록 정보와 저장 동작**
   - `촬영일`과 `메모`를 같은 행/그룹으로 묶는다. 촬영일은 날짜만 직접 지정하고, 비어 있으면 EXIF를 쓴다는 설명은 입력 아래 한 줄의 옅은 보조 문구로 축소한다.
   - 하단은 시트에 고정된 작업 바를 둔다. 왼쪽에는 `N장 준비됨` 또는 업로드 진행·실패 상태, 오른쪽에는 하나의 주 행동 `추가하기`를 둔다.
   - 성공 완료 상태에서는 `N장 기록했어요`와 `닫기` 한 가지만 남긴다. 업로드 중에는 닫기·배경 닫기를 막는 현행 안전 규칙을 유지한다.

## 반응형 배치

- 모바일: 하단 시트 안에서 헤더와 하단 작업 바는 고정하고, 사진 목록·메타데이터 영역만 스크롤한다. 키보드가 올라오면 촬영일·메모가 작업 바 아래로 가려지지 않아야 한다.
- 데스크톱: 지도 우측 패널에서도 같은 순서를 유지한다. 넓은 화면에서 촬영일과 메모만 한 줄 두 칸으로 배치하고, 선택 영역은 세로 흐름을 유지한다.

## 구현 경계

- `BatchPhotoUploadPanel`은 파일 선택, EXIF 추출, 업로드 대기열, 상태·재시도, React Query 갱신을 계속 책임진다.
- 새 표시 단위는 예를 들어 `PhotoUploadSelection`, `PhotoUploadMetadata`, `PhotoUploadActionBar`로 분리한다. 지도 시트는 여는/닫는 상태와 선택 위치 전달만 맡는다.
- 일반 앨범 추가 화면도 같은 대기열을 쓰므로, 지도 전용 레이아웃 조건이 업로드 규칙·API 요청을 바꾸지 않게 한다. 위치 입력 표시만 지도 시트에서 읽기 전용으로 바뀐다.

## 회귀 위험과 확인 항목

- 사진 선택 전·후에 같은 파일 선택 제어가 이중으로 보이지 않는지.
- 날짜를 비우면 파일별 EXIF 날짜가 유지되고, 날짜를 넣으면 선택 파일 전체에 `00:00`으로 저장되는지.
- 20장 제한, HEIC/HEIF를 포함한 허용 형식, 3건 동시 업로드, 실패 항목 재시도가 기존과 같은지.
- 선택한 시·군의 코드와 표시명이 업로드 요청의 `mapRegionCode`, `mapCityCode`, `placeName`에 그대로 적용되는지.
- 업로드 중 바깥 클릭·닫기·지도 조작으로 시트가 사라지지 않는지, 완료·닫기 후 지도 필터·확대·마커 포커스가 그대로인지.
- 360px 폭과 모바일 키보드에서 파일 선택, 날짜, 메모, 추가 버튼이 모두 접근 가능한지.

## 판정

기능 계약을 바꾸지 않는 프런트 표시 구조 정리로 적합하다. 다만 `BatchPhotoUploadPanel`이 이미 업로드 상태와 지역 표시를 함께 갖고 있으므로, JSX만 압축해서 수정하기보다 파일 선택·메타데이터·작업 바를 읽을 수 있는 단위로 분리해야 한다.
