↔ 소비자 `types.ts:ContestMapPin` (id:number, title, thumbUrl, lat:number, lng:number, awardGrade, sido:string|null).
- 필드명·순서·타입 7/7 일치. `api.ts:39` `apiClient.get<ContestMapPin[]>` 로 제네릭 명시, `any` 없음.
- 컨트롤러 `getContestMapPins` 가 `List<ContestMapPinDto>` 직접 반환 → 배열 직접(페이지네이션 래핑 없음). 훅/ api 도 `ContestMapPin[]` 로 unwrap 없이 그대로 수신. PASS.
- 테스트 `ContestControllerTest.getContestMapPins_returnsArrayShape` 가 `$` isArray + 7필드 값 고정으로 shape 회귀 방어.

### P2. lat/lng number non-null 보장이 양쪽에서 성립
- 백엔드: `ContestSpecifications.hasCoordinates()` = `isNotNull(lat) AND isNotNull(lng)` 를 `findMapPins` 에서 `.and()` 합성(`ContestService:66`) → DB 레벨에서 좌표 없는 건 제외. 응답에 포함된 건 항상 좌표 존재.
- 매퍼: `ContestMapper.toMapPin` 이 엔티티 `Double lat/lng`(nullable) 를 record `double`(primitive) 에 넣음. hasCoordinates 필터가 선행하므로 언박싱 NPE 안전 — 주석(`ContestMapper:58`)에 근거 명시됨.
- 프론트: `ContestMapPin.lat/lng: number`(non-null). `ContestMapView` 가 `new kakao.maps.LatLng(pin.lat, pin.lng)` 로 옵셔널 체크 없이 사용 — 계약상 non-null 보장에 부합. PASS.

### P3. 필터 파라미터 목록과 동일 + 지도 전용(sort/page/size 미전달)
- 백엔드 목록 `getContests` 와 지도 `getContestMapPins` 둘 다 동일 5개 `@RequestParam`(season·grade·division·sido·keyword) → 동일 `ContestSearchCondition` → 동일 `ContestSpecifications.from`. 지도만 `hasCoordinates()` 추가. 중복 로직 없음(계약 준수).
- 지도 컨트롤러는 page/size/sort 파라미터 자체가 없음 → 넘겨도 무시.
- 프론트 `fetchContestMap` (`api.ts:38`) 이 `const { sort: _sort, ...filters } = query` 로 sort 제거 후 `cleanParams(filters)` 만 전달. page/size 미주입(목록 `fetchContests` 만 주입). 계약 준수. PASS.
