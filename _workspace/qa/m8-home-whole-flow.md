# M8 홈 전체 흐름 개편 QA 기준

- 작성일: 2026-08-14
- 역할: 통합 QA
- 범위: 홈(`/`)을 독립된 카드·띠의 나열이 아니라, 사진을 따라 다음 행동으로 이어지는 하나의 흐름으로 재구성하는 변경
- 코드 변경: 없음

## 현재 구조 점검

현재 홈은 대표 사진, 추천 여행지 필름, 혼잡도 안내, 사진 탐색, 로그인 사용자 영역으로 나뉘어 있다. 각 섹션의 목적과 기존 경로 연결은 명확하다.

| 항목 | 현재 장점 | 전체 흐름 개편 시 위험 |
| --- | --- | --- |
| 대표 장면 | 첫 사진에서 수상작 상세로 바로 이동할 수 있다. | 대표 장면만 배경색·모서리·그림자가 강하면 다음 섹션과 분리된 배너처럼 보인다. |
| 추천 여행지 | 사진 중심의 가로 필름이며 수상작 상세와 전체 목록으로 연결된다. | 제목/설명/사진 필름이 별도 카드 묶음처럼 반복되면 에디토리얼 리듬이 사라진다. |
| 혼잡도 | 여행지를 고른 뒤 방문 시점을 확인한다는 다음 행동이 명확하다. | 테두리·강한 배경면·CTA 상자가 동시에 쓰이면 추천 필름과 무관한 프로모션 띠로 보인다. |
| 사진 탐색 | 키워드와 `/explore` 진입 계약이 분리돼 있다. | 키워드 칩, 큰 링크 상자, 제목이 모두 강조되면 같은 수준의 버튼이 과도해진다. |
| 내 사진 | 로그인 사용자에게만 보여 개인정보·기능 상태가 자연스럽다. | 다른 섹션과 같은 크기의 박스가 되면 개인 기록의 조용한 성격이 약해진다. |

## 구조 수용 기준

홈은 다음 순서를 유지하되, 각 구간의 시각적 밀도와 표면을 달리해 하나의 산책 흐름으로 느껴져야 한다.

`대표 장면 → 추천 여행지 → 언제 갈지 → 사진으로 더 찾기 → 내 기록(로그인 시)`

1. 대표 장면만 첫 화면의 주인공으로 둔다. 큰 사진과 짧은 문장, 다음 섹션으로 내려가는 한 가지 행동만 남긴다.
2. 추천 여행지는 카드 그리드가 아니라 사진이 이어지는 필름으로 유지한다. 카드별 테두리·배경·버튼을 추가하지 않는다.
3. 혼잡도는 카드나 배너가 아닌 본문 중간의 여백 있는 편집면으로 표현한다. 좌우 분할은 넓은 화면에서만 사용하고, 모바일에서는 문장 뒤에 한 줄 행동을 둔다.
4. 사진 탐색은 입력 폼처럼 독립시키지 않는다. 키워드는 가벼운 보조 수단이고, 탐색 링크 하나만 주 행동으로 유지한다.
5. 내 사진은 로그인한 사람에게만 마지막에 조용히 이어지며, 새 기능을 약속하는 빈 카드나 가짜 통계를 넣지 않는다.

## 민트 톤·대비 기준

- 기본 바탕은 가장 옅은 민트 하나로 유지하고, 화면 전체에 서로 다른 민트 박스를 반복하지 않는다.
- 더 진한 민트 표면은 대표 장면 또는 탐색 진입처럼 행동을 강조할 곳 한두 군데에만 쓴다.
- 사진 위 텍스트는 사진 밝기와 무관하게 읽혀야 한다. 밝은 패널, 충분한 어두운 오버레이, 텍스트 그림자 중 하나를 적용한다.
- 본문·링크는 중성 짙은 청록을 유지한다. `text-primary`의 낮은 투명도는 작은 영문 라벨에만 제한하고, 한국어 본문/행동 라벨에는 사용하지 않는다.
- 경계선은 구간 전환을 돕는 경우에만 사용한다. 모든 섹션에 테두리와 그림자를 동시에 사용하지 않는다.

## 반응형 수용 기준

| 너비 | 확인 시나리오 | 통과 조건 |
| --- | --- | --- |
| 360px | 첫 진입부터 마지막 링크까지 세로 스크롤 | 대표 문장과 사진이 한 장면으로 이어지고, 각 섹션이 흰 카드처럼 끊겨 보이지 않는다. 가로 필름은 다음 사진 일부가 보이며 세로 화면이 가로 스크롤에 끌리지 않는다. 하단 탭이 마지막 행동을 가리지 않는다. |
| 768px | 모바일에서 태블릿으로 전환되는 폭 | 대표 장면, 섹션 제목, 혼잡도 문장이 급격히 두 단으로 깨지지 않는다. 가로 필름 폭·높이 차이가 과장되지 않고, 링크의 터치 영역은 44px 이상이다. |
| 1280px | 넓은 데스크톱에서 상단부터 하단까지 | 대표 문장과 사진의 시선이 연결되고, 추천·혼잡도·탐색 구간마다 여백 리듬이 다르다. 과도하게 넓은 빈 공간, 줄이 지나치게 긴 본문, 같은 크기의 상자 반복이 없다. |

## 데이터·상태별 QA

### 수상작 로딩·빈 상태

- 로딩 중: 대표 사진과 필름의 자리 비율이 유지돼 레이아웃이 흔들리지 않는다. 스켈레톤은 사진 영역에만 쓰고, 여러 개의 회색 카드가 화면을 지배하지 않는다.
- 수상작 없음: 빈 배경만 남기지 않는다. `수상작 둘러보기`로 갈 수 있는 짧은 안내와 행동을 제공한다.
- 대표 이미지 실패: 대체 표면 안에도 제목/이동 경로가 남아 있으며, 이미지 실패가 클릭 불가로 이어지지 않는다.
- 필름 항목이 1개일 때: 가로 스크롤처럼 보이게 만들지 않고, 하나의 사진에 맞는 폭과 여백을 사용한다.

### 로그인 사용자 섹션

- 비로그인: 내 사진 관련 문구·여백·빈 영역이 렌더링되지 않는다.
- 로그인: 마지막 섹션은 `내 사진` 또는 사진 놓기 화면으로 실제 이동한다. 개인 사진 수, 최근 사진 등 API로 보장하지 않는 정보를 표시하지 않는다.
- 인증 초기화 중: 사용자 정보가 확정되기 전 로그인 전용 영역이 순간적으로 깜빡이지 않는다.

## 기능 회귀 확인

- 대표 장면·추천 사진: `/contests/:id`
- 수상작 전체: `/contests`
- 혼잡도: `/crowd`
- 키워드/사진 탐색: `/explore`, `/explore?keyword=<인코딩된 키워드>`
- 로그인 사용자 내 기록: `/compare` 또는 실제 내 사진 경로
- 모든 링크는 키보드 포커스가 보이고, 사진 전체가 링크인 경우 내부에 중첩된 클릭 요소가 없다.

## QA 판정

전체 흐름 개편은 API·데이터 계약 변경 없이 프런트엔드에서 진행 가능하다. 최종 수용 전에는 위 360/768/1280 화면 확인, 로딩·빈 상태, 로그인/비로그인 전환, 기존 경로 회귀 확인과 `npm run build` 통과가 필요하다.

차단 조건은 다음과 같다.

1. 모든 섹션이 같은 민트 카드·테두리·그림자 조합으로 반복되는 경우
2. 모바일에서 대표 문장과 사진이 떨어진 블록처럼 보이거나 하단 탭이 행동을 가리는 경우
3. 수상작 로딩 실패/빈 목록에서 사용자가 다음 행동을 할 수 없는 경우
4. 비로그인 상태에서 내 사진 영역이 남거나 로그인 상태가 깜빡이는 경우
