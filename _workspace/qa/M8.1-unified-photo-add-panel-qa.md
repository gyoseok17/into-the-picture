# M8.1 사진 추가 패널 통합 QA

## 사전 조사 (2026-09-07)

### 현재 진입점과 중복 구현

| 진입점 | 현재 동작 | 위험 |
| --- | --- | --- |
| 스토리 고정 `+` | `PhotoRecordAlbum`의 `isAdding`을 토글하고 앨범 본문 상단에 `BatchPhotoUploadPanel`을 인라인으로 표시 | 스크롤 위치가 화면 상단의 패널로 이동해 맥락을 잃을 수 있음. 고정 `+`의 `isAdding` 닫기 상태가 화면에 따라 중복될 수 있음. |
| 맵의 `사진 추가` | 시·군 선택 뒤 `MapUploadSheet` 안에 같은 `BatchPhotoUploadPanel`을 표시, `showLocationField=false`로 장소 변경 불가 | 지역을 미리 채운다는 요구에는 맞지만, 다른 진입점과 UI·장소 편집 동작이 다름. 맵 바깥 클릭과 업로드 중 닫기 방지가 별도 구현임. |
| 보관함/일반 앨범 | 현재 `AlbumHeaderV2`에서 스토리·맵이 아닌 레이아웃 조건일 때만 버튼을 렌더. 현 `AlbumLayout`은 `story | map`뿐이라 사실상 진입 불가 | 새 통합 패널을 보관함에서도 명시적으로 열 수 있도록 경로를 복원/명확화해야 함. |

현재 `PhotoUploadPanel`은 단일 파일용 레거시 컴포넌트로 남아 있으나 해당 앨범 진입점에서는 사용되지 않는다. 새 패널과 기능이 중복되지 않게 사용 여부를 확인해야 한다.

### 계약 검토 기준

1. 장소는 모든 업로드에서 필수다. 사진, 촬영일, 장소가 유효하지 않으면 저장 버튼이 활성화되면 안 된다.
2. 지도 진입은 선택한 `mapRegionCode`, `mapCityCode`를 초기값으로 표시하되, 동일 패널 안에서 장소를 변경할 수 있어야 한다.
3. 스토리·맵·보관함은 같은 패널 컴포넌트와 같은 파일 묶음 업로드 API를 사용한다. 장소를 숨기는 `showLocationField=false` 식의 분기와 진입점별 별도 폼은 제거 대상이다.
4. 패널은 모달/시트로 현재 화면 위에 열리고, 취소·성공 후 원래의 스토리/맵/보관함 상태와 스크롤 위치를 유지해야 한다. 맵은 선택한 시·군을 유지한다.
5. 여러 사진은 한 묶음으로 저장하며, 공통 장소·방문 기간·메모와 사진별 EXIF/직접 지정 촬영일 규칙을 보존한다.
6. 실패 시 선택 사진·입력값·실패 상태를 유지하고 재시도할 수 있어야 하며, 성공했을 때만 자동으로 닫혀야 한다.
7. 동시에 두 패널이 렌더되지 않고, 업로드 중에는 닫기·중복 저장을 막아야 한다.
8. 모바일에서 안전영역·배경 스크롤 잠금·키보드/포커스 이동·ESC/닫기 버튼 접근성을 확인한다. 데스크톱에서도 모달 크기와 배경 클릭 동작을 확인한다.

### 발견된 사전 차단 위험

- `BatchPhotoUploadPanel`은 현재 장소 선택을 선택 사항처럼 처리하며(`PhotoRegionField`에 필수 검증 없음), `placeName`도 별도 선택 입력이다. 통합 전에 저장 조건을 지도 시·군 선택 기준으로 명확히 해야 한다.
- 맵의 `MapUploadSheet`만 `useDocumentScrollLock`을 사용한다. 스토리와 보관함도 같은 오버레이 컨테이너를 사용하지 않으면 배경 스크롤/복귀 동작이 달라진다.
- `PhotoRecordAlbum`의 단일 `isAdding` 상태를 진입점과 함께 관리하지 않으면 맵에서 열던 패널이 스토리 전환 뒤 인라인으로 나타나는 등의 상태 누수가 생길 수 있다. `open/close + origin + initialLocation`의 단일 상태 계약이 필요하다.

- `frontend` TypeScript 빌드와 변경 diff를 검토하고, 아래 시나리오의 판정을 추가한다.

### 수동 QA 시나리오

1. 스토리 `+` → 패널 열기 → 지도/권역/시·군 선택 → 저장 → 스토리 원위치 확인.
2. 맵에서 권역·시·군 선택 → 사진 추가 → 미리 선택된 장소 표시 → 다른 장소로 변경 → 저장 → 맵의 기존 선택 상태와 새 마커 확인.
3. 보관함에서 사진 추가 → 같은 패널 열기와 저장 후 보관함 원위치 확인.
4. 사진 1장·여러 장, EXIF 있음/없음, 수동 촬영일, 기간 종료일 오류, 장소 미선택을 확인.
5. 업로드 실패 후 재시도, 업로드 중 닫기/배경 클릭/중복 저장 방지를 확인.
6. 모바일 폭에서 패널 높이·안전영역·배경 스크롤 잠금·포커스·닫기 버튼을 확인.

## 최종 검증 (2026-09-07)

### 계약 대조

| 기준 | 결과 | 근거 |
| --- | --- | --- |
| 스토리·맵·보관함 공통 진입 | 통과 | `PhotoRecordAlbum`이 하나의 `photoAddRequest` 상태와 `PhotoAddSheet`를 소유한다. 스토리 고정 `+`, 보관함 고정 추가 버튼, 맵 `onAdd`가 모두 이 상태를 연다. |
| 맵 선택 시·군 사전 선택 | 통과 | `PhotoRecordMapView`가 `onAdd(regionFilter)`로 선택한 권역·시군 코드를 전달하고, `PhotoAddSheet`/`BatchPhotoUploadPanel`이 `initialLocation`으로 표시한다. |
| 패널 안 장소 변경 | 통과 | 공통 패널의 `LocationPickerDialog`에서 권역·시군을 다시 선택할 수 있고, 선택 뒤 원래 사진 추가 시트로 복귀한다. |
| 장소 필수 저장 방어 | 통과 | `mapRegionCode`와 `mapCityCode`가 모두 없으면 `pendingCount`가 0이며 저장 버튼과 업로드 함수가 이중으로 차단한다. 장소 필드는 선택 안내를 표시한다. |
| 다중 사진·촬영일·실패 재시도 | 통과 | 기존 bundle API와 사진별 EXIF/수동 촬영일 규칙을 유지하며, 실패 항목은 패널을 닫지 않고 재시도 대상이 된다. |
| 성공 후 복귀·중복 패널 제거 | 통과 | 성공 시 상위 `photoAddRequest`만 닫혀 현재 화면·맵 선택은 유지된다. 대체된 `MapUploadSheet` 경로와 관련 import/state는 제거됐다. |
| 모바일/접근성 기반 | 통과 | 공통 시트와 장소 선택 다이얼로그는 portal, `role=dialog`, `aria-modal`, 닫기 레이블, 배경 스크롤 잠금을 사용한다. 업로드 중 닫기와 중복 저장을 막는다. |
