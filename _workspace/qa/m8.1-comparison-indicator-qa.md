# M8.1 수상작별 사진 놓기 상태 표시 QA

작성일: 2026-09-02
범위: 마이 저장 수상작·수상작 상세의 비교 상태 표시와 기존 결과 deep link

## 표시·조회 계약

- 비교가 없는 즐겨찾기 수상작: 텍스트 CTA `사진 놓기`만 표시한다.
- 비교가 있는 수상작: 실제 내 사진의 작은 썸네일과 완료 표시를 보여 주고, 전체 표시 영역은 기존 비교 결과를 여는 링크다. 빈 이미지·가짜 placeholder를 완료 표시로 쓰지 않는다.
- 마이 목록은 `useComparisons()` 한 번의 목록 조회를 공유해 contest ID→comparison을 매핑한다. 카드마다 `/me/comparisons` 또는 상태 API를 호출하면 안 된다.
- 상세도 비교 목록/상태를 하나만 조회하거나 이미 캐시된 같은 query key를 사용한다. 수상작 이미지/즐겨찾기 조회와 결합해 항목별 N+1 요청을 만들지 않는다.
- 결과 링크는 `/compare?contestId=<id>`이며 ComparePage가 기존 comparison을 찾아 composer 없이 결과·수정 흐름을 연다.

## 수동 QA

- [ ] 비교 없는 저장 수상작: 마이·상세에서 `사진 놓기` 텍스트 CTA만 보이고 클릭하면 해당 contestId의 새 composer로 이동한다.
- [ ] 비교 있는 저장 수상작: 마이·상세에서 내 사진 썸네일+완료 표시가 보이고 클릭하면 해당 contestId 기존 결과가 열린다. 새 comparison POST는 발생하지 않는다.
- [ ] 수상작 A/B 중 A만 비교 있음: A만 썸네일 상태, B는 CTA이며 상태가 서로 섞이지 않는다.
- [ ] 목록 20개를 열어 Network 확인: comparisons 목록 요청은 화면 진입/캐시 갱신당 한 번이며 카드별 추가 요청 없음.
- [ ] 사용자 사진 URL 404/로드 실패: 깨진 이미지 아이콘·레이아웃 붕괴 없이 중립 placeholder/텍스트 완료 상태가 보이고 결과 링크는 계속 동작한다.
- [ ] comparison 응답이 비어 있음/로딩/오류: 모든 카드를 완료로 오인하지 않으며 로딩은 과한 카드별 skeleton 없이, 오류는 CTA·기존 목록 조작을 막지 않는 안전한 fallback을 쓴다.
- [ ] 비교 결과에서 사진 교체·결과 삭제 후 마이/상세 재방문: 썸네일은 새 사진으로 갱신되거나 CTA로 되돌아간다.
- [ ] 즐겨찾기 해제 후 기존 비교: 저장 목록에서는 사라지지만 `/compare?contestId` 기존 결과는 계속 열리고, 재즐겨찾기 시 썸네일 상태가 다시 정확히 표시된다.
- [ ] 모바일 320px: 썸네일·완료 표시·CTA가 저장 해제 하트와 겹치지 않고 터치 영역이 충분하다. 키보드/스크린리더는 `A 수상작의 사진 놓기 결과 열기`처럼 상태와 행동을 구분해 읽는다.

## 차단

- 카드별 비교 조회로 N+1 요청 발생, 없는 비교를 완료로 표시, 비교가 있는데 새 composer/중복 생성으로 이동, 또는 썸네일 실패가 카드/링크를 깨면 차단이다.
