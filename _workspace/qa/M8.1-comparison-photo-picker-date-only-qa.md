# M8.1 비교 사진 선택 촬영일 날짜 전용 QA

## 판정

통과. 화면은 날짜만 입력·표시하고, 업로드 multipart의 `takenAt`은 서버 `LocalDateTime` 바인딩에 맞는 `YYYY-MM-DDT00:00:00` 형식으로 보낸다.

## 계약 교차 확인

- 공통 `ComparisonPhotoPickerDialog`의 입력은 `type="date"`다. 시간 선택 UI는 남아 있지 않다.
- EXIF 값은 `toDateInputValue`로 `YYYY-MM-DD`만 표시한다. 사용자가 날짜를 바꾸면 같은 날짜 형식만 유지된다.
- 확정 시 `toTakenAtStart`가 날짜에 `T00:00:00`을 붙인다. 빈 값은 확정 버튼이 막고, `takenAt`을 누락시키지 않는다.
- `/me/photos` 컨트롤러의 `takenAt`은 ISO `LocalDateTime`으로 바인딩되므로 `YYYY-MM-DDT00:00:00`을 정상 수용한다.

## 세 진입 흐름

1. `ComparePage` 새 비교: 공통 선택창 → `uploadUserPhoto` → `POST /me/photos`로 날짜+자정 시각을 전송한다.
2. `ComparePage` 기존 비교 사진 변경: 같은 공통 선택창과 `uploadUserPhoto` 경로를 사용하므로 동일하다.
3. `AlbumComparisonPicker` 수상작 비교 시작: 같은 공통 선택창 → `uploadPhotoRecord` → `POST /me/photos`로 동일한 값을 전송한다.

## 검증

- `frontend/npm run typecheck` 통과.
- `frontend/npm run build` 통과.
- Vite 814KB 청크 경고만 기존 비차단 권고다.

## 메모

- 이 변경은 촬영 **시간**을 보존·수정하는 기능이 아니라 촬영 **날짜**를 기록하는 UX다. EXIF에 시간이 있더라도 비교용 새 사진 업로드에서는 해당 날짜의 자정으로 정규화된다.
