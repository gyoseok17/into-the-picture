# M8.1 전역 상단 내비 실제 폭 기반 축약 QA

## 대상

- `frontend/src/components/layout/TopNav.tsx`
- 데스크톱 상단 내비의 아이콘·텍스트 축약 기준

## 최초 독립 점검 결과

### 차단 이슈: 실제 넘침 기반 동작이 아님

현재 구현은 `md:max-lg` Tailwind 규칙으로 768px 이상 1024px 미만 전체에서 메뉴 레이블을 숨긴다. `ResizeObserver`, `scrollWidth`, `clientWidth` 또는 로그인 상태·닉네임 길이에 따른 실측 판단은 없다.

따라서 다음 요구를 충족하지 못한다.

- 메뉴 전체가 들어가는 768~1023px 폭에서도 항상 아이콘만 표시된다.
- 로그아웃 상태와 짧은 닉네임 로그인 상태는 더 좁은 폭까지 레이블을 유지할 수 있는데도 조기 축약된다.
- 긴 닉네임 로그인 상태에서만 필요한 축약과 구분되지 않는다.
- 폭을 다시 넓혔을 때 실제 여유에 따라 레이블을 복원하는 경로가 없다. 단지 1024px에서 CSS가 바뀐다.

판정: **수정 필요 (차단)**.

## 보정 후 최종 검증

### 실제 content box 기준

- `TopNav`는 확장형 메뉴 전용의 숨겨진 측정 DOM을 사용한다. 실제 메뉴가 아이콘 모드가 되어도 확장형 폭은 계속 측정되므로, 축약 상태가 스스로를 유지시키는 feedback loop가 없다.
- 필요한 폭은 브랜드 + 확장 메뉴 + 계정 영역 + 두 flex gap의 합으로 계산한다.
- 가용 폭은 `container.clientWidth`에서 `paddingInlineStart`, `paddingInlineEnd`를 뺀 실제 flex content box로 계산한다. 따라서 `px-8`의 좌우 64px을 잘못 여유 폭으로 판단하지 않는다.
- 필요한 폭이 가용 폭보다 클 때만 아이콘 모드가 되며, 다시 넓어져 전체가 들어가면 같은 확장형 측정값으로 레이블을 복원한다.

### 상태·리사이즈·접근성

- `ResizeObserver`가 컨테이너, 브랜드, 계정 영역, 확장 메뉴를 관찰한다. 로그아웃/로그인 전환, 긴 닉네임, 폰트 로드, 창 폭 변화가 모두 재측정 조건에 포함된다.
- effect는 `isBootstrapping`, `user?.nickname` 변경 시 다시 구성하고 cleanup에서 observer와 예약된 animation frame을 해제한다.
- 상태값이 달라질 때만 `setIsCompact`을 수행한다. 측정용 메뉴는 실제 메뉴와 분리돼 있어 observer 재귀 루프가 발생하지 않는다.
- 아이콘 모드에서도 `NavLink`의 링크, 활성 상태, 키보드 포커스, `aria-label`, `title`을 유지하며 가시 텍스트만 `sr-only`가 된다.
- `BottomTabBar`의 `md:hidden`은 변경되지 않아 768px 미만은 기존 모바일 하단 탭을 그대로 사용한다.

최종 판정: **통과**.

## 권장 구현 계약

1. 768px 이상에서만 상단 내비를 표시한다. 768px 미만의 `BottomTabBar` 동작은 변경하지 않는다.
2. 메뉴 레이블 표시 상태는 고정 브레이크포인트가 아니라, 상단 한 줄 컨테이너의 실제 `scrollWidth > clientWidth` 여부로 결정한다.
3. `ResizeObserver`로 폭 변화, 로그인 전환, 닉네임 길이 변화를 다시 측정한다. 언마운트 때 observer를 해제한다.
4. 측정용 전체 레이블 레이아웃과 실제 표시 레이아웃을 분리하거나, 축약 후 다시 넓힐 때 전체 레이블 폭을 재측정할 수 있게 해 축약 상태가 자기 자신을 유지시키는 feedback loop를 막는다.
5. 축약 모드에서도 각 링크의 `aria-label`, `title`, 활성 상태, 키보드 포커스와 링크 목적지는 유지한다.

## 회귀 확인

- `BottomTabBar`는 `md:hidden`으로 유지되어 768px 미만에서 기존 모바일 하단 탭을 사용한다.
- 현재 아이콘 전용 링크에는 `aria-label`과 `title`이 있으며, 활성 상태는 `NavLink`에 남아 있다.
- 단, 위 차단 이슈가 해결되기 전에는 로그인 상태별 실제 폭 검증과 resize 복귀 검증을 통과로 판정할 수 없다.
