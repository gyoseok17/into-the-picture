# M8 목록 복귀 · 사진 앨범 스크롤 QA 기준

- 작성일: 2026-08-16
- 역할: 통합 QA 사전 검토
- 대상: 수상작 목록에서 상세 진입 후 복귀 위치, 키워드 검색의 사진 앨범 상세 모달 내부 스크롤
- API·DB 계약 변경: 없음. 브라우저 히스토리 상태와 클라이언트 UI 상태만 다룬다.

## 현재 위험 확인

1. `ContestCard`는 상세로 일반 `Link` 이동하고, 상세의 목록 링크는 항상 `/contests`로 새 이동한다. 따라서 뒤로 가기와 목록 링크가 서로 다른 히스토리 흐름을 만들 수 있으며, 목록의 스크롤·필터 상태를 명시적으로 보존하지 않는다.
2. `PhotoAlbumDetail`은 화면 전체 고정 오버레이와 `max-h-[90vh] overflow-auto` 카드만 가진다. 사진이 많은 앨범을 카드 내부에서 끝까지 스크롤할 때 wheel/touch 잔여 스크롤이 배경 문서로 전파될 수 있고, 배경 스크롤 잠금·복귀·포커스 처리가 없다.

## 수상작 상세 복귀 수용 기준

### 위치와 히스토리

- 목록에서 충분히 아래로 내린 뒤 작품 카드를 열고 브라우저 **뒤로 가기**를 하면, 목록의 이전 `scrollY`로 복귀한다. 목록 데이터가 이미 캐시에 있으면 즉시, 재요청이 필요하면 해당 카드와 앞선 목록 높이가 렌더된 뒤 한 번만 복원한다.
- 브라우저 **앞으로 가기**로 다시 상세에 들어간 후 다시 뒤로 가도, 같은 목록 위치를 복원한다.
- 상세의 "수상작 목록" 이동도 사용자가 목록에서 진입한 경우에는 단순 `/contests` 새 이동이 아니라 동일한 복귀 계약을 따라야 한다. 직접 상세 URL로 진입한 경우에는 정상적인 새 목록 최상단으로 이동해도 된다.
- 복원 동작이 smooth scroll 애니메이션으로 목록을 흔들거나, 복원 직후 무한 로딩 감지기로 불필요한 다음 페이지 요청을 만들면 안 된다.

### 목록 상태와 데이터 타이밍

- 복귀 전의 적용된 쿼리(계절·등급·부문·지역·키워드), 임시 필터 선택값, 모바일 1/2/3열 설정, 로드된 무한 목록 페이지 수는 유지한다. URL로 표현되는 검색 조건은 URL과 일치해야 한다.
- URL을 직접 `/contests?...`로 열거나 새로고침한 경우는 저장된 과거 `scrollY`를 임의 적용하지 않는다. 기본 진입 위치는 최상단이다.
- 필터/검색 조건이 실제로 바뀐 뒤에는 이전 조건의 위치를 새 결과에 적용하지 않는다. 새 조건은 최상단에서 시작한다.
- 빈 결과, 오류, 목록 길이 감소, 삭제/즐겨찾기 상태 변경 때문에 원래 높이에 도달할 수 없을 때는 가능한 최대 위치에 머물고 오류 없이 렌더한다.
- 복귀 대상 카드가 늦게 렌더되는 동안에는 페이지가 최상단에서 번쩍였다가 여러 번 점프하지 않아야 한다. 복원 시도는 데이터 준비 뒤 단 한 번이며, 실패·취소 시 다음 탐색을 방해하지 않는다.

### 접근성·다른 진입점

- 키보드로 카드에 포커스 후 Enter로 상세에 들어갔다가 뒤로 오면, 복귀한 카드가 보이는 위치이고 키보드 포커스도 해당 카드(또는 목록의 의미 있는 복귀 지점)에 남아야 한다. 마우스 진입은 포커스 강제가 필요 없다.
- 지도 핀, 홈, 마이페이지 등 다른 화면에서 상세로 직접 들어온 경우에는 목록 복귀 상태를 만들거나 오염하지 않는다.
- 상세에서 로그인 유도 후 복귀, 상세 API 오류/재시도, 즐겨찾기 토글은 목록 복귀 상태를 잃지 않아야 한다.

## 키워드 사진 앨범 모달 수용 기준

### 스크롤 경계

- 사진이 여러 장인 앨범을 열면 배경 문서의 `scrollY`는 즉시 고정된다. 모달 내부 컨테이너만 스크롤된다.
- 모달 내부가 맨 위/맨 아래에 도달한 뒤 mouse wheel, trackpad 관성, 터치 드래그를 계속해도 배경 결과 목록이 움직이지 않는다(스크롤 체이닝 차단).
- 모달 내부 콘텐츠가 짧아 스크롤이 필요 없을 때도 wheel/touch로 배경이 움직이지 않는다.
- 닫을 때 모달을 열기 전의 정확한 배경 `scrollY`를 복원한다. 무한 스크롤 목록의 추가 페이지 요청, 레이아웃 점프, 빠른 도구의 예기치 않은 열림이 없어야 한다.
- 360px 모바일 세로/가로, iOS/Android 계열 터치 환경과 데스크톱 wheel/trackpad에서 카드 높이가 viewport를 넘지 않고, 내부 스크롤 도달 가능해야 한다. 모바일 브라우저 주소창 변화에도 하단 사진·닫기 버튼이 가려지지 않아야 한다.

### 모달 상호작용

- 열릴 때 포커스는 모달 제목 또는 닫기 버튼으로 이동하고, Tab/Shift+Tab은 모달 안에서 순환한다. 닫을 때는 앨범을 연 카드로 포커스를 돌려준다.
- 닫기 버튼, Escape, 배경 클릭은 모두 모달만 닫고 배경 스크롤 위치를 보존한다. 카드 내부 클릭과 앨범 내부 스크롤은 닫기로 처리되지 않는다.
- 관련 키워드를 누르면 모달을 닫고 해당 키워드 검색을 적용한다. 이때 이전 검색의 스크롤 위치를 보존하면 안 되며 새 검색은 의도한 시작 위치에서 열린다.
- 앨범의 이미지가 404/지연/실패하거나 일부 사진이 없는 경우에도 모달 내부 스크롤 컨테이너·닫기·포커스·배경 잠금은 정상이어야 한다.
- 모달이 열린 상태에서 라우트 변경, 브라우저 뒤로 가기, 컴포넌트 언마운트가 일어나면 body lock 및 이벤트 리스너를 반드시 정리한다.

## 권고 구현 경계

- 수상작 복귀 상태는 `ContestListPage`/라우팅 경계의 전용 훅 또는 명시적인 navigation state에 두고, 카드·상세 화면에 복원 로직을 복사하지 않는다.
- 사진 모달의 body lock, 포커스 복원, Escape/outside 동작은 `PhotoAlbumDetail`의 UI 내용과 분리 가능한 공통 dialog 훅/컴포넌트로 둔다. 기존 `ScrollAssist`와 스크롤 상태를 공유하지 않는다.
- 브라우저 자체 `history.scrollRestoration` 전역 변경을 쓴다면 앱 해제 시 원래 값을 복원하고, 두 목록 화면 외 라우트에 부작용이 없는지 확인한다.

## 통합 판정 전 필수 증빙

- 수상작: 필터 적용 + 2페이지 이상 로드 + 상세 진입/뒤로/앞으로/목록 링크/직접 URL의 수동 QA 영상 또는 단계별 캡처.
- 사진 검색: 10장 이상 앨범에서 모달 상·하단 wheel/touch, Escape/outside/닫기/키워드 이동, 모바일 360px 및 데스크톱의 수동 QA.
- `npm run build` 및 관련 단위/통합 테스트가 있다면 결과 첨부. 자동화가 없다면 위 수동 시나리오와 브라우저를 기록한다.
