# M8.1 비교 공개 관리 화면 QA

## 판정

통과. 비교 공개 상태의 제어 위치만 이동했으며 API·DB·공개 사진 접근 경계는 변경하지 않았다.

## 교차 확인

- `/me/comparisons`는 `RequireAuth` 내부에 있고, 마이의 `공개 관리` 항목만 이 경로로 연결된다.
- 하단 내비게이션의 `내 앨범`은 계속 `/me/album`을 사용한다. `/me/comparisons`에서는 상위 `/me` 탭이 활성화된다.
- `ComparePage`에는 `useUpdateComparisonVisibility`, 공개/비공개 제어 및 해당 오류 경로가 남아 있지 않다.
- `ComparisonVisibilityManager`는 비교 목록의 개인 사진 썸네일, 수상작명, 현재 상태와 행 단위 전환만 표시한다. 앨범의 장소·메모·촬영일 데이터는 표시하지 않는다.
- 각 행은 독립 mutation을 사용하므로 한 행을 변경하는 동안 다른 행은 계속 조작할 수 있다. 성공 시 `comparisons`와 `public-contest-comparisons` 캐시를 함께 무효화해 내 목록과 수상작 공개 모음이 다음 조회에서 일치한다.
- 로딩·목록 조회 실패 재시도·빈 목록·행 단위 변경 실패가 모두 화면 상태로 처리된다. 상태 변화는 `aria-live="polite"`, 실패는 `role="alert"`로 전달되고 버튼의 전환 목적도 `aria-label`로 제공된다.
- 목록은 모바일 1열, `sm` 이상 2열이며 긴 수상작명은 줄임 처리한다.

## 검증

- `frontend`: `npm run typecheck` 통과
- `frontend`: `npm run build` 통과
- 작업트리: `git diff --check` 통과

Vite의 500kB 청크 권고는 기존 비차단 항목으로 남아 있다. 실제 브라우저에서는 로그인 계정으로 공개→비공개→공개 전환 후 수상작 상세의 사진 모음을 새로 열어 반영 여부만 최종 수동 확인하면 된다.
