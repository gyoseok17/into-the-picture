# M8.1 네 가지 사진 형식 프런트엔드 검토

## 지원 범위

- 업로드 선택은 JPEG, PNG, WebP, HEIC/HEIF 확장자와 MIME 타입을 허용한다.
- 브라우저 사전 촬영일 추출은 JPEG APP1 EXIF, PNG `eXIf`, WebP `EXIF` 청크의 `DateTimeOriginal`, `DateTimeDigitized`, `DateTime` 순서를 지원한다.
- HEIC/HEIF EXIF 컨테이너 파싱은 별도 대용량 디코더가 필요하므로 브라우저에서는 촬영일 자동 채우기를 지원하지 않는다는 안내를 보인다. 사용자는 직접 촬영일을 입력할 수 있다.

## 사용자 상태와 보호

- 브라우저가 파일 미리보기를 렌더링하지 못하면 이미지 깨짐 대신 “이 기기에서는 미리보기를 볼 수 없지만 사진은 추가할 수 있다”는 상태를 보인다.
- 촬영일 직접 입력, 비동기 추출 결과의 경합 방지, 서버 EXIF 보완 경로는 기존 동작을 유지한다.
- PNG/WebP에 EXIF가 없으면 직접 입력 또는 서버 기본 동작으로 계속 진행한다.

## 검증

- `frontend npm run build` 통과.
- `git diff --check`는 최종 통합 단계에서 다시 실행한다.
- 기존 Vite 500KB 청크 경고만 남아 있다.

## 수동 QA

1. JPEG, PNG(eXIf 포함), WebP(EXIF 포함) 파일에서 촬영일이 각각 입력칸에 들어오는지 확인한다.
2. EXIF 없는 PNG/WebP와 HEIC/HEIF에서 형식별 안내와 직접 입력이 가능한지 확인한다.
3. HEIC/HEIF 미리보기가 지원되지 않는 브라우저에서 대체 안내와 업로드 가능 상태가 보이는지 확인한다.
4. 촬영일을 직접 입력한 후 다른 형식의 파일을 골라도 입력값이 유지되는지 확인한다.

## 비교 화면 회귀 보완

- 비교 화면의 내 앨범 추가와 비교 결과 수정 안의 추가가 같은 `PhotoPickerDialog`를 사용하므로 JPEG·PNG·WebP·HEIC/HEIF 선택 규칙을 한 곳에서 적용했다.
- 비교 화면 업로드 실패 문구와 마이 앨범 업로드 실패 문구를 네 가지 형식 및 10MB 제한으로 통일했다.
- 공통 `ImageSource`는 개인 사진 Blob을 포함해 브라우저 미리보기 실패 시 깨진 이미지 대신 미리보기 불가 안내를 표시한다. 업로드 성공 여부와는 분리한다.
- 검증: `frontend npm run build`, `git diff --check` 통과. 기존 Vite 500KB 청크 경고만 남아 있다.
