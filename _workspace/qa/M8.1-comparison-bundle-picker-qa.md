# M8.1 사진 놓기 앨범 묶음 선택 QA

작성일: 2026-09-14
판정: 통과

## 검토 범위

- `ComparisonPhotoPickerDialog`의 앨범 후보 흐름
- 새 비교, 기존 비교 사진 교체, 앨범에서 수상작 비교 시작의 세 진입 경로
- `GET /me/photos/bundles?archived=false` 계약과 프런트 선택 타입 교차 검토

## 확인 결과

| 항목 | 결과 |
| --- | --- |
| 실제 묶음 우선 선택 | 통과. 공통 선택창이 활성 묶음을 조회하고, 묶음 카드 뒤에 `bundle.photos` 한 장 선택 단계로 이동한다. |
| 새 비교 | 통과. `ComparePage`의 새 비교 선택창이 공통 창을 사용하고 선택한 `photo.id`를 기존 생성 흐름으로 전달한다. |
| 기존 사진 교체 | 통과. 같은 공통 창을 쓰며 기존 비교에 사용 중인 사진은 기존 `availablePhotos` 필터로 제외된다. |
| 앨범에서 시작 | 통과. `AlbumComparisonPicker`도 공통 창을 사용하며, 활성 앨범의 사진 `id`를 비교 생성으로 전달한다. |
| 레거시 단일 사진 | 통과. `legacy=true`, `id=null` 묶음도 첫 사진 ID를 키로 삼는 한 장 묶음 카드로 표시된다. |
| 빈/비정상 묶음 | 통과. 사진이 없는 묶음은 후보에서 제거되고, 후보가 없으면 빈 상태를 표시한다. |
| 보관함 제외 | 통과. 선택창은 `usePhotoRecordBundles(false, step !== 'start')`로 활성 데이터만 지연 조회한다. |
| 선택 상태 | 통과. 다른 묶음으로 이동하거나 뒤로 가면 현재 선택을 초기 선택값으로 되돌려 이전 묶음 사진을 확정하지 않는다. |
| 오류·권한 | 통과. 묶음 요청 실패에 재시도 UI가 있으며, 서버 `/me` API가 현재 사용자 권한을 계속 강제한다. |
| 캐시 갱신 | 통과. 사진 기록 업로드·수정·삭제 훅은 `photo-record-bundles`와 `user-photos`를 함께 무효화한다. |

## 발견 및 해결

- 최초 구현은 `usePhotoRecordBundles(step !== 'start')`를 사용했다. 첫 번째 인자가 `enabled`가 아니라 `archived`여서 앨범 단계가 보관함을 조회하는 차단 결함이었다.
- 훅을 `usePhotoRecordBundles(archived, enabled = true)`로 확장하고, 선택창은 `usePhotoRecordBundles(false, step !== 'start')`를 사용하도록 수정했다. 따라서 활성 묶음만 지연 조회한다.
