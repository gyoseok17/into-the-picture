# M8.1 사진첩 추가·지도 보기 통합 QA 계획

작성일: 2026-08-26
상태: 구현 대기 — UI·좌표 계약 도착 후 통합 판정

## 현재 구조 확인

- `PhotoRecord`에는 `placeName`만 있고 `lat`·`lng` 또는 지오코딩 상태 필드가 없다.
- 수상작 지도는 이미 카카오 지도 SDK, 마커 클러스터, 지도 로딩 실패 안내를 사용한다. 지도 API 키가 없거나 SDK 로딩에 실패해도 목록 화면은 유지된다.
- 수상작 좌표 보강은 서버의 지오코딩 경계에서 처리한다. 사진첩 지도도 REST 키나 외부 지오코딩 비밀값을 브라우저로 보내면 안 된다.

## 사진 추가 온디맨드 UX

- 기본 앨범 진입은 업로드 폼을 펼치지 않고 사진·정렬·지도 전환을 우선 보여 준다.
- `사진 추가`는 버튼·링크 역할과 이름이 명확하고 키보드로 열 수 있어야 한다. 열리면 파일 입력 또는 첫 입력으로 초점이 이동한다.
- 닫기·취소·업로드 성공 후에는 열기 버튼으로 초점이 돌아가며, 기존 앨범 정렬·스크롤·선택 상태가 불필요하게 초기화되지 않는다.
- 업로드 중에는 중복 제출을 막고, 실패 시 파일 선택과 사용자가 입력한 촬영일·장소·메모를 잃지 않으며 재시도 방법을 안내한다.
- 모바일 360px에서는 열기/닫기/파일 선택/촬영일 입력/추가 버튼이 하단 탭이나 화면 가장자리에 가려지지 않는다. 데스크톱에서는 앨범 목록 폭과 업로드 패널이 서로 밀지 않는다.

## 시간순·지도 보기 전환

- 시간순은 기존 `takenAt ?? createdAt` 순서를 유지하며, 지도 보기와 오갈 때 활성·보관 탭, 정렬, 앨범 데이터가 임의로 초기화되지 않는다.
- 지도 전환은 필요한 때만 지도 SDK·좌표 데이터를 요청한다. 시간순에서 지도를 초기화하지 않는다.
- 지도는 데스크톱에서 지도와 선택 목록을 함께, 모바일에서 지도와 선택 내용을 세로로 안전하게 제공한다. 지도 자체를 조작할 수 없는 키보드 사용자도 선택된 사진 목록과 상세/편집 진입을 사용할 수 있어야 한다.
- 지도 로딩 중·키 없음·SDK 실패는 재시도 또는 안내를 표시하며, 시간순으로 돌아갈 수 있어야 한다.

## 장소·좌표·지오코딩 안전 조건

| 상황 | 기대 동작 |
| --- | --- |
| 장소 미입력 | 사진 기록은 시간순에 정상 보이며 지도에서는 제외하고 `장소 정보가 없어 지도에 표시되지 않음`을 안내한다. |
| 좌표 없음 | 기존 기록을 삭제·수정·보관하지 않는다. 지도 대상 수와 제외 수를 구분한다. |
| 지오코딩 실패/타임아웃 | 업로드·수정은 성공할 수 있어야 하며, 실패를 좌표 `(0,0)`·임의 중심점으로 저장하지 않는다. 재시도 경계와 사용자 안내를 제공한다. |
| 같은 장소·같은 좌표 | 사진별 기록은 모두 유지한다. 지도는 클러스터/그룹으로 개수를 표현하고 선택 목록에서 각 사진을 구별한다. |
| 애매한 장소명 | 자동으로 첫 검색 결과를 확정 저장하지 않는다. 후보 선택 또는 좌표 없음 상태를 유지한다. |
| 보관 사진 | 기본 지도에는 활성 사진만 표시한다. 보관 탭 지도 지원 시 활성/보관 데이터가 섞이지 않는다. |
| 장소 수정 | 기존 좌표를 새 장소에 그대로 재사용하지 않는다. 새 장소 좌표가 확정될 때만 교체하고, 실패하면 이전 좌표·장소의 의미가 어긋나지 않게 무효화 또는 명시적 재시도 상태를 둔다. |

## 데이터·보안·계약 교차 검토

- 좌표를 저장한다면 `PhotoRecord` 단위의 nullable 좌표, 좌표 출처/상태, 변경·보관·삭제 시 데이터 보존 규칙과 마이그레이션을 확인한다.
- 좌표를 저장하지 않는 온디맨드 지오코딩이라면 요청 수·중복 장소 캐시·실패 재시도와 외부 API 쿼터를 확인한다.
- 사용자 소유권은 모든 사진 목록·좌표 조회·갱신에서 서버가 확인한다. 다른 사용자의 사진·장소·좌표가 지도 응답에 섞이면 차단한다.
- 지오코딩 REST 키·토큰은 서버 환경 변수에만 둔다. 프런트에는 지도 표시용 공개 키 외 비밀값을 전달하지 않는다.
- 지도 응답 DTO와 프런트 타입에서 `null` 좌표 의미, 표시 대상 수, 중복 장소 그룹 규칙을 동일하게 정의한다.

## 최종 수동 QA 시나리오

1. 사진 없는 앨범 → 사진 추가 열기/취소/업로드 성공/실패, 모바일·데스크톱 확인
2. 촬영일만 있는 사진, 장소만 있는 사진, 장소·좌표가 있는 사진을 섞어 시간순·지도 전환 확인
3. 좌표 없는 장소와 지오코딩 실패를 포함해 사진은 유지되고 지도에서만 제외되는지 확인
4. 같은 장소 사진 여러 장의 클러스터/선택 목록/상세·편집 경로 확인
5. 활성 사진 보관 → 지도에서 즉시 제외, 보관 복원 → 다시 표시되는지 확인
6. 지도 SDK 실패/키 미설정 상태에서도 앨범·시간순·사진 추가가 정상인지 확인

## 현재 판정

- 차단: 위치 좌표·지오코딩 API 및 지도 UI 구현이 아직 도착하지 않아 판정할 수 없다.
- 구현 완료 후 API 응답·DB 변경·프런트 전환 상태를 함께 대조하고, 빌드·테스트·수동 화면 확인 결과를 이 문서에 누적한다.
