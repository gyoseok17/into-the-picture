# M10.1 신안군 코드 정규화 QA

검토 일시: 2026-09-22

## 데이터·마이그레이션

- V16은 이미 적용될 수 있는 Flyway 이력이므로 변경하지 않고 `V22__normalize_contest_sinan_map_city_code.sql`에서 `contest_work.map_city_code`의 `SHINAN`만 `SINAN`으로 보정한다.
- V22는 멱등적이다. 적용 뒤 다시 실행해도 `SHINAN` 행이 없으면 변경 행 수 0으로 종료한다.
- 새 동기화 원본 `ContestLocationOverrides`도 `SINAN`으로 바뀌어 이후 sync가 구 코드를 재기록하지 않는다.

## 계약 일치

- 백엔드 앨범 카탈로그 `MapLocationCatalog`: `SINAN`.
- 프런트 선택 목록 `koreaRegions.ts`: `SINAN`.
- 프런트 지도 좌표 목록 `albumMapCityPositions.ts`: `SINAN`.
- 수상작의 새 동기화와 DB 보정 뒤 값도 `SINAN`이므로 수상작 비교 시 지역 동등 비교와 앨범 지도 좌표 조회가 일치한다.

## 구버전 서버 호환성

- DB 엔티티·DTO의 `mapCityCode`는 enum이 아닌 `String` 컬럼/필드이므로 구버전 서버도 DB에서 `SINAN` 문자열 자체를 읽고 API로 직렬화하는 데 실패하지 않는다.
- 단, 구버전 `MapLocationCatalog`이 아직 `SHINAN`만 알고 있다면, 새 `SINAN`을 상속한 사진 기록의 **도시 앵커 지도 핀**을 해석하지 못할 수 있다. 이는 문자열 읽기 오류가 아니라 구 카탈로그와의 의미 불일치다.
- 현재 Docker Compose의 교체 배포처럼 구버전 서버를 내리고 M10.1 컨테이너로 교체하는 절차에서는 노출되지 않는다. 구·신 서버를 동시에 운영하는 롤링 배포는 피해야 한다.

## 테스트·정적 검증

- `backend`: `gradlew.bat test --no-daemon --tests "com.intothepicture.external.contest.sync.ContestSyncJobTest" --tests "com.intothepicture.domain.photorecord.location.MapLocationCatalogTest"` 통과.
- 추가 sync 테스트가 `염전체험 → JEOLLA / SINAN` 저장을 검증한다.
- `frontend`: `npm run build` 통과.
- `git diff --check` 통과.
- 기존 Vite 500 kB 청크 경고만 존재.

## 발견 사항

- `_workspace/frontend/M10.1-location-code-contract-review.md`는 현재 소스와 달리 `SHINAN`으로 통일됐다고 적혀 있어 갱신이 필요하다. 실제 코드 계약은 위 표처럼 `SINAN`이다.

## 판정

코드·DB 정규화는 통과. 배포는 구·신 서버 동시 운영 없이 이미지 교체 방식으로 진행하고, 프런트 계약 보고서의 오래된 설명만 정정해야 한다.

## 최종 재검토 — 프런트 정정 후

- 런타임 프런트의 `koreaRegions.ts`, `albumMapCityPositions.ts`는 모두 `SINAN`만 사용한다.
- 런타임 백엔드의 `MapLocationCatalog`, `ContestLocationOverrides`도 모두 `SINAN`만 사용한다.
- `SHINAN`의 허용 잔재는 불변 과거 이력 `V16__add_contest_standard_map_locations.sql`과 이를 보정하는 `V22__normalize_contest_sinan_map_city_code.sql`의 주석·WHERE 절뿐이다.
- 즉 새 DB sync·기존 DB V22 적용·프런트 지역 선택·앨범 지도 좌표의 정본은 모두 `SINAN`이다.

### 문서 일치성

- `_workspace/frontend/M10.1-location-code-contract-review.md`에는 아직 `SHINAN` 정본이라고 적혀 있어 실제 코드와 불일치한다. 이 보고서만 `SINAN` 기준으로 갱신되면 문서도 일치한다.
