# M8.4 Docker Hub Compose QA · 보안 검토

- 검토일: 2026-09-18
- 검토 범위: `backend/docker-compose.yml`, `backend/.env.example`, `backend/README.md`, Docker Hub `m8.3` 이미지

## 계약 대조

- frontend/backend 모두 `gyoseok/into-the-picture-...:${APP_IMAGE_TAG:-m8.3}`를 사용하며 `build:`는 제거되었다.
- `APP_IMAGE_TAG`는 `.env.example`에 고정 버전 `m8.3`으로 제시되어 있고, `latest`를 기본값으로 사용하지 않는다.
- backend만 `.env`를 `env_file`로 읽는다. DB·JWT·외부 API 시크릿은 frontend/Caddy 환경으로 전달되지 않는다.
- backend는 Compose 내부 `8080`만 `expose`하고, frontend(Caddy)만 호스트 `80`/`443`을 공개한다.
- S3 자격 증명 파일·AWS access key·로컬 `.aws` bind mount는 배포 Compose에 없다. EC2 IAM 역할의 Default Credentials Provider 사용 설계와 일치한다.
- `APP_DOMAIN`은 Caddy 컨테이너에만 전달된다. 운영에서는 실제 DNS가 EC2를 가리키는 도메인이어야 TLS 인증서 발급이 성공하며, `localhost`는 EC2 운영값으로 사용할 수 없다.

## 검증

1. `docker manifest inspect gyoseok/into-the-picture-backend:m8.3`
   - amd64/linux 이미지 매니페스트 확인.
2. `docker manifest inspect gyoseok/into-the-picture-frontend:m8.3`
   - amd64/linux 이미지 매니페스트 확인.
3. `docker pull gyoseok/into-the-picture-backend:m8.3`
   - 성공.
4. `docker pull gyoseok/into-the-picture-frontend:m8.3`
   - 성공.
5. `docker compose -f docker-compose.yml config --quiet`
   - 성공.

## 발견 및 조치

- 차단 이슈 없음.
- README의 기존 로컬 빌드 안내에 남은 `VITE_KAKAO_JS_KEY` 필수 문구와 `up --build` 예시는 Hub 이미지 실행 구조와 맞지 않았다. 담당자가 `pull` + `up -d`, 빌드 시점 공개 키 설명으로 정정했다.
- `docker compose config` 일반 출력은 실제 `.env` 값을 펼쳐 보일 수 있으므로, 검증·스크린샷에는 `--quiet`만 사용한다.
- 실제 EC2 통합 시에는 DNS A 레코드 연결 뒤 Caddy TLS 발급, EC2 IAM 역할의 S3 Put/Get/Delete, HTTPS refresh 쿠키, Supabase Session Pooler 연결을 별도 확인해야 한다.

## 재검증

1. `docker compose -f docker-compose.yml config --quiet` 성공.
2. `docker compose -f docker-compose.yml config --images`가 frontend/backend 모두 `m8.3` 고정 태그를 출력.
3. `git diff --check` 성공.
4. README에 `up --build` 사용처 없음. `VITE_KAKAO_JS_KEY`는 배포 `.env` 불필요라는 설명만 남음.

## 판정

- 최종 통과. 차단 이슈 없음.
- 실제 EC2 통합 확인 항목은 DNS/TLS, IAM 기반 S3 접근, DB 연결, HTTPS 쿠키다.
