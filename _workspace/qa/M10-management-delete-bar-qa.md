# M10 비교 관리 다중 선택 삭제 바 QA

## 조사 범위

- 비교 관리 화면에서 선택된 항목 수와 삭제 동작을 스크롤 중에도 접근할 수 있게 하는 고정 작업 바.
- 모바일 하단 탭, 선택 0건, 삭제 확인과 오류, 키보드 접근성을 함께 검토했다.

## 현재 구조 확인

- 비교 관리 화면(`ComparisonManagementPage`)은 `ComparisonVisibilityManager`에 비교 목록만 전달한다.
- 현재 비교 관리에는 다중 선택/삭제 UI가 아직 없다. 비교 삭제 API는 `DELETE /me/comparisons/{id}?deletePhoto={boolean}`이며, 기존 비교 결과 팝업은 결과만 삭제와 사진도 삭제를 구분한다.
- 앨범 관리의 `SelectionBar`는 같은 요구에 사용할 수 있는 선례다. `fixed bottom-[calc(5.25rem+env(safe-area-inset-bottom))] ... md:bottom-6`로 모바일 하단 탭 위에 배치하고, `selectedItems.size > 0`일 때만 렌더링한다.
- 전역 하단 탭은 모바일에서 `fixed bottom-0 z-40`, `AppShell` 본문은 `pb-24`다.

## 구현 전제 및 차단 조건

1. 작업 바는 선택 수가 1 이상일 때만 렌더링한다. 0건에서 빈 고정 바나 비활성 삭제 버튼을 표시하지 않는다.
2. 모바일은 `bottom-[calc(5.25rem+env(safe-area-inset-bottom))]`, 데스크톱은 `md:bottom-6`을 사용한다. 이 값보다 낮으면 하단 탭과 겹치고, `z-40`보다 높게 올리면 하단 탭을 덮을 위험이 있다.
3. 비교 관리의 삭제도 기존 결과 팝업과 같은 의미를 유지해야 한다. 기본 다중 삭제는 **비교 결과만 삭제**로 명시하고, 원본 앨범 사진 삭제를 섞지 않는다. 사진 삭제를 제공하려면 항목별 확인 흐름을 별도 설계해야 한다.
4. 삭제 클릭 뒤에는 확인 다이얼로그에서 선택 개수와 영향(공개 비교가 사라짐, 앨범 사진은 유지됨)을 알려야 한다. 취소·Esc가 선택 상태나 목록을 바꾸면 안 된다.
5. 진행 중에는 삭제 버튼과 선택 변경을 막거나, 최소한 중복 삭제 요청을 막아야 한다. 성공 뒤 삭제된 ID를 선택 집합에서 제거하고 목록 캐시 무효화 뒤 남은 선택 수를 다시 계산한다.

## 접근성·회귀 확인 항목

- 각 카드의 체크 입력은 실제 `input type=checkbox` 또는 동등한 버튼(`aria-pressed`, 카드 제목 포함 `aria-label`)이어야 한다.
- 고정 바에는 선택 개수가 텍스트로 노출되고, 삭제 버튼 이름은 `N개 선택 삭제`처럼 동작을 명확히 한다. 개수 변화는 필요하면 `aria-live=polite`로 알린다.
- 키보드 Tab 순서가 화면 카드 뒤 고정 바에 정상 도달하며, 고정 바가 마지막 카드의 체크 영역을 가리지 않아야 한다.
- 확인 다이얼로그는 Esc/취소/배경 클릭 동작, 포커스 복귀, pending 중 닫기/중복 실행 차단을 확인한다.
- 375px 폭, iPhone safe area, 768px 전환점, 긴 수상작 제목, 1·여러 건 선택과 마지막 선택 해제, 삭제 성공·실패를 수동 확인한다.
