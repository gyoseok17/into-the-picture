# M8.1 사진 기록 앨범 클린 리팩터 QA

## 범위

- 대상: `PhotoRecordAlbum`의 책임 분리. API, DB, URL, 사용자 동작은 유지한다.
- 함께 대조: 현재 사진 묶음 업로드 한도와 문서의 일치 여부.

## 사전 계약·문서 조사 (2026-09-12)

### 실제 동작 기준

- `POST /api/v1/me/photos/bundles`는 요청 하나에 사진 1~3장을 받는 단일 multipart 묶음이다.
- 각 파일은 최대 10MB, 전체 multipart 요청은 최대 32MB다.
- 프런트 `BatchPhotoUploadPanel`과 `PhotoRecordBundleService.MAX_FILES`가 모두 3을 사용하며, Spring 설정도 `10MB`/`32MB`다.
- 이 정책에는 20장 대기열, 파일별 동시 3개 POST, 부분 성공·파일별 재시도 계약이 없다. 묶음 요청은 한 번 성공하거나 실패하며 실패 시 입력을 유지해 전체 묶음을 재시도한다.

## 리팩터 전 구조 위험

- 한 파일이 화면 조립, 조회·mutation 상태, 스토리 렌더링, 카드, 상세 라이트박스, 편집 모달, 삭제 집계, 날짜 그룹화까지 모두 소유했다.
- `PhotoBundleLightboxLegacy`와 비교 연결용 라이트박스는 키보드 닫기·슬라이드·썸네일 구조가 중복돼 있다.
- 현재 사용처가 없는 구 `PhotoUploadPanel`, 구 `AlbumHeader`는 분리 대상이 아니라 제거 대상이다. 남기면 두 업로드 흐름·두 헤더가 살아 있는 것처럼 보이게 한다.

## 허용되는 분리 경계

- `PhotoRecordAlbum`: 조회 훅, 큰 화면 상태, mutation 조합, 화면 조립만 소유.
- 스토리 뷰: 날짜 그룹과 카드 배치 렌더링만 소유.
- 카드: 한 묶음의 표시·선택·열기 이벤트만 소유.
- 라이트박스: 사진 인덱스·키보드 닫기·선택적 비교 오버레이를 한 구현으로 소유.
- 편집기: 단일 기존 사진의 draft/삭제 확인 UI만 소유.
- presentation helper: 날짜 그룹화, 키, 문구, 카드 배치처럼 API/React 상태가 없는 순수 함수만 소유.

- `npm run typecheck`, `npm run build`, `git diff --check` 결과를 확인한다.

## 1차 구현 검토 (2026-09-12)

### 통과

- `photoRecordAlbumPresentation`, `PhotoRecordStoryTimeline`, `PhotoRecordBundleCard`로 순수 표시 규칙·타임라인 조립·카드 표현이 분리됐다. 상위 화면은 기존 조회 훅, mutation, URL 상태, 선택 삭제를 유지한다.
- 새 모듈은 상위 앨범을 import하지 않아 순환 import가 없고, API endpoint·DTO·쿼리 키도 변경하지 않는다.
- `npm run typecheck`, `npm run build`, `git diff --check`를 통과했다. Vite의 794.60kB 청크 권고는 기존 비차단 항목이다.

### 차단 해소: 중복·죽은 경로

- 새 `PhotoRecordBundleCard`와 겹치던 기존 inline 카드·표식, 사용처 없는 구 `AlbumHeader`·`PhotoUploadPanel`를 제거했다.
- 두 라이트박스는 하나의 `PhotoBundleLightbox`로 합쳤다. 비교가 연결된 현재 사진에만 `PhotoComparisonOverlay`를 조건부로 보여 주므로, 일반 사진·비교 사진의 닫기/키보드/이전·다음/썸네일 동작은 같은 구현을 사용한다.
- 컴포넌트 디렉터리에서 상위 `PhotoRecordAlbum`을 다시 import하는 하위 모듈이 없음을 확인해 순환 import가 없다.

### 차단 해소: 현재 계약 문서 불일치

- `_workspace/contracts/M8.1-photo-record-bundles.md`, `M8.1-manual-taken-at-multipart.md`, `M8.1-unified-photo-add-panel.md`, `_workspace/api-shapes/M8.1-photo-record-bundles.md`의 주 계약 bullet을 모두 1~3장·파일당 10MB·전체 32MB로 직접 갱신했다.
- 남은 1~20 언급은 현재 의미가 아닌 초기 계획이라는 명시적 역사 주석뿐이다. 현재 프런트 선택 제한, 서버 서비스 한도, Spring multipart 설정과 교차 일치한다.
