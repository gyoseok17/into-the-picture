# M10 혼잡도 연관 사진 가로 스트립 QA

## 조사 범위

- `frontend/src/features/crowd/pages/CrowdPage.tsx`
- `frontend/src/features/photo-search/components/PhotoAlbums.tsx`
- 관련 조회 훅·캐시 키

## 현재 구조

- 혼잡도 예측값이 있으면 수상작은 `RelatedContests`의 2~3열 그리드, 키워드 결과는 공용 `PhotoAlbumGrid`의 1~3열 그리드로 렌더링된다.
- 둘 모두 항목 수에 비례해 세로 길이가 늘어난다.
- 수상작 카드는 상세 라우트 링크이고, 키워드 앨범 카드는 버튼이며 선택하면 앨범 상세 다이얼로그가 열린다.
- 두 조회는 관광지명이 정해진 뒤에만 실행되고, 각 로딩·빈 상태는 이미 독립적으로 처리한다.

## 변경 검토

- 수상작과 키워드 결과를 각각 `overflow-x-auto`, `shrink-0`, 일정 폭의 작은 카드로 바꾸면 세로 점유를 고정하고 넘치는 항목은 가로 스크롤로 볼 수 있다.
- 스크롤바는 기존 `.no-scrollbar` 유틸리티를 적용해 숨기되, 터치·휠·키보드 포커스로 스크롤 가능한 `overflow-x-auto` 자체는 유지해야 한다.
- 스크롤 위치가 명확하도록 `snap-x snap-mandatory`와 카드 `snap-start`를 권장한다. 첫 카드가 잘리지 않도록 좌우 여백을 컨테이너와 맞춘다.
- 키워드 결과에 공용 `PhotoAlbumGrid`의 기존 그리드 클래스를 직접 덮어쓰면 검색 화면 레이아웃까지 영향을 줄 위험이 있다. 혼잡도 전용의 얇은 앨범 스트립 컴포넌트를 두거나, 공용 컴포넌트에 명시적 `variant="strip"` 계약을 추가해 기본 그리드 동작을 보존해야 한다.
- 앨범 카드는 기존과 동일하게 `button`으로 유지해 다이얼로그 진입을 보장하고, 수상작은 `Link`를 유지한다. 작은 카드에서도 이미지 `alt`, 제목·장소의 `line-clamp`, 키보드 포커스 테두리를 유지해야 한다.

## 회귀 및 확인 항목

1. 수상작 또는 키워드 결과가 0건일 때 현재 빈 상태 문구·영역이 그대로 나온다.
2. 로딩·실패 상태가 가로 컨테이너 내부에 갇히거나 카드 폭으로 찌그러지지 않는다.
3. 모바일과 좁은 PC 폭에서 카드가 줄어들지 않고 가로로 넘기며, 세로 페이지 길이가 결과 수에 따라 크게 늘지 않는다.
4. 키보드 Tab으로 모든 카드에 도달하고, 선택한 앨범은 기존 상세 다이얼로그를 연다.
5. 수상작 카드 선택은 기존 상세 라우트로 이동한다.
6. 관광지 변경 시 기존 쿼리 키의 새 결과만 보이며, 이전 관광지 결과가 잠시 남아 섞이지 않는지 확인한다.

## QA 판정

- API·데이터 계약 변경 없이 프런트 표시 레이아웃만 바꾸는 작업이다.
- 차단 이슈 없음. 공용 `PhotoAlbumGrid` 기본 레이아웃을 암묵적으로 바꾸지 않는 방식이면 검색 화면 회귀 위험도 낮다.
