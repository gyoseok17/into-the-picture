# M8 에디토리얼 홈 QA 검토

- 검토일: 2026-08-14
- 범위: 홈(`/`)의 비정형 에디토리얼 구조 전환과 기존 탐색 기능 진입점
- 검토 방식: 라우터, 홈 컴포넌트, 공통 내비게이션, 검색·혼잡도·수상작 기능의 소비자 경로를 정적 교차 검토했다. 이 문서는 코드 변경 없이 QA 기준만 기록한다.

## 현재 연결 계약 확인

| 홈의 행동 | 현재 목적지 | 확인 결과 | 유지 조건 |
| --- | --- | --- | --- |
| 키워드 입력 후 찾기 | `/explore?keyword=<encodeURIComponent 값>` | 정상. `ExplorePage`가 `keyword` 쿼리를 초기 검색어로 읽고 같은 URL을 갱신한다. | 빈 검색어는 `/explore` 전체 사진 탐색으로 이동해야 한다. |
| 대표·추천 수상작 선택 | `/contests/:id` | 정상. 라우터와 수상작 상세 경로가 일치한다. | 카드 전체가 하나의 명확한 링크여야 하며, 카드 안에 중첩 링크·버튼을 두지 않는다. |
| 수상작 더 보기 | `/contests` | 정상. 수상작 목록으로 연결된다. | 홈에서 보여준 일부 항목과 목록의 정렬 기준이 달라도 ‘추천’임을 표현한다. |
| 혼잡도 진입 | `/crowd` | 정상. 지역·시군구·관광지 선택 기반 혼잡도 화면으로 연결된다. | 홈에서 선택값이 없는 단순 진입임을 분명히 하고, 혼잡도를 즉시 특정 장소 정보처럼 보이게 하지 않는다. |
| 관광 사진 탐색 진입 | `/explore` | 정상. 기존 키워드 사진 검색·앨범 목록으로 연결된다. | 검색창과 링크가 같은 화면으로 향한다는 것을 사용자가 알 수 있어야 한다. |
| 내 사진/사진 놓기 | 로그인 보호 경로 `/me`, `/compare` | 홈에 새 진입점을 추가할 때는 비로그인 상태에서 로그인 안내 또는 로그인 후 원래 목적지 복귀가 필요하다. | 인증 상태에 따라 숨김과 안내 중 한 방식을 일관되게 선택한다. |

## 에디토리얼 홈 구현 체크리스트

### 정보 구조와 흐름

- [ ] 첫 화면은 사진, 짧은 메시지, 다음 행동 하나로 제한한다. 검색·수상작·혼잡도·개인 사진을 같은 우선순위의 카드 묶음으로 나열하지 않는다.
- [ ] 스크롤 흐름은 `장면 감상 → 추천 여행지 → 탐색 또는 혼잡도 행동`처럼 한 방향으로 읽힌다.
- [ ] 추천 여행지는 현재 `useContests({})`의 첫 페이지 4건임을 전제로 한다. 고정 순서·인기 순서라는 인상을 주는 문구는 API 정렬 계약을 확인하기 전에는 사용하지 않는다.
- [ ] 대표 이미지 로딩 실패·목록 오류·빈 목록에서도 홈의 제목, 검색, 수상작 전체 보기 링크는 남아 있어야 한다. 현재 빈 이미지 대체 배경만 있으므로 오류 상태의 안내 또는 재시도 필요성은 구현 시 판단한다.
- [ ] 사진을 가로로 넘기는 스트립을 도입하면 스와이프가 유일한 조작 수단이 되면 안 된다. 데스크톱에는 버튼 또는 자연스러운 가로 스크롤, 모바일에는 스와이프와 현재 위치 단서를 제공한다.

### 접근성

- [ ] 모든 이미지에 작품 제목 기반의 대체 텍스트를 유지하고, 장식용 배경 이미지는 빈 대체 텍스트로 분리한다.
- [ ] 사진 위의 텍스트는 어떤 썸네일에서도 읽히는 대비를 보장한다. 단순 그라데이션만 믿지 말고 검은 오버레이·텍스트 그림자·안전 영역 중 하나를 적용한다.
- [ ] 검색 입력에는 보이는 라벨 또는 이미 존재하는 `aria-label`을 유지하고, 제출 버튼은 아이콘만으로 바꾸지 않는다.
- [ ] 가로 스트립, 칩, 화살표 제어는 키보드 탭·Enter/Space로 조작 가능하고 포커스 표시가 보여야 한다.
- [ ] 섹션 제목은 `h1` 다음의 논리적인 `h2` 순서를 유지한다. 영문 장식 문구는 읽기 순서를 방해하면 장식 처리한다.
- [ ] `prefers-reduced-motion` 사용자는 자동 이동, 긴 패럴랙스, 과도한 확대 전환을 보지 않아야 한다.

### 반응형과 시각 품질

- [ ] 360px 폭에서 제목이 의도치 않게 세 줄 이상으로 깨지지 않고, 검색 입력과 제출 행동이 서로 겹치지 않는다.
- [ ] 768px 전후에서 데스크톱 상단 내비게이션 전환과 홈의 2열 레이아웃 전환이 동시에 답답해지지 않는지 확인한다.
- [ ] 1280px 이상에서는 지나치게 넓은 빈 여백이 생기지 않으며, 사진·텍스트의 시선 흐름이 좌우 어느 한쪽에 몰리지 않는다.
- [ ] 홈 하단은 모바일 탭 바에 가려지지 않고, 가로 스크롤 영역은 페이지 전체의 수평 스크롤을 만들지 않는다.
- [ ] 파스텔 민트는 배경 용도로 제한하고 본문·링크·비활성 텍스트의 명도 대비를 별도로 확인한다. 색만 바꾼 동일 크기 카드 반복은 이번 구조 전환의 목표와 맞지 않는다.

### 기능 회귀와 성능

- [ ] 홈 검색은 공백만 입력했을 때 안전하게 전체 탐색으로 이동하고, 한글·공백·특수문자가 포함된 키워드도 URL에서 보존된다.
- [ ] 홈에서 수상작 상세로 들어갔다가 뒤로 돌아오면 홈의 스크롤 위치와 검색 입력 손실이 사용자 경험상 허용되는지 확인한다.
- [ ] 대표 작품과 추천 목록이 같은 `useContests({})` 데이터를 공유하므로 중복 호출·로딩 깜빡임이 없는지 React Query 개발 도구 또는 네트워크 탭에서 확인한다.
- [ ] 이미지가 큰 가로 스트립은 초기에는 화면 근처 항목만 로드하고, 이미지의 고정 비율 상자를 유지해 레이아웃 이동(CLS)을 줄인다.
- [ ] 링크 목적지는 모두 현재 라우터에 존재한다. 새 홈 행동을 만들면서 로그인 보호 경로를 직접 노출할 경우 `returnTo` 로그인 복귀를 실제로 확인한다.

## 통합 판정

- 현재 홈의 검색·수상작·혼잡도·사진 탐색 링크 계약에는 차단 이슈가 없다.
- 비정형 에디토리얼 전환은 API·데이터 계약을 바꾸지 않는 프런트엔드 작업으로 진행 가능하다.
- 커밋 전 차단 게이트: 모바일 360px, 태블릿 768px, 데스크톱 1280px 확인; 키보드로 검색·수상작·혼잡도 링크 도달 확인; 빈/오류 수상작 데이터에서 홈 행동 유지 확인; `npm run build` 통과.
- 권고: 개인 사진 섹션은 사진첩 API가 준비되는 다음 M8 단계에서 인증 흐름과 함께 추가한다. 지금 홈에 임시 카드만 두면 사용 목적과 데이터 상태가 어긋날 위험이 있다.
