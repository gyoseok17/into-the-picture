# M8 결과 빠른 도구: 메뉴 전환 QA 기준

- 검토일: 2026-08-14
- 범위: 무한 스크롤 결과 화면의 고정 빠른 도구를 `메뉴 → 왼쪽 확장 명령 → 현재 위치의 검색/필터 패널` 흐름으로 변경하는 프런트엔드 UI
- 코드 변경: 없음 (QA 사전·통합 검토)

## 확인한 현재 구조

- `ScrollAssist`가 검색과 수상작 목록에서 공통으로 사용된다.
- 480px 이상 내려가면 도구가 노출되고, 모바일에서는 하단 탭과 안전 영역 위에, 데스크톱에서는 화면 오른쪽 아래에 위치한다.
- 현재는 검색/필터 아이콘과 위로 가기 아이콘이 각각 곧바로 보이며, 검색·필터 아이콘을 누르면 현재 위치에 입력 패널이 열린다.
- 패널은 Escape·바깥 포인터 입력으로 닫히고, 닫을 때 기존 트리거로 포커스를 돌린다. 위로 가기는 `prefers-reduced-motion`을 따라 즉시 또는 부드럽게 이동한다.

## 전환 상태 계약

| 상태 | 표시 | 허용 동작 | 닫힘·이동 규칙 |
| --- | --- | --- | --- |
| `closed` | 메뉴 아이콘만 | 메뉴 열기 | 480px 이하로 올라가면 유지하지 않음 |
| `menu-open` | 메뉴 아이콘의 **왼쪽**에 `위로 가기`, 현재 화면의 `재검색` 또는 `필터 변경` 명령 | 위로 가기, 검색/필터 패널 열기, 메뉴 닫기 | Escape·바깥 클릭·메뉴 재클릭 시 닫고 메뉴 아이콘에 포커스 |
| `panel-open` | 현재 위치의 검색 또는 필터 입력 패널. 명령 목록은 숨김 | 적용, 초기화(필터), 닫기 | Escape·바깥 클릭·적용 후 닫음. 결과 적용 뒤에도 스크롤 위치를 강제로 맨 위로 옮기지 않음 |

- `위로 가기`를 선택하면 메뉴를 닫은 뒤 기존 reduced-motion 규칙으로 이동한다.
- 검색/필터 명령을 선택하면 메뉴 목록은 즉시 닫고 패널만 하나 열어야 한다. 메뉴와 패널이 동시에 남거나 두 패널이 동시에 열리면 안 된다.
- 화면별 명령은 검색 결과에서는 `재검색`, 수상작에서는 `필터 변경`으로 구분한다. 실제 버튼 텍스트는 보여도 되고 아이콘만 사용해도 되지만 접근 가능한 이름은 반드시 각각의 행동을 말해야 한다.
- 목록이 다시 480px 이하가 되거나 라우트가 바뀌면 열린 메뉴·패널을 닫는다. 포커스가 사라진 DOM에 남지 않아야 한다.

## 접근성·키보드 기준

- 메뉴 아이콘은 실제 `button`이며 `aria-label="결과 빠른 도구 열기"`, `aria-expanded`, `aria-controls`를 제공한다.
- 확장 영역을 `role="menu"`로 구현한다면 각 명령은 `role="menuitem"`이고, Enter/Space 실행, Escape 닫기, 위/아래 화살표 이동을 지원한다. 이 동작을 구현하지 않을 경우 `role="menu"`를 쓰지 않고 일반 `role="group"`과 일반 버튼으로 구현한다.
- 메뉴를 열면 첫 명령으로 포커스를 이동한다. Escape 또는 바깥 클릭으로 닫으면 메뉴 아이콘으로 포커스를 복귀한다.
- 검색/필터 패널은 첫 입력 요소에 포커스를 준다. 이 패널은 배경을 잠그지 않는 작은 도구이므로 포커스 트랩 없이 `aria-modal="true"`를 선언하면 안 된다. 모달로 선언하려면 포커스 트랩과 배경 비활성화를 함께 구현해야 한다.
- 패널을 닫거나 적용하면 메뉴 아이콘으로 포커스를 복귀한다. 적용 버튼·초기화 버튼은 아이콘만 쓰더라도 `aria-label`을 가진다.
- 바깥 클릭 감지는 메뉴 아이콘, 확장 메뉴, 패널 각각의 내부 클릭을 닫힘으로 오인하지 않아야 한다. 터치의 첫 탭으로 명령이 실행되고 즉시 다시 닫히는 회귀가 없어야 한다.

## 반응형·표시 기준

- 확장 명령은 고정 도구의 **왼쪽**으로만 펼쳐지며, 모바일 360px 너비에서도 오른쪽 화면 밖으로 잘리지 않아야 한다.
- 검색/필터 패널의 너비는 뷰포트 여백을 남기고, 낮은 높이에서는 최대 높이와 내부 세로 스크롤을 가져야 한다.
- 모바일: 도구·확장 메뉴·패널의 가장 아래가 하단 탭과 `env(safe-area-inset-bottom)` 위에 있어야 한다. 하단 탭의 터치 영역을 가리면 안 된다.
- 데스크톱: 기존 오른쪽 하단 여백을 유지하고 본문·브라우저 스크롤바를 가리지 않으며, 좁은 데스크톱에서도 왼쪽 확장 영역이 화면 밖으로 나가지 않아야 한다.
- 360px, 768px, 1280px에서 메뉴 닫힘/열림/패널 열림을 각각 확인한다.

## 모션·회귀 기준

- 메뉴·패널의 열림/닫힘 전환에 애니메이션을 넣으면 `prefers-reduced-motion: reduce`에서 즉시 표시·숨김으로 처리한다.
- 위로 가기 동작은 기존처럼 reduced-motion이면 `auto`, 그 외에는 `smooth`여야 한다.
- 검색 적용은 기존 URL 쿼리와 결과 갱신 경로를, 필터 적용은 기존 `ContestQuery`와 목록 갱신 경로를 그대로 사용한다.
- 무한 스크롤 감시, 모바일 사진 열 수 설정, 결과 데이터와 현재 필터/검색어는 이번 메뉴 전환으로 초기화되지 않아야 한다.

## 사전 판정 및 구현 후 차단 확인

- 현재 구현의 별도 아이콘 구조는 사용자 요구의 단일 메뉴 구조와 다르므로 교체가 필요하다.
- 현재 패널은 포커스 트랩 없이 `aria-modal="true"`를 사용한다. 새 구현에서는 위 접근성 기준 중 하나를 선택해 이 불일치를 해소해야 한다.
- 차단 조건: 메뉴와 패널의 동시 표시, Escape/바깥 클릭 뒤 포커스 유실, 모바일 하단 탭과의 겹침, reduced-motion 무시, 적용 뒤 강제 상단 이동.
- 권고: 메뉴 명령은 아이콘만으로 의미를 전달하지 말고 최소한 시각 텍스트 또는 툴팁을 제공한다. 모바일에서 특히 `위로 가기`와 검색/필터가 혼동되지 않는지 실제 화면으로 확인한다.
