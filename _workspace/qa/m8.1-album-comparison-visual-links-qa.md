# M8.1 앨범 비교 연결 시각 표현 QA

작성일: 2026-09-04
상태: 구현 전 계약 검토 완료 · 최종 검증 대기

## 표시 계약

- 묶음 카드의 트로피와 숫자는 **묶음 안에서 비교에 연결된 개별 사진 수**를 나타낸다. 한 사진이 여러 비교에 연결돼도 사진 수를 중복 집계하지 않는다.
- 카드의 대표 이미지 자체가 연결됐는지와 묶음 전체 연결 수는 구분한다. 대표 사진 상태 아이콘은 대표 `PhotoRecord` 기준이고, 묶음 요약은 연결 사진 수를 기준으로 한다.
- 라이트박스 썸네일의 트로피는 각 썸네일 사진의 연결 여부만 표시한다. 현재 사진이 바뀌면 수상작 미니 폴라로이드 버튼도 해당 사진의 비교만 표시한다.
- 미니 폴라로이드는 연결된 비교의 내 사진/수상작 맥락과 결과 보기 동작을 제공하며 `/compare?contestId=<id>`로 기존 결과를 연다.
- 일반 사진, 연결이 없는 썸네일, 일반 묶음에는 트로피·숫자·미니 폴라로이드·빈 공간이 남지 않는다.

## 최종 체크리스트

- [ ] 묶음 사진 0/1/2장 연결, 한 사진의 복수 연결에 대해 트로피 및 연결 사진 수가 정확하다.
- [ ] 썸네일 각각에 연결 상태가 정확히 표시되고, 이전/다음·썸네일 선택으로 버튼/오버레이가 즉시 갱신된다.
- [ ] 현재 연결 사진의 미니 폴라로이드 버튼은 결과를 열며, 일반 사진으로 전환하면 사라진다.
- [ ] 모바일에서 닫기·사진 전환·썸네일·미니 폴라로이드/이미지 오버레이가 서로 겹치지 않고 safe area 안에서 조작 가능하다.
- [ ] 기존 비교 결과의 사진 교체, 결과만 삭제, 사진까지 삭제 뒤 카드·라이트박스·지도 캐시/링크가 갱신된다.
- [ ] 지도 비교 배지/결과 링크와 비로그인 보호 흐름은 변경되지 않는다.
- [ ] `tsc -b`, `git diff --check`를 수행한다.

## 차단 기준

- 묶음의 연결 사진 수가 비교 레코드 수로 잘못 계산되거나 대표 사진 상태와 혼동된다.
- 일반 사진에 연결 표현이 남거나, 전환 후 이전 사진의 수상작 버튼이 남는다.
- 미니 폴라로이드가 잘못된 수상작/결과로 이동하거나 삭제 뒤 stale 링크가 남는다.
## 구현 도착 검증 (2026-09-04)

### 통과

- 묶음 연결 수는 각 `PhotoRecord`에 비교가 하나 이상 있는지로 계산하므로, 한 사진이 여러 비교에 연결돼도 사진 수를 중복 집계하지 않는다.
- 라이트박스 썸네일은 각 `item.id`의 연결 여부만 트로피로 표시한다. 현재 사진의 오버레이/미니 폴라로이드는 `photo.id`의 비교만 사용하며 `/compare?contestId=<id>`로 결과를 연다.
- 비교 없는 묶음·사진·썸네일에서는 marker/overlay가 `null`이라 빈 UI가 남지 않는다. 사진 전환·닫기·썸네일 구조도 기존 흐름을 유지한다.
- `tsc -b` 통과, `git diff --check` 공백 오류 없음(LF/CRLF 경고만 출력).

### 차단 이슈: 사진까지 삭제 후 앨범 캐시 미갱신

- 서버의 `PhotoComparisonService.delete(..., deletePhoto=true)`는 실제 `PhotoRecord`를 삭제한다.
- 하지만 프런트 `useDeleteComparison`은 comparisons와 user-photos만 invalidate한다. 앨범이 소비하는 photo-records, photo-record-bundles, photo-record-map, photo-record-bundle-map 캐시는 그대로다.
- 따라서 앨범을 열어 둔 채 “사진까지 삭제”하면 삭제한 사진/묶음·마커가 stale하게 남는다.
- 수정 기준: 비교 삭제 mutation 성공 시 위 네 photo-record query key도 함께 invalidate한다. 결과만 삭제는 comparisons 갱신으로 연결 표시가 사라지는지 다시 확인한다.

## 삭제 캐시 보완 재검증 (2026-09-04)

- `useDeleteComparison` 성공 시 comparisons·user-photos와 함께 photo-records, photo-record-bundles, photo-record-map, photo-record-bundle-map을 모두 invalidate한다. 사진까지 삭제했을 때 앨범·스토리·지도 캐시가 함께 갱신된다.
- 묶음 트로피 수는 연결된 개별 사진만 filter해 집계하므로 중복 비교 레코드가 있어도 사진 수는 정확하다. 썸네일 marker와 현재 사진 미니 폴라로이드도 각 photo ID 기준이다.
- 일반 사진에서는 모든 marker/overlay가 `null`이며, 결과 링크는 현재 사진의 comparison contestId를 사용한다.
- `tsc -b` 통과, `git diff --check` 공백 오류 없음(LF/CRLF 경고만 출력).
