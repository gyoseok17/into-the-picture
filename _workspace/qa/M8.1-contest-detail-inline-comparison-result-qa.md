# M8.1 수상작 상세 내부 비교 결과 보기 QA

## 검토 범위

- 수상작 상세의 저장된 비교 결과 진입이 `/compare?contestId=...` 이동 대신 현재 상세 위 결과 창을 여는지 검토했다.
- 로그인 사용자 비교 기록, 공개 비교 사진 모음, 비교 기록 없음의 기존 흐름과 중첩 오버레이의 Escape·초점·레이어를 교차 확인했다.

## 계약 대조

- `ContestDetailPage`는 현재 수상작 ID에 해당하는 로그인 사용자의 비교만 `contestComparisons`로 모아 `PhotoComparisonResultDialog`에 전달한다.
- 상세 이미지의 저장 비교 진입은 `ContestComparisonEntry`에 `onOpen`을 전달해 링크가 아닌 버튼으로 렌더링된다. 따라서 URL·상세 상태·목록 복귀 상태를 바꾸지 않는다.
- 공용 `ContestComparisonEntry`는 `onOpen`이 없는 마이 화면에서는 기존 `/compare` 링크 동작을 유지한다.
- 저장 비교가 없는 경우의 `사진 놓기`는 새 비교 생성 흐름이므로 기존 앨범 진입을 유지한다.
- 공개 사진 버튼은 기존 `PublicComparisonDialog`를 유지하며, 저장 비교 결과 창과 별도 상태로 열린다.

## 오버레이·접근성 검토

- 결과 창은 포털 `z-[100]`, 목록에서 연 상세 오버레이는 `z-30`, 공개 사진 창은 `z-50`이므로 결과 창이 상세보다 위에 표시된다.
- 상세 오버레이는 저장 비교 또는 공개 사진 창이 열린 동안 Escape·Tab 트랩을 중단한다. 결과 창 Escape는 캡처 단계에서 소비돼 상세 또는 목록으로 전파되지 않는다.
- Escape·배경 클릭·닫기 버튼이 모두 공통 `close` 경로를 사용하며, 닫은 뒤 열기 버튼으로 초점을 되돌린다.
- 직접 상세 URL과 목록 위 상세 오버레이 모두에서 URL을 변경하지 않으므로 닫은 뒤 같은 상세 내용과 스크롤 문맥이 유지된다.

## 발견과 해결

1. 최초 구현의 `triggerRef` 타입이 버튼 `ref` 타입과 달라 TypeScript 빌드가 실패했다. `Ref<HTMLButtonElement>`로 정정한 뒤 타입 검사를 통과했다.
2. 최초 `PhotoComparisonResultDialog`의 Escape 처리만 `onClose`를 직접 호출해 초점 복귀가 빠졌다. Escape도 공통 `close`를 호출하도록 수정해 계약을 충족했다.

## 검증

- `npm run typecheck` 통과.
- `npm run build`는 프런트 역할에서 통과했고, QA 재실행에서도 타입 검사를 통과했다. 기존 Vite 청크 크기 경고 외 신규 오류 없음.
- `git diff --check` 통과. 기존 CRLF 변환 경고만 표시됨.

## 판정

통과. API·DB·인증·공개 비교 조회 계약 변경 없이 상세 내부 결과 보기로 전환됐으며, 기존 링크 동작이 필요한 마이 화면과 새 비교 시작 경로는 유지된다. 실제 브라우저에서는 목록에서 연 상세와 직접 URL 상세 각각에서 결과 창을 연 뒤 Escape·배경·닫기 버튼으로 닫아 상세 위치가 남는지 한 차례 확인하면 된다.
