# M8.1 다중 사진 추가: 직접 촬영일 QA 체크

## 확인 대상 계약

- 다중 업로드의 공통 `촬영일`을 사용자가 직접 입력하면, 선택한 모든 파일은 EXIF 유무와 관계없이 그 입력값을 `takenAt`으로 전송한다.
- 공통 `촬영일`을 비우면, 각 파일이 읽어 둔 EXIF 촬영일을 **파일별로** 전송한다. EXIF가 없는 파일은 `takenAt` 필드를 보내지 않아 서버의 재추출 또는 `null` 처리를 따른다.
- 전송 형식은 `multipart/form-data`의 선택 필드 `takenAt`이며, 값은 Spring `ISO.DATE_TIME`으로 파싱 가능한 로컬 일시(예: `2026-08-28T14:30`)여야 한다.
- 업로드 완료 뒤 반환되는 `PhotoRecord.takenAt`과 앨범·지도·수정 화면에 표시되는 촬영일은 같은 값이어야 한다.

## 필수 수동 QA

1. EXIF 촬영일이 서로 다른 JPEG/PNG/WebP 두 장 이상을 선택한다. 공통 촬영일을 비운 채 업로드한 뒤 각 사진이 원본별 EXIF 날짜로 저장·표시되는지 확인한다.
2. 위와 같은 여러 파일에 공통 촬영일을 직접 지정해 업로드한다. 모든 항목이 동일한 직접 지정값으로 저장되고, 목록에 보인 EXIF 날짜가 남아 있더라도 서버 결과를 덮어쓰지 않는지 확인한다.
3. 공통 촬영일을 입력했다가 비운 뒤 업로드한다. 이전 직접 입력값이 FormData 또는 React 상태에 남지 않고 파일별 EXIF 날짜로 다시 저장되는지 확인한다.
4. EXIF가 없는 JPEG와 HEIC/HEIF를 함께 선택한다. 공통 촬영일이 비어 있으면 촬영일이 없는 상태로 저장될 수 있고, 직접 입력하면 두 파일 모두 그 값으로 저장되는지 확인한다.
5. 촬영일 입력에 일시까지 포함해 저장하고, 스토리 정렬 및 지도 상세에 날짜가 올바른 로컬 날짜로 보이는지 확인한다. 시간대 변환으로 전날·다음 날로 바뀌지 않아야 한다.
6. 업로드 완료 후 해당 사진의 `수정`에서 촬영일을 다른 값으로 바꾸고 저장한다. `PATCH /me/photos/{id}`의 `takenAt`과 목록·지도 표시가 새 값으로 갱신되는지 확인한다.
7. 수정 화면에서 촬영일을 비우고 저장한다. JSON의 `takenAt: null`이 서버에 전달되어 기존 날짜가 실제로 지워지는지 확인한다.
8. 업로드 대상 중 하나가 실패하도록 만든 뒤 재시도한다. 재시도 요청도 최초와 동일한 직접 입력 촬영일(또는 해당 파일 EXIF)을 사용하며, 이미 성공한 항목은 중복 전송되지 않는지 확인한다.
9. 업로드 진행 중 시트를 닫거나 배경을 눌렀을 때 전송이 취소·중복되지 않는지, 완료 후 지도 확대·권역·시군 선택이 유지되는지 확인한다.

## 네트워크/API 대조

- 브라우저 개발자 도구 Network에서 `POST /api/v1/me/photos`의 Request Payload/Form Data를 파일별로 확인한다.
  - 직접 지정: 모든 요청에 같은 `takenAt=YYYY-MM-DDTHH:mm` 존재.
  - 직접 입력 없음 + EXIF 있음: 각 요청의 `takenAt`이 각 파일의 EXIF와 일치.
  - EXIF 없음: `takenAt` 필드 자체가 없음(빈 문자열 전송 금지).
- 응답 JSON의 `takenAt`은 요청 값과 일치하며, 예외적으로 비어 있는 경우에만 서버 EXIF 재추출 결과 또는 `null`이다.
- 인증되지 않은 요청은 기존과 같이 401이고, 다른 사용자의 사진 `PATCH`·`DELETE`·파일 조회는 접근할 수 없어야 한다.

## 구현 전 코드 기준 발견 사항

- 현재 `BatchPhotoUploadPanel`은 `UploadItem.takenAt`에 파일별 EXIF만 보관하고 `uploadPhotoRecord`에도 그 값을 그대로 전달한다. 공통 직접 촬영일 입력과 “직접값 우선” 선택 규칙은 아직 이 컴포넌트에 없다.
- 서버 `UserPhotoService.upload`는 요청 `takenAt`이 `null`이 아닐 때만 EXIF 추출보다 우선하므로, 프런트는 직접 입력값을 각 업로드 요청에 명시적으로 넣어야 한다.
- `appendOptionalField`는 빈 문자열을 생략한다. 따라서 공통 입력을 비웠을 때 파일별 EXIF로 되돌리는 판단은 FormData 생성 직전이 아니라 업로드 항목별 값 선택 규칙으로 명확히 구현해야 한다.

## QA 판정 기준

- 차단: 직접 입력값이 EXIF로 덮임, 파일별 EXIF가 동일 값으로 덮임, 빈 날짜가 이전 입력값으로 재전송됨, 재시도가 성공 항목을 중복 업로드함.
- 권고: 업로드 대기 목록에 `직접 지정`과 `사진 정보` 출처를 함께 표시해 사용자가 실제 저장 예정값을 알 수 있게 한다.
