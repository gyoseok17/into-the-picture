# M8.1 지도 사진 추가 시트 QA

작성일: 2026-08-28
역할: 통합 QA (코드 수정 없음)

## 변경 전제

- 지도 화면에서 `사진 추가`를 누르면 기존 인라인 `BatchPhotoUploadPanel` 대신 현재 지도 위에 업로드 시트가 열린다.
- 업로드 시트의 닫기·완료는 지도 화면의 스크롤 위치, 선택 권역·시군 필터, 마커 포커스와 확대 상태를 바꾸지 않는다.
- 기존 업로드 계약은 유지한다. 파일은 최대 20장, 동시 업로드는 최대 3장이고, 완료 뒤 `photo-records`, `photo-record-map`, `user-photos`, `comparisons` 쿼리를 갱신한다.

## 차단 기준

1. 시트 열기/닫기 또는 업로드 완료로 지도 선택·확대·스크롤 상태가 초기화된다.
2. 업로드 중 닫기·재열기·재클릭으로 같은 파일이 중복 업로드되거나 진행 중 요청을 추적할 수 없다.
3. 모바일에서 파일 선택창·갤러리를 열 수 없거나, 시트의 완료/닫기 조작이 하단 내비게이션 또는 키보드에 가려진다.
4. 실패한 업로드의 원인·재시도 대상·성공한 항목을 구분할 수 없다.

## 우선 회귀 위험과 확인 기준

| 영역 | 위험 | 확인 기준 |

## 수동 QA 체크리스트

### 1. 지도 상태와 시트 생명주기

- [ ] 전체 지도에서 권역을 선택하고 시군까지 선택한 뒤 시트를 열어도 필터된 마커·선택 색상이 그대로다.
- [ ] 마커를 눌러 확대 및 사진 카드가 열린 상태에서 시트를 열고 닫아도 같은 마커·사진·확대 시점으로 돌아온다.
- [ ] 지도 빈 공간 클릭 또는 선택 권역 재클릭으로 전체 보기로 복귀하는 기존 동작이 시트 사용 뒤에도 같다.
- [ ] 시트를 닫아도 페이지가 맨 위로 이동하지 않고, 지도 및 상단 조작줄의 스크롤 위치가 보존된다.
- [ ] 업로드 성공 뒤 시트가 닫히더라도 현재 권역·시군 필터에 맞는 새 사진만 마커/목록에 갱신된다. 현재 필터 밖이면 성공은 안내하되 시점은 바꾸지 않는다.
- [ ] 업로드 실패, 파일 선택 취소, 파일 0장 상태에서 닫기를 각각 확인해 지도 상태가 보존되는지 확인한다.

### 2. 데스크톱 시트

- [ ] 1280px 이상에서 시트가 지도 오른쪽 패널로 열리고, 지도 중요한 영역·상단 메뉴·사진 카드 닫기 버튼을 가리지 않는다.
- [ ] 패널의 내부 콘텐츠가 길어져도 창 전체가 스크롤되지 않고 패널 내부만 스크롤된다.
- [ ] 패널 바깥 지도 클릭은 의도한 닫기 동작일 때만 시트를 닫으며, 닫히기 전 마커 선택이나 권역 필터가 바뀌지 않는다.
- [ ] 닫기, 사진 고르기, 지역 선택, 업로드 버튼의 클릭 영역이 겹치지 않는다.

### 3. 모바일 시트와 키보드

- [ ] 360×800과 390×844 세로 화면에서 시트가 하단에서 열리고, 하단 내비게이션 위에 충분한 여백을 둔다.
- [ ] 시트가 열린 뒤 배경 지도는 스크롤·핀치·마커 클릭이 되지 않는다.
- [ ] 장소/메모/시군 검색에 키보드를 열어도 입력 필드와 `추가하기`/`업로드`/닫기 조작을 내부 스크롤로 도달할 수 있다.
- [ ] 키보드를 닫아도 시트 높이와 이전 입력값·선택 파일·선택 시군이 유지된다.
- [ ] 가로 회전 뒤 지도와 시트의 높이 계산이 깨지지 않고, 닫기와 업로드 조작이 화면 안에 있다.

### 4. 파일 선택·대기열·EXIF

- [ ] 사진 고르기를 누르면 데스크톱 파일 선택창, 모바일 갤러리/파일 선택기가 열린다.
- [ ] 선택을 취소해도 시트가 닫히거나 기존 대기열이 사라지지 않는다.
- [ ] JPEG, PNG, WebP, HEIC, HEIF 각각에서 선택·미리보기/촬영일 안내·업로드 가능 여부가 의도대로 보인다.
- [ ] 1장, 3장, 20장 업로드를 확인하고 21장 이상은 최대 20장 안내 및 처리 대상이 명확한지 확인한다.
- [ ] EXIF 읽기 중 다른 파일을 다시 고르거나 시트를 닫아도 이전 비동기 결과가 새 파일의 날짜를 덮어쓰지 않는다.
- [ ] 사진별 날짜는 유지되고, 공통 장소·메모·시군이 모든 대기열 요청에 같은 값으로 전달된다.

### 5. 중복 요청·실패·완료

- [ ] 업로드 버튼을 빠르게 여러 번 눌러도 파일별 `POST /api/v1/me/photo-records` 요청은 한 번만 생긴다.
- [ ] 업로드 중 사진 고르기와 업로드 재실행이 비활성화되거나, 허용한다면 기존 대기열과 절대 섞이지 않는다는 안내가 있다.
- [ ] 업로드 중 닫기 버튼의 정책(차단/확인/백그라운드 진행)을 실제 동작과 문구가 동일하게 보여준다.
- [ ] 네트워크 실패 시 성공 항목은 성공으로 유지되고 실패 항목만 오류 표시 및 재시도 대상이 된다.
- [ ] 재시도 뒤에는 실패 항목에만 새 요청이 생기며, 이미 성공한 사진은 다시 POST하지 않는다.
- [ ] 모든 항목 성공 뒤 `완료`를 누르면 시트가 닫히고, 마커·스토리·마이 화면에서 중복 없이 새 기록을 확인할 수 있다.

### 6. 키보드·스크린리더

- [ ] 시트 열 때 포커스가 시트 제목 또는 닫기 버튼으로 옮겨지고, Tab/Shift+Tab이 배경 지도와 상단 메뉴로 빠지지 않는다.
- [ ] Escape 또는 닫기 버튼이 시트를 닫고 닫기 전 `사진 추가` 버튼으로 포커스를 돌려준다.
- [ ] 시트에 접근 가능한 제목, 닫기 버튼의 이름, 업로드 진행/성공/실패 상태의 라이브 안내가 있다.
- [ ] 파일 입력은 보조기술에서 `사진 고르기`라는 조작으로 인식되고, disabled 상태와 최대 20장 제한 안내를 확인할 수 있다.

## 통합 판정 조건

- 위 차단 기준 4개가 모두 해소되고, 데스크톱·모바일 최소 1회씩 파일 선택과 성공·실패 흐름을 확인해야 통과다.
- 특히 지도 상태 보존과 중복 POST는 브라우저 Network 기록으로 확인한다.
- 시트 구현 도착 후 실제 결과를 이 문서 하단에 날짜·번호를 붙여 누적한다.
