# M8 모바일 홈 재구성 QA 기준

- 작성일: 2026-08-14
- 역할: 통합 QA
- 범위: 360px 우선 모바일 홈의 첫 화면·배경·읽기 흐름·수평 사진 필름·하단 탭 간섭 검토
- 코드 변경: 없음

## 현재 코드에서 확인한 문제

1. 홈 첫 섹션이 모바일에서 `min-h-[calc(100dvh-9rem)]`이고, 텍스트 블록과 사진 블록이 독립적으로 아래로 이어진다. 순서가 텍스트→사진으로 바뀌었더라도 한 화면 안에서 하나의 도입 장면으로 읽히기보다 두 개의 큰 블록이 세로로 쌓인 인상이 남는다.
2. 앱 전체 배경과 카드 배경이 거의 같은 매우 밝은 민트 계열이다. 여백의 층위가 보이지 않아 흰 화면처럼 느껴질 수 있다. 첫 섹션만의 배경 면·질감·경계가 부족하다.
3. 대표 사진은 모바일에서 `min-h-[42vh]`로만 결정되어 뷰포트 높이에 따라 비율이 크게 흔들린다. 사진의 주제와 문장이 함께 기억되는 고정된 장면을 만들기 어렵다.
4. 추천 필름은 184px 폭의 세로 사진과 높이 차이를 함께 써서 360px에서 첫 카드가 화면의 절반 이상을 차지한다. 다음 카드의 존재, 가로 스크롤 가능성, 현재 위치를 충분히 알리지 못한다.
5. `AppShell`의 본문 하단 패딩(96px)은 있으나, 홈 최하단의 실제 링크·터치 영역이 고정 하단 탭과 겹치지 않는지 360px 실기기에서 확인이 필요하다. 특히 iOS safe-area에서는 탭 높이가 커진다.

## 권장 모바일 구조

모바일은 데스크톱의 좌우 분할을 세로로 접는 것이 아니라, 아래의 한 장면 흐름으로 별도 구성한다.

1. **도입 장면 (첫 1뷰포트)**
   - 전체를 옅은 민트 배경 면으로 묶고, 배경은 본문 기본색보다 한 단계 진하게 둔다.
   - 상단에는 작은 서비스명·문장, 중간에는 제목, 하단에는 대표 사진을 둔다.
   - 사진은 전체 폭이 아니라 좌우 여백을 둔 카드형 또는 화면 가장자리를 넘는 한 장면으로 처리한다. 텍스트와 사진 사이에 별도의 흰 여백 구획을 만들지 않는다.
   - 사진 높이는 `clamp()` 또는 고정 aspect ratio로 제어해 360×640과 360×800에서 인상이 과도하게 달라지지 않게 한다. 권장 범위는 약 220~300px이다.
   - 대표 사진 위 제목 텍스트는 이미지와 겹치지 않으며, 이미지 위 장소 정보는 최소 대비 4.5:1을 유지한다.

2. **본문 리듬**
   - 전체 배경은 아주 연한 민트, 섹션 중 하나는 더 짙은 민트 면 또는 낮은 채도의 크림 면으로 교차한다. 모든 구간을 흰 카드로 분리하지 않는다.
   - 섹션 첫머리·사진 묶음·다음 행동 사이 간격을 24/40/64px 같은 소수의 단계로 통일한다.
   - 긴 문구는 2~3줄 이내로 제한하고, 작은 영문 눈썹 문구는 필수 정보가 아니므로 모바일에서 대비와 크기를 낮추거나 제거해도 된다.

3. **추천 여행지 사진 필름**
   - 첫 카드의 시작점과 두 번째 카드의 일부를 항상 보이게 해 옆으로 넘길 수 있음을 드러낸다.
   - 카드 폭은 360px에서 약 68~74vw(245~266px)로 두고, 가로 여백은 최소 16px을 지킨다.
   - 사진마다 높이를 다르게 하는 연출은 최대 12~16px 정도로 제한한다. 현재처럼 큰 상단 공백은 첫 화면 밀도를 해치므로 데스크톱 전용으로 두거나 모바일에서는 축소한다.
   - 모든 카드가 키보드 포커스를 받을 때 보이는 포커스 표시를 유지하고, 제목·장소·링크의 터치 영역은 최소 44×44px을 보장한다.
   - 수평 스크롤 영역은 손가락으로 넘길 때 세로 스크롤을 과하게 방해하지 않아야 하며, `scroll-snap` 뒤에도 마지막 카드가 충분히 노출돼야 한다.

4. **하단 탭과 안전 영역**
   - 360px·iOS safe-area 기준으로 마지막 본문 행동 요소와 탭 상단 사이에 최소 24px의 실제 여백이 남아야 한다.
   - 하단 탭은 5개 항목에서 라벨이 두 줄이 되거나 잘리지 않는지 확인한다. 길이가 긴 라벨은 글자 축소보다 짧은 명칭을 우선 검토한다.
   - 고정 탭이 링크, 수평 필름, 스크롤 종점의 터치 이벤트를 가리지 않는지 확인한다.

## 수용 기준 및 확인 시나리오

| 기준 | 360px 확인 방법 | 통과 조건 |
| --- | --- | --- |
| 첫 화면 흐름 | 360×640, 360×800에서 첫 진입 | 제목·도입문·대표 사진이 같은 도입 장면으로 연결되고, 사진만 먼저 튀어나오거나 큰 빈 공간이 생기지 않음 |
| 배경 층위 | 홈을 처음부터 두 섹션까지 스크롤 | 기본 배경, 도입 면, 강조 섹션의 구분이 보이되 과한 카드·테두리 반복이 없음 |
| 가독성 | 밝은 사진·어두운 사진 각 1개로 확인 | 이미지 위 장소·제목 및 일반 본문이 읽히며, 색만으로 의미를 구분하지 않음 |
| 대표 사진 | 짧고 긴 화면에서 확인 | 왜곡 없이 표시되고 220~300px 수준의 일관된 시각적 비중을 유지함 |
| 사진 필름 | 첫 카드, 중간 카드, 마지막 카드로 스와이프 | 다음 카드 일부가 보이고, 카드별 제목이 잘리지 않으며, 마지막 카드까지 접근 가능 |
| 탭 간섭 | 끝까지 스크롤 후 마지막 링크 탭 | 하단 탭에 가려지지 않고 44px 이상 터치 가능, safe-area에서도 동일 |
| 회귀 | 대표 사진·추천 카드·혼잡도·검색·로그인 홈 링크 탭 | 기존 `/contests/:id`, `/contests`, `/crowd`, `/explore`, `/compare` 이동 경로가 유지됨 |

## 통합 판정

- 현재 구조는 기능 회귀 위험은 낮지만, 사용자가 지적한 모바일의 부자연스러운 도입과 단조로운 바탕을 해결하려면 모바일 전용 첫 섹션과 배경 면의 재구성이 필요하다.
- API·데이터 계약 변경은 필요 없다. 프런트엔드 구현 완료 후 360px/768px/1280px 실화면 확인과 `npm run build`를 통합 게이트로 한다.
