# M8.1 사진 놓기 사진 선택 정리 QA

## 판정

통과. 새 사진 우선 흐름과 앨범 정리 선택 흐름이 새 비교, 기존 비교 사진 교체, 앨범에서 수상작 비교 시작에 공통으로 적용됐다.

## 교차 확인

- `ComparisonPhotoPickerDialog`이 공통 선택 책임을 맡고, `ComparePage`의 새 비교와 기존 비교 사진 교체가 이를 사용한다.
- `AlbumComparisonPicker`도 같은 공통 선택창을 사용한다. 따라서 앨범에서 수상작 비교를 시작하는 경로가 이전의 전체 사진 그리드로 남지 않는다.
- 첫 화면은 `새 사진 추가`를 우선 제공하고, 기존 사진은 별도 `앨범에서 고르기`를 눌러야 나타난다. 사진이 하나도 없을 때는 앨범 진입을 막고 안내한다.
- 앨범 선택은 최근·날짜·장소 정렬을 제공한다. 날짜·장소는 그룹 제목으로 묶이며, 최근은 최신 촬영일(없으면 생성일) 우선으로 정렬된다.
- 선택한 사진은 스크롤 영역 상단에 고정 요약되고, 명시적인 `선택` 확정 뒤에만 비교 사진으로 적용된다. 긴 목록은 다이얼로그 내부만 스크롤하므로 창 전체가 계속 길어지지 않는다.
- 새 사진은 EXIF 촬영일을 채우거나 직접 입력해야 업로드할 수 있다. 업로드 성공 뒤 선택 사진으로 이어지고, 취소·실패 시에는 입력 상태를 유지한다.
- 모바일은 기본 2열, `sm` 이상은 3열로 표시한다. 이미지에는 대체 텍스트, 다이얼로그에는 `role=dialog`·`aria-modal`, 버튼에는 명확한 이름을 제공한다.

## 자동 검증

- `frontend/npm run typecheck` 통과.
- `frontend/npm run build` 통과.
- `git diff --check` 통과.
- Vite 번들 814KB의 500KB 경고는 기존 비차단 권고이며, 이번 선택 UI가 새 번들 경계를 만들지는 않았다.

## 수동 확인 권고

1. 사진이 없는 계정에서 새 사진 추가 → EXIF 없음 촬영일 입력 → 업로드 → 구도 지정 흐름.
2. 날짜·장소가 섞인 긴 앨범에서 정렬 전환, 선택 요약 고정, 내부 스크롤.
3. 기존 비교의 사진 변경 및 앨범에서 수상작 비교 시작, 두 경로에서 업로드·기존 사진 선택 모두 확인.
