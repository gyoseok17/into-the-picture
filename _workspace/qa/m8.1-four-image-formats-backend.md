# M8.1 네 가지 사진 형식 — 백엔드 결과

## 변경 범위

- `ImageUploadValidator`로 업로드 검증 책임을 `UserPhotoService`에서 분리했다.
- `ImageFormat`은 JPEG, PNG, WebP, HEIC/HEIF의 요청 MIME과 실제 파일 서명을 교차 확인한다.
- JPEG 전용 `JpegTakenAtExtractor`를 `ImageTakenAtExtractor`로 교체했다. `metadata-extractor 2.19.0`의 컨테이너 판별을 사용해 네 형식에서 EXIF 촬영일만 시도한다.
- 기존 `UserPhotoService`는 검증된 content type을 저장하고, 메타데이터 추출 실패를 `takenAt: null`로 폴백한다.

## 검증 정책

| 형식 | 요청 MIME | 실제 형식 검사 | 저장 MIME |
| --- | --- | --- | --- |
| JPEG | `image/jpeg` | SOI `FF D8 FF` | `image/jpeg` |
| PNG | `image/png` | PNG 8바이트 서명 | `image/png` |
| WebP | `image/webp` | `RIFF` + `WEBP` | `image/webp` |
| HEIC/HEIF | `image/heic`, `image/heif` | ISO BMFF `ftyp` + HEIF 계열 브랜드 | 검증된 요청 MIME |

- HEIF 일반 MIAF 브랜드 `mif1`은 AVIF 브랜드가 동반되지 않을 때만 허용한다. AVIF는 이번 범위가 아니므로 거부한다.
- 확장자는 판별에 사용하지 않는다. MIME 또는 매직 바이트가 맞지 않으면 `INVALID_REQUEST` 400이다.
- 기존 10MB 제한·소유권 검사·파일 URL·비교 참조 삭제 규칙은 변경하지 않았다.

## 메타데이터·보안 결정

- 요청 `takenAt`이 우선이고, 없을 때만 EXIF `DateTimeOriginal`, 대체 `DateTime`을 시도한다.
- PNG, WebP, HEIC/HEIF에서 EXIF가 없거나 라이브러리가 지원하지 않는 변형이면 업로드를 거부하지 않고 `takenAt`을 `null`로 둔다.
- GPS·위치·카메라 모델은 디렉터리·태그 조회 대상에 포함하지 않는다.
- `metadata-extractor 2.19.0`은 JPEG, PNG, WebP 및 HEIF 컨테이너 리더를 포함함을 로컬 의존성과 공식 프로젝트 문서로 확인했다.

## 자동 검증

- `ImageUploadValidatorTest`
  - JPEG/PNG/WebP/HEIC/HEIF의 MIME+서명 일치 수용
  - MIME-서명 불일치와 AVIF 브랜드 거부
- `ImageTakenAtExtractorTest`
  - JPEG `DateTimeOriginal` 추출
  - EXIF가 없는 PNG/WebP/HEIF 컨테이너의 null 폴백
- `backend/.\\gradlew.bat test` 통과.
- `git diff --check` 통과.

## 남은 수동 확인

- 실제 iPhone HEIC와 일반 HEIF, EXIF를 포함한 WebP/PNG 파일을 각각 업로드해 브라우저 표시와 촬영일 추출을 확인한다.
- 배포 파일 저장소가 `image/heic`와 `image/heif` 응답 MIME을 보존하는지 확인한다.

## 판정

**통과 (실물 형식 파일 수동 확인 조건부).** 서버가 임의 파일을 MIME만으로 허용하지 않고, 지원 형식의 메타데이터 미지원은 안전한 null 폴백으로 처리한다.
