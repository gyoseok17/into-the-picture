# M8 현재 위치 빠른 조작 QA 검토

- 검토일: 2026-08-14
- 범위: 긴 수상작 목록(`/contests`)과 키워드 검색(`/explore`)의 `ScrollAssist`를 아이콘 전용으로 바꾸고, 페이지 맨 위로 이동하지 않은 현재 위치에서 검색·필터를 수정하는 패널
- 코드 변경: 없음

## 현재 구조 확인

- `ScrollAssist`는 `window.scrollY > 480`일 때만 보이며, `search` 또는 `filters` 한 가지 동작과 위로 가기 동작만 가진다.
- 현재 보조 동작은 `scrollToTop()` 후 `setTimeout(onAction, 0)`으로 상단 입력에 초점을 준다. 따라서 현재 위치에서 수정하는 요구와 양립하지 않는다.
- `/explore`의 검색어는 `draft`(입력 중 값), `keyword`(조회 값), URL `?keyword=` 세 상태로 나뉜다. 검색 확정 시에만 URL과 조회 값을 함께 갱신한다.
- `/contests`의 `ContestFilterBar`는 검색 초안(`keywordDraft`)을 내부 상태로 관리하고, 실제 조회 조건은 `ContestListPage`의 `query`에 있다. 계절·등급·부문·시도 옵션은 `useContestFilters()`가 상위 페이지에서 받는다.
- 공통 Popover/Sheet 컴포넌트는 없다. 기존 직접 구현 dialog는 Escape 처리와 포커스 복귀를 공통 보장하지 않으므로, 이 패널을 단순한 임시 div로 추가하면 접근성 회귀 위험이 있다.
- 모바일 하단 탭은 `z-40` 고정이다. 현 `ScrollAssist`는 `bottom: calc(5.5rem + safe-area)`·`z-30`라서 탭 위에 위치하며, 새 패널도 이 기준을 유지해야 한다.

## 권장 책임 경계

1. `ScrollAssist`는 표시 임계값, 아이콘 버튼, 열림/닫힘, Escape·바깥 클릭·초점 복귀만 담당한다.
2. 페이지별 빠른 내용은 슬롯/children 또는 `renderPanel` 계약으로 주입한다. `ScrollAssist`가 검색어·수상작 필터 도메인을 알면 안 된다.
3. `/explore`는 빠른 검색 제출 시 기존 `submit`과 동일한 한 함수로 `draft`, `keyword`, URL을 갱신한다.
4. `/contests`는 `query`, `filterOptions`, `setQuery`를 소유한 `ContestListPage` 쪽에서 빠른 필터 패널을 만든다. 현재 `ListView` 안의 `ScrollAssist`만으로는 옵션과 조건 전체에 접근하기 어려우므로 위치를 상위로 올리거나 명시적으로 계약을 전달해야 한다.

## 수용 기준

### 공통 아이콘 및 패널

- 텍스트 라벨은 화면에서 제거한다. 검색은 돋보기, 조건 변경은 슬라이더, 위로 가기는 위 화살표만 표시한다.
- 아이콘 전용 버튼에는 각각 의미 있는 `aria-label`과 hover/focus tooltip 또는 동등한 시각 라벨이 있다. 아이콘만으로 기능을 추측하게 두지 않는다.
- 검색/필터 아이콘을 누르면 페이지 위치는 유지하고, 버튼 인접 패널이 열린다. 위로 가기만 스크롤을 이동한다.
- 패널은 같은 버튼 재클릭, Escape, 바깥 클릭으로 닫힌다. 닫을 때 초점은 연 버튼으로 돌아간다. 열릴 때 첫 입력 또는 첫 조작 요소에 초점을 둔다.
- 열린 동안 `aria-expanded`, 패널 식별자(`aria-controls`)가 실제 상태와 맞는다. 버튼 묶음은 `role=group`과 한국어 이름을 가진다.
- 작은 화면에서 패널은 화면 밖으로 잘리지 않고, 내부 내용이 화면 높이를 넘으면 패널 안에서만 스크롤된다. 하단 탭·safe-area·키보드와 겹치지 않는다.
- `prefers-reduced-motion`에서 기존 위로 가기 동작은 즉시 이동을 유지한다. 패널 열림/닫힘도 필수 애니메이션에 의존하지 않는다.

### `/explore` 빠른 검색

- 입력에 기존 검색어가 보인다. 제출 전 입력만 바꿔도 현재 결과·URL·무한 스크롤 페이지는 바뀌지 않는다.
- 제출하면 기존 상단 검색과 동일하게 공백을 trim하고, `keyword`, `draft`, `?keyword=`를 한 트랜잭션으로 갱신한다. 빈 값은 URL 쿼리를 제거하고 최신 사진 조회로 돌아간다.
- 새 검색을 제출하면 이전 검색의 페이지·sentinel 관찰 결과가 새 검색 결과에 섞이지 않는다. 로딩·오류·빈 결과 표시는 기존 `usePhotos(keyword)` 흐름을 재사용한다.
- 브라우저 뒤로/앞으로 또는 홈의 `/explore?keyword=...` 링크로 진입한 뒤 패널을 열어도 URL 값과 입력 초안이 일치한다.

### `/contests` 빠른 조건 변경

- 패널은 상단 `ContestFilterBar`와 같은 검색어, 계절, 등급, 부문, 시도 및 초기화 동작을 제공한다. 어느 한쪽에서 확정한 조건은 다른 쪽에 즉시 반영된다.
- 필터 옵션 로딩 중에는 선택 가능한 것처럼 보이는 빈 필터를 만들지 않고, 상단과 동등한 skeleton/disabled 상태를 보인다. 옵션 요청 실패 시 기존의 keyword-only graceful degradation 정책을 지킨다.
- 적용은 `ContestQuery` 한 객체를 갱신해 기존 `useContests(query)`를 다시 조회한다. 지도 보기에서는 이 고정 도구를 노출하지 않거나, 노출한다면 지도 query에도 같은 변경이 적용돼야 한다.
- 빠른 패널에서 조건을 바꾼 뒤 리스트가 짧아져도 이전 sentinel의 `fetchNextPage`가 중복 실행되지 않으며, 현재 화면은 결과 시작점 또는 사용자가 이해 가능한 위치로 일관되게 처리한다. 이 위치 정책은 구현 전에 결정·기록한다.

## 화면별 확인 표

| 상황 | 통과 기준 |
| --- | --- |
| 360px 모바일 | 3개 아이콘과 열린 패널이 하단 탭 위에 있고, 탭·입력·적용 버튼이 가려지지 않는다. |
| 데스크톱 | 우측 하단에서 패널이 viewport를 넘지 않으며, 마우스 바깥 클릭과 키보드 Escape가 동일하게 닫는다. |
| 긴 목록 | 480px 전에는 숨김, 이후 표시. 다음 페이지 로딩 중에도 조작 가능하되 중복 요청은 없다. |
| 새 검색/필터 | 결과, 로딩, 빈 상태, 오류가 기존 상단 조작과 동일하다. |
| 접근성 | Tab 순서가 예측 가능하고, Escape 후 트리거로 복귀하며 아이콘 버튼의 이름을 스크린리더가 읽는다. |

## 차단 및 권고

- **차단:** 현재 `handleAction`의 상단 이동을 남긴 채 아이콘만 바꾸면 사용자 요구(현재 위치에서 입력/변경)를 충족하지 못한다.
- **차단:** 검색 패널이 `draft`만 바꾸거나 수상작 패널이 별도 query 상태를 가지면 URL·상단 필터·결과가 서로 어긋난다.
- **권고:** 공통 접근성 패널 primitive를 이번 범위에서 작게 만들거나 검증된 라이브러리를 도입한다. 기능별로 직접 `fixed` div를 복제하지 않는다.
- **권고:** 수상작 리스트와 지도에서 도구 노출 정책을 명시한다. 현재 도구는 리스트에만 렌더링된다.
