# M8 홈 월별 대표작 · 원본 이미지 QA 수용 기준

- 검토일: 2026-08-14
- 범위: 홈 대표 사진을 현재 월 촬영작에서 무작위로 고르고, 선택한 작품의 상세 API에서 `imageUrl` 원본을 한 번만 받아 표시하는 프런트 변경
- 코드 변경: 없음

## 기존 계약 확인

| 항목 | 현재 계약 | QA 판단 |
| --- | --- | --- |
| 목록 | `GET /contests?page=1&size=20`의 `content[]`은 `filmMonth: string`을 포함한다 | 현재 홈은 첫 페이지 6건만 사용하므로, 그 안에서만 후보를 고르면 데이터 전체의 월별 무작위 선택은 아니다. |
| 상세 | `GET /contests/{id}`는 공개 응답이며 `ContestDetail.imageUrl` 원본 URL을 포함한다 | 대표작 1건에 한해 사용 가능하다. 로그인·개인 파일 권한은 필요 없다. |
| 이미지 URL | 백엔드가 `thumbUrl`, `imageUrl`을 HTTPS로 정규화한다 | 프런트가 원본 URL을 별도 변환하거나 외부 URL을 조합하면 안 된다. |

## 수용 기준

### 1. 현재 월 후보 선정

1. 브라우저 현지 시간의 월을 두 자리 `MM`으로 만든다. 예: 8월은 `08`.
2. `filmMonth`는 `YYYYMM` 형식만 유효 후보로 인정하고, 마지막 두 자리와 현재 월이 같은 작품만 후보로 삼는다. `null`, 빈 문자열, 길이 6이 아님, 숫자가 아닌 값은 제외한다.
3. 현재 월 후보가 하나 이상이면 그 집합에서 한 작품을 무작위 선택한다. 첫 페이지 일부만 보고 "현재 달 작품"이라고 표시해서는 안 되므로, 구현은 전체 후보를 얻는 명확한 범위를 가져야 한다(예: 목록 요청의 충분한 범위 또는 월 필터 API 추가). 현재 공개 목록 API에는 `filmMonth` 필터가 없다.
4. 현재 월 후보가 없으면 전체 수상작 중 하나를 안전한 대체 대표작으로 선택한다. 이때 화면에 현재 월 촬영작이라는 문구를 표시하지 않는다.
5. 수상작 자체가 없으면 이미지 영역은 기존 빈 상태를 유지하며, 상세 API 요청을 보내지 않는다.

### 2. 무작위성·안정성

1. 무작위 선택은 같은 홈 마운트 동안 고정되어야 한다. 리렌더, 인증 상태 갱신, 이미지 로드 실패만으로 대표작이 바뀌면 안 된다.
2. 새로고침 또는 새 방문에서는 같은 월 후보 중 다른 작품이 선택될 수 있다.
3. 개발 모드 React Strict Mode의 효과 재실행으로 대표작이 두 번 뽑히거나 상세 요청이 중복되지 않아야 한다.

### 3. 상세·원본 이미지 요청

1. 대표작 ID가 정해진 뒤에만 `GET /api/v1/contests/{id}`를 요청한다.
2. 정상 홈 진입 한 번당 상세 API는 최대 1회다. 목록 API, 이미지 CDN 요청은 이 횟수에 포함하지 않는다.
3. 상세 응답의 `imageUrl`이 유효한 문자열이면 히어로는 이를 사용한다. 필름 스트립은 기존처럼 `thumbUrl`을 유지한다.
4. 상세 요청이 실패하거나 `imageUrl`이 비어 있으면, 선택된 동일 작품의 `thumbUrl`로 즉시 대체한다. 오류 화면·무한 재시도·대표작 재추첨을 하지 않는다.
5. 원본 이미지 자체가 404/네트워크 오류로 실패해도 동일 작품의 `thumbUrl`로 한 번 대체하고, 깨진 이미지 아이콘을 남기지 않는다.

### 4. 레이아웃·반응형

1. 원본 이미지와 대체 썸네일 모두 기존 히어로 컨테이너의 비율과 `object-fit: cover` 규칙을 지킨다. 이미지 로드 후 컨테이너 높이가 변하지 않아야 한다.
2. 모바일은 문장 다음에 대표 사진이 오고, 데스크톱은 기존 좌우 구성을 유지한다.
3. 모바일과 데스크톱 모두 제목·장소 오버레이의 대비와 링크 탭 영역이 유지되어야 한다.

### 5. 공개 범위·보안

1. `/contests`와 `/contests/{id}`는 공개 수상작 API이므로 비로그인 사용자도 대표 원본을 볼 수 있어야 한다.
2. `/me/*`, 개인 사진 파일 API, 토큰·쿠키를 이 흐름에서 호출하거나 화면에 노출하면 안 된다.
3. 상세 API 응답 전체를 로그·문서에 저장하지 않는다. 화면에는 현재 사용 중인 공개 필드만 소비한다.

## 최종 검증 체크리스트

- [ ] 1~12월 각각을 주입하거나 날짜 함수를 모킹해 `YYYYMM` 매칭을 검증한다.
- [ ] `filmMonth`가 null/빈 값/비정상인 작품만 있는 경우 대체 대표작이 보인다.
- [ ] 현재 월 후보가 없는 경우에도 홈이 정상 렌더링된다.
- [ ] 목록 0건이면 상세 요청 없이 빈 상태가 보인다.
- [ ] 네트워크 탭에서 홈 진입 시 선택 작품의 상세 요청이 1회인지 확인한다.
- [ ] 상세 4xx/5xx, `imageUrl` 없음, 이미지 로드 오류 각각에서 썸네일 대체를 확인한다.
- [ ] 로그인/비로그인 모두 동일한 공개 API 흐름으로 동작하고 개인 API 요청이 없다.
- [ ] 360px 및 768px 이상에서 이미지 비율·오버레이·링크를 확인한다.

## 차단 조건 및 권고

- **차단:** 첫 목록 페이지 20건(또는 6건)만 필터링하면서 서비스 전체에서 이번 달 작품을 무작위로 고른다고 표현하는 구현. 데이터 범위를 명시적으로 넓히거나, 문구를 해당 범위에 맞춰야 한다.
- **차단:** 상세 요청 실패가 대표 사진 전체 실패·무한 재시도·재추첨으로 이어지는 구현.
- **권고:** 장기적으로는 `month` 기반의 전용 공개 대표작 API를 두면, 전체 목록 다운로드 없이 서버가 후보 선정 범위와 정렬을 보장할 수 있다. 이번 요청은 API 변경 없이 기존 공개 상세 API 1회 사용으로 처리 가능하다.
