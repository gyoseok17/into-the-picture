# M8 모바일 목록 보기 설정 QA 기준

- 작성일: 2026-08-14
- 범위: 수상작 목록과 키워드 검색 결과의 모바일 사진 목록 보기 전환
- 구현 변경: 없음 (QA·검토 역할)

## 사용자 경험 계약

1. 작은 화면의 기본값은 **2열**이다. 수상작 목록과 키워드 검색 결과가 같은 선택값을 사용한다.
2. 사용자는 목록 상단의 명확한 보기 전환 컨트롤로 `2열`과 `1열`을 고를 수 있다. 아이콘만 쓰면 각 버튼에 보이는 텍스트 또는 접근 가능한 이름(`aria-label`)을 제공한다.
3. 선택은 브라우저 저장소에 공통 키 하나로 보존한다. 한 화면에서 바꾼 값은 다른 화면과 새로고침 뒤에도 적용된다.
4. 데스크톱 열 수 규칙은 유지한다. 이 설정은 모바일(기본적으로 640px 미만)에서만 열 수를 바꾸며, `sm` 이상에서는 기존 반응형 열 수를 우선한다.
5. 보기 설정은 표시 방식만 바꾼다. 수상작의 목록/지도 탭, 필터, 정렬, 무한 스크롤, 검색어 URL, 앨범 묶음과 상세 모달의 데이터·순서는 바꾸지 않는다.

## 반응형 및 앨범 묶음 확인

- 수상작: 360px에서 카드 두 장이 가로로 모두 보이고, 카드 안 제목·위치·하트가 넘치거나 서로 겹치지 않는다. 1열 선택 시 카드가 충분히 넓어져 기존 정보 밀도와 상호작용이 유지된다.
- 검색: `PhotoAlbumGrid`의 항목은 개별 사진이 아니라 같은 페이지 안에서 묶인 앨범이다. 2열/1열 전환이 앨범 묶음 경계, 표지 사진, 사진 수, 상세 모달에 전달하는 `album` 데이터를 변경하면 안 된다.
- 새 페이지가 무한 스크롤로 합쳐져도 현재 보기 설정이 유지된다. 전환 중 중복 항목, 순서 변경, 스크롤 위치 초기화가 없어야 한다.
- 320px, 360px, 390px, 640px 경계와 가로 방향에서 수평 페이지 스크롤이 생기지 않아야 한다.

## 상태별 수용 기준

- 로딩: 수상작 스켈레톤과 검색 스켈레톤도 현재 선택 열 수를 따른다. 기본 2열에서 실제 카드가 나타날 때 레이아웃이 크게 흔들리지 않는다.
- 빈 결과: `사진을 찾지 못했어요` 및 수상작 빈 상태는 보기 설정과 무관하게 한 칸 전체 폭으로 정상 표시된다.
- 오류: 오류 메시지와 재시도 버튼이 한 열/두 열에서 모두 전체 폭으로 읽히며, 재시도 후 선택값은 유지된다.
- 설정값이 없거나 잘못됐으면 예외 없이 2열로 복구한다. 읽기·쓰기 실패(비공개 모드, 저장소 차단, quota 오류)는 화면을 깨지지 않게 하고 현재 세션에서는 2열 기본값 또는 사용자가 방금 고른 값으로 계속 표시한다.

## 접근성 기준

- 전환 컨트롤은 키보드만으로 도달·선택할 수 있고, 현재 선택 상태가 `aria-pressed` 또는 라디오 그룹 의미로 전달된다.
- 최소 터치 영역은 44×44px 수준을 확보한다. 두 열 카드도 카드 전체가 하나의 버튼/링크라면 중첩 인터랙션을 만들지 않는다.
- 전환 뒤 포커스가 사라지지 않고, 이미지 `alt`·앨범 제목·사진 수 안내는 기존 수준으로 유지된다.
- 모션 없이 즉시 배치만 바뀌어야 하며, 전환으로 모달이 닫히거나 무한 스크롤 추가 요청이 발생하지 않아야 한다.

## 구현 검토 권고

- 보기 설정 상태와 저장소 접근은 공통 훅(예: `useMobileGridPreference`)으로 분리한다. 각 화면은 해당 값을 CSS 열 클래스에만 전달한다.
- 수상작의 `ContestGrid`, 검색의 `PhotoAlbumGrid`, 그리고 각각의 스켈레톤이 같은 열 값 계약을 받도록 한다. 페이지마다 별도 `localStorage` 키나 다른 기본값을 두지 않는다.
- 서버·API 계약 변경은 필요 없다. 개인 정보나 로그인 상태에 연결하지 않는 UI 환경설정이므로 클라이언트 저장소에만 둔다.

## 통합 판정

- 사전 판정: 위 계약으로 구현 가능. 차단 이슈 없음.
- 최종 판정 전 확인: 실제 360px/390px 화면에서 수상작·검색의 기본 2열, 1열 전환, 새로고침 보존, 저장소 차단 fallback, 검색 앨범 상세 모달과 무한 스크롤 회귀를 확인해야 한다.
