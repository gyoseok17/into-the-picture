# M8.1 사진 놓기 후보 일관성·앨범 재사용 QA

검토일: 2026-09-14
검토 역할: QA·계약 검토

## 판정

통과. 백엔드·DB API 계약 변경 없이 프런트 후보 표시 규칙과 React Query 무효화 범위만 보완했다.

## 계약 교차 확인

| 검토 항목 | 결과 |
| --- | --- |
| 새 비교 | `ComparePage`가 전체 `user-photos`와 비교 목록 기반 `usedPhotoIds`를 공통 선택창에 전달한다. 연결 사진은 보이지만 `disabled`와 `비교 중` 표기로 선택할 수 없다. |
| 기존 비교 사진 교체 | `ComparisonView`도 전체 사진과 같은 `usedPhotoIds`를 전달하고, 선택 콜백에서도 다시 차단한다. 현재 비교의 사진을 포함한 어떤 연결 사진도 재선택할 수 없다. |
| 앨범에서 수상작 비교 | `AlbumComparisonPicker`가 현재 앨범의 활성 묶음·평면 사진·같은 `unavailablePhotoIds`를 전달하고 콜백에서 한 번 더 차단한다. |
| 묶음 조회 재사용 | `bundles` prop이 있으면 `usePhotoRecordBundles(false, false)`가 되어 별도 GET을 실행하지 않는다. 없는 두 경로만 앨범 단계 진입 시 활성 묶음을 조회한다. |
| 보관함 경계 | 선택창의 직접 조회는 `archived=false`이고, 앨범 진입도 활성 앨범 배열만 전달한다. |
| 새 파일 | 업로드 성공 전에는 비교 연결 id가 없으므로 새 사진은 자르기·저장 단계로 정상 진행한다. |
| 캐시 | `useUploadUserPhoto` 성공 뒤 `user-photos`와 `photo-records`, `photo-record-bundles`, `photo-record-map`, `photo-record-bundle-map`을 무효화한다. React Query는 구독 중인 화면만 재조회하므로 모든 앨범·지도 화면을 강제로 호출하지 않는다. |

## 오류·빈 상태

- 직접 묶음 조회 실패에는 재시도 UI가 유지된다.
- 묶음이 비었으면 기존 빈 안내를 보이고, 모든 사진이 비교 중이어도 사진은 상태와 함께 남아 있으므로 사용자에게 불가 사유가 보인다.
- 이미 선택했던 사진이 비교 연결 상태로 바뀌면 선택 요약·확정은 숨기고 `confirmSelection`에서도 차단한다.
