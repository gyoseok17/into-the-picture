# M8.1 수상작 공개 비교 사진 중앙 다이얼로그 QA

## 최종 판정

통과.

## 비교·선택 흐름

- 수상작 상세의 사진 버튼을 누를 때만 공개 비교 목록을 조회한다.
- 중앙 다이얼로그는 원본 수상작 이미지와 선택된 공개 비교 사진을 같은 2열 영역에 표시한다.
- 공개 사진이 여러 장이면 첫 사진을 기본 선택하고, 아래 썸네일 버튼을 누르면 선택 이미지와 선택 표시가 즉시 바뀐다.
- 선택 상태는 비교 id로 관리하므로 목록 순서가 바뀌거나 선택 사진이 사라져도 첫 유효 사진으로 안전하게 복귀한다.
- 공개 비교가 0건이면 비교 영역·썸네일을 만들지 않고 안내만 표시한다. 로딩과 오류는 기존 `LoadingState`·`ErrorState` 및 재시도 경로를 유지한다.

## 반응형·접근성

- 바깥 레이어는 `fixed inset-0` 중앙 정렬이며, 기존 모바일 하단 시트가 아니다.
- 다이얼로그는 모바일에서 화면 여백을 유지한 전체 폭, PC에서는 `max-w-4xl` 중앙 폭으로 제한되고 `max-h-[90dvh]` 내부 스크롤을 사용한다.
- 비교 이미지는 모바일에서 4:5, `sm` 이상에서 4:3으로 표시해 좁은 화면에서도 두 사진을 함께 볼 수 있다.
- Escape와 배경 클릭은 공개 사진 다이얼로그만 닫으며, 부모 수상작 상세의 Escape 처리는 열린 동안 중지된다.
- Tab/Shift+Tab 포커스는 다이얼로그 안에서 순환하고, 닫으면 사진 버튼으로 포커스가 복귀한다.
- 썸네일은 실제 `button`, `aria-pressed`, 선택 상태를 포함하며 키보드로 선택 가능하다.

## 공개 범위·데이터 경계

- 갤러리는 `PublicContestComparison`의 `id`, `photoUrl`, `createdAt`만 소비한다.
- 원본 수상작 정보는 이미 공개된 상세 데이터만 사용한다.
- 장소, 메모, 촬영일, 파일명, 앨범·지도 정보, 소유자 정보는 응답·화면 어느 곳에도 추가되지 않았다.
- 공개 목록·파일 API는 여전히 `PUBLIC` 및 활성 비교만 반환하므로 비공개 사진은 선택 목록에 들어오지 않는다.

- `npm run typecheck` 통과
- `npm run build` 통과
- `git diff --check` 통과
- Vite 500kB 초과 청크 권고만 기존과 동일하게 남아 있으며 이번 변경의 차단 이슈는 아니다.
