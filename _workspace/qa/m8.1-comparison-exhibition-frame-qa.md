# M8.1 비교 결과 전시 액자·폴라로이드 QA

작성일: 2026-09-04
상태: 구현 전 계약 검토 완료 · 최종 검증 대기

## 화면·데이터 계약

- `WITH_CONTEST` 결과는 수상작을 전시 액자 영역, 내 사진을 폴라로이드 영역으로 각각 구분해 표시한다. `PHOTO_ONLY`는 수상작 액자와 관련 레이블·공백을 렌더링하지 않고 내 사진 중심 구성을 유지한다.
- 결과 목록의 loading, error, empty, display 상태는 서로 배타적이며, 기존 카드 클릭과 결과 열기 링크의 동작을 유지한다.
- 상세 결과에서 사진 변경은 비교 레코드의 userPhoto만 교체하고, 결과만 삭제와 사진도 삭제는 기존 `deletePhoto` 계약을 유지한다. 요청 중에는 중복 클릭을 막고 성공 시 목록·사진·앨범 캐시가 최신화되어야 한다.
- 모바일에서는 두 이미지가 잘리지 않고 세로 흐름으로 전환되며, 액자 장식이 클릭·초점·스크린리더 텍스트를 가리지 않는다.
- 모달에는 제목과 닫기 접근 경로가 있고, 배경 클릭 닫기와 내부 클릭 전파 차단을 유지한다.

## 폰트 계약

- 명조 계열은 시스템 fallback으로 제공하고, 필기체 외부 폰트는 전역 엔트리 한 곳에서만 import한다.
- 같은 Google Fonts 요청이나 `@font-face` 선언을 화면 컴포넌트별로 중복 추가하지 않는다. 로딩 실패 시에도 fallback으로 읽을 수 있어야 한다.

## 최종 체크리스트

- [ ] `WITH_CONTEST` 전시 액자와 내 사진 폴라로이드가 시각·의미상 분리되고 이미지 비율/대체 텍스트가 보존된다.
- [ ] `PHOTO_ONLY`에서 수상작 영역·장식·불필요한 2열 공간이 없다.
- [ ] loading/error/empty/display 상태가 겹치지 않고 재시도가 유지된다.
- [ ] 모바일 320px에서 세로 배치, 안전한 여백, 오버플로우 및 장식 clipping을 확인한다.
- [ ] 사진 변경, 결과만 삭제, 사진도 삭제 각각의 pending·성공·실패 동작과 카드/링크 갱신을 확인한다.
- [ ] dialog role/label/close, 버튼 이름, 키보드 초점 경로와 배경 클릭 처리 회귀가 없다.
- [ ] 폰트 import와 fallback 중복이 없다.
- [ ] `tsc -b`, `git diff --check`를 통과한다.

## 구현 전 발견

- 현재 전역 `index.css`에 Nanum Pen Script import가 한 번 존재하고, 명조는 `font-editorial` 시스템 fallback으로 제공된다. 새 화면에서 중복 import하지 않는 것이 조건이다.
- 기존 삭제 mutation은 comparisons·user-photos·photo-record 관련 cache를 무효화하며, 이 범위를 줄이지 않아야 한다.

## 1차 구현 검토 (2026-09-04)

### 통과

- Noto Serif KR와 Nanum Pen Script는 전역 `index.css`의 Google Fonts import 한 곳에서 요청되며, 각 화면 컴포넌트에 중복 import가 없다. 두 class는 fallback도 제공한다.
- 전시 액자와 폴라로이드는 별도 컴포넌트로 분리됐고, desktop 2열·mobile 1열 grid 전환 및 각 이미지의 대체 텍스트는 확인했다.
- 결과 목록 loading/error/empty는 배타적으로 렌더링되고, 사진 변경과 두 삭제 요청은 기존 mutation·cache invalidation을 사용한다.
- `tsc -b` 통과, `git diff --check` 공백 오류 없음(LF/CRLF 경고만 출력).

### 차단 이슈

1. `ComparisonExhibit`가 `comparison.displayMode`를 분기하지 않는다. 따라서 `PHOTO_ONLY`에도 수상작 액자와 트로피가 표시되어 데이터·화면 계약을 위반한다.
2. 기존의 mutation 오류 안내가 제거되어 업로드·사진 교체·결과/사진 삭제 실패 때 사용자에게 원인이나 다음 행동이 보이지 않는다.

### 권고

- 상세 결과 및 삭제 선택 dialog에 `aria-label` 또는 `aria-labelledby`를 연결한다.

**판정: 차단 이슈 수정 대기.**

## 최종 재검증 (2026-09-04)

### 차단 이슈 해결 확인

- `ComparisonExhibit`는 `PHOTO_ONLY`일 때 수상작 액자·트로피 없이 standalone 내 사진 폴라로이드만 렌더링한다. 상세 header도 내 사진 파일명(없으면 `내 사진`)으로 분기한다.
- 업로드·사진 교체·두 삭제 mutation의 실패 메시지는 `ComparisonErrorNotice`의 `role="alert"`로 안내되고, 닫기 시 mutation 오류 상태를 초기화한다.
- 상세 dialog은 `aria-label`, 삭제 dialog은 `aria-labelledby`를 가지며, mobile에서 높이가 넘치면 `max-h-[calc(100dvh-2rem)] overflow-y-auto`로 내부 스크롤된다.

### 최종 확인

- `WITH_CONTEST`: 액자 수상작, 구분 트로피, 폴라로이드 내 사진이 desktop 2열·mobile 1열로 표시된다.
- `PHOTO_ONLY`: 수상작 시각 요소와 제목을 노출하지 않으며 내 사진 정보만 유지한다.
- 목록의 loading/error/empty/display 상태는 배타적이고, 사진 변경·결과만 삭제·사진도 삭제는 기존 API와 cache invalidation을 유지한다.
- Noto Serif KR·Nanum Pen Script는 전역 import 한 건과 fallback으로 구성돼 중복 로딩이 없다.
- `tsc -b` 통과, `git diff --check` 공백 오류 없음(LF/CRLF 경고만 출력).

### 수동 시각 확인 권고

- 실제 320px 기기에서 긴 파일명·메모·장소명이 있는 폴라로이드와 상세 dialog 스크롤 감각을 한 번 확인한다.

## 디프티크 개편 계약 (2026-09-04)

- `WITH_CONTEST`는 중앙 트로피·선·기호 없이 동일 폭의 두 전시 인화물로만 구성한다. 두 인화물의 이미지/매트 높이는 md 이상에서도 동일해야 한다.
- 비교 상세의 내 사진 filename은 제목/캡션 어디에도 출력하지 않는다. `PHOTO_ONLY` header·전시 인화물에서도 filename 대신 의미 있는 고정 제목을 사용한다.
- 내 기록 캡션은 촬영일, 장소, 메모의 값만 노출하고, `촬영일:`·`장소:` 같은 label을 추가하지 않는다. 값이 없을 때 빈 캡션·여백도 남기지 않는다.
- 모바일은 두 인화물을 자연스러운 세로 순서로 보이고, `PHOTO_ONLY`는 단독 인화물 하나만 보인다.
- 기존 dialog 접근성, 내부 스크롤, 사진 변경·결과만 삭제·사진도 삭제, mutation 오류 안내·cache 갱신은 유지한다.

## 디프티크 최종 검증 (2026-09-04)

### 통과

- 상세 `WITH_CONTEST`는 `md:grid-cols-2`의 같은 폭 두 칸과 공통 `ExhibitPrint`를 사용한다. 두 인화물은 동일한 아이보리 매트·내부 프레임·`aspect-[4/3]` 이미지 규격이다.
- `ComparisonTrophy`와 lucide `Trophy` import가 제거되어 중앙 기호·연결선이 남지 않는다.
- 내 사진 상세의 filename은 header와 `PersonalExhibitCard`에서 제거됐다. `PHOTO_ONLY` header는 고정 `내 사진`, 인화물은 title 없이 단독 표시된다. 목록/사진 선택기에서의 filename은 식별·선택 목적이라 상세 전시 계약과 분리된다.
- 내 기록은 촬영일·장소·메모 값만 출력하며, 값이 없으면 캡션 영역 자체를 만들지 않는다. icon은 보조 정보이고 텍스트 label은 없다.
- mobile은 세로 흐름이고, 상세 modal의 최대 높이·스크롤, a11y 이름, 사진 변경·결과만 삭제·사진도 삭제, mutation 오류 alert 및 cache 갱신 경로는 유지된다.
- `tsc -b` 통과, `git diff --check` 공백 오류 없음(LF/CRLF 경고만 출력).

### 수동 시각 확인 권고

- desktop에서 긴 수상작 제목과 내 기록 캡션이 있을 때, 인화물 자체의 상단 정렬과 캡션 간격을 한 번 확인한다.

## 동등 전시 인화물 개편 계약 (2026-09-04)

- `WITH_CONTEST`의 수상작과 내 사진은 같은 아이보리 매트·전시 인화물 구조를 사용한다. 기존 폴라로이드 회전, 하단 흰 여백, 필기체 메모 패널은 비교 상세에서 남지 않는다.
- `PHOTO_ONLY`는 수상작·트로피·비교용 빈 칸 없이 같은 전시 인화물 하나만 단독으로 보인다.
- 내 사진의 촬영일·장소·메모는 프레임 외부의 기록 캡션에 두고, 이미지·제목·캡션의 읽기 순서를 유지한다.
- 명조는 작품/전시 제목, 본문 sans는 정보 캡션에 한정한다. 필기체는 기존 앨범 스토리에서만 유지하며 비교 상세에 새로 적용하지 않는다.
- 이전 검증 범위인 mobile dialog 스크롤, dialog label, photo change, 결과만 삭제, 사진도 삭제, mutation error alert/cache invalidation은 보존한다.

## 동등 전시 인화물 최종 검증 (2026-09-04)

### 통과

- 비교 상세의 기존 `PersonalPolaroid`와 회전·하단 흰 여백·필기체 패널은 `ComparePage`에서 제거됐다. 수상작과 내 사진은 공통 `ExhibitPrint`의 아이보리 매트·내부 흰 이미지 프레임을 사용한다.
- `PHOTO_ONLY`는 `PersonalExhibitCard` 하나만 단독 렌더링하므로 수상작, 트로피, 비교용 빈 2열을 남기지 않는다. 상세 header도 내 사진 제목으로 분기한다.
- 촬영일·장소·메모는 이미지 프레임 바깥의 내 기록 캡션으로 배치되고, label → image → title → record detail 순서가 유지된다.
- 명조(`font-editorial`)는 양쪽 작품 제목에 사용되고, 내 기록 캡션은 일반 본문이다. 비교 상세에 `font-handwritten` 사용처는 없다. 전역 폰트 요청도 한 건이다.
- 상세/삭제/사진 선택 dialog의 접근 가능한 이름, 320px용 최대 높이·내부 스크롤, 사진 변경·두 삭제·실패 alert·cache invalidation 경로가 이전 검증 결과대로 유지된다.
- `tsc -b` 통과, `git diff --check` 공백 오류 없음(LF/CRLF 경고만 출력).

### 수동 시각 확인 권고

- 실제 320px에서 긴 장소명·메모가 포함된 내 기록 캡션의 줄바꿈과 modal 스크롤 감각을 확인한다.
