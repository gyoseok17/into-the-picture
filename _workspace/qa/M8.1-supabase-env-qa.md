# M8.1 Supabase 환경변수 QA

검토일: 2026-09-07

## 설정·보안 확인

- `backend/.env`는 Git 추적 대상이 아니며, `.gitignore`가 해당 경로를 제외한다.
- `DB_HOST`, `DB_PORT`, `DB_NAME`, `DB_USERNAME`은 사용자가 전달한 Supabase 직접 접속 정보와 일치한다.
- `DB_PASSWORD`는 존재 여부만, `JWT_SECRET`은 32바이트 이상 여부만 확인했다. 값 자체는 열람·기록하지 않았다.
- `application.yml`은 `DB_HOST`, `DB_PORT`, `DB_NAME`, `DB_USERNAME`, `DB_PASSWORD`, `JWT_SECRET`을 모두 환경변수 참조로 사용한다. DB/JWT 시크릿 기본값은 없다.
- `backend/.env.example`에는 필요한 키 이름만 있고 실제 시크릿은 없다.

## 기동·연결 확인

- 포트 `8080`은 Java/Spring 프로세스가 수신 중이다.
- HTTP 요청은 현재 `500`을 반환한다. 최신 로그의 오류 범주는 PostgreSQL 연결 실패이며, 기록된 원인은 `UnknownHostException`으로 `aws-0-ap-southeast-1.pooler.supabase.com`을 해석하지 못한 것이다.
- 이 로그의 호스트는 현재 `backend/.env`에 검증된 직접 접속 호스트와 다르다. 따라서 실행 프로세스가 새 설정으로 재기동됐는지, 혹은 기존 프로세스·로그가 응답한 것인지 통합 확인이 필요하다.

## 판정

환경변수 파일 분리와 민감정보 비노출은 통과. 백엔드의 실제 DB 연결은 `500` 상태이므로 통과 판정을 보류한다. 새 설정으로 단일 백엔드 프로세스를 재기동한 뒤 DB 연결 성공 로그와 정상 API 응답을 확인해야 한다.
