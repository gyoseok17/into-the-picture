# M8 수상작 상세 오버레이 QA

- 검토일: 2026-08-18
- 범위: 목록에서 수상작 상세를 열 때 목록 상태를 유지하는 라우트 기반 오버레이

## 확인 결과

| 항목 | 판정 | 근거 |
| --- | --- | --- |
| 목록 유지 | 통과 | `ContestRoute`가 목록 진입 상태에서 `ContestListPage`와 자식 상세를 함께 렌더링한다. 목록 컴포넌트가 언마운트되지 않아 필터, 무한 스크롤 페이지, 스크롤 위치가 유지된다. |
| 주소와 앞/뒤 이동 | 통과 | 주소는 `/contests/:id`를 유지한다. 닫기·배경 클릭·Escape는 이전 history 항목으로 돌아가고, 브라우저 앞으로 가기는 같은 상세 오버레이 항목을 다시 연다. |
| 독립 상세 진입 | 통과 | 직접 주소, 홈, 혼잡도, 마이, 지도에서 전달하는 `contestListEntry` 상태가 없으면 목록을 렌더링하지 않는 독립 상세가 된다. 목록 버튼은 `/contests`로 안전하게 이동한다. |
| 스크롤 격리 | 통과 | 오버레이가 열릴 때 body 스크롤을 잠그고, 상세 본문은 별도 `overflow-y-auto overscroll-contain` 영역에서 스크롤된다. |
| 레이어 | 통과 | 오버레이가 `z-50`으로 상단 내비게이션·모바일 하단 탭(`z-40`)보다 위에 표시된다. |
| 키보드·초점 | 통과 | 최초 초점을 상세 패널로 옮기고 Tab 순환, Escape 닫기, 닫은 뒤 원 카드 초점 복귀를 구현했다. |
| 빌드·형식 | 통과 | `frontend/npm run build`, `git diff --check` 통과. 기존 500KB 번들 경고만 남는다. |

## 권고 및 남은 위험

1. 실제 브라우저에서 긴 목록을 2페이지 이상 불러온 뒤 카드 선택 → 배경 클릭·상세의 목록 버튼·브라우저 뒤로가기·앞으로가기를 각각 한 번 확인한다. 이 QA는 코드 경로와 빌드 검토 기준이다.
2. `ContestListPage`의 기존 session/history 기반 복원 코드는 오버레이 목록 진입에서는 더 이상 핵심 경로가 아니다. 현재 호환용으로 남아 있어 기능 충돌은 없지만, 다음 정리 때 사용 시나리오를 재확인한 뒤 제거 또는 별도 문서화하면 복잡도를 줄일 수 있다.

## 통합 판정

차단 이슈 없음. 수상작 목록에서 상세를 열고 닫을 때 목록을 유지한다는 목표에 적합하다.
