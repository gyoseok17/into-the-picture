# M8.1 수상작 상세 하단 탭 경계 QA

## 판정

통과. 목록 진입 상세의 하단 공백으로 목록이 비칠 수 있던 레이어 경계가 제거되었다.

## 코드 교차 확인

- `DetailPresentation`은 모바일에서 `fixed inset-0 z-30 ... bg-background`이므로, 오버레이 표면이 뷰포트 하단까지 이어진다.
- `BottomTabBar`는 `fixed ... bottom-0 z-40 bg-background/95`다. 따라서 탭은 상세보다 한 레이어 위에서 계속 보이고 클릭 가능하지만, 반투명·blur 뒤에는 `z-30` 상세 배경이 있다.
- 상세 본문은 `pb-[calc(6rem+env(safe-area-inset-bottom))]`로 마지막 내용을 탭 위까지 올린다. 오버레이 높이를 축소하는 이전 `bottom-[4.5rem]` 방식은 남아 있지 않다.
- `md:top-[4.25rem]`만 적용돼 데스크톱은 상단 내비게이션 아래부터 화면 하단까지 덮고, 모바일에서는 탭과 안전 영역을 포함한 전체 높이를 덮는다.
- `overflow-y-auto overscroll-contain`은 상세 안에서만 스크롤하게 하며, 오버레이 열 때 `document.body.style.overflow = 'hidden'`으로 뒤 목록 스크롤을 막는다. 닫기·뒤로가기는 기존 라우팅·포커스 복귀 흐름을 유지한다.

## 반응형 확인 기준

- 320/375/430/767px 폭: 모바일 탭의 아이콘·라벨 사이와 safe area에 뒤 목록 표면이 노출될 경로가 없다.
- 768px 이상: 하단 탭은 `md:hidden`이고, 상세는 상단 내비게이션 아래부터 하단까지 덮는다.
- 568px처럼 낮은 높이와 높은 창: 상세 본문의 하단 패딩은 내용 가림을 방지하되 오버레이 하단 배경을 비우지 않는다.

## 자동 검증

- `frontend`: `npm run typecheck` 통과.
- `frontend`: `npm run build` 통과. Vite의 500 kB 초과 청크 경고만 존재하며 이번 레이어 변경의 실패는 아니다.
- 저장소 루트: `git diff --check` 통과. 기존 파일의 CRLF 변환 경고만 출력됨.

## 남은 확인

- 이 실행 환경에는 실제 모바일 브라우저 화면 캡처 자동화가 없어 물리 기기 safe area 렌더링은 코드·CSS 경계로 검토했다. 실제 기기에서는 목록의 이미지가 하단 탭 바로 아래에 있는 상태로 상세를 열어 한 번 확인하면 충분하다.
