# M8.1 프런트 생성 산출물 shadowing QA

- 점검일: 2026-09-09
- 범위: `frontend/src`의 stale JS·declaration 산출물, Vite 모듈 해석, 부산 좌표 반영 여부

## 원인 확정

`PhotoRecordMapView.tsx`는 확장자 없이 `../lib/albumMapCityPositions`를 import한다. Vite 기본 해석 순서는 다음과 같고, 프로젝트의 `vite.config.ts`는 이를 바꾸지 않는다.

```text
.mjs → .js → .mts → .ts → .jsx → .tsx → .json
```

따라서 같은 경로의 `albumMapCityPositions.js`가 `albumMapCityPositions.ts`보다 먼저 선택됐다. stale JS에는 `BUSAN: point(70, 72)`, TS에는 `BUSAN: point(68, 69)`가 있었으며, 수정 전 빌드 bundle도 실제로 `BUSAN:M(70,72)`를 포함했다.

근본 원인은 `package.json`의 `typecheck`가 `tsconfig.app.json`의 `noEmit: true`를 `--noEmit false --emitDeclarationOnly false`로 덮어 `src/` 안에 JS와 `.d.ts`를 생성한 것이었다.

## 수정 후 검증

- `typecheck`를 `tsc -b`로 변경해 `noEmit`을 유지한다.
- generated JS·`.d.ts`를 실제 `frontend/src`에서 제거했다.
- Git 추적 원본 선언 파일만 남았다: `src/vite-env.d.ts`, `src/types/kakao.d.ts`.
- `frontend/src/**/*.js`, `frontend/src/**/*.d.ts` ignore와 위 두 원본 파일 예외를 추가해 재발을 방지한다.

실제 결과:

| 항목 | 결과 |
| --- | --- |
| `frontend/src` JS 파일 | 0개 |
| `frontend/src` declaration 파일 | 원본 2개만 존재 |
| `npm run typecheck` | 통과, 산출물 재생성 없음 |
| `npx vite build` | 통과 |
| 새 bundle | `BUSAN:A(68,69)` 포함 |
| 새 bundle | `BUSAN:A(70,72)` 미포함 |
| `git diff --check` | 통과 |

Vite dev와 build는 같은 resolve 설정을 사용하므로, 새로 시작하거나 HMR이 갱신된 개발 화면도 TypeScript의 `(68,69)` 좌표를 선택한다.

## 판정

통과. stale JS shadowing 원인은 제거됐고, 생성 방지·Git ignore·실제 production build의 좌표 확인까지 완료했다. Vite 청크 크기 500kB 권고만 기존 비차단 항목으로 남는다.
