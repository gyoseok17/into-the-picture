# M8.1 지도 핀 묶음·숫자 의미 정적 진단

작성일: 2026-08-29
범위: 읽기 전용. 지도 API 계약, 프런트 변환·그룹화·문구를 대조했다.

## 현재 데이터 기준

백엔드 `GET /me/photos/bundles/map`의 배열 원소 하나는 다음 중 하나다.

- 새 업로드: **사진 묶음 1개** (`id != null`, `legacy=false`, `photos`에 묶음 사진 전체).
- 기존 사진: **개별 사진 1개** (`id=null`, `legacy=true`, `photos` 길이 1).

즉 서버 API의 배열 길이는 지도에 올릴 **기록 단위 수 = 사진 묶음 수 + 기존 개별 사진 수**다. 새 묶음 하나 안의 사진 여러 장은 한 지도 핀의 콘텐츠여야 한다.

## 현재 프런트 동작과 문제

`PhotoRecordMapView`는 `pins`를 `photoPins`로 평탄화한 뒤 `groupPins`로 다시 묶는다.

- 새 묶음은 `bundle-{bundleId}`로 재결합된다. 결과적으로 마커 하나와 내부 사진 넘김은 정상이다.
- 단, 마커의 숫자와 상단 `맵에 기록 N장`의 `N`은 **사진 수**(`group.pins.length`, `filteredPins.length`)다.
- API가 이미 묶음 단위인데 다시 평탄화하므로, “N”이 묶음/기록 수처럼 읽힐 수 있다.
- legacy 사진은 bundleId가 없어 화면 좌표를 4% 단위로 반올림한 값으로 합쳐진다. 서로 다른 기존 사진이 근처에 있으면 한 핀으로 합쳐지고, 숫자는 그 사진 수가 된다. 이는 서버 계약의 ‘legacy 한 장 = 한 핀’과 다르며, 의도된 겹침 처리라면 별도의 ‘공간 클러스터’로 명시돼야 한다.

## 프런트가 따라야 할 기준

1. **핀 단위:** API의 `PhotoRecordBundleMapPin` 한 원소당 핀 하나.
   - 새 업로드는 사진 묶음 1개당 핀 하나.
   - legacy는 사진 1장당 핀 하나.
2. **핀 안 사진 탐색:** 핀을 열면 해당 `pin.photos`만 넘겨본다. 묶음은 여러 장, legacy는 한 장이다.
3. **상단 기본 숫자:** ‘맵에 기록 **N개**’라면 `filteredBundles.length`(핀/기록 단위)를 사용한다. 사진 총수도 표시할 필요가 있으면 `사진 M장`을 별도로 명시한다.
   - 권장 문구: `맵에 기록 4개 · 사진 9장`.
4. **마커 숫자:** 여러 사진을 가진 묶음에만 숫자를 쓰되, 숫자의 뜻을 카드/aria에 `사진 3장`으로 명확히 한다. 한 장은 위치 아이콘으로 유지한다.
5. **겹침 해결:** 서로 다른 bundle/legacy 핀은 ID 기준을 유지한다. 같은 화면 위치에서 클릭이 어렵다면 시각적 군집은 별도 상태/자료형으로 만들고, `기록 2개 · 사진 5장`처럼 두 수를 구분한다. 좌표 반올림을 ID로 써서 데이터 단위를 합치면 안 된다.

## 수정 지점

- `PhotoRecordMapView.tsx`
  - `pins` 상태에서 권역·시군 필터를 먼저 적용한 `filteredBundles`를 만든다.
  - 핀 렌더는 `filteredBundles`에서 직접 수행한다.
  - 상세 보기는 선택한 bundle의 `photos`를 그대로 사용한다.
  - 상단 문구의 기록 수와 사진 총수는 분리 계산한다.
  - `groupPins`의 legacy 좌표 반올림 병합은 제거하거나, 별도 ‘시각적 클러스터’ 계층으로 분리한다.
- `PhotoRecordAlbum.tsx`
  - `unplacedCount`는 여전히 사진 수로 계산하는 현재 방식이 맞지만, 문구에서 ‘사진’임을 유지한다.

## 회귀 QA

- 사진 3장 묶음 1개 + legacy 1장: 지도 핀/기록 수 2개, 사진 수 4장인지.
- 사진 3장 묶음 마커: 핀 하나, 배지 `3`의 뜻이 사진 3장임이 명확하고 상세에서 세 장만 넘겨지는지.
- 같은 시·군에 서로 다른 묶음 2개: 서로 다른 두 기록이 임의로 한 묶음으로 합쳐지지 않는지.
- 거의 같은 좌표의 legacy 사진 2장: 데이터 단위가 하나로 합쳐지지 않는지; 클러스터 UI를 둔다면 기록 2개/사진 2장 표시와 각 항목 접근이 되는지.
- 권역/시군 필터: 상단 기록 수·사진 수·마커·상세가 모두 같은 필터 결과를 쓰는지.
- 위치 없는 사진: 상단의 ‘표시하지 않는 사진 N장’은 사진 수이며, 기록 수와 혼동되지 않는지.
- 지도 핀 선택 후 사진 추가/삭제/캐시 갱신: 삭제된 묶음의 핀·상세가 사라지고 새 묶음은 핀 하나로 나타나는지.
- 모바일 360px 및 데스크톱: 겹친 핀·마커 배지·상세 캐러셀의 터치/키보드 접근성 확인.

## 판정

현재 새 묶음의 사진을 한 핀에서 넘겨보는 핵심 동작은 맞다. 다만 현재 숫자는 모두 사진 수이고, legacy 근접 사진을 좌표 반올림으로 합치는 방식 때문에 ‘묶음 수’ 기준으로 표시·조작하려는 다음 UI에는 그대로 쓰면 안 된다.
