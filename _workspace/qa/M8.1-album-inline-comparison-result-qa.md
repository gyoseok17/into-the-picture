# M8.1 앨범 내부 비교 결과 보기 QA

작성일: 2026-09-15
판정: 통과

## 계약·경로 교차 검토

- `PhotoComparisonOverlay`와 `PhotoComparisonLinks`는 더 이상 `Link`·`navigate`로 `/compare`를 열지 않고, 선택한 비교 ID를 `PhotoComparisonResultDialog`에 전달한다.
- 스토리(`PhotoBundleLightbox`)와 지도(`MapPhotoLightbox`) 모두 같은 `PhotoComparisonOverlay`를 사용한다. 지도 패널의 연결 수상작 목록도 같은 `PhotoComparisonLinks`를 사용한다.
- 새 결과 창은 기존 `ComparisonPlacementPair`를 재사용하므로 수상작·내 사진·`PHOTO_ONLY`의 기존 표시 계약을 유지한다. API 요청·DB·라우트·권한 경계 변경은 없다.

## 상호작용·회귀 검토

- 비교창은 포털의 `z-[100]`, 사진 확대창은 `z-[90]`이므로 모바일·PC에서 비교창이 최상위에 놓인다.
- Escape는 capture 단계에서 소비해 비교창만 닫고, 아래 사진 확대창의 Escape 처리까지 전파되지 않는다. 배경 클릭·닫기 버튼도 비교창만 닫는다.
- 닫은 뒤에는 `requestAnimationFrame`으로 연 수상작 미리보기/연결 항목 버튼에 초점을 복귀한다. 사진 확대창을 이후 닫을 때는 기존 사진 트리거로 복귀하는 흐름을 유지한다.
- 현재 사진의 비교 목록만 전달되므로 비교 없는 사진에는 진입 요소·빈 공간이 생기지 않는다. 여러 비교가 있으면 창 내부의 썸네일로 비교 대상을 바꾼다.

## 검증

- `npm run typecheck` 통과.
- `npm run build` 통과. 기존 Vite 500KB 청크 크기 경고만 비차단으로 발생.
- `git diff --check` 통과. 기존 작업 트리의 CRLF 경고만 출력.

## 수동 확인 권고

- 실제 브라우저에서 스토리와 지도 각각에서 `사진 확대 → 우측 하단 수상작 미리보기 → 비교창 닫기`를 수행해, URL과 앨범 스크롤·선택 사진이 유지되는지 확인한다.
- 비교 2건 이상인 사진에서 비교창 내 썸네일 전환과 모바일 터치 영역을 확인한다.
