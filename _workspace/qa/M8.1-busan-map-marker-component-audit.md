# M8.1 부산 지도 마커 컴포넌트 진단 QA

- 점검일: 2026-09-09
- 범위: 부산 마커의 실제 SVG 도형 위치, 좌표 검증 기준, 지도 안내문 제거 회귀

## 결론

사용자 피드백은 맞다. 현재 `BUSAN: point(70, 72)`는 경상 본토가 아니라 SVG가 별도로 그린 작은 남동 섬 도형에 놓인다. 퍼센트 좌표나 반응형 stage 계산의 오류가 아니라, 좌표 보정 검사가 같은 권역 안의 본토와 섬을 구분하지 못한 문제다.

## 근거

`AlbumMapSvg`의 경상 권역은 하나의 코드에 두 SVG path를 함께 연결한다.

| 구분 | SVG path | 렌더 PNG 연결 도형 | 현재 해당 도시 |
| --- | --- | --- | --- |
| 경상 본토 | `#C2D1BA`, `translate(853,504)` | 154,490px, x 470~900 / y 504~1169 | 대구·울산·김해 등 |
| 남동 작은 섬 | `#C2D0BB`, `translate(733,1081)` | 1,329px, x 696~735 / y 1081~1144 | 거제(적절), 부산·양산(부적절) |

- 부산 `(70,72)` → PNG `(717,1106)` → 남동 작은 섬
- 양산 `(70,73)` → PNG `(717,1121)` → 같은 작은 섬
- 거제 `(69,74)` → PNG `(707,1137)` → 같은 작은 섬이며 섬 위치이므로 적절

실제 상대 지리에서 부산은 울산의 남서, 김해의 북동에 있어야 한다. 본토 안의 `BUSAN: point(68,69)`은 이 관계를 유지하면서 본토 연결 도형에 놓이는 안전 후보다. 같은 이유로 양산도 본토 후보 `(69,67)`을 함께 검토해야 한다.

## 기존 161개 검사의 한계

기존 검사는 각 좌표가 배경이 아닌 해당 권역 색상에 있는지를 확인했다. 이 방식은 바다에 찍히는 문제는 막지만, 하나의 권역 코드 아래에 본토·도서 path가 여럿 있을 때 **잘못된 섬에도 통과**시킨다. 따라서 `161/161 도형 내부`는 필요조건이지만 실제 위치 정확성의 충분조건은 아니다.

## 후속 전수 보정 방식

1. SVG path를 권역뿐 아니라 `본토`, `거제`, `서남해 도서`, `제주`, `울릉도` 같은 의미 있는 component ID로 구분한다.
2. 각 시·군 코드에 허용 component를 선언한다. 예: 부산·양산은 `GYEONGSANG_MAINLAND`, 거제는 `GEOJE_ISLAND`.
3. 좌표 검증은 배경 여부와 함께 허용 component 일치까지 검사한다.
4. 해안·도서 도시는 인접 도시와의 상대 방향 앵커도 검사한다. 예: 부산은 울산보다 남서, 김해보다 북동이어야 한다.
5. 수정 전후에는 실제 앨범 SVG 위에 전체 좌표를 오버레이한 수동 감사표를 남긴다.

## 안내문 제거 UI 회귀

- 일반 지도 상태에서 표시하던 `맵에 기록 … / 장소를 기록한 사진 …` 안내문은 제거됐다.
- `unplacedCount`는 API·상위 호출 호환성을 유지한 채 화면에서만 사용하지 않는다.
- 사진이 전혀 없을 때의 빈 상태 안내, 권역·시군 선택, 사진 추가, 마커 선택·확대는 유지된다.
- 좌표표는 여전히 161개이며, PNG 배경 밖 좌표는 0개다. 단, 본 문서의 부산·양산 component 정확성 문제는 별도 보정 대상이다.

## 부산 최종 좌표(72,68) 독립 재검증

이전 본토 안전 후보 `(68,69)` 이후 사용자 승인에 따라 부산만 `(72,68)`로 다시 조정됐다. 이 항목은 앞선 보정 기록을 덮어쓰지 않고, 최종 승인값을 별도로 검증한 결과다.

- 소스 좌표: `BUSAN (72,68)`, `ULSAN (75,66)`, `GIMHAE (66,71)`.
- component-aware 검사: 161개 모두 지도 도형 내부이고, 부산·양산은 경상 **본토** 연결 component, 거제는 별도 도서 component로 확인됐다 (`161/161` 통과).
- 상대 위치: 부산은 울산보다 서쪽·남쪽, 김해보다 동쪽·북쪽이다. 즉 해안 도시 간 최소 상대 방향 앵커를 유지한다.
- 실행 개발 서버: `localhost:5173`에서 제공한 TypeScript 모듈에 `BUSAN: point(72, 68)`가 포함됐다. `.js` 요청의 200 응답은 Vite SPA fallback HTML이며 좌표 모듈이 아니었다.
- 산출물 격리: `frontend/src` 생성 JavaScript는 0개, 선언 파일은 허용된 원본 2개뿐이다. production bundle은 `(72,68)`만 포함하며 `(70,72)`, `(68,69)`는 포함하지 않는다.
- 검증: `npm run typecheck`, `npx vite build`, `git diff --check` 통과. Vite의 500kB 초과 청크 권고만 기존 비차단 경고로 남는다.

최종 판정: 통과. 부산 최종 좌표는 본토 component와 인접 도시 상대 위치를 모두 만족하며, 개발 서버와 production bundle이 동일한 최신 TypeScript 원본을 사용한다.
