# M8 스크롤 빠른 도구: 2동작 타원형 전환 QA

- 검토일: 2026-08-14
- 범위: 긴 결과 화면의 `ScrollAssist` 열린 상태
- 코드 변경: 없음 (QA 검토)

## 사용자 요구와 현재 구현의 차이

열린 상태는 메뉴 버튼을 남긴 채 왼쪽에 `위로 가기`, `검색/필터` 원형 버튼을 추가하는 3개 버튼 구조다. 따라서 **메뉴가 사라지고, 두 동작만 들어 있는 하나의 가로 타원형으로 늘어난다**는 이번 요구를 충족하지 못한다.

## 수용 기준

| 항목 | 수용 기준 | 현재 판정 |
| --- | --- | --- |
| 닫힌 상태 | 44 x 44px 이상의 메뉴 원형 버튼 하나만 보인다. | 통과 |
| 열린 상태 | 메뉴 아이콘은 보이지 않고, 위로 가기와 검색/필터 아이콘 두 개만 보인다. | 차단 |
| 형태 | 두 아이콘을 감싸는 단일 가로 타원형 표면이며, 각 아이콘은 최소 44 x 44px 터치 영역이다. | 차단 |
| 위치 | 오른쪽 하단 기준 위치를 유지하고, 열릴 때 왼쪽으로만 넓어진다. 모바일 하단 탭보다 위(`z-30`/bottom safe-area)다. | 부분 통과 |
| 메뉴 닫기 | 열린 타원형의 바깥 클릭 및 Escape로 닫힌 원형 상태로 돌아간다. | 부분 통과 |
| 키보드 초점 | 열리면 첫 동작(위로 가기)에 초점이 가고, Escape/바깥 클릭으로 닫히면 닫힌 메뉴 버튼에 초점이 돌아온다. | 차단 |
| 동작 보존 | 위로 가기는 reduced-motion 설정을 지키고, 검색/필터는 현재 위치에서 패널을 열며 목록·URL·무한 스크롤 상태를 건드리지 않는다. | 통과 |

## 구현 시 확인할 점

1. 열린 상태에서 기존 메뉴 `Button`을 렌더링하지 말고, 두 동작을 하나의 `rounded-full` 컨테이너 안에 둔다. 아이콘마다 별도 44px 버튼을 유지한다.
2. 메뉴를 다시 눌러 닫는 경로는 없어지므로, 열린 타원형의 바깥 클릭과 Escape가 닫기 경로가 된다. Escape 처리에서 `menuTriggerRef.current.focus({ preventScroll: true })`를 호출해야 한다. 바깥 클릭도 같은 닫기 함수를 사용한다.
3. 메뉴 버튼이 열린 동안 DOM에서 사라지므로, `aria-expanded`/`aria-controls`는 닫힌 버튼에서만 의미 있게 유지한다. 열린 컨테이너는 `role="group"`과 `aria-label="결과 빠른 도구"`로 충분하다. 실제 메뉴 키보드 규칙을 구현하지 않는 한 `role="menu"`는 사용하지 않는다.
4. 열린 순간 첫 버튼에 초점을 주고, 두 아이콘의 이름은 각각 `aria-label="페이지 맨 위로 이동"`, 화면별 `검색하기` 또는 `필터 변경`으로 유지한다.
5. 360px에서 두 44px 버튼과 내부 여백을 합친 폭이 오른쪽 여백을 기준으로 화면 밖으로 나가지 않는지, iOS safe-area와 모바일 하단 탭을 가리지 않는지 확인한다.

## 최종 판정

**구현 전 차단.** 현재 3개 원형 버튼 방식은 요구와 다르다. 위 수용 기준대로 열린 상태를 단일 2동작 타원형으로 바꾼 뒤, 360px/768px/1280px에서 클릭·키보드·safe-area를 재검증해야 한다.
