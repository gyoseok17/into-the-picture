# M8.1 사진 추가·삭제 완료 후 자동 닫힘: 현 상태 점검

작성일: 2026-08-29
범위: 읽기 전용 정적 점검. 코드 변경 없음.

## 현 상태

### 사진 추가

- **자동으로 닫히지 않는다.** `BatchPhotoUploadPanel.uploadPending()`은 묶음 저장 성공 시 항목 상태만 `success`로 바꾸고 캐시를 무효화한다.
- 이후 화면에는 `완료` 버튼이 나타나며, 사용자가 그 버튼을 눌러야 `onComplete()`이 호출된다.
- 스토리 추가 화면의 `onComplete`은 `PhotoRecordAlbum`에서 `setIsAdding(false)`다.
- 지도 시트의 `onComplete`도 `onAddComplete -> setIsAdding(false)`다. 따라서 사용자가 완료를 누르면 시트가 닫히고, 지도 컴포넌트가 유지되어 필터·확대 상태는 보존된다.
- 실패 시에는 닫히지 않고 실패 항목과 재시도 버튼을 유지한다. 이 동작은 적절하다.

### 사진 삭제

- **개별 legacy 사진 편집창:** `remove.mutate(..., { onSuccess: () => setEditing(null) })`로 성공 시 자동 닫힌다.
- **묶음/여러 건 선택 삭제:** 성공한 선택 키만 선택 집합에서 제거하고 결과 문구를 표시한다. 관리 모드는 유지하고 자동으로 닫히지 않는다. 409 비교 참조 충돌 또는 일반 실패가 섞일 수 있으므로, 현재 동작은 남은 실패 대상을 사용자가 볼 수 있게 한다.
- 묶음은 현재 관리 모드에서만 삭제한다. 단일 묶음 상세/편집 창은 없다.

## 자동 닫힘 적용 지점

1. `frontend/src/features/photo-record/components/BatchPhotoUploadPanel.tsx`
   - `uploadPending()`의 성공 분기와 캐시 무효화가 끝난 뒤 `onComplete()`을 호출하면 된다.
   - 호출 조건은 **전체 요청이 성공했을 때만**이다. 현재 bundle API는 한 요청의 파일을 트랜잭션으로 처리하므로 성공/실패가 섞이지 않는다.
   - 성공 후 `완료` 버튼과 상태 문구를 잠시 보여줄 필요가 있으면 지연 처리보다 toast를 사용하는 편이 상태가 단순하다.

2. 상위 연결은 이미 존재한다.
   - 스토리: `PhotoRecordAlbum.tsx`의 `BatchPhotoUploadPanel onComplete={() => setIsAdding(false)}`.
   - 지도: `PhotoRecordMapView.tsx`의 `MapUploadSheet onComplete={onAddComplete}` 및 상위 `setIsAdding(false)`.
   - 따라서 상위 API/상태 계약을 추가로 바꿀 필요는 없다.

3. 삭제는 현재 두 경로를 구분해야 한다.
   - 개별 편집창은 이미 성공 시 닫힌다.
   - 다중 삭제는 성공·409·실패가 섞일 수 있으므로 무조건 관리 모드를 닫으면 실패 항목을 잃는다. **선택한 모든 항목이 성공한 경우에만** 관리 모드를 닫고, 하나라도 충돌/실패면 유지하는 것이 안전하다.

## QA 체크리스트

- 사진 2~3장 묶음 저장 성공 → 스토리 추가 패널/지도 시트가 자동으로 닫히는지.
- 지도 시트 자동 닫힘 뒤 선택한 권역·시군, 지도 확대·포커스가 유지되는지.
- 저장 직후 React Query 무효화 후 새 묶음 카드·마커가 하나만 나타나는지.
- 파일 형식/네트워크 오류 → 화면이 닫히지 않고 실패 문구·재시도 버튼이 남는지.
- 저장 중 → 닫기, 바깥 클릭, 다시 저장이 계속 차단되는지.
- legacy 개별 삭제 성공 → 편집창이 닫히고 카드가 사라지는지.
- 선택 삭제 전부 성공 → 선택 수 초기화 및 (자동 종료를 적용할 경우) 관리 모드 종료.
- 선택 삭제에 비교 참조 409 또는 네트워크 실패 포함 → 관리 모드는 유지되고, 성공 항목만 선택 해제되며 결과 문구가 정확한지.
- `npm run build`, `git diff --check` 및 모바일/데스크톱 시트 흐름 확인.
