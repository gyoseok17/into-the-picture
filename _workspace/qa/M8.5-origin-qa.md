# M8.5 HTTPS 배포 Origin QA · 보안 검토

- 검토일: 2026-09-18
- 상태: 최종 통과

## 사전 계약·코드 대조

- Caddy는 `APP_DOMAIN` 사이트 주소를 사용하므로 실제 도메인 DNS가 EC2를 가리키면 HTTP→HTTPS 전환과 TLS 인증서를 처리한다.
- Compose는 backend `8080`을 호스트에 공개하지 않고 Caddy만 `80`/`443`을 공개한다.
- Compose가 backend의 `APP_AUTH_REFRESH_COOKIE_SECURE=true`를 강제한다. refresh 쿠키는 `HttpOnly`, `Secure`, `SameSite=Lax`, `/api/v1/auth` 경로로 생성된다.
- Spring CORS는 `app.cors.allowed-origins`를 명시 목록으로 사용하며 credentials를 허용한다. 따라서 운영값은 `https://<APP_DOMAIN>` 하나여야 한다.
- Kakao 서버 측 redirect URI 검증은 절대 URI, 쿼리·fragment·userinfo 없음, 경로 `/login`, 그리고 CORS 허용 origin과의 정확한 일치를 요구한다. 계약의 `https://<APP_DOMAIN>/login`과 일치한다.
- frontend는 backend `.env`를 읽지 않아 DB·JWT·외부 API 시크릿이 Caddy/frontend 컨테이너로 전달되지 않는다.

## 변경 검증

1. Compose backend 환경은 `APP_CORS_ALLOWED_ORIGINS: https://${APP_DOMAIN}`로 설정되어 있다. backend `.env`의 별도 CORS 값을 덮어쓰므로 운영 origin이 단일 원천으로 고정된다.
2. 이 Compose 경로가 주입하는 CORS origin은 `https://` 접두어만 사용한다. Spring CORS 설정과 `KakaoAccountClient`의 `/login` origin 검증이 같은 `CorsProperties` 목록을 사용하므로 `https://<도메인>/login`만 유효하다.
3. `APP_AUTH_REFRESH_COOKIE_SECURE=true` 강제, backend `expose: 8080`만 유지, frontend만 80/443 `ports`를 보유한 것을 확인했다.
4. frontend가 backend `.env`를 읽지 않으므로 DB·JWT·외부 API 시크릿이 이미지 실행 환경으로 노출되지 않는다. Compose 일반 `config` 출력은 시크릿을 펼칠 수 있으므로 `config --quiet`만 실행했다.
5. `docker compose -f docker-compose.yml config --quiet` 및 `git diff --check` 성공.

## 잔여 운영 확인

- EC2 `.env`의 `APP_DOMAIN`은 스킴·경로 없이 실제 도메인만 입력한다.
- DNS A 레코드가 EC2를 가리킨 뒤 Caddy TLS 발급을 확인한다.
- Kakao Developers 콘솔 Redirect URI를 `https://<APP_DOMAIN>/login`으로 등록한다.
- 실제 브라우저에서 로그인 후 refresh 응답의 `Secure`, `HttpOnly`, `SameSite=Lax`를 확인한다.

## 판정

- 차단 이슈 없음. M8.5 Origin 구성은 계약·보안 경계와 일치한다.
