# M8.1 사진 추가 시트 종합 UI QA 체크리스트

- 작성일: 2026-08-28
- 역할: QA·검토 (코드 수정 없음)
- 대상: 지도에서 여는 사진 추가 시트의 지역 표시, 사진 선택/재선택, 촬영일, 메모, 업로드 결과 및 모바일 흐름

## 검증 전제

- 선택 위치는 읽기 전용 정보이며 `지역 · 시군구`만 한 번 표시한다. `선택한 지역`처럼 의미가 중복되는 접두어는 표시하지 않는다.
- 사진 선택, 촬영일, 메모, 업로드는 하나의 작업 흐름으로 읽히되 각각의 목적과 현재 상태가 명확히 구분돼야 한다.
- 업로드 API, 파일 형식/최대 개수, 날짜 전송 계약은 기존 M8.1 계약을 유지한다.

## 차단 기준

1. 현재 지도 위치와 시트에 표시되는 위치가 다르거나, 위치가 중복·누락된다.
2. 파일을 재선택하거나 시트를 닫은 뒤 이전 대기열·날짜·메모가 의도치 않게 남거나 사라진다.
3. 업로드 진행 중 재선택/닫기/재시도로 동일 파일이 중복 POST 된다.
4. 실패 항목과 성공 항목을 구분할 수 없거나 실패 항목만 재시도할 수 없다.
5. 360px 폭 또는 모바일 키보드가 열린 상태에서 필수 조작이 가려진다.

## 체크리스트

### 1. 정보 구조와 지역 표시

- [ ] 시트 제목은 사진 추가 행동을 분명히 말하고, 위치는 제목과 경쟁하지 않는 보조 정보(아이콘/칩/짧은 텍스트)로 보인다.
- [ ] 위치는 `경기 · 수원`처럼 실제 선택값만 표시되며, 같은 위치가 레이블·도움말·입력 필드에 반복되지 않는다.
- [ ] 파일을 선택하기 전, 선택 후, 업로드 결과 상태 모두에서 같은 위치가 유지된다.
- [ ] 지도에서 선택 위치를 바꾼 뒤 시트를 다시 열면 최신 위치만 표시된다.
- [ ] 위치가 없는 진입 경로에서는 사진 선택/업로드가 시작되지 않고, 위치를 먼저 선택하는 다음 행동이 안내된다.
- [ ] 텍스트가 긴 지역명에서도 줄바꿈/말줄임이 버튼이나 닫기 조작과 겹치지 않는다.

### 2. 사진 선택과 대기열

- [ ] 첫 화면에서 사진 고르기 조작, 허용 형식, 최대 20장 제한이 한눈에 파악된다.
- [ ] 파일 선택 취소는 시트를 닫거나 기존 대기열을 초기화하지 않는다.
- [ ] JPEG, PNG, WebP, HEIC, HEIF의 1장·여러 장·20장 선택이 정상적으로 미리보기/대기열에 반영된다.
- [ ] 21장 이상 또는 허용하지 않는 파일은 명확한 사유와 함께 거부되며, 허용된 기존 항목은 보존된다.
- [ ] 파일명·썸네일이 긴 경우에도 삭제, 재선택, 항목 수가 읽히고 조작 영역이 눌릴 수 있다.
- [ ] 대기열이 없는 상태에서 업로드 버튼은 비활성 또는 필요한 행동을 안내하는 상태다.

### 3. 재선택과 개별 변경

- [ ] `사진 다시 고르기`는 목적이 분명하고 첫 선택 조작과 시각적 위계가 충돌하지 않는다.
- [ ] 재선택 시의 정책(전체 대체 또는 기존 목록에 추가)이 UI 문구 및 실제 동작과 일치한다.
- [ ] 재선택 후 선택 장수, 미리보기, 업로드 가능 여부가 즉시 갱신된다.
- [ ] 개별 사진 삭제 후에도 나머지 항목의 순서, 날짜/메모 적용 범위, 업로드 대상이 정확하다.
- [ ] 업로드 중에는 파일 선택·재선택·삭제가 중복 요청을 만들지 않도록 잠기거나 안전하게 안내된다.

### 4. 촬영일

- [ ] 촬영일은 사진 선택 영역과 분리돼 있으면서, 선택한 전체 사진에 적용되는 공통 값임을 이해할 수 있다.
- [ ] 날짜 입력은 `YYYY-MM-DD`만 받으며 시간 선택 UI가 노출되지 않는다.
- [ ] 날짜를 직접 지정하면 각 사진의 EXIF보다 우선하고, 요청값은 로컬 날짜 기준 `YYYY-MM-DDT00:00:00` 계약을 따른다.
- [ ] 날짜를 비우면 EXIF 또는 날짜 미지정의 기존 폴백 규칙으로 정확히 복귀한다.
- [ ] 날짜 오류/미래 날짜 제한 등이 있다면 오류 문구가 입력 근처에 표시되고 업로드 조건과 일치한다.
- [ ] 재선택·개별 삭제·실패 항목 재시도에서 날짜 값이 의도치 않게 바뀌지 않는다.

### 5. 메모

- [ ] 메모는 선택 사항임이 분명하며, 입력 목적과 적용 범위(이번 업로드 전체)가 혼동되지 않는다.
- [ ] 메모 미입력 상태에서도 업로드할 수 있다.
- [ ] 글자 수 제한·줄바꿈·붙여넣기·한글 조합 입력이 안정적이고, 제한 도달 시 현재 글자 수와 이유가 보인다.
- [ ] 재선택, 파일 삭제, 키보드 열기/닫기 후에도 사용자가 입력한 메모는 정책에 맞게 보존된다.
- [ ] 실패 항목 재시도 시 메모가 원래 요청값과 일치하며, 성공 항목에는 다시 전송되지 않는다.

### 6. 업로드 중·성공·실패와 재시도

- [ ] 업로드 시작 즉시 버튼과 대기열 상태가 `업로드 중`으로 바뀌어 중복 클릭을 막고, 진행 사실이 텍스트로도 전달된다.
- [ ] 진행 중 닫기 조작의 허용 여부와 결과가 명확하다. 허용하면 백그라운드 진행/취소 여부를 오해 없이 안내한다.
- [ ] 항목별 성공·실패·대기 상태와 전체 진행 상태를 구분해 확인할 수 있다.
- [ ] 일부 실패 시 성공한 사진은 다시 업로드되지 않으며, 실패한 항목만 재시도된다.
- [ ] 재시도 실패/네트워크 오류/서버 오류에서 사용자가 이해할 수 있는 오류 문구와 다음 행동(재시도 또는 닫기)이 제공된다.
- [ ] 모든 항목 성공 후 완료 동작은 시트를 닫고 지도/앨범의 새 기록을 중복 없이 갱신한다.
- [ ] 실패 후 시트를 닫았다가 다시 열 때의 대기열 보존/초기화 정책이 일관되고 안내와 일치한다.

### 7. 모바일·접근성·반응형

- [ ] 360×800, 390×844 세로 화면에서 제목, 위치, 사진 선택, 날짜, 메모, 업로드 버튼을 스크롤로 모두 도달할 수 있다.
- [ ] 모바일 키보드가 날짜/메모 입력을 가리더라도 현재 필드와 저장/업로드 조작으로 이동할 수 있다.
- [ ] 하단 안전 영역과 하단 내비게이션 위에 충분한 여백이 있어 고정 버튼이 가려지지 않는다.
- [ ] 가로 회전 후 시트 높이·내부 스크롤·닫기/업로드 버튼이 정상이다.
- [ ] 터치 대상은 충분히 크고, 썸네일 삭제/재선택/닫기 조작이 서로 겹치지 않는다.
- [ ] 키보드 Tab 순서, 포커스 트랩, Escape/닫기 후 포커스 복귀가 정상이며, 상태 변경은 스크린리더에 전달된다.

## 최종 통합 판정 조건

- 위 차단 기준이 모두 해소되고, 데스크톱과 모바일에서 최소 한 번씩 다중 파일 선택 → 날짜·메모 입력 → 일부 실패 → 실패 항목 재시도 → 완료 흐름을 확인한다.
- 브라우저 Network에서 파일별 POST 수와 재시도 대상이 대기열 상태와 일치하는지 확인한다.
- 구현 후 실제 결과, 발견 이슈, 판정은 이 파일 하단에 날짜와 번호를 붙여 누적한다.
