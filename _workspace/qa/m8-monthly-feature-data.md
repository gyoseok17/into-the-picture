# M8 홈 월별 대표작 데이터·계약 검토

- 검토일: 2026-08-14
- 범위: 읽기 전용. 수상작 촬영월 데이터, 공개 목록/상세 API 계약, 홈 대표 이미지 선택 방식.

## 실제 데이터 확인

- 실행 중인 로컬 API `GET /api/v1/contests?page=1&size=100&sort=filmMonth,asc`로 전체 95건을 확인했다.
- `filmMonth`가 비어 있거나 `null`인 작품은 0건이다. 모든 값은 `YYYYMM` 여섯 자리 문자열이다.
- 월별 작품이 1월부터 12월까지 모두 존재한다. 현재 8월 기준 후보는 4건(`202308`)이다.
- 현재 데이터의 최신 촬영월은 `202407`이며, 월 선택은 연도가 아닌 마지막 두 자리(`filmMonth.slice(-2)`)를 비교해야 한다. 현재 연도인 `202608`과 정확히 일치시키면 후보가 없다.

## 기존 API 계약

- 목록: `GET /api/v1/contests`는 `filmMonth`와 목록용 `thumbUrl`을 반환한다. 서버가 허용하는 최대 `size`는 100이고, 95건 전체를 1회에 가져올 수 있다. 기본 정렬은 `id,desc`; `sort=filmMonth,asc|desc`도 허용된다.
- 목록 필터에는 촬영월 파라미터가 없다. 따라서 현재 계약만 사용할 때는 1회 목록 수신 후 클라이언트에서 월 후보를 필터링해야 한다.
- 상세: `GET /api/v1/contests/{id}`는 동일 요약 필드와 함께 원본 `imageUrl`을 반환한다. 예시 응답에서 `thumbUrl`은 `..._image3_1.jpg`, `imageUrl`은 `..._image2_1.jpg`였으며, 홈 히어로에는 상세의 `imageUrl`을 쓰는 것이 맞다.

## 권장 동작

1. 홈에서 `size=100`의 수상작 목록을 1회 읽고, 현재 월의 `filmMonth` 끝 두 자리가 일치하는 후보만 만든다.
2. 후보 중 하나를 무작위 선택한다. 후보가 비어 있으면 전체 목록에서 무작위 선택한다. 데이터가 없는 경우만 기존 빈 상태를 보인다.
3. 선택된 `id`로 상세 API를 정확히 1회 호출하고, 히어로는 `detail.imageUrl`을 사용한다. 제목·장소 등은 목록값을 즉시 쓰고 상세 완료 뒤 이미지 URL만 교체해도 계약상 안전하다.

## 판정 및 위험

- 서버·DB·외부 연동 변경 없이 기존 공개 계약만으로 구현 가능하다.
- 목록 1회(최대 100개 요약) + 선택 작품 상세 1회라는 요청 구조는 적합하다. 상세를 후보 수만큼 호출하면 안 된다.
- 프런트의 현 `fetchContests`는 페이지 크기를 20으로 고정하므로, 홈 전용으로 `size`를 전달할 수 있는 API 호출 경계를 추가해야 한다. 기존 수상작 무한 스크롤 호출은 20건을 유지해야 한다.
- `filmMonth`는 촬영 시점일 뿐 계절의 정확한 여행 적합성 보장은 아니다. 표시는 '이달에 담긴 장면' 정도가 정확하다.
