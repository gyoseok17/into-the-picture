# M10 비교 결과 수정 UI QA

## 사전 계약 검토 (2026-09-20)

### 확인 대상

- 계약: `_workspace/contracts/M10-comparison-editing.md`
- 화면: `PhotoComparisonResultDialog`, `ComparisonCropEditor`, `ComparisonPhotoPickerDialog`
- API 훅: `useReplaceComparisonPhoto`, `useUpdateComparisonCrop`, `useDeleteComparison`

### 기대 흐름

1. 비교 결과 확대 팝업에서 `수정`을 누르면 별도 행동 선택 팝업을 거치지 않고, 현재 비교 사진과 현재 크롭값을 가진 크롭 편집 화면으로 바로 진입한다.
2. 크롭 편집 화면 안에서 사진 변경·결과 삭제·사진도 삭제를 선택할 수 있다.
3. 사진 변경은 앨범 사진 선택 또는 새 업로드 후 같은 크롭 편집기로 돌아와 `PATCH /me/comparisons/{id}`에 `userPhotoId`, `crop`을 함께 보낸다.
4. 크롭 저장은 `PATCH /me/comparisons/{id}/crop`에 `crop`만 보낸다.
5. 삭제는 확인 단계에서 두 선택지를 명확히 분리한다.
   - 결과만 삭제: 비교 연결만 삭제하고 앨범 사진은 유지한다.
   - 사진도 삭제: 비교 연결과 앨범 사진을 함께 삭제한다.

### 교차 검토 기준

- 수정 진입 직후 `actions` 중간 레이어가 보이지 않는가.
- 크롭 편집 중 사진 변경을 열고 닫아도 원래 크롭 편집 문맥으로 안전하게 돌아오는가.
- 사진 변경 후 선택 사진·신규 업로드 사진 모두 수상작 비율 크롭을 확정해야만 PATCH가 호출되는가.
- 사진 변경 PATCH와 크롭 PATCH의 요청 본문이 서로 섞이지 않는가.
- 성공 시 `comparisons`, 공개 비교, 앨범 관련 캐시가 필요한 범위로 갱신되는가.
- 실패 시 편집 화면을 닫지 않고 오류와 재시도 가능한 상태가 남는가.
- `Escape`, 배경 클릭, 닫기 동작이 가장 위 오버레이 하나만 닫고 부모 비교 결과 팝업을 의도치 않게 닫지 않는가.
- 중첩 오버레이의 z-index·스크롤 잠금·포커스가 충돌하지 않는가.
- 삭제 대기 중 중복 실행, 닫기, 사진 변경을 막는가.
- 기존 두 삭제 계약(`deletePhoto=false/true`)이 그대로 유지되는가.

### 사전 발견 사항

- 현재 `PhotoComparisonResultDialog`은 `수정 → actions → 크롭 변경`의 두 단계이며 계약 및 사용자 요구와 다르다.
- `ComparisonCropEditor`에는 사진 변경·삭제 진입점이 없어서, 수정 UI가 도착한 뒤 위 기준으로 최종 교차 검토가 필요하다.

## 최종 교차 검토 (2026-09-20)

### 확인 결과

- `수정`은 `editStep='crop'`으로 바로 전환된다. 이전 행동 선택 단계는 제거됐다.
- 크롭 편집기에 `사진 변경`, `삭제` 행동을 주입했다. 사진 변경은 기존 선택기 또는 새 업로드 뒤 새 사진의 크롭 편집으로 이어진다.
- 사진 변경 확정은 `replaceComparisonPhoto(id, userPhotoId, crop)`를 통해 `PATCH /me/comparisons/{id}`로, 현재 사진의 크롭 저장은 `updateComparisonCrop(id, crop)`를 통해 `PATCH /me/comparisons/{id}/crop`으로 분리되어 있다.
- 삭제는 별도 확인 오버레이에서만 `deletePhoto=false`(결과만 삭제)와 `deletePhoto=true`(사진도 삭제)를 선택한다. 기존 DELETE 계약과 서버 `PhotoComparisonService.delete`의 분기와 일치한다.
- 사진 교체·크롭·삭제 성공 뒤 비교 목록·공개 비교·앨범 관련 React Query 키를 무효화한다. 실패하면 결과 팝업을 유지하고 오류를 표시한다.
- 오버레이는 결과 `z-[100]`, 사진 선택 `z-[120]`, 크롭/로딩 `z-[130]` 순으로 쌓이며, 상위 오버레이의 배경 클릭은 하위 결과 팝업으로 전파되지 않는다.
- Escape는 상태별로 가장 위 화면 하나만 되돌린다: 삭제 확인→크롭, 사진 선택→크롭, 교체 크롭→사진 선택, 크롭→결과 팝업. 이전에 발견한 삭제 확인 Escape 회귀는 수정됨을 코드로 재확인했다.
- 대기 중에는 크롭 저장·사진 변경·삭제 버튼이 함께 비활성화되어 중복 요청을 막는다.
