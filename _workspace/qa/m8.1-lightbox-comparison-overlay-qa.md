# M8.1 스토리 라이트박스 비교 연결 오버레이 QA

작성일: 2026-09-04
상태: 구현 전 계약 검토 완료 · 최종 검증 대기

## UI 계약

- 비교 연결된 현재 사진일 때만 결과 진입 링크가 이미지 위 오버레이로 표시돼, 라이트박스를 열자마자 스크롤 없이 보인다.
- 비교 연결이 없는 현재 사진, 또는 묶음의 다른 사진을 보고 있을 때는 오버레이·빈 자리·수상작 문구가 렌더링되지 않는다.
- 오버레이 링크는 현재 사진의 `PhotoComparisonLinks`와 같은 비교 ID/`contestId`를 사용해 `/compare?contestId=<id>` 결과를 연다.
- 닫기, 이전/다음 사진, 썸네일 선택은 기존대로 동작한다. 사진을 전환하면 오버레이도 개별 사진 연결 상태에 맞게 즉시 갱신된다.
- 모바일에서는 오버레이가 이미지 안에서만 배치되고, 닫기/화살표/썸네일/하단 safe area와 겹치거나 화면 밖으로 밀리지 않는다.

## 점검 항목

- [ ] 현재 사진의 `photo.id`로 비교를 찾으며 묶음 전체 비교를 합산하지 않는다.
- [ ] 일반 사진의 라이트박스는 기존 레이아웃과 스크롤 동작을 유지한다.
- [ ] 비교 연결 링크가 이미지 오버레이 내부에 있고, 카드 하단에 중복 링크가 남지 않는다.
- [ ] 오버레이는 키보드 포커스 가능 링크와 읽을 수 있는 이름을 가진다.
- [ ] 지도 `PhotoRecordMapView`의 비교 배지·링크는 변경되지 않는다.
- [ ] `tsc -b`, `git diff --check`를 수행한다. Vite 샌드박스 실패는 코드 실패와 분리해 기록한다.

## 차단 기준

- 연결된 현재 사진에서 결과 링크를 보려면 라이트박스를 스크롤해야 한다.
- 연결되지 않은 사진에 오버레이가 보이거나, 사진 전환 뒤 이전 사진의 링크가 남는다.
- 링크가 잘못된 수상작 결과로 이동하거나 모바일 조작 요소/safe area와 겹친다.
## 최종 소스·타입 검증 (2026-09-04)

### 통과

- 라이트박스는 현재 인덱스의 `photo.id`로 `photoComparisons`를 계산하고, `PhotoComparisonOverlay`에만 전달한다. 연결이 없는 현재 사진에서는 오버레이가 `null`이라 일반 사진에 빈 영역이 남지 않는다.
- 오버레이는 이미지의 `relative overflow-hidden` 컨테이너 안쪽 하단에 배치된다. 비교 수상작 제목과 결과 보기가 스크롤 없이 보이고, 하단의 기존 `PhotoComparisonLinks`는 라이트박스에서 제거됐다.
- 오버레이 링크는 `/compare?contestId=<현재 사진 연결 수상작>`을 사용하며 포커스 가능한 `Link`와 포커스 링을 가진다.
- 이전/다음·썸네일로 인덱스를 바꾸면 `photoComparisons`가 다시 계산되어 이전 사진의 링크가 남지 않는다. 닫기·Escape·배경 닫기와 썸네일 목록은 기존 흐름을 유지한다.
- 지도 `PhotoRecordMapView`는 기존 `PhotoComparisonBadge` 및 `PhotoComparisonLinks`를 그대로 사용해 지도 결과 진입 회귀가 없다.
- `tsc -b` 통과, `git diff --check` 공백 오류 없음(LF/CRLF 경고만 출력).

### 수동 확인 항목

- 실제 320px 모바일에서 이미지 오버레이와 닫기·전환 버튼·썸네일이 모두 safe area 안에 보이는지 확인한다. 소스상 오버레이는 이미지 안에 한정되고 하단 내비게이션보다 높은 dialog 레이어(`z-[90]`)에 있어 충돌 경로는 없다.

### 최종 판정

**통과. 차단 이슈 없음.**
