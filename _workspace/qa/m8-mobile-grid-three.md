# M8 모바일 사진 3열 설정 QA 기준

## 검토 범위

- 대상 화면: 수상작 목록(`/contests`)과 키워드 사진 검색(`/explore`).
- 변경 예정: 공통 모바일 열 설정을 `1 | 2`에서 `1 | 2 | 3`으로 확장한다. 기본값과 저장 키는 기존 `2`, `into-the-picture:mobile-grid-columns`을 유지한다.
- 제외: 데스크톱(`sm` 이상) 열 수, API·URL·무한 스크롤·앨범 묶기 규칙은 변경하지 않는다.

## 360px 수용 기준

- 본문 좌우 여백 16px와 그리드 간격 12px 기준으로 3열 카드 폭은 약 101px이다. 이 크기에서도 사진 비율은 유지하고 가로 스크롤·카드 겹침·이미지 찌그러짐이 없어야 한다.
- 3열은 사진을 빠르게 훑는 밀도 선택지다. 카드 제목·장소는 각각 한 줄 말줄임을 유지하고, 두 줄 제목이나 긴 장소명이 카드 높이·다음 카드 위치를 밀어서는 안 된다.
- 수상작 카드의 등급·하트 등 보조 정보가 101px 폭에서 겹치거나 잘려서는 안 된다. 불가피하면 3열에서만 덜 중요한 보조 텍스트를 숨기되, 작품 제목과 카드 전체 선택 기능은 남긴다.
- 앨범 카드의 사진 수·장소 정보도 제목과 겹치지 않아야 한다. 제목과 사진 수가 함께 보이지 않는 경우에는 제목을 우선한다.
- 카드 전체가 상세/앨범 열기 버튼으로 계속 동작해야 하며, 최소 44×44px 이상의 실제 터치 영역을 유지한다. 시각적으로 좁아도 카드 이미지와 텍스트 영역 전체를 누를 수 있어야 한다.

## 설정 UI 수용 기준

- `1열`, `2열`, `3열`은 모두 실제 버튼이며 현재 선택 항목에 `aria-pressed=true`가 설정된다. 각 버튼은 아이콘만으로 구분하지 않고 접근 가능한 이름에 열 수와 의미를 포함한다.
- 360px에서 결과 제목, 전체 보기 링크, 3개 열 설정이 한 줄 강제로 겹치거나 화면 밖으로 넘치지 않아야 한다. 필요하면 설정을 다음 줄로 내리되, 검색어·전체 보기 동작을 가리지 않는다.
- 토글 버튼은 각 항목이 최소 32px 높이와 충분한 가로 여백을 갖고, 키보드 포커스 링이 세 항목 모두에서 보여야 한다.

## 공통 상태·회귀 수용 기준

- 설정은 두 대상 화면에서 같은 값으로 즉시 반영되고, 새로고침 후에도 유지된다. 이미 저장된 `"1"`, `"2"` 값은 그대로 호환한다.
- 저장소 값이 없거나 `"1"`, `"2"`, `"3"` 이외의 값이면 안전하게 기본값 `2`로 복원한다. localStorage 차단 시에도 화면은 2열로 정상 렌더링된다.
- 수상작 목록의 일반/로딩 스켈레톤과 검색 결과의 일반/로딩 스켈레톤이 모두 같은 열 수를 사용한다.
- 사진 검색의 페이지별 앨범 묶기, 앨범 상세 모달, 관련 키워드 재검색, 무한 스크롤 sentinel은 열 수 변경과 무관하게 유지된다.
- 수상작 목록의 지도 보기와 데스크톱 `sm:grid-cols-*` 규칙은 영향을 받지 않는다.

## 최종 확인 항목

1. 360px에서 수상작 목록: 1/2/3열 전환, 긴 제목, 하트, 상세 진입을 확인한다.
2. 360px에서 키워드 검색: 1/2/3열 전환, 긴 앨범명·장소, 앨범 모달과 키워드 재검색을 확인한다.
3. 768px 이상에서 두 화면이 기존 데스크톱 열 수로 렌더링되는지 확인한다.
4. `localStorage`에 각각 `1`, `2`, `3`, 잘못된 값이 있을 때 초기 열 수와 양쪽 화면 동기화를 확인한다.
5. 로딩 중과 다음 페이지 로드 중에도 열 수 변경 후 레이아웃이 깨지지 않는지 확인한다.

## 판정

- 코드 변경 전 사전 검토 기준이다. 3열은 360px에서 읽기보다 사진 훑기를 우선하는 선택지로 수용 가능하다.
- 차단 조건: 카드 내 핵심 정보 또는 조작 요소의 겹침, 44px 미만의 실제 터치 영역, 설정 UI의 가로 넘침, 두 화면 사이 저장값 불일치가 하나라도 남으면 통합 불가다.
